# 语学星 Phase 1 开发实施总纲与功能链条任务分解

> 版本：v1.0  
> 建立日期：2026-08-20  
> 适用范围：Phase 1（18+ 成人与大学生、规则化学习闭环）  
> 权威基线：`AGENTS.md`、`requirements/feature-matrix.md`、`requirements/acceptance-criteria.md`、`docs/09-roadmap/roadmap.md`、`docs/06-design/detailed-specs/01~09`

## 1. 这份文档解决什么问题

设计文档是施工图，本文件把施工图转换为 Agent 可以认领、开发、提交、验收和回滚的最小任务单元。任务按“学习目标 → 练习 → 反馈 → 复习 → 掌握/报告”主链拆分，再接入内容供应链、用户服务、成长激励和商业化运营链。

本版本固定：

- **14 个开发章节**
- **140 个开发任务**
- **7 个执行批次（B0~B6）**
- 8 份业务详细设计的 171 个功能点全部挂接到任务的 Feature Ref；横向能力挂接到全局任务
- Phase 1 明确不实现 LLM、AI 评分、AI 数字人、实时 AI 语音、RAG、K12/未成年人入口

Feature Ref 中的 `A..B` 表示闭区间，例如 `FEAT-VOC-001..004` 表示 001、002、003、004 四项功能。

## 3. 功能链与批次依赖

### 3.1 主学习闭环

`DEV-00/01 → DEV-02/03 → DEV-04/05 → DEV-06/07 → DEV-12 → DEV-13`

其中首日可用的最小路径是：

`DEV-02-001/003/004/005/006/007/008 → DEV-03-008 → DEV-05-001/004/006/007 → DEV-04-003/004/005/012 → DEV-05-008/009/012`

这条路径必须先打通，才能把“有设计”变成“可学习、可反馈、可复习、可复盘”的产品。

### 3.2 内容供应链

`内容模型 → 导入/校验 → 版权与来源 → 草稿预览 → 双审发布 → 学习端可见 → 下线/恢复`

对应任务：`DEV-03-001~010`、`DEV-11-002~004`、`DEV-13-007`。

### 3.3 用户与实时服务链

`身份/设备 → 自习室/通知 → 离线队列 → 增量同步 → 冲突解决 → 客服/审计`

对应任务：`DEV-02-001~002`、`DEV-09-001~012`、`DEV-11-009~010`。

### 3.4 交易与权益链

`商品/套餐 → 收银台 → 渠道验签 → 订单幂等 → 权益生效 → 到期/退款 → 财务对账`

对应任务：`DEV-10-001~010`、`DEV-11-007~008`、`DEV-13-003/006/007`。

### 3.5 成长与激励链

`学习事件 → XP/Streak → 游戏/星系 → Avatar/奖励 → 数据回链`

对应任务：`DEV-08-001~009`，它们依赖学习核心事件，但必须由 Feature Flag 控制，不能阻断主学习链。

## 6. Agent 任务执行规则

1. **先认领再开发**：Agent 只能认领状态为“未开始”的任务；认领时填写 Agent、分支/PR、开始时间和预计完成批次。
2. **契约先行**：涉及 API、事件或数据结构的任务，先提交 `packages/contracts/` 和迁移，再写服务与页面。
3. **单任务可验收**：每个任务必须能指向代码、契约、迁移、测试、截图/日志或运行报告；只改文档不算业务任务完成。
4. **不跨越依赖**：依赖未完成时只能做设计/夹具准备，并将任务标为“阻塞”，不能标为“已完成”。
5. **主学习链优先**：任何游戏、社群、商业化任务不得让登录、测评、练习、反馈、复习和报告变得不可用。
6. **Phase 1 边界**：不得把 AI 评分、LLM、实时 AI 对话、K12/未成年人入口写入实现；若发现需求冲突，创建 ADR/阻塞记录。
7. **完成不是自报**：Agent 完成后先改为“待验收”；统筹 Agent 或评审人核对证据后，才改为“已完成”。
8. **证据最小集**：API/事件任务要有契约测试；DDL 任务要有空库和存量库迁移证据；页面任务要有关键端截图或自动化结果；安全/弱网任务要有专项报告。
9. **回滚可追踪**：数据库、支付、发布、权限、内容和同步任务必须写明回滚或补偿路径。
10. **状态报表是唯一任务状态源**：任务标题、依赖和 Feature Ref 以本文件为基线；实际状态、负责人、证据和阻塞以《Agent 开发状态总报表》为准。

## 9. 统筹 Agent 的每日动作

- 从状态报表筛选“依赖全部已完成、优先级最高、未开始”的任务，生成下一轮认领列表。
- 每个任务只允许一个主 Agent；跨域任务指定一个主 Agent 和最多两个协作 Agent。
- 每次状态变化必须写证据路径、测试命令/结果和下一步；“进行中”超过一个工作日自动提醒。
- 每日检查阻塞任务：依赖缺失、契约冲突、迁移冲突、平台权限、第三方沙盒或测试环境问题分别归类。
- 每个批次结束执行 Gate；Gate 未通过时，相关下游任务自动保持“阻塞/待开始”，不得靠口头确认放行。
- 每周从任务报表生成：总进度、按章节进度、P0 未完成数、阻塞 Top、待验收数、变更任务数和上线风险。
