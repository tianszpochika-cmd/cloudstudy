## 2. Agent 更新协议

### 2.1 认领

Agent 先把目标行更新为：

`状态=已认领；Agent=姓名/线程 ID；分支/PR=...；开始=YYYY-MM-DD HH:mm；预计批次=B...`

认领前必须确认所有前置任务均为“已完成”。若只需要等待接口或夹具，应保持“已认领”，并在“阻塞/下一步”写明等待项。

### 2.2 开发中

至少在以下节点更新一次：契约提交、迁移提交、核心逻辑完成、测试开始、准备验收。每次只改自己的任务行，并追加一条更新日志。

### 2.3 待验收

必须同时提供：

- 代码路径或 PR/Commit；
- `packages/contracts/` 变更（如任务涉及 API/事件）；
- `database/mysql/migrations/` 变更（如任务涉及数据）；
- 测试命令与结果；
- 截图、录屏、日志、报告或可复现步骤；
- 已知限制、回滚方式和下游影响。

### 2.4 验收完成

主 Agent/评审人核对 DoD 后，把状态改为“已完成”，填写验收人、完成时间和合入记录。只有“已完成”任务才能解除下游依赖。

### 2.5 阻塞与返工

阻塞格式：

`阻塞类型=依赖|契约|迁移|环境|权限|平台|第三方|数据|合规；影响=...；下一步=...；责任人=...；预计解除=...`

返工必须链接失败证据，不能直接覆盖原有验收结论。

## 3. 表格字段解释

- **Feature Ref**：来自详细设计的功能编号，不得改名或自造编号。
- **依赖**：只写任务 ID；依赖未完成不能进入“进行中”。
- **Agent**：填写线程昵称 + Agent ID，便于追踪。
- **PR/Commit**：填写分支、PR 或提交哈希；未进入版本库时填工作区路径。
- **证据**：填写测试报告、截图、日志、契约 diff、迁移演练等链接/路径。
- **阻塞/下一步**：必须给出下一步动作，不得只写“等待”。
- **最近更新**：使用北京时间 `YYYY-MM-DD HH:mm`。
