## 2. 资产处理标签

| 标签 | 含义 | 允许动作 | 禁止动作 |
|---|---|---|---|
| `REUSE-VERIFY` | 结构和意图基本符合新基线 | 保留代码，补契约、测试和当前 Evidence | 直接继承旧完成状态 |
| `REPAIR` | 有可用主体，但存在契约、owner、状态或质量差距 | 小步修正并做兼容/迁移 | 在旧接口上继续堆叠冲突语义 |
| `REWRITE` | 实现与正式边界根本冲突或无法安全迁移 | 在新契约下替换，保留迁移窗口和回滚 | 无审计删除旧事实或一次性大爆炸切换 |
| `NEW` | 设计已确定但没有可用实现 | Contract/Data/Security first 新建 | 复制其他服务事实或建立第二套 owner |
| `HISTORICAL` | 只保留审计、迁移或旧证据价值 | 链接、对照、标记 superseded | 作为当前验收或执行入口 |
| `PHASE-GATED` | Phase 2/3 或生产能力未开放 | 隔离、默认关闭、验证不可达 | 放入 Phase 1 默认路由 |

## 4. 必须优先解决的结构问题

1. 清理被 Git 跟踪的编译产物和生成缓存，补 `.gitignore` 与 CI 防回归；不得删除源代码或唯一证据。
2. 处理 `apps/miniapp-wechat` 的历史边界，确保四项目冻结规则在目录、构建和文档中一致。
3. 统一 Java 25、Spring Boot 4.1.x、Node/pnpm 和容器工具链；Windows/Linux 命令不得依赖 shell 通配符偶然展开。
4. 将 CI 的分支、缓存、构建、测试、契约、安全和证据检查改为真实门禁，不保留 `echo` 式占位成功。
5. 将事件目录统一为 Kafka + AsyncAPI + Outbox；RabbitMQ/Redis Streams 只保留明确的 v1 历史兼容语义。
6. 将多套部署目录收敛为单一事实源，并在 D5 前证明所有目标服务的镜像、配置、凭据、探针和回滚责任。

## 5. 现有代码的复用判断流程

```text
找到候选代码
  → 对照当前 JNY/PAGE/RULE/INT/E2E 与 owner
  → 对照 OpenAPI/AsyncAPI/schema/policy
  → 运行当前提交的最小测试
  → 分类 REUSE-VERIFY / REPAIR / REWRITE / NEW
  → 在任务 Evidence 中记录理由
  → 通过对应 Gate 后才允许合并
```

如果候选实现依赖客户端 role/tenant/owner、共享表写入、内存唯一事实、Kafka RPC、旧 OIDC、未授权内容、生产支付默认开启、Phase 1 AI/K12 或第二套页面/API owner，默认不得标记 `REUSE-VERIFY`。

## 6. M0 结束时必须形成的基线

- 当前提交、工具链、端口和依赖锁可重复；
- 所有主要资产具有复用标签和 owner；
- 旧任务/证据已建立只读映射且全部标记 `historical-candidate`；
- 代码库无被跟踪的临时构建产物，CI 对 `dev/master` 真实执行；
- 合成账号、内容、订单、音频元数据和隐私夹具可安全复现；
- 任务、状态、Evidence 目录和计划校验器可以阻止漏追溯和虚假完成。
