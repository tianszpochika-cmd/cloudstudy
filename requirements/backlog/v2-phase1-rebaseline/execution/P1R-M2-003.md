# P1R-M2-003 — 领域服务 Resource Server PEP 与默认拒绝扩展

状态：`IN_PROGRESS`

追溯：`ARCH-SEC-001`、`ARCH-SVC-001`；依赖 `P1R-M2-001`、`P1R-M2-002`（均已 `ACCEPTED`）。资产策略：`REPAIR`（复用/修复 B-era 实现，不新造平台）。

## 1. 任务目标与最小退出证据

把 Resource Server PEP、`owner/tenant/phase/rights/consent` 默认拒绝扩展到 `service-template` + 11 个领域服务（learner、content、learning、assessment、media、gamification、social、commerce、notification、analytics、admin-ops）。

最小退出证据（台账口径）：
1. **每服务 JWT 校验与授权负例**：缺 token/坏签名/过期/错误 issuer/aud/alg、权限不足、owner/tenant 不匹配、phase/consent/rights 不满足均默认拒绝。
2. **客户端角色头/tenant/owner 不扩大权限**：伪造授权头必须被显式拒绝（403/400），绝不参与授权事实。
3. **PDP 异常 fail closed**：策略缓存未命中/过期、PDP 超时/未实现/版本不匹配、撤销状态未知，一律拒绝。

范围边界：不实现 durable audit/NetworkPolicy/HA（归 M2-006/008/010/M8-013）；不改冻结契约（如需改契约遵循 contract-first）；Phase 1 不引入 OIDC/OAuth 或第三方 IdP。

## 2. 现状盘点（2026-09-11 只读调研）

- 11 服务均已有 `spring-boot-starter-oauth2-resource-server` 与 `anyRequest()` 默认拒绝，但实现分成 3 个复制粘贴族谱；`service-template` 的 `security/` 基线组件（`PepGuard`/`LocalPolicyEvaluator`/`PolicyCache`/`PdpPort`/`ClientAuthorityHeaderFilter`/`WorkloadIdentityFilter`/`VerifiedJwtAuthenticationConverter` 等）**零复用**。
- 高危排序：
  1. `assessment-service`：无 AccessPolicy/PEP/权限模型，仅 controller 内联 tenant 与 session ownership。
  2. `learning-service`：principal 解析硬编码 `ConsentState.GRANTED` 与整套固定 permissions（consent/权限事实不来自 JWT），域 PEP 被绕过（fail-open）。
  3. `content-service`：无统一 PEP，admin 授权散落 controller；tenant 固定 `platform`。
  4. `notification-service`：无客户端授权头拒绝过滤器，无统一 401/403 错误通道。
  5. `commerce-service`：客户端头静默剥离而非显式拒绝；callback 鉴权语义待明确。
  6. `learner/media/social/admin-ops/analytics/gamification`：已有较完整本地策略，但普遍缺 PDP fail-closed 路径与 JWT/头负例；social 的 tenant 缺失回退 `platform` 需改 fail-closed。
- 死配置：`learner/learning/assessment` 的 `pdp-timeout/policy-cache-ttl`、`assessment.security.default-deny` 无消费方。

## 3. 实施方案（模板参照 + 逐服务就地修复）

采用**逐服务就地修复**（保持现有服务边界与依赖，不新建跨服务共享库/模块；`service-template` 组件作为参考实现拷贝并对齐）。若后续决定抽取共享安全模块，另立 ADR 与新任务。

- **Batch 0 测试基座**：为每个服务补 `spring-security-test`，沉淀 MockMvc + 自签 RS256 JWT 夹具模板（缺 token、坏签名、过期、错误 issuer/aud/alg、权限不足、伪造头、策略/PDP 异常）；先在一个代表服务（learner）跑通并复制模板。
- **Batch 1（最高危）**：`learning-service`（移除 `phaseOne()` 的 consent/permissions 硬编码，改从已验证 JWT + 本地策略派生并默认拒绝）、`assessment-service`（新建统一 PEP、权限模型与默认拒绝矩阵）、`content-service`（统一 PEP 收敛 admin 内联判断，tenant/phase/consent/rights 默认拒绝）、`learner-service`（接入 PDP fail-closed 路径，清理死配置）。
- **Batch 2**：`media-service`、`social-service`（tenant 缺失改显式拒绝）、`admin-ops-service`；补 HTTP JWT/头负例与策略失败关闭测试。
- **Batch 3**：`notification-service`（新增头拒绝过滤器与统一 401/403）、`commerce-service`（头显式拒绝、callback 鉴权明确 fail-closed）、`analytics-service`（补 owner 级 PEP）。
- **Batch 4**：`gamification-service`（tenant/phase/consent/rights 扩展与头集合补全）。
- 每批收尾：删除对应死配置、跑该批服务 Maven 全套（JDK 25）、记录执行日志；全部完成后按验收标准准备运行证据与独立复审。
