## 目标与退出条件

冻结 Phase 1 每服务数据所有权、迁移和保留 D2 政策。退出前必须同时满足：

1. Gateway、IAM、audit/workflow 和 11 个领域服务全部进入唯一矩阵；有数据的服务各自拥有唯一 schema、运行凭据、Flyway location 和回滚责任，Gateway 明确无业务 schema/write authority；
2. 每个服务 Redis namespace 唯一且 Redis 永不作为学习、订单、身份、权限或审计的唯一事实源；历史 `core-api.*` key owner 具备目标 owner 和迁移责任；
3. Phase 1 tenant 只能由服务端派生，租户表与唯一键/索引必须包含 `tenant_id`，数据访问必须受 `TenantScope` 约束；不得声称 MySQL 自动提供行级隔离；
4. 每个 owner 具备数据分类、retention policy、删除/匿名化、legal hold 和跨 owner receipt 责任；精确业务期限由具名政策决定，不允许由 Redis TTL 代替；
5. 空库、存量库、前向修复、失败恢复、回滚/补偿、owner grant 对账和兼容窗口策略明确；破坏性 down migration、跨服务 SQL join/write、共享 ORM entity 和 Gateway/core-api 新写默认禁止；
6. owner/schema/namespace 唯一性、migration 命名/责任、候选资产映射和失败关闭负例可机器检查，专项测试与独立终验通过。
