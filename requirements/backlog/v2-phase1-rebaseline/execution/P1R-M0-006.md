## 阻塞

`GHSA-fx2h-pf6j-xcff` 要求 Vite >= 6.4.3，而当前可用的 `@dcloudio/vite-plugin-uni` Vue3 编译器族仍声明精确 Vite 5.2.8 peer。强制跨 major 覆盖会把安全问题变成不受支持的构建/运行风险，因此没有添加豁免，也没有伪造绿色结果。

集成结论：`BLOCKED`。解除条件是 DCloud 发布官方兼容的编译器族，或项目通过独立 ADR、全平台回归和安全评审批准替代路线；之后必须重跑 H5/App/mp-weixin、B10/B11/B12 与供应链 Gate。

### 2. 附带发现的真实缺陷

`package.json` 的 `pnpm.overrides`（5 条）自工作区使用 pnpm 10 起被**静默忽略**——pnpm 10 已把该字段迁移到 `pnpm-workspace.yaml`，启动时输出 `The "pnpm" field in package.json is no longer read by pnpm`。

失效条目及其目标恰是本次审计的报告对象（`@dcloudio/uni-cli-shared>@intlify/core-base: 9.1.11`、`@dcloudio/uni-cli-shared>adm-zip: 0.6.0`），说明**依赖治理机制自工具升级后长期失效且无人察觉**。本任务一并修复（Phase 1.4）。

### 4. 迁移面评估（风险定位）

- `apps/mobile/src`：**93** 个源文件；真实 `uni.*` API 调用 **0**、`<uni-*>` 组件 **0**、条件编译指令 **0**；原生能力全部经 `src/platform/uni-runtime.ts`（149 行，仅用 uni 公开稳定 API）访问。
- 依赖变更面收敛为 4 个包（`@dcloudio/*` 锁步 + `vite` + `@vitejs/plugin-vue` + `@vitejs/plugin-legacy`）。
- `@dcloudio/types` 两线同为 `3.4.31`；Node 要求 `^20.19.0 || >=22.12.0` 由项目 **20.19.5** 满足；`vue 3.5.41` 不动。
- **风险集中在两处贴编译器内部的 shim**：`vite.config.ts` 的 `vue → src/compat/vue.ts` 别名，以及 `vue-router-public-entry` 插件。`compat/vue.ts` 当前手工补齐 4 个 Vue 内部符号（`isInSSRComponentSetup`、`onBeforeActivate`/`onBeforeDeactivate`、`injectHook`、`createVueApp`）——此类 shim 是跨代升级最可能失效的部分。
