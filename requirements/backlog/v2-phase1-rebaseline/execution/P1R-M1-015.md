## 目标与验收

- 冻结 commerce-service 对 SKU/catalog、price snapshot、order/payment attempt、callback receipt、activation redemption、entitlement ledger、refund 与 reconciliation case 的唯一事实所有权；客户端成功页、Gateway、content、learning、support 或 workflow 不得授予或改写权益。
- 冻结 Phase 1 provider 边界：仅 `SANDBOX_HMAC`可用，`productionPaymentEnabled=false`、`autoRenewalEnabled=false`、live provider/credential/route/traffic 不可达；readiness 不得把已编译枚举当作可用渠道。
- 冻结 callback 签名覆盖、时间窗、nonce/key 旋转、`tenant + provider + providerEventId`去重、同 event 不同 digest 冲突、order/paymentAttempt/provider/amount/currency/result 绑定；坏签名、过期/未来回调、重放、乱序和金额不符不得激活权益。
- 冻结激活码明文短暂输入、SHA-256 digest-only 持久化、原子一次兑换、限流/冷却、主体/tenant/SKU/有效期绑定与 opaque redemption reference；raw code/hash/hash prefix 不得进入事件、审计或 entitlement sourceRef。
- 冻结版本化 entitlement snapshot/ledger、content/learning 自身 PEP 的只读查询与短时安全缓存、单调 version/invalidation/tombstone 与失败关闭；GRACE 默认为零，只允许最近已验证 ACTIVE 的服务端有界政策，refund/revoke/expire/security/unknown 永不 grace。
- 冻结退款/撤销/到期、对账差异、受控人工恢复、双人审批、precondition version、不可变 receipt/audit 与 post-recovery rerun；退款只降级访问，不删除合法学习记录。
- 建立 canonical B13 OpenAPI、commerce v2 事件、AsyncAPI/B26 static binding、generated TypeScript、source-bound compatibility、专项 checker 和对抗测试；只在全部静态证据和独立终验通过后关闭 `CONTRACT-GAP-COM-001`。
- 所有结论只能是 `D2_CONTRACT_READY` / `NOT_RUNTIME_VERIFIED`；B20 runtime 保持 `BLOCKED`，B21/B26 保持 `NO-GO`/`pending`。

## 冻结冲突处理

- B5 与 B13 v1 route/event/Java/migration 只作 historical adapter/candidate；新 canonical 契约使用 M1-015 具名 schema/operation 与 commerce v2 事件，不双发旧通用事件。
- SKU 模型可表达 `PERPETUAL`，但 Phase 1 不得将终身 SKU 标为可售；Free/Month/Quarter/Year 也只是版本化 catalog 候选，不在契约中硬编码价格或永久权益。
- Household 人数存在 4/6 人冲突，优惠券缺少税务/叠加/退款政策，账号/会员合并涉及跨 owner Saga；本任务禁止它们进入 canonical 写路径，不自行选一个数字或补造跨域规则。
- Phase 1 refund 按 `FULL_ONLY` 冻结；partial refund 需后续产品/财务单独批准。refund `PROCESSING` 不直接撤销权益，只有已验证 settlement 事实才可触发撤销/失效。
- 生产开启前置按资质、平台审核、sandbox、验签、退款、对账、回滚、审计、隐私、安全/PEP 的严格并集记录，本任务不开启任一项。
