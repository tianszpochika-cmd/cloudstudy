# P1R-M1-001 — API 公共契约基座

状态：`IN_PROGRESS`  
开始检查点：`dev@53642e5`  
依赖：`P1R-M0-008=ACCEPTED`

## 目标与退出条件

统一所有 `/api/v1` 外部接口的成功/错误 envelope、稳定错误码、分页、写请求幂等键、`requestId/traceId`、版本与弃用语义。退出前必须同时满足：

1. canonical OpenAPI 只有一套公共定义，生成客户端不再依赖域级重复 envelope；
2. 401、403、409、422、429 与 5xx 的含义和响应结构固定，并有失败关闭的自动检查；
3. 写操作声明 `Idempotency-Key` 和重放语义，列表操作声明统一分页；
4. 所有外部路径均为 `/api/v1`，弃用接口声明 `deprecated`、`Deprecation`、`Sunset` 与替代链接；
5. merge、validate、generate、compatibility、类型检查和专项负例测试通过；
6. 实现源提交与 canonical manifest 分离，独立评审后才允许 `ACCEPTED`。

## 恢复命令

```powershell
git switch dev
git pull --ff-only origin dev
pnpm plan:p1r:check
pnpm p1r:evidence:check
node scripts/contracts/merge-b1-fragments.mjs
pnpm contracts:validate
pnpm contracts:generate -- --check
pnpm contracts:compatibility:git -- --ref 4d7f73a867ff3e1db8582eab7593c173625bc8a3 --kind all
```

兼容性基线 `4d7f73a867ff3e1db8582eab7593c173625bc8a3` 是 M1-001 开始前已推送的真实 `dev` 提交；命令会直接读取该提交中的三个 canonical 合约 blob，不会把当前文件与自身比较。merge 与 generate 均使用只读检查模式，恢复验收不会改写工作区。

在未生成 M1-001 canonical manifest 前，`IN_PROGRESS` 是唯一允许的状态；静态文件存在不能替代上述命令结果。
