# Agent 开发 SOP 与状态流转模板

> **文档分类：混合模板**。通用状态流转和 Evidence 规则可继续复用；旧 B0–B36、`DEV-*` 与 G0–G4 内容均是 Historical / Superseded 记录。旧批次、旧技术栈和旧功能数量不得作为当前开发命令，当前入口见 [`v2-phase1-rebaseline`](./v2-phase1-rebaseline/README.md)。

> 适用范围：`P1R-*` 新任务复用本文件的通用执行规则；旧 `DEV-*`、B 与 G 任务仅作历史回放
>
> 状态事实源：`P1R-*` 使用 [`02-编号任务台账.md`](./v2-phase1-rebaseline/02-编号任务台账.md)；全部旧台账状态不得自动迁移

## 1. Agent 开工前检查

Agent 必须先阅读：

1. 根目录 `AGENTS.md`。
2. 任务的 `Feature Ref` 对应的 `requirements/` 与 `docs/`。
3. 任务依赖是否已在 `P1R-*` 状态事实源标记为 `ACCEPTED（已完成）`；并确认 Source/Trace Ref、`ARCH-*`、Service/Data Owner、Client Host、Contract/Security Ref 和 Evidence 已填写。
4. `P1R-*` 先阅读 `docs/06-design/v2-980plus/`、Phase 1 业务运行设计、v2 微服务架构和当前重基线；旧任务文件仅用于迁移核对。
5. 当前仓库的 `git status`，识别其他 Agent 已有改动，不得覆盖或回滚。

如果依赖未完成，只能准备设计、夹具或兼容适配，并将任务保持为“阻塞”；不得把未实现的功能标记为完成。

## 2. 状态定义与允许迁移

| 状态 | 含义 | 进入条件 | 必填字段/证据 |
|---|---|---|---|
| 未开始 | 尚未分配给 Agent | 任务依赖可排程或等待排程 | 无 |
| 已认领 | Agent 已明确负责人、文件边界和预计交付 | 只能认领“未开始”任务 | Agent、分支/PR、开始时间、预计完成时间、文件白名单 |
| 进行中 | 已开始修改或实现 | 认领信息完整、依赖未违反 | 当前进度、变更摘要、下一步、风险 |
| 待验收 | Agent 认为实现完成，但还未被统筹验收 | 最小证据集齐全，测试命令可复现 | 代码/契约/迁移/测试/截图或日志/回滚/未覆盖事项 |
| 已完成 | 统筹 Agent/评审人验证证据并接受 | Gate 通过，无未关闭 P0/P1 阻塞 | 验收人、验收时间、证据路径、CHANGELOG/文档状态 |
| 阻塞 | 依赖、权限、外部资质、冲突或环境阻止继续 | 写清阻塞事实，不用“感觉困难”代替 | 阻塞原因、影响任务、已尝试、解除条件、责任人 |
| 返工 | 验收未通过或完成后发现回归，需要重新实现 | 由评审人/统筹 Agent 触发 | 失败证据、返工范围、原完成记录保留 |

标准迁移：

```text
未开始 -> 已认领 -> 进行中 -> 待验收 -> 已完成
                         |          |
                         v          v
                       阻塞       返工 -> 进行中
                         |
                         v
                       进行中
```

“已完成”不是 Agent 自报状态；若完成后需要变更，必须保留原验收记录并新开“返工”记录。`P1R-*` 的状态变化追加到当前任务行和 Evidence manifest；旧 B/`DEV-*`/G 台账只保留历史，不得删除历史行或迁移其完成结论。代码层完成也不能替代运行态、真机或发布 Gate 验收。

## 3. 文件边界与协作规则

认领时先声明文件白名单和禁止触碰的共享文件：

- API/事件任务：先改 `packages/contracts/`，再改服务 DTO/Controller 和客户端生成类型。
- 数据任务：只新增对应 `database/mysql/migrations/` 版本文件，不直接改存量 schema 作为上线方案。
- 页面任务：只改所属 `apps/` 或 UI 任务明确的设计令牌/组件目录；不得擅自修改后端契约来迁就页面。
- 文档/ADR/治理任务：只改任务允许的 `docs/` 与 `requirements/backlog/` 文件；本人已认领的 `P1R-*` 任务行可按本模板更新，其他任务行、历史总报表、共享 README 与根脚本需先由统筹分配。
- 不覆盖其他 Agent 的未提交修改；发现文件重叠先阻塞并报告，禁止 `git reset --hard`、`git checkout --` 或大范围格式化。
- 每个任务交付时列出新增、修改和未触碰的路径；未列入白名单的改动视为越界，需要返工或拆分。

## 4. 标准执行步骤

### 4.1 认领

```text
时间=YYYY-MM-DD HH:mm
Agent=agent-name
任务=<任务ID>
原状态=未开始
新状态=已认领
分支/PR=codex/...
文件白名单=path/a; path/b
依赖核验=全部已完成 / 阻塞于 <依赖任务ID>
预计完成=YYYY-MM-DD HH:mm
```

### 4.2 进行中

```text
时间=YYYY-MM-DD HH:mm
Agent=agent-name
任务=<任务ID>
原状态=已认领
新状态=进行中
本次进度=...
已写入=...
下一步=...
风险/阻塞=无 / ...
```

### 4.3 阻塞

```text
时间=YYYY-MM-DD HH:mm
Agent=agent-name
任务=<任务ID>
原状态=进行中
新状态=阻塞
阻塞事实=缺少 ...；可复现证据=...
影响=阻断 <依赖任务ID> 及下游 ...
已尝试=...
解除条件=需要 ... 在 ... 前完成
建议责任人=...
```

### 4.4 待验收交付

```text
时间=YYYY-MM-DD HH:mm
Agent=agent-name
任务=<任务ID>
原状态=进行中
新状态=待验收
实现摘要=...
代码证据=path/to/file:line 或 PR/commit
契约证据=packages/contracts/...
迁移证据=database/mysql/migrations/...
测试证据=命令 + 结果 + 报告路径
运行证据=日志/截图/录屏路径
回滚方式=...
未覆盖事项=...
```

### 4.5 返工与完成

```text
返工：任务=<任务ID>；失败证据=...；必须修复=...；回归命令=...；责任人=...
完成：任务=<任务ID>；验收人=...；验收时间=...；Gate=G0/G1/G2/G3/G4；证据=...；CHANGELOG=...；回滚=...
```

## 5. 交付前最小证据集

| 任务类型 | 最少证据 |
|---|---|
| API/事件 | OpenAPI/事件 schema、生成或快照 diff、成功/错误/幂等测试、权限测试 |
| 数据库 | migration 文件、空库迁移、存量库迁移或兼容说明、索引/约束验证、回滚/补偿方案 |
| 前端页面 | 关键路径截图/录屏、Web/H5/移动端尺寸、加载/错误/空态、无障碍和性能降级证据 |
| 算法/状态机 | 固定输入输出、边界与非法迁移测试、状态迁移图、版本字段 |
| 内容/CMS | 来源/版权/授权记录、草稿不可见、双审、发布/下线/指定版本恢复证据 |
| 支付/权益 | 沙盒验签、重复回调、金额/状态校验、退款/补单/对账、关闭开关和回滚证据 |
| 隐私/安全 | 越权、脱敏、Token/设备、数据导出/注销、敏感信息扫描报告 |
| 弱网/同步 | 断网、重试、乱序、幂等冲突、空间不足、版本迁移和恢复报告 |

证据推荐存放于 `requirements/backlog/evidence/<TASK-ID>/`，文件名以 `YYYYMMDD-HHmm_<kind>.<ext>` 命名；若使用 CI、PR 或外部测试平台，对应的状态事实源必须保留可访问链接和复现命令。

## 6. 回滚规则

- 代码回滚：说明可安全回退的 commit/PR，以及数据兼容窗口。
- API/事件：优先兼容旧版本；撤回新 producer 前确认旧 consumer 仍可消费。
- 数据库：只能通过反向 migration、补偿脚本或 feature flag 停止写入；禁止直接删除未知数据。
- 内容：下线当前版本并恢复指定 `contentVersionId`，保留发布/审核日志。
- 支付/权益：暂停入口、保留渠道回调快照，按订单/权益状态机补偿，不手工改余额绕过审计。
- 客户端：保留旧端可读字段和离线队列迁移；升级失败时能恢复到上一版本或安全只读态。

## 7. Agent 自检清单

```text
[ ] 已阅读 AGENTS.md、任务依赖、v2-980plus/ARCH-*、Phase 1 业务运行设计与 `P1R-*` 当前任务基线；旧基线仅作迁移核对
[ ] 未跨越未完成依赖，未越过文件白名单
[ ] API/事件先契约，数据先 migration
[ ] 有单元/集成/契约/E2E 中与任务匹配的测试
[ ] 有异常、权限、幂等、弱网或降级证据（按任务适用）
[ ] 有回滚/补偿方式和未覆盖事项
[ ] 无真实密钥、真实隐私或生产凭证
[ ] 状态只提交到待验收，等待统筹验收
```
