# 验收标准

## A. 新用户首日路径

- 用户能在 3 分钟内完成登录和目标选择。
- 测评中断后可以恢复，不重复提交已完成题目。
- 测评结束后生成可解释的起点建议、首个目标和今日任务。
- 首次任务完成后展示下一次复习时间和继续学习入口。

## B. 课程与练习

- 每个单元必须有目标、输入材料、练习、反馈和完成条件。
- 练习提交必须幂等，重复点击不会生成重复记录。
- 题目、答案、解析和评分规则均有版本号。
- 用户可以查看自己的历史答案和建议改写。

## C. AI 反馈

- AI 输出必须符合约定 schema，解析失败时使用安全的规则化降级结果。
- 反馈必须引用当前课程目标，不得泛泛评价整段对话。
- 不把不确定的模型判断显示为确定事实；无法判断时明确提示用户。
- 反馈生成失败不能阻塞用户完成课程，也不能丢失原始练习记录。
- 生产请求要记录模型、提示词版本、耗时、token/成本估计和错误类型，但不得记录不必要的敏感原文。

## D. 复习

- 错误能进入个人复习队列，并带有来源和优先级。
- 到期复习按时间、错误严重程度和用户可用时长排序。
- 用户完成复习后更新下一次复习时间。

## E. 后台

- 草稿内容不能被学习者访问。
- 发布、下线和批量修改都有操作者、时间和变更记录。
- 后台 API 按角色限制课程、用户、订单和数据导出权限。

## F. 质量与安全

- 核心 API 有鉴权、权限校验、速率限制和输入校验。
- 关键事件能在日志和分析系统中关联到 request id。
- 测试环境只使用合成或脱敏数据。
- 生产发布前完成隐私、内容版权、AI 安全和平台审核清单。
