# 沉浸式前端架构与 AI/动效渲染引擎设计方案 (Immersive Frontend & VFX Architecture)

> **设计目标**：针对 EnglishFlow 中 **AI 实时交互、3D 发音解剖、动态语法树、游戏化特效与多端稳定帧率** 的核心诉求，在 uni-app (Vue 3) 全端体系下构建分层渲染（Layered Rendering Pipeline）的高性能前端技术体系。重型渲染（Three.js/Rive/Phaser）统一通过 H5/App 端 web-view 承载，与 uni-app 原生页面通过消息桥通信。

---

## 1. 前端多层渲染管线 (Layered Rendering Pipeline)

为了保证大体量特效、高频 AI 流式输出与复杂动画并行时不掉帧、不引发 DOM 重排，前端采用 **“四层分层渲染架构”**：

```
+-----------------------------------------------------------------------------------------+
| Layer 4: HUD & DOM UI 层 (Vue 3 / uni-app + CSS 动画 / @vueuse/motion)                |
| - 业务按钮、文字排版、流式打字机 Markdown 渲染、弹窗与表单                                |
+-----------------------------------------------------------------------------------------+
| Layer 3: 2D 交互动效、游戏引擎与数字人骨骼层 (Phaser 3 + Rive Engine + Pixi.js)             |
| - 游戏化小游戏矩阵（塔防/消消乐/拼句火车/大富翁）、卡通伴学数字人情绪状态机、答题连击反馈  |
+-----------------------------------------------------------------------------------------+
| Layer 2: 3D 沉浸空间与解剖模型层 (Three.js + WebGL，web-view 承载)                     |
| - 48 音标 3D 口腔舌位气流解剖模型、3D 空间音效可视化、全景考场氛围                       |
+-----------------------------------------------------------------------------------------+
| Layer 1: 底层音频与可视化图表层 (Web Audio API + Vue Flow / AntV G6 WebGL)             |
| - 实时音频基频 F0 曲线、波形切片、12,000+ 节点知识图谱、长难句依存树动态力导向渲染       |
+-----------------------------------------------------------------------------------------+
```

## 2. 针对各核心交互场景的最优选型方案

| 核心业务场景 | 挑战与痛点 | 🏆 业内最优解技术栈 | 核心优势与技术机理 |
| :--- | :--- | :--- | :--- |
| **3D 口腔发音解剖实验室** | 舌位升降、唇形开合、气流动画需 360° 丝滑旋转与剖切。 | **Three.js + GLTF/Draco 压缩**（H5/App 端 web-view 承载） | 模型体积压缩 70%（Draco），配合自定义 Shader 展现呼吸气流辉光；小程序端降级为 2D 帧动画。 |
| **卡通伴学数字人 (Rive)** | 传统 Lottie 无法交互，帧动画体积过大，需要随 AI 情绪无缝变表情。 | **Rive Runtime (强烈推荐，降维打击 Lottie)** | 矢量无损体积仅几十 KB，内置 State Machine（状态机），AI 返回 `happy` 或 `confused` 时毫秒级无缝切换骨骼动画，且支持鼠标/触屏注视跟随。 |
| **长难句 X 光机 & 知识图谱** | 几百上千节点展开时 DOM 树爆炸，导致拖拽卡顿。 | **Vue Flow + AntV G6 (Canvas/WebGL 模式)** | 采用虚拟化节点视口裁剪与 WebGL 硬件加速，支持流畅拖拽、缩放、层级折叠与连线粒子流动效果。 |
| **AI 流式 Token 渲染 (打字机)** | 大模型高频推送 Token 容易导致频繁全组件重渲染造成打字卡顿。 | **细粒度响应式更新 (shallowRef) + 分块虚拟切片 + CSS content-visibility** | 仅对最新一行或单词触发局部更新，规避全局 Layout Thrashing。 |
| **四六级/考研波形精听** | 0.5x-2.0x 无损变速、A-B 复读、连读弱读音节高亮。 | **Wavesurfer.js + Web Audio API (AudioWorklet)** | 独立音频渲染线程，毫秒级音频波形绘制，避免主线程 JS 阻塞导致爆音。 |
| **游戏化特效 (连击/金币/能量树)** | 答题 Combo、金币爆开、能量树生长、激光发射等粒子特效。 | **Pixi.js / canvas-confetti** | 极高性能 2D WebGL 渲染，单屏同开 5000+ 粒子稳定保持 60fps。 |
| **游戏化小游戏矩阵 (塔防/消消乐/拼句/大富翁)** | 需要游戏循环、碰撞检测、场景管理与指针拖拽，纯渲染器无法胜任。 | **Phaser 3**（纳入四级画质开关统一管控，低配档降级为静态 DOM 玩法） | 2D 游戏引擎事实标准，与 Pixi 同属 WebGL 高性能阵营，塔防/消除/棋盘类玩法均有成熟模式；拼句火车拖拽直接用其指针系统。 |

## 3. 多端 (PC / 移动 App / 微信小程序) 落地策略

### 3.1 PC Web 与 H5 学习端 (uni-app H5 编译)
- **定位**：终极视觉与沉浸体验承载端。
- **配置**：支持 GPU 硬件加速与后处理滤镜（泛光 Bloom 等），让 3D 实验室与语法树极具科技感；PC 与手机浏览器用响应式断点自适应。

### 3.2 移动端 App (uni-app 原生渲染，iOS/Android/iPad)
- **定位**：随时随地实时语音通话 + 与 Web 端一致的沉浸视觉体验。
- **选型亮点**：
  - **一套代码多端编译**：业务页面用 uni-app 原生渲染保证滚动与交互性能；重型特效页（3D/Rive/游戏）通过 web-view 承载 H5 模块，视觉资产与 Web 端共用；
  - **帧率与渲染**：H5/web-view 渲染上限约 60fps，配合四级画质自适应已足够流畅，不追求 120Hz 高刷指标；
  - **原生能力**：通过 uni-app 原生插件/条件编译调用麦克风、震动、本地存储预载与推送；
  - **iPad**：同一 iOS 包适配大屏，支持 Apple Pencil 手写与分屏。

### 3.3 微信小程序端 (轻量化与兼容性方案)
- **策略**：小程序环境对内存和包体限制严格（2MB 主包）。
- **降级与优化**：
  - 3D 口腔模型采用 **预渲染帧动画 + 微信同层渲染 Canvas 2D/WebGL**。
  - 动效优先采用 **Lottie 小程序版 / 预渲染帧动画** 播放轻量矢量动画（Rive 无官方小程序运行时，WASM 在小程序内不可靠，不采用）；
  - 重度 3D 互动页面支持通过 **内嵌 Webview 弹性加载 PC/H5 沉浸模块**。

## 4. 沉浸感关键要素：音效 (Audio) 与触感 (Haptics) 联动

沉浸感不仅在视觉，还在多模态反馈：
1. **空间音效 (Sound FX)**：引入 **Howler.js** 统一管理答题正确提示音、连击 Combo 升调音、战队能量注入音效，具备音频池缓存与零延迟播放。
2. **移动端震动反馈 (Taptic Engine)**：在单词拼写正确、游戏消除方块、倒计时警报时触发 iOS/Android 微震动（Light / Medium / Rigid Haptic），极大增强操控质感。

## 5. P1 预研：实时语音数字人 Lip-Sync 口型同步方案

实时对讲时数字人需要“说话时嘴型对得上”，落地路径（列入 P1 技术预研清单）：

1. **TTS 音素时间轴**：选用支持返回音素级时间戳（phoneme timestamps）的国内流式 TTS 供应商，随音频流下发。
2. **viseme 口型映射**：将音素映射为 8–15 个基础口型（viseme）集合，在 Rive 中预先建好口型状态机。
3. **前端驱动**：音频播放时钟对齐音素时间轴，驱动 Rive 状态机切换口型；无时间轴时降级为随音量包络开合的通用口型。
4. **验收标准**：首包音频与口型启动偏差 <100ms，主观评测无明显“对不上口型”感。
5. **降级策略**：低配档/Performance 档直接静态立绘 + 说话状态指示器，不做口型同步。
