### 0.2 补充原则

1. 既有 FEAT 不改名、不拆成伪 FEAT；只有当 PRD 原子需求具有独立入口、状态、权限、接口或验收时，才登记 SUBFEAT。
2. 页面状态、设备差异、错误态和权限态是每个原子的验收维度，不另计功能。
3. Phase 1 仅服务 18 岁以上成人与大学生；不实现 K12、未成年人画像或生成式 AI。测评、推荐、反馈和复习均为可解释的规则化结果。
4. 本文只定义边界和追溯。任何接口、表结构或事件落地前，必须先在 packages/contracts/ 的 OpenAPI 单一事实源中确认；本文不能替代契约、迁移和测试。
5. 所有学习记录带 userId、contentId、contentVersion、sessionId、clientEventId、发生时间和来源；内容下线后历史记录仍可回放，但不能重新开学。
6. 失败写入采用客户端 outbox 和服务端幂等键；本地显示“待同步”不能冒充服务端已计分。离线期间不产生需要服务器裁决的新等级或正式排名。
7. 前端矩阵固定为 apps/mobile（uni-app，移动 H5、iOS、Android、iPad，并由此条件编译小程序）、apps/learner-web（PC Web/PWA）和 apps/admin-web。Windows Phase 1 以 learner-web/PWA 为准，Tauri 仅在另有 ADR 后进入范围。
8. 动效、地图、波形、口腔图和结构图均受 AdaptivePerformanceEngine 的 Ultra、High、Medium、Performance 四级控制；低配必须能降为 2.5D、SVG、2D 静态切片或纯文本。

### 0.3 每个补充章节的最小契约

以下每一章都明确：PRD 证据、与既有设计边界、主流程、异常流程、恢复流程、页面/路由、API/数据边界、权限与隐私、事件、跨端/弱网/性能、验收。除特别注明外，所有写入均要求幂等，所有读取均按内容版本和用户权限过滤。

## 1. ONB｜新用户、地图、首页与课程编排

### SUBFEAT-ONB-001-A｜目标选项与主辅目标归一

- PRD证据：PRD §3.1 要求成人零基础、日常交流、CET-4、CET-6、阅读提升、写作提升、听力提升、口语自练等目标选项；目标用于后续路径和首页排序。
- 与既有设计边界：detailed-specs/01 已有目标表单、主目标和辅助标签的保存流程；本项只补齐 PRD 目标全集、目标版本和下游映射，不重写表单视觉或推荐算法。
- 主流程：用户在 onboarding/goal 查看当前生效的目标配置；选择一个主目标，可选择辅助方向；客户端提交目标版本、主目标、辅助标签和确认时间；服务端保存并返回可解释的路径映射和待完成下一步。
- 异常流程：配置版本过期、目标已下线、重复提交、未满足 18+ 门槛或网络失败时，保留当前草稿并显示可重试状态；不静默改成其他目标。
- 恢复流程：重新拉取目标配置后按仍有效的选项重放；若原目标已下线，进入“需要重新选择”状态，原选择只作为历史审计，不用于新推荐。
- 页面/路由：apps/mobile 与 apps/learner-web 的 onboarding/goal；从 onboarding/welcome、onboarding/age 进入，完成后到 onboarding/assessment 或 onboarding/plan；不进入 admin-web 的学习路由。
- API/数据边界：沿用 POST /api/v1/onboarding/profile 的目标字段；返回 goalConfigVersion、primaryGoal、secondaryGoals、mappingVersion。用户画像由 learner-service、学习计划由 learning-service 写入；前端不自行推导课程集合，不写课程内容表。
- 权限隐私：仅本人可读写自己的目标；年龄校验只保存合规所需的成年状态，不在埋点中记录身份证件或敏感原文；辅助目标不得推断健康、职业或未公开身份。
- 事件：onboarding.goal_config_viewed、onboarding.goal_selected、onboarding.goal_confirmed、onboarding.goal_save_failed；载荷只含目标枚举、版本、端、sessionId 和结果，不含自由文本隐私。
- 跨端/弱网/性能：移动端用分步单选/多选，Web 支持键盘操作；配置可缓存但提交前校验版本；弱网保存本地草稿并显示待提交；选项配置懒加载，不阻塞首屏，低配不使用复杂动效。
- 验收：PRD 八类目标均能在配置版本中逐项定位；提交后刷新仍得到同一主辅目标；下线目标不会被新用户选中；重复点击只产生一条生效画像记录；完成、失败和待同步状态均可回放。

### SUBFEAT-ONB-001-B｜每日学习强度选择

- PRD历史证据（非当前实现口径）：PRD §3.1 要求用户选择每日投入 5、10、20、30+ 分钟，且每日任务量应受目标和投入约束。
- 与既有设计边界：detailed-specs/01 和已有 API/DDL 使用过另一组时长枚举；本项只保留产品证据与实现枚举的冲突定位、展示归一和计划输入边界，不复制计划计算。
- 主流程：用户在 onboarding/goal 或 onboarding/plan 选择每日强度；服务端保存 intensityValue、intensityUnit、intensityConfigVersion；计划预览显示预计任务量和可调整入口。
- 异常流程：传入未配置值、前端与服务端枚举不一致、计划已开始或保存超时，拒绝本次写入并保留上一个生效值；不把 30+ 自动截断为 30。
- 恢复流程：使用本地草稿重试；若服务端已经接受但响应丢失，以幂等键查询最新画像/计划；计划已开始时只生成从下一个日历日生效的变更。
- 页面/路由：onboarding/goal、onboarding/plan、learn/plan 的计划设置抽屉；回到 learn/home 时只展示生效值。
- API/数据边界：沿用 POST /api/v1/onboarding/profile 和计划读模型；字段必须能表达定量值与开放上限，不允许前端硬编码转换；learning_plan 保存生效时间和来源。
- 权限隐私：本人可改；不把投入时长解释为能力或健康结论；运营后台只能按授权查看聚合结果。
- 事件：onboarding.intensity_viewed、onboarding.intensity_selected、learning_plan.intensity_changed、learning_plan.intensity_sync_failed。
- 跨端/弱网/性能：移动端拖动或单选均提供文本等效；弱网只暂存草稿，避免同一天多次计划写入；计划预览只拉取汇总字段，不下载全量课程。
- 历史验收记录：5、10、20、30+ 均可表达且显示 PRD 原文语义；强度变化不修改历史任务；重复提交幂等；服务端拒绝不兼容值时 UI 给出重新拉取配置而非静默降级。当前 v2 UI/API 必须改用已裁决的 5/15/30/45 版本化配置。

### SUBFEAT-ONB-003-A｜规则化水平测评的维度覆盖

- PRD证据：PRD §3.1 要求测评覆盖词汇识别、基础语法、阅读理解和听力理解，并输出等级、参考 CEFR、预估词汇量与建议路径；不得宣称官方认证。
- 与既有设计边界：detailed-specs/01 已定义测评会话、题目版本、断点续答和服务端判分；本项只补齐“阅读维度必须可追溯”和维度覆盖声明。
- 主流程：assessment 页面显示当前测评版本和维度进度；服务端按版本发题；用户完成四类维度；提交后服务端按确定性规则返回各维度结果、总结果、参考区间和建议路径。
- 异常流程：题目资源缺失、音频不可播放、提交重复、单题超时或检测到版本不一致时，记录可诊断失败原因；不以缺失维度推算完整等级。
- 恢复流程：使用 GET/POST /api/v1/assessment/placement/start、/submit-step、/skip 的既有会话语义恢复；若阅读/听力资源仍不可用，允许按产品规则延期测评，但结果标记 incomplete，直到补齐维度。
- 页面/路由：onboarding/assessment、onboarding/result；中断从 onboarding/welcome 或登录后继续入口回到原 assessmentSession。
- API/数据边界：题目包由 content-service 提供，维度、答案、耗时和结果由 assessment-service 维护；/submit-step 只接收题目版本、选项/答案、clientEventId 和耗时，不接收客户端计算的分数；结果模型必须区分 dimensionScores、completionStatus、referenceLevel 和 recommendationPath。
- 权限隐私：仅本人可见详细答案和结果；原始作答和音频若存在按安全边界保存，默认不公开；结果展示注明“学习参考，不是官方考试或认证”。
- 事件：assessment.started、assessment.dimension_started、assessment.item_answered、assessment.item_skipped、assessment.resumed、assessment.submitted、assessment.incomplete。
- 跨端/弱网/性能：听力资源支持预缓存和离线待同步；移动端只预取当前及下一题，Web 适度预取；弱网不可确认提交时显示本地已保存/服务器待确认；音频和题面分离加载，低配关闭非必要动效。
- 验收：四维度在题包和结果中均可定位；任何单维度缺失都不能返回“完整测评”；断点恢复后题序和已答状态一致；同一答案幂等；结果不出现官方 CEFR/考试认证暗示。

### SUBFEAT-ONB-003-B｜测评结果解释与路径建议

- PRD证据：PRD §3.1 要求输出语学星等级、参考 CEFR、预估词汇量、推荐学习路径，并让用户理解评估依据。
- 与既有设计边界：既有详细设计已覆盖雷达图、结果页和计划创建；本项只补齐结果字段的可解释性、参考性质和“建议而非强制”边界。
- 主流程：完成 assessment 后打开 onboarding/result；用户可查看各维度表现、题目版本、参考区间、建议路径和下一步；确认后写入 onboarding/plan。
- 异常流程：结果正在计算、维度不完整、规则版本被撤回或推荐路径无可用内容时，展示处理中/需补测/暂不可推荐，不伪造等级。
- 恢复流程：刷新或重新登录通过 assessmentSessionId 查询同一结果；路径内容恢复后重新生成建议版本，保留旧结果及原因。
- 页面/路由：onboarding/result、onboarding/plan；结果卡可 Deep Link 到 learn/plan 或 learn/map。
- API/数据边界：沿用 placement result 读接口和计划创建接口；结果必须包含 ruleVersion、dimensionEvidenceRef、referenceDisclaimer、recommendationVersion；客户端只渲染，不重新计算词汇量或等级。
- 权限隐私：结果是用户的学习画像，默认仅本人和最小授权的支持/教研角色可见；不得在事件或分享链接中带出详细弱项。
- 事件：assessment.result_viewed、assessment.explanation_expanded、assessment.path_opened、assessment.plan_confirmed、assessment.result_pending。
- 跨端/弱网/性能：雷达图提供列表和文本替代；结果摘要可离线查看，深链接目标无缓存时显示待加载；图表按需渲染，Performance 级使用列表。
- 验收：结果中的每个等级/建议都能回指规则版本和维度证据；参考 CEFR 明确非官方；路径无内容时有可恢复状态；从结果到计划只产生一次确认记录。

### SUBFEAT-ONB-002-A｜学习世界分区、节点前置与解锁状态

- PRD证据：PRD §3.2 要求语言世界包含起点、词汇森林、语法工坊、听力港、阅读书店、口语街区、写作工坊、挑战塔、CET 训练场、游戏岛、复习营；节点对应真实学习内容，按前置解锁。
- 与既有设计边界：detailed-specs/01 已定义地图拓扑、节点状态、缩放和继续学习；本项只补齐“分区/内容/前置/状态”的逐项绑定，避免地图只成为装饰。
- 主流程：learn/map 请求指定 mapVersion；服务端返回分区、节点、内容引用、prerequisite、锁定原因、完成星级和下一可学节点；用户点击节点进入课程或学习会话。
- 异常流程：节点内容下线、前置引用失效、拓扑版本不兼容或地图资源加载失败时，节点显示维护/不可用原因并提供替代可学入口。
- 恢复流程：缓存拓扑用于浏览；重新联网后以服务端版本替换；完成前置任务后刷新局部节点，不重新下载整张地图。
- 页面/路由：learn/map、learn/node/:id、learn/session/:id；课程入口可转 courses/home、courses/:id、courses/grammar、courses/listening、courses/reading、courses/speaking、courses/writing。
- API/数据边界：沿用 GET /api/v1/world/sectors/{sectorCode}/topology 与学习内容读取接口；节点只持有 learningItemRef/courseRef，不复制题目；解锁由 learner-service/learning-service 根据 mastery、prerequisite 和版本计算。
- 权限隐私：本人学习状态只对本人返回；公开内容与用户完成状态分离；地图分享不得暴露弱项和学习时长。
- 事件：world.map_opened、world.sector_selected、world.node_locked_viewed、world.node_unlocked、world.node_opened、world.node_completed。
- 跨端/弱网/性能：移动端地图支持缩放、拖拽和列表模式；Web 支持键盘/滚轮；弱网先显示已缓存状态并标记可能过期；地图按视口分片、节点资源懒加载，Performance 级使用 2D/SVG。
- 验收：每个 PRD 分区至少能定位一个真实内容引用；锁定节点显示可解释前置；完成前置后局部状态更新；内容下线不出现可开始的假入口；四级画质均能完成节点进入。

### SUBFEAT-ONB-003-C｜Adaptive Home 的解释、关闭、固定与恢复默认

- PRD证据：PRD §3.3 要求用户看到首页模块排序原因，可关闭智能调整、恢复默认、固定模块、编辑模块，以及选择不基于某信号调整。
- 与既有设计边界：detailed-specs/01 已定义 home/feed 和继续学习上下文；本项不重做 feed 排序，而补齐用户控制和审计状态。
- 主流程：learn/home 拉取 feed 与 explanation；用户打开“为什么推荐”、关闭某信号、固定/取消固定、恢复默认或编辑模块；服务端保存偏好版本并返回重新计算后的顺序。
- 异常流程：偏好冲突、模块已下线、频繁写入、推荐源暂不可用时，保留上次可用 feed，显示固定模块和静态默认任务；不因排序失败隐藏主任务。
- 恢复流程：沿用现有 feed 偏好写契约提交幂等；若现有 contracts 尚未覆盖该写入，先补 OpenAPI 再实现，本文不冻结新路径；响应丢失时按 preferenceVersion 查询；恢复默认只撤销用户覆盖，不删除历史审计。
- 页面/路由：learn/home、首页模块设置抽屉、learn/plan；“继续学习”详情进入 learn/session/:id。
- API/数据边界：GET /api/v1/home/feed 返回 moduleId、reasonCode、sourceRefs、orderVersion、isPinned；偏好写接口只写用户设置，不能修改原始学习记录；没有新增 AI 服务调用。
- 权限隐私：本人可控制；解释只展示规则信号的可读名称，不显示他人数据、内部风控字段或敏感推断；后台聚合不得回溯个人排序原因。
- 事件：home.feed_viewed、home.recommendation_reason_opened、home.signal_disabled、home.module_pinned、home.preferences_reset、home.feed_fallback。
- 跨端/弱网/性能：feed 摘要可缓存；设置写入进入 outbox；弱网使用最后一次服务器 feed 并明确时间；首屏先渲染任务卡，解释面板和装饰动画延后；低配使用静态卡片。
- 验收：用户可逐项执行五类控制并在刷新后保持；每个智能模块都有可读 reasonCode 或标记为默认；关闭智能调整后首页仍有确定性默认顺序；回退 feed 不产生错误推荐事件。

### SUBFEAT-ONB-004-A｜课程层级、目录与启动包定位

- PRD证据：PRD §3.4 定义 LearningItem → Lesson → Scenario → Course → Learning Path 层级，并列出成人零基础、日常交流、旅行、CET 词汇、听力、发音、阅读、写作、商务等首发课程包。
- 与既有设计边界：detailed-specs/01 已有课程包与 lesson 进入；本项只补齐层级字段、首发目录、前置和内容来源，避免把课程、场景、学习项混成一个页面。

- API/数据边界：场景、角色、scriptStep、choiceRef、rubricRef 归内容域；turnAttempt、recordingRef、selfRating 和完成状态归学习/媒体域；不创建开放式对话和生成式回应接口。
- 权限隐私：录音、角色选择和自评仅本人可见，默认可删除；基础医疗场景仅语言学习材料，不提供医疗建议；内容授权和版本需随场景返回。
- 事件：roleplay.catalog_viewed、roleplay.scene_opened、roleplay.turn_started、roleplay.choice_selected、roleplay.recording_uploaded、roleplay.turn_completed、roleplay.fallback_used、roleplay.completed。
- 跨端/弱网/性能：移动端一轮一屏，Web 可侧栏展示脚本；弱网缓存固定脚本，媒体待上传；场景背景和动画可关闭；Performance 级使用静态角色卡和文本。
- 验收：十类场景均能定位到目录/未发布状态；脚本和选项均来自固定版本；无麦克风仍能完成文本流程；中断恢复不跳 turn；不产生开放式 AI 对话。

## 8. ASM｜评测、练习中心、错题修复与报告

### SUBFEAT-ASM-004-A｜今日任务组成与数量调整

- 验收：九类任务能逐项定位或显示当天无可用内容；调整数量不删除已开始/到期任务；清单重算可回放；重复提交幂等；离线状态明显。

### SUBFEAT-ASM-013-A｜Checkpoint 八维评测、失败回路与重测

- PRD证据：PRD §13.3 要求 Checkpoint 覆盖词汇、词块、语法、听力、阅读、口语、写作、综合应用八个维度，并在失败后生成可执行的修复循环。
- 与既有设计边界：detailed-specs/05 已有 checkpoint、结果和 mastery 读模型；本项只补齐维度清单、未完成/失败状态和“复习—重测”回路，不复制正式考试算法。
- 主流程：用户从 learn/session、practice/checkpoint 或课程节点进入；服务端创建 checkpoint attempt 和八维题包；完成后按维度返回结果、通过条件、薄弱来源、修复任务和可重测时间。
- 异常流程：题包缺失、音频/麦克风不可用、维度未完成、提交超时或版本冲突时，checkpoint 为 incomplete/pending，不返回整体通过。
- 恢复流程：按 checkpointAttemptId 续答；失败后生成 repairTaskRefs，用户完成修复后重新创建或进入允许的 retest；旧结果只读，重测结果作为新 attempt 关联。
- 页面/路由：practice/checkpoint、practice/result/:id、learn/session/:id、practice/mistakes、learn/plan。
- API/数据边界：沿用 /api/v1/assessment/*、/api/v1/exam/*、/api/v1/mastery/* 的既有权限和幂等规范；checkpointDimension、attemptRef、repairTaskRef、passRuleVersion 为最小跨域字段；各域答案仍由各域保存。
- 权限隐私：结果、未通过维度和修复任务仅本人可见；口语录音/写作答案按媒体和写作隐私边界；不宣称官方考试成绩。
- 事件：checkpoint.started、checkpoint.dimension_started、checkpoint.dimension_completed、checkpoint.incomplete、checkpoint.failed、checkpoint.repair_plan_created、checkpoint.retest_started、checkpoint.passed。
- 跨端/弱网/性能：可缓存题包支持续答但正式判定需服务端；音频/录音按维度加载；弱网按维度提交并显示确认；低配使用静态结果卡。
- 验收：八维均能定位题包、结果或明确不可用；未完成不等于失败/通过；失败必有可执行 repairTaskRef 或说明不可生成；重测不覆盖原结果；跨端恢复一致。

### SUBFEAT-ASM-019-A｜Practice Hub、错题来源和修复闭环

- PRD证据：PRD §13.4 要求 Practice Hub 汇总语法、词汇、听力、阅读、写作、口语、模拟题等错题，按错误类型、来源、时间、掌握状态统计，并支持进入修复、再次练习和完成标记。
- 与既有设计边界：detailed-specs/05 已有 mistakes/mastery 入口；本项只补齐跨域错题索引、来源过滤、修复任务和关闭条件，不复制各域错误详情。

- 异常流程：原题下线、来源不可见、错误统计延迟、跨域索引失败或批量操作部分失败时，显示 stale/unavailable 和来源说明，不删除原始错误。
- 恢复流程：修复任务使用 repairTaskId 幂等；索引异步重建期间展示最后可信快照；原题恢复发布后重新关联；用户可从具体来源回到阅读/听力/语法/写作/口语 session。
- 页面/路由：practice/home、practice/mistakes、practice/quick、practice/checkpoint、各 courses/* 与 learn/session/:id。
- API/数据边界：沿用各域 attempt/error、/api/v1/mastery 读模型和现有 mistakes/targeted pack 接口；索引只保存 sourceAttemptRef、domain、errorCode、contentRef、repairStatus，不能复制受限正文和原始录音。
- 权限隐私：本人错题私有；写作、口语原始数据默认不展示在聚合列表；管理员按最小权限访问，事件只传错误码和引用。

- 跨端/弱网/性能：索引分页和服务端过滤；弱网可读缓存但写入待同步；大列表虚拟滚动/增量加载；Performance 级不显示复杂跨域图表。
- 验收：七类来源至少能按 domain/sourceRef 定位；错题打开、修复、再次练习和关闭均可回放；原题下线不导致错误消失；索引不越权泄露自由答案；重复修复不重复关闭。

### SUBFEAT-ASM-021-A｜日、周、月学习报告与月度指标

## 9. PLOS｜Personal Learning OS 的计划、搜索、历史和全局掌握编排

> PLOS 在现有 feature-matrix 中没有单独的 FEAT 行。本节的 FEAT-PLOS-* 是本文的追溯占位，用于把 PRD §13 的跨域编排需求定位到页面、读模型和验收；是否纳入正式总账需由产品/架构在后续台账校准中确认。PLOS 不复制 VOC、GRM、ASM 等域的内容或算法。

### FEAT-PLOS-001｜Study Plan 计划创建、日历和重排

- PRD证据：PRD §13.2 要求计划输入目标、当前水平、目标日期、每日时长、每周学习日和进度；输出总/月/周/日/Checkpoint 层级，支持休息、补学、重排、提前完成、落后处理、预计完成日期和手动拖拽。
- 与既有设计边界：detailed-specs/01、05 已有 onboarding/plan、learning_plan 和结果读取；本项只定义跨域计划编排的输入、日历事件、计划版本和可恢复重排。
- 主流程：用户在 onboarding/plan 或 learn/plan 确认输入；服务端生成 planVersion、阶段、日历、任务引用、checkpoint 和 expectedFinishDate；用户可查看日/周/月并拖动未开始任务；服务端重算后返回差异。
- 异常流程：目标日期早于可行范围、每周学习日为空、任务依赖冲突、已开始任务被拖动、重排超时或内容不可用时，拒绝不安全变更并显示可调整字段。
- 恢复流程：按 planVersion 和 changeSetId 幂等提交；客户端保存未提交拖拽草稿；响应丢失时查询变更状态；落后时只重排未开始任务并保留历史。
- 页面/路由：onboarding/plan、learn/plan、learn/home、me/reports。
- API/数据边界：沿用 onboarding profile、learning_plan、home feed、stream/today 和 continue-context 接口；计划只保存 taskRef/phaseRef/checkpointRef，不复制各域题目；重排输入包含 operation、targetDay、sourcePlanVersion。
- 权限隐私：本人读写；计划目标和落后状态不进入公共排行；管理端只读授权聚合；预计完成日期标记为规则估算。
- 事件：plan.created、plan.viewed、plan.day_dragged、plan.rest_day_set、plan.makeup_created、plan.replanned、plan.conflict、plan.recovered。
- 跨端/弱网/性能：日历提供列表替代；弱网先保存草稿，服务端确认后更新正式计划；只拉取当前视窗；重算异步时显示版本和进度；低配使用静态日历。
- 验收：六类输入和五类重排行为均可定位；已开始任务不可被静默移动；计划版本可回放；落后/提前/休息/补学都有确定结果；跨端打开同一 planVersion。

### FEAT-PLOS-002｜Today Stream 跨域任务编排与继续学习上下文

- PRD证据：PRD §13.1 要求今日任务覆盖新词、到期复习、词块、语法薄弱、阅读、听力、复习游戏、考试和场景任务，并允许调整任务量；§3.3 要求首页可继续上次学习。
- 与既有设计边界：ONB 和 ASM 已定义任务来源与首页卡片；本项只定义 PLOS 如何组合 taskRef、继续上下文、优先级和回退，不复制各域任务内容。
- 主流程：服务端从计划、SRS due、错误修复、课程进度和 checkpoint 读取候选；按规则生成 streamVersion；learn/home 展示任务和原因；用户点击后通过 continue-context 进入最近 session。
- 异常流程：某域超时、候选为空、排序信号缺失、跨端 session 冲突或 stream 版本过期时，使用固定优先级和安全默认；不生成 AI 任务。
- 恢复流程：GET /api/v1/learning/continue-context 读取服务器游标；PUT 只写最近学习上下文；stream 失败时读最后可信快照并在下次同步重算。
- 页面/路由：learn/home、learn/session/:id、learn/plan、practice/home。
- API/数据边界：沿用 /api/v1/learning/stream/today、/action、/api/v1/home/feed、/learning/continue-context；stream 项只含 taskType、taskRef、reasonCode、priority、estimatedMinutes、status，详情由所属域提供。
- 权限隐私：用户只能看到本人任务和原因；原因不暴露内部风控/他人基线；不以跨域行为推断敏感属性。
- 事件：plos.stream_generated、plos.stream_viewed、plos.task_opened、plos.task_completed、plos.task_skipped、plos.stream_fallback、plos.continue_context_updated。
- 跨端/弱网/性能：stream 摘要可缓存，详情懒加载；弱网只在本地标记开始，完成需服务端确认；候选聚合异步；首屏不等待所有域；Performance 级用列表卡片。
- 验收：九类任务可逐项回指来源或空原因；任务顺序可解释；继续学习进入同一 session 或明确恢复状态；生成失败有固定回退；跨域编排不复制题面。

### FEAT-PLOS-003｜全局搜索与确定性结果排序

- PRD证据：PRD §13.7 要求搜索课程、词汇、语法点、阅读、听力、口语、写作、错题，并按相关性、学习相关性、最近使用和版本状态确定性排序。
- 与既有设计边界：各域已有详情和内容读取；本项只定义统一索引入口、类型过滤、权限过滤和 Deep Link，不重新设计各域搜索。
- 主流程：用户从 learn/home 或通用搜索入口输入关键词；服务端返回类型、标题/短摘要、contentRef、权限状态、matchReason 和 sortKey；用户点击进入对应页面。
- 异常流程：空关键词、无结果、索引延迟、结果已下线、无权限或网络失败时，显示空态/最近合法搜索/替代入口，不展示受限标题。
- 恢复流程：搜索 query 可本地保存最近一次但不保存私密正文；索引更新后刷新同一 query；结果点击按 contentVersion 重新校验，过期则回到可用父级。
- 页面/路由：learn/home 的全局搜索、courses/home、practice/mistakes、词汇库；目标路由见 uiux-specs/24 的 courses/*、practice/*。
- API/数据边界：优先复用各域只读接口和统一搜索契约；索引字段为 searchableTitle、type、contentRef、version、permissionFlag、lastUsedAt、relevanceKey；用户 note、写作全文、录音原文不进入公共索引。
- 权限隐私：服务端先做权限过滤再排序；私有词库、错题、写作和录音仅返回本人；搜索日志脱敏，允许清除本地历史。
- 事件：search.opened、search.submitted、search.filter_changed、search.result_opened、search.no_result、search.permission_filtered。
- 跨端/弱网/性能：服务端分页/游标；输入防抖但提交有明确动作；弱网可展示最近缓存结果并标过期；移动端不加载全量索引；Performance 级使用列表无缩略图。
- 验收：七类内容和错题均有 type/route 映射；同一 query 在同一索引版本排序稳定；权限过滤先于结果返回；下线内容不产生可进入假链接；私密自由文本不被搜索。

### FEAT-PLOS-004｜学习历史、最近继续和跨端合并

- PRD证据：PRD §13.8 要求历史覆盖最近课程、阅读、听力、Checkpoint、游戏和表达，并能继续上次学习。
- 与既有设计边界：各域已有 session 和完成记录；本项只定义统一历史卡、继续条件、排序和跨端冲突，不复制域内记录。
- 主流程：用户打开历史/继续入口；服务端按最近活动和可继续状态返回 course、reading、listening、checkpoint、game、expression 六类记录；点击继续进入正确 session 或父级。
- 异常流程：session 过期、内容下线、版本不可迁移、记录部分同步或权限撤销时，显示只读历史和原因，不提供死链。
- 恢复流程：客户端以 serverLastActivityAt 和 sessionVersion 合并本地游标；可迁移则继续，不可迁移则创建新的 session 并保留旧历史；断网时显示缓存时间。
- 页面/路由：learn/home 的继续卡、learn/session/:id、courses/*、practice/checkpoint、practice/quick、me/reports。
- API/数据边界：沿用 /api/v1/learning/continue-context 和各域 session/status API；历史索引只保存 sessionRef、type、contentVersion、lastActivityAt、resumeRef、completionState，不保存正文。
- 权限隐私：只读本人历史；可删除的本地历史不等于删除服务端法定留痕，界面需说明；不向他人暴露课程和表达历史。
- 事件：history.opened、history.item_viewed、history.resume_clicked、history.resume_blocked、history.local_server_conflict、history.remapped。
- 跨端/弱网/性能：历史分页；继续上下文摘要可缓存；弱网不把本地游标显示为服务端完成；按类型懒加载图标/媒体；低配使用文本列表。
- 验收：六类历史均可定位；继续入口不会进入过期死链；跨端冲突可解释且不丢服务器记录；删除/保留边界清晰；未同步状态不会进入完成报告。

### FEAT-PLOS-005｜Memory & Mastery 中心与全局状态映射

- PRD证据：PRD §13.9 要求四个首页入口、交错复习、置信度、延迟测试、全局地图；全局项目类型含词汇、词块、语法、听力现象、阅读理解、口语音标、写作结构，状态含新接触、熟悉、掌握、熟练、易忘、高风险，并关联错误、复习队列和 backlog 保护。
- 与既有设计边界：VOC、GRM、LST、SPK、WRT 和 ASM 已分别产生状态；本项只定义统一读模型和状态映射，不改变域内算法或状态机。
- 主流程：用户从 learn/home、practice/home、practice/mastery 或 me/reports 进入中心；服务端返回 itemType、domain、masteryDisplayState、confidence、risk、nextReviewAt、errorRefs、backlogBucket 和来源入口；用户进入原域修复或延迟测试。
- 异常流程：某域无数据、状态映射未知、聚合延迟、内容下线或跨域引用失效时，显示 unknown/stale/unavailable；不把缺失标为新接触或掌握。
- 恢复流程：各域 signal 确认后异步更新；按 signalId 去重、按 contentVersion 映射；映射失败进入 repair queue，用户仍可查看原域记录；历史状态只读可回放。
- 页面/路由：practice/mastery、learn/home、practice/home、me/reports、learn/map、practice/mistakes。
- API/数据边界：沿用 /api/v1/learning/srs/overview、/states、/api/v1/grammar/mastery、/api/v1/mastery、writing/listening/speaking mastery 读接口；统一 read model 只保存稳定 ref、display state、signal refs、timestamps 和入口，禁止复制原始答案/录音。
- 权限隐私：全局掌握是个人学习画像；本人默认可读，后台需最小授权；置信度、风险和错误不得用于公共排名或外部画像。
- 事件：mastery.center_opened、mastery.filter_changed、mastery.item_opened、mastery.delayed_test_started、mastery.state_mapped、mastery.state_unknown、mastery.backlog_protected。
- 跨端/弱网/性能：中心提供列表、树和简单图三种密度；弱网使用带 lastSyncedAt 的快照；聚合分页/按域加载；Performance 级禁用复杂图和动画，保留状态文本。
- 验收：七类 itemType 和七类显示状态均有映射或明确未覆盖；未知状态不误报；每个状态可进入来源/错误/复习；backlog 保护可见；相同 signal 在各入口显示一致。

### FEAT-PLOS-006｜交错复习、置信度和延迟测试入口

- PRD证据：PRD §13.9 要求交错复习、置信度、延迟测试和 backlog 保护，以避免只刷单一题型或绕过到期复习。
- 与既有设计边界：VOC 的 SRS、GRM targeted pack、ASM quick/checkpoint 已有各自练习入口；本项只定义跨域选择策略的可解释入口和安全约束，不新增算法。
- 主流程：用户从 mastery center 选择“交错复习/延迟测试”；服务端依据已确认状态和到期队列返回混合 taskRefs、原因和预计时长；完成后分别回写各域 attempt。
- 异常流程：可用域不足、某域媒体缺失、背压/队列过大或任务状态冲突时，减少混合范围并显示原因；不得用新题填充为已完成。
- 恢复流程：按 interleaveSessionId 续答；每个 taskRef 独立幂等；失败域可稍后单独重试；队列同步完成后刷新中心。
- 页面/路由：practice/mastery、practice/srs/session/:id、practice/quick、practice/checkpoint。
- API/数据边界：沿用 /api/v1/learning/stream/action、各域练习接口和 /api/v1/mastery；编排只保存 taskRefs、selectionReason、sessionVersion；评分和 SRS 仍由所属域完成。
- 权限隐私：本人可见；跨域选择理由使用学习信号，不展示内部权重；不向第三方暴露薄弱域组合。
- 事件：mastery.interleave_started、mastery.interleave_item_opened、mastery.interleave_item_completed、mastery.delayed_test_submitted、mastery.interleave_fallback。
- 跨端/弱网/性能：混合题包分块下载；离线只练已缓存且结果待同步；一次只加载当前 item；Performance 级按列表串行，不显示复杂跨域过渡。
- 验收：交错会话能回指每个所属域 attempt；到期/高风险项目不会被普通新题静默替换；中断可恢复；失败域可单独补练；结果在 mastery 中一致。

### FEAT-PLOS-007｜Backlog 保护与计划/掌握一致性

- PRD证据：PRD §13.1、§13.2、§13.9 要求到期复习、落后任务、计划重排和 backlog 保护协同，不能因用户调整数量而丢失应复习项目。
- 与既有设计边界：ASM 负责任务和 Checkpoint，VOC/GRM 负责域队列，PLOS 负责汇总；本项只定义优先级保护、冲突提示和跨域一致性。
- 主流程：计划或今日任务变更时服务端计算 protectedBuckets（due/high-risk/failed-checkpoint 等）和可调整 buckets；用户确认后只调整可变部分；首页、复习中心和报告读取同一 plan/stream version。
- 异常流程：保护队列超过今日时长、用户拖动保护任务、计划已被其他端更新或聚合落后时，显示超量/冲突和选择：保留、延期到可用日或进入补学；不自动丢弃。
- 恢复流程：按 planVersion、streamVersion 和 changeSetId 重放；服务端合并成功后刷新三个读模型；合并失败保留服务端状态和本地草稿供再次确认。
- 页面/路由：learn/home、learn/plan、practice/srs、practice/mastery、me/reports。
- API/数据边界：沿用 plan、stream/today、SRS overview、mastery 和 continue-context；保护状态只保存 bucket/ref/reason/deadline，不能修改域内 interval 或评分；所有写入带版本条件。
- 权限隐私：本人操作；保护原因只显示学习规则；不把“落后”分享给其他用户；管理端仅看聚合 backlog。
- 事件：backlog.calculated、backlog.protected、backlog.defer_confirmed、backlog.conflict、backlog.plan_aligned、backlog.recovery_completed。
- 跨端/弱网/性能：弱网禁止确认破坏性延期，先保存草稿；首页显示最后可信保护状态；计算和聚合异步；列表优先于图表，低配不加载复杂日历动画。
- 验收：保护队列不会因数量调整消失；延期、补学、保留均有明确状态；计划、今日任务、掌握中心同版本一致；并发变更可检测；恢复后没有重复或丢失待复习项。

## 12. 统一完成门槛

- 每个 SUBFEAT/FEAT 都能从 PRD 章节回到页面/路由、接口/数据边界、权限、事件和验收；不能定位的内容保持为冲突或待确认，不伪造需求。
- 任何接口变更先更新 packages/contracts/ 的 OpenAPI，再生成 Java DTO 与前端类型；本文不授权手写裸 any、业务代码或数据库迁移。
- 学习结果、错题、掌握信号、计划变更和媒体处理均有幂等键、版本、失败态和恢复路径；服务端未确认的数据不可进入正式掌握、报告或排名。
- 移动 H5/App/iPad、learner-web/PWA 和低配四级画质均能完成文本主流程；音频、录音、地图、波形、口腔图和结构图都有静态/列表替代。
- Phase 1 所有反馈保持规则化、可解释、可回放；不调用生成式 AI，不扩展未成年人/K12 范围，不把学习参考结果包装成官方认证。
