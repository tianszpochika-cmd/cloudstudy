# 06 作文训练设计

> 需求溯源：PRD §2.5 作文训练、mvp-scope P0；第二阶段升级为 AI 批改与升格。

---

## 一、功能设计

### 1.1 句式写作（汉译英）
- **内容结构**：中文句 → 用户写英文 → 提交后展示参考答案 + 逐要点对照。
- **评分要点预制**：每句配 2–4 个检查点（时态正确/主谓一致/固定搭配），用户提交后按要点自查勾选"我写对了"，系统记录自查结果用于薄弱统计。
- **难度分级**：简单句 → 复合句 → 段落（3–5 句主题翻译）。
- **权益**：每日免费 5 句，VIP 不限 + 段落级题目。

### 1.2 模板仿写
- **内容结构**：范文（四六级真题范文/教研范文）→ 模板抽取（骨架句高亮，关键词挖空）→ 用户填充仿写 → 对照范文自评。
- **模板库分类**：书信、议论文、图表描述、通知等四六级高频文体。
- **仿写辅助**：挖空处提供候选词块（含干扰项），降低起步难度。

### 1.3 病句改错
- **内容结构**：教研预制错误句（每句 1 处错误）→ 用户直接在句上点选错误片段并给出修正 → 判定 + 规则解析。
- **错误类型覆盖**：时态、主谓一致、冠词、介词、非谓语、从句引导词（与语法模块薄弱项联动推荐）。

### 1.4 写作档案
- 我的作文记录（汉译英答案、仿写作品、改错记录）全历史保留；免费层近 30 天、VIP 全历史（对齐错题本权益）。
- 每篇可"再练一次"（隔 3 天后提示，利用记忆规律）。

### 1.5 第二阶段预留
- 作文提交接口预留 `aiReview` 字段（批改结果/升格建议）；第一阶段该字段恒空，UI 上"AI 批改"位不展示。

### 1.6 边界情况
| 场景 | 处理 |
| :--- | :--- |
| 汉译英多种合法译法 | 参考答案给 1–2 个 + 要点判定只看检查点，不逐词比对 |
| 仿写填充词块语法错误 | 候选词块本身合法，判分只查选择正确性 |
| 用户输入纯中文/乱码 | 提交前基础校验提示 |

## 二、交互设计

### 2.1 汉译英线框

```
+----------------------------------+
| 句式写作     今日 3/5（免费）      |
+----------------------------------+
| 中文：他昨天因为生病没有来上课。    |
| ┌────────────────────────────┐  |
| │ (英文输入区，多行)           │  |
| └────────────────────────────┘  |
|  [提示：时态/原因状语]  [提交]    |
+----------------------------------+
| 提交后：                          |
| 参考答案：He didn't come to      |
| class yesterday because he was   |
| ill.                             |
| 自查要点：                        |
| ☐ 过去时态  ☐ because 引导原因    |
| [都写对了 +★] [有差距 → 加入复习]  |
+----------------------------------+
```

### 2.2 病句改错线框

```
+----------------------------------+
| 找出并改正错误：                   |
| She [go] to school [every] day.  |
|   ↑ 点选错误片段                  |
| 修正输入：[goes      ]  [判定]    |
| → 正确：主谓一致（第三人称单数）   |
+----------------------------------+
```

### 2.3 关键交互细节
- **输入区**：移动端自适应高度；Web 端支持 Tab 缩进；拼写不做实时纠错（避免干扰）。
- **模板仿写**：挖空槽为下划线胶囊，点槽弹出候选词块面板；填满后可整句朗读（TTS）。
- **反馈基调**：不出现"低分/差"等负面评价；差距反馈统一用"再练一次会更好"正向文案。
- **结算**：完成一组展示"今日写作小结"（句数/自查正确率/积累句型数）。
