# 19｜并行设计评审：练习中心与反馈闭环

> 状态：Draft / 并行评审稿  
> 日期：2026-08-20  
> 范围：Phase 1 学习者端 Practice Hub，不修改既有设计总册与其他 agent 正在编辑的文件。  
> 配套主稿：../mockups/complete-ui-ux-command-center.html（进入“练习与反馈”页面族）

## 1. 这次设计要解决的问题

现有首页已经能回答“今天该学什么”和“从哪里继续”，但练习中心仍缺少一个可直接交付的中段体验：

    首页主任务
      → 练习中心判断优先级
      → 选择一个可完成的小任务
      → 练习/修复
      → 解释与结果
      → 进入下一次复习队列
      → 回到首页或报告

Practice Hub 的首要任务不是展示所有题型，而是让用户在 3 秒内完成三次判断：

1. 今天最值得练什么；
2. 需要投入多少时间；
3. 做完后下一步是什么。

## 2. 对当前稿件的评审结论

### 保留

- 首页 Continue Learning 作为全局第一主操作；
- “待修复”与“到期复习”使用具体数量，不用泛化的“继续加油”；
- 轻量的 3/5/10 分钟入口，符合成人用户的碎片化学习场景；
- 品牌渐变只给主任务卡使用，学习正文继续保持低密度；
- 规则推荐提供“为什么推荐给我？”解释入口，不以消费因素排序。

### 下一轮必须修正

| 优先级 | 问题 | 设计处理 |
| --- | --- | --- |
| P0 | 首页的推荐、错题修复与练习入口缺少统一的队列解释 | Practice Hub 首屏固定“今日最值得练”主卡，并展示来源、预计时长、完成条件 |
| P0 | 练习完成后没有形成“反馈 → 下一次复习”的可见闭环 | 结束态显示结果、薄弱点、下次复习时间，并提供唯一主 CTA“加入今日后续” |
| P0 | 小屏学习操作容易被底部内容挤出视口 | 练习 Session 使用固定底部操作区；列表页不把关键 CTA 放在长页面末尾 |
| P1 | Onboarding 的跳过测评入口目前是可点击 div，键盘和辅助技术不可发现 | 实现时改为真实 button，提供焦点样式、可读名称和确认反馈 |
| P1 | 目标卡、图标按钮部分依赖 onclick/title 表达状态 | 使用 button/radio 语义、aria-pressed/aria-label，并用文字表达选中/收藏/播放状态 |
| P1 | 首页模块较多，用户可能把“探索”误当成“今日任务” | Practice Tab 用“今日优先”置顶，其余题型降为可扫描的能力入口 |

## 3. Practice Hub 信息架构

### 一级页面结构

    练习
    ├── 今日优先
    │   ├── 薄弱点修复
    │   └── 到期复习
    ├── 快速练习
    │   ├── 3 分钟
    │   ├── 5 分钟
    │   ├── 10 分钟
    │   └── 自定义
    ├── 按能力练习
    │   ├── 词汇
    │   ├── 短语
    │   ├── 语法
    │   ├── 听力
    │   ├── 阅读
    │   └── CET 训练
    └── 最近练习

### 首屏信息顺序

1. 页面标题 + 今日完成进度；
2. 今日最值得练主卡；
3. 快速时长选择；
4. 按能力练习；
5. 最近练习与历史入口。

首屏不同时放 XP、星币、VIP、排行榜等非当前任务状态。它们属于其他页面或全局轻量状态。

## 4. 核心交互与状态

### 4.1 主卡：今日最值得练

默认显示：

- 来源：最近 7 天错题 / 到期复习 / Checkpoint 未掌握；
- 数量：例如 7 个知识点；
- 预计时间：例如 8 分钟；
- 训练路径：规则回顾 → 变式练习 → 延迟复测；
- 主 CTA：开始修复。

点击主卡的次级入口可打开 Bottom Sheet，解释为什么推荐和本次会覆盖什么。解释不是另一套报告，不阻断开始练习。

### 4.2 快速时长

点击时长后，立即生成端侧预览状态：

    未选择 → 选择 5 分钟 → “已按 5 分钟生成队列” → 开始练习

如果队列不足，明确告诉用户实际可完成内容，例如：

> 当前只有 3 个到期词条，预计 2 分钟完成；可以补充 1 组语法变式。

不要用空白页或无解释的“暂无内容”结束路径。

### 4.3 完成反馈

练习结束页/底部结果面板固定回答：

- 我完成了什么；
- 哪些点暂时修复；
- 哪些点仍需帮助；
- 下次何时复习；
- 现在最推荐的唯一下一步。

建议文案：

    已完成 7 个修复点
    暂时修复 5 个，2 个将加入明日复测
    下一次复习：明天 19:30
    [继续今日学习]   查看结果

结果页不把一次正确率等同于“永久掌握”，使用“暂时修复”“待复测”等可解释状态。

## 5. 内容与合规边界

- Phase 1 只展示确定性规则、题目解析和复习时间，不出现 AI 评分或 AI 导师话术；
- 模拟考试结果必须标注“语学星自研模拟训练结果，不是官方成绩”；
- 正误颜色必须配合文字和图标，不能只依赖红绿；
- 错题来源、题目版本和下次复习时间要能在详情里回溯；
- 结果反馈鼓励具体行为，不使用连续打卡羞耻、惩罚式或赌博式奖励文案。

## 6. 跨端落地基线

| 端 | 页面形态 | 关键约束 |
| --- | --- | --- |
| Mobile/H5 | 单列流 + 固定底部 CTA | 主卡、时长、能力入口按纵向扫描；不把唯一 CTA 放在折叠区 |
| iPad | 左侧今日优先 + 右侧能力/最近练习 | 保持一个视觉主轴，避免三栏同时抢焦点 |
| Web | 左侧全局导航 + 中央主卡 + 右侧队列摘要 | 主卡宽度优先，右侧只放队列和历史，不重复首页所有模块 |

四级画质降级不影响本页面的信息结构。Practice Hub 不是 3D 主场景，低配设备应保持静态卡片和即时反馈。

## 7. 验收清单

- [ ] 用户打开页面后 3 秒内能看到一个明确的主任务；
- [ ] 主任务显示来源、数量、预计时长和完成路径；
- [ ] 3/5/10 分钟选择后有即时状态反馈；
- [ ] 无任务、弱网、队列不足、已完成四种状态都有可行动 CTA；
- [ ] 练习完成后能看到下一次复习时间；
- [ ] 所有图标按钮有可读名称和键盘焦点；
- [ ] 关键 CTA 在 390×844 视口内可达；
- [ ] 练习结果不宣称官方考试能力或永久掌握；
- [ ] Web/iPad 只扩展布局，不改变主任务优先级。

## 8. 给实现 agent 的交接

优先实现以下最小链路：

    Practice Hub
      → 修复详情 Bottom Sheet
      → 规则回顾
      → 变式题
      → 完成结果
      → 写入复习队列

接口和数据契约仍以 packages/contracts/ 为准；本稿只定义交互顺序、信息层级和内容状态，不替代 API 或数据库设计。
