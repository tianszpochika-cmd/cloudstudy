## 3. 原子需求拆解规则

1. 保留现有 `FEAT-*` 作为功能包主键。
2. 对同一功能包内可以独立验收、独立授权、独立页面或独立接口的子功能，建立 `SUBFEAT-*` 编号。
3. 对页面状态、设备适配、错误态、权限态等，不重复计为业务功能；它们作为该子功能的设计维度记录。
4. 对 Phase 2/3 的原子需求必须保留阶段隔离，不提前放入 Phase 1 路由、默认数据和 UI。
5. 没有 PRD 或冻结基线证据的内容不得为了凑数新增。
