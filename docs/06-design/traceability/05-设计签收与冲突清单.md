### 3.2 产品规则（已裁决与仍待决）

1. **每日时长与音频（已裁决）**：每日时长为 `5/15/30/45`；音频为 `0.5x~2.0x` 与六档快捷速度。Quick Practice 的 3/5/10/20 分钟仅为单次碎片练习预算；已同步需求基线、Onboarding、媒体与验收引用。
2. **游戏数量（已裁决）**：P0 首发 `拼句小火车 (Sentence Train)` 1 款，P1 扩展至共 4 款，6~8 款为长期目标；`FEAT-GAM-009` 为 P0，`FEAT-GAM-010..012` 为 P1。
3. **账号合并（未决，非本批次）**：PRD/MVP 要求账号冲突处理；详细设计禁止静默自动合并，要求二次认证、权益/订单/Household/学习记录/回滚和审计。仍需确认产品交互和人工客服兜底。
4. **支付开启条件（已裁决）**：P0 只覆盖建模、provider 适配、验签和沙盒；三渠道生产支付默认关闭，须通过资质、审核、退款、对账、回滚和审计 Gate 后才可开启。
5. **社交范围（未决，非本批次）**：Phase 1 只允许系统动态和预设互动；Phase 2 才考虑自由文本 UGC。仍需确认产品宣传、官网入口、后台审核和数据策略不越界。

## 4. 设计签收规则

每个 `PRD-ATOM-*` 只有在下列证据齐全后才能进入“设计签收完成”：

1. 指向一个明确 `FEAT-*`、`SUBFEAT-*` 或治理主题，且没有把选项/状态重复计成业务功能；
2. 详细设计写明目标、前置、主流程、异常、恢复、权限、隐私、内容/版本和跨端降级；
3. UIUX 写明页面/路由、入口、成功/空/加载/错误/离线/权限/恢复状态和 Deep Link；
4. `packages/contracts/` 有 API/事件 Schema 计划，数据所有权和幂等键明确；
5. `requirements/acceptance-criteria.md` 或域内验收表有可执行断言，并能关联测试证据；
6. Phase 2/3 通过独立 Gate；真实数据、模型密钥、未授权教材和儿童隐私不得进入开发夹具或 Git。

当前登记册给出的“业务设计包已绑定”只完成第 1～3 项的设计入口绑定；contracts、migration、测试和签署完成前，不得将其标记为“已实现”。
