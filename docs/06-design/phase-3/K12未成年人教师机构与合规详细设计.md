## 0. 设计结论与不可越界边界

### 0.1 结论

Phase 3 是**逐功能、逐地区、逐主体、逐内容版本的资质门控扩展**，不是 Phase 1 的自然解锁。任何一个 K12 或高中能力只有在以下四类能力同时有效时才允许从服务端放行：

1. 业务分类、主体资质和地区规则已核验；
2. 适用的线上培训、收费/预收费、平台备案和安全要求已核验；
3. 内容、教材、题目、媒体和衍生素材的版权/授权范围可证明；
4. 未成年人保护、隐私、内容安全、客服申诉、应急下线和审计能力已就绪。

门控由服务端持有事实，客户端不得提交角色、年龄、监护关系、地区、资质或 `featureFlag` 来扩大权限。条件不满足时返回稳定错误并保持关闭，不以“试用”“灰度”“内部链接”绕过门控。

### 0.2 阶段隔离

| 能力 | Phase 1 默认状态 | Phase 2 默认状态 | Phase 3 设计状态 |
|---|---|---|---|
| 未成年人注册、年龄识别、监护绑定 | 不出现入口 | 不出现入口 | 仅在 `K12_GATE` 通过后按功能开启 |
| K12/高中同步课程、教材版本 | 不加载、不宣传 | 不默认导入未授权 K12 教材 | 仅消费已授权、已审、已发布版本 |
| 家长模式、防沉迷 | 不存在 | 不存在 | 单独权限与状态机，默认关闭 |
| 教师、机构、班级、组织报告 | 仅现有成人 Admin 能力 | 可按成人业务试点 | K12/学校场景需专项业务合规后开启 |
| AI Tutor、RAG、语音评测 | 按各阶段边界 | 仅成人能力 | 未成年人场景需单独安全评估、结构化输出和审计 |

不得把本文的任何页面、导航、数据种子、宣传文案或深链加入 Phase 1 默认产品。不得以现有 `Household` 家庭权益关系替代监护授权；共享会员权益不等于共享未成年人学习数据。

### 0.3 共同契约基线

- API 使用 `/api/v1`；JSON 使用 camelCase，数据库使用 snake_case；成功响应为 `{requestId,data,meta,serverTime}`，错误响应为 `{requestId,error:{errorCode,message,retryable,details}}`。
- 所有写操作带 `Idempotency-Key`；离线学习流水额外带 `clientEventId`、`clientSeq` 和 `contentVersionId`；列表使用不透明 cursor。
- 所有接口服务端重新解析 `actorId`、`tenantId`、`orgId`、`classId`、`subjectUserId` 和内容授权，不信任客户端同名字段。
- API、Java DTO、前端 TypeScript 类型和事件 Schema 必须先进入 `packages/contracts/` 并由生成器产出；本文只给出设计级路径和字段，不替代 OpenAPI 单一事实源。
- 事件使用 `domain.action.vN`；至少含 `eventId`、`schema`、`occurredAt`、`actorId`、`tenantId`、`requestId`、`correlationId` 和脱敏 `payload`。先写 outbox，再投递 Kafka-compatible Event Bus，消费者按 `eventId` 幂等；RabbitMQ 仅供 `services/core-api` 的 v1 可选兼容使用，Redis Streams 不得作为 v2 事件事实源或迁移主线。
- 儿童个人信息、监护人手机号、年龄证据、原始录音、原始作文、RAG 原始问答和资质凭证均不得进入普通日志、埋点或无权限导出。

## 1. Phase 3 总门控、角色与数据隔离

### 1.1 `K12_GATE` 状态机

门控粒度为 `featureCode + regionCode + tenantId + contentVersionId`；只要某个维度缺失或过期，就按关闭处理。

```text
OFF
  -> EVIDENCE_PENDING
  -> CLASSIFICATION_REVIEW
  -> LEGAL_REVIEW
  -> LICENSE_READY
  -> RIGHTS_READY
  -> CHILD_SAFETY_READY
  -> SECURITY_READY
  -> PILOT_READY
  -> ENABLED

ENABLED -> SUSPENDED -> ENABLED
ENABLED -> REVOKED -> ARCHIVED
任意非终态 -> OFF / REJECTED
```

状态转移要求：

- `CLASSIFICATION_REVIEW` 必须留下“是否属于学科类校外培训、当地是否允许该主体开展、需要何种许可”的判断及证据引用。
- `LICENSE_READY` 不能只表示“已申请”；需要有效的主体/业务资质状态。
- `RIGHTS_READY` 必须覆盖教材、题库、图片、音频、视频、录音示例和衍生内容的使用目的、地区、期限及发布渠道。
- `CHILD_SAFETY_READY` 至少覆盖年龄识别、监护授权、家长控制、使用时长、夜间限制、内容安全、投诉和撤回流程。
- `SECURITY_READY` 覆盖访问控制、加密/脱敏、删除导出、备份恢复、供应商数据边界和应急处置。
- `SUSPENDED` 或 `REVOKED` 优先级高于缓存中的任何客户端开关；学习端立即停止新内容分发，已下载内容按授权和 availability 策略处理。

### 1.2 Phase 3 角色与权限候选

以下是 Phase 3 的领域角色/权限候选，不表示它们已经存在于当前 B0 策略文件。落地前必须在现有“默认拒绝、租户内最小角色”体系中注册，并通过权限契约测试。

| 角色/权限域 | 最小作用域 | 允许 | 明确禁止 |
|---|---|---|---|
| `k12Subject` / `K12_SUBJECT_SELF` | 本人 `subjectUserId` | 读取已授权课程、提交本人学习记录、查看本人反馈 | 读取其他未成年人、修改监护关系、绕过时长锁 |
| `k12Guardian` / `K12_GUARDIAN_LINK` | 已验证监护链路下的本人子女 | 查看授权范围内报告、设置时段/内容/隐私策略、管理同意 | 查看其他家庭、教师后台、原始敏感凭证 |
| `k12Teacher` / `K12_CLASS` | 所属租户的被分配班级 | 发布已发布内容的作业、查看班级学情和授权范围内学生反馈 | 跨班级/跨租户查询、读取监护人手机号、支付和原始身份证件 |
| `k12OrgAdmin` / `K12_ORG` | 所属机构/租户 | 维护机构成员、班级、内容授权和组织级聚合报告 | 修改平台资质结论、读取机构外数据、扩大教师权限 |
| `k12ContentEditor` / `K12_CONTENT_EDIT` | 内容租户 | 创建教材映射、题目和媒体草稿，维护来源 | 审核自己的版本、读取儿童学习档案 |
| `k12ReviewerL1/L2` | 内容/地区授权范围 | 初审/终审并留下依据 | 自审自发、跳过版权/安全门 |
| `k12Compliance` | 平台或指定租户 | 审核门控、应急暂停、查看受限凭证摘要 | 修改学习成绩、导出无关个人信息 |
| `k12Auditor` | 受授权租户/平台审计范围 | 只读审计、策略评估和导出审计摘要 | 直接变更业务数据 |
| `supportMasked` | 工单所需的最小对象 | 查看脱敏摘要、处理投诉/删除/授权工单 | 查看原始年龄证据、原始录音、完整手机号 |

所有角色都必须有稳定 `id`、`roles`、`tenantId` 和请求原因；无租户或无资源作用域直接拒绝。教师和机构权限是资源权限，不是全局管理员权限。

### 1.3 数据隔离分层

所有 Phase 3 记录至少携带以下可过滤字段：

| 层 | 关键字段 | 隔离规则 |
|---|---|---|
| 主体 | `subjectUserId`、`ageGroup`、`gradeBand` | 学习者只可命中本人；监护人只能命中有效监护链路的子女 |
| 家庭 | `guardianLinkId`、`familyScopeId` | 家庭关系与会员 Household 关系分开；撤回授权立即停止新读取 |
| 组织 | `tenantId`、`orgId`、`orgMembershipId` | 机构、学校、教师和班级全部租户内隔离 |
| 班级 | `classId`、`classMembershipId` | 教师只可访问被分配班级；学生只能看到本人作业/反馈 |
| 内容 | `contentVersionId`、`curriculumVersionId`、`licenseScopeId` | 只检索与地区、年级、组织权益和授权目的匹配的已发布版本 |
| 报告 | `reportScope`、`purposeCode`、`dataWatermark` | 先做权限和字段过滤，再聚合/导出；不得用客户端筛选实现隔离 |

敏感字段采用“业务表引用 + 受限证据存储”模式。身份证件原文、证件图片、监护证明和完整手机号不进入普通业务表；业务表只保存哈希、加密值、证据引用、状态、版本、有效期和访问审计信息。

## 3. Canonical 功能详细设计

### 3.1 `FEAT-K12-001`｜全国主流中小学教材版本库

**目标与范围**：提供按地区、学段、年级、学期、出版社/版本、册次和单元组织的教材索引。feature-matrix 中列举的人教版、外研版、牛津上海版、北师大版等只是目标覆盖清单；没有有效授权的版本只可登记为待授权资产，不得出现在学习端。

- **前置合规门**：`K12_GATE=ENABLED`；版本对应的分类鉴别、主体资质、教材授权、内容审核、个人信息保护和安全审核均通过；`licenseScope` 覆盖实际地区、终端、学习/答疑用途和有效期。
- **角色权限**：`k12Subject` 只能读取分配给本人且 `PUBLISHED + AVAILABLE` 的版本；`k12Guardian` 只读子女当前使用版本；`k12ContentEditor` 可建草稿但不能审核；L1/L2 审核和 `k12Compliance` 分离；机构只能读取购买/授权范围内版本。
- **数据隔离**：以 `curriculumVersionId`、`contentVersionId`、`regionCode`、`licenseScopeId` 和 `tenantId` 做服务端过滤；未授权版本、过期版本和其他租户版本不进入搜索、缓存、离线包或 RAG 索引。
- **状态机**：资产 `DRAFT -> IN_REVIEW -> APPROVED -> PUBLISHED -> ARCHIVED`；可用性另行维护 `AVAILABLE -> BLOCKED -> EXPIRED/REVOKED`，不得用发布状态掩盖版权失效。
- **API**：`GET /api/v1/k12/curriculum/versions`、`GET /api/v1/k12/curriculum/versions/{curriculumVersionId}`、`GET /api/v1/k12/curriculum/units?curriculumVersionId=...`；管理侧 `POST /api/v1/admin/k12/curriculum/versions`、`POST /api/v1/admin/k12/curriculum/versions/{id}/review`。
- **数据**：`k12_curriculum_version`（地区、学段、年级、学期、版本、册次、`contentVersionId`、权利范围、状态）；`k12_unit`、`k12_lesson`、`k12_learning_item`、`content_rights_ref`；不得复制一套独立的通用 `contentVersionId`。
- **异常**：`K12_GATE_CLOSED`、`CURRICULUM_NOT_PUBLISHED`、`RIGHTS_SCOPE_MISMATCH`、`RIGHTS_EXPIRED`、`REGION_NOT_ALLOWED`、`CONTENT_VERSION_REVOKED`；列表只能返回可解释的“暂不可用”，不泄露未发布内容。
- **事件**：`k12.curriculum.draft_saved.v1`、`k12.curriculum.reviewed.v1`、`k12.curriculum.published.v1`、`k12.curriculum.revoked.v1`；payload 只含版本 ID、状态、授权证据引用摘要和 `contentVersionId`。
- **跨端**：feature-matrix 标记为 All；`apps/mobile` 统一承载 App/H5/iPad/微信小程序条件编译，`apps/learner-web` 提供 PC/平板工作区，`apps/admin-web` 提供高密度教研审核。小程序不另建业务项目；Performance 档只呈现索引和静态文本。
- **验收**：无有效门控或授权的版本在所有终端不可搜索、不可学习、不可下载；发布前可还原来源、版权状态、审核人、版本和有效期；撤回后新请求拒绝且缓存/离线策略按授权回收；跨租户、跨地区、跨版本访问均被拒绝并有审计记录。

### 3.2 `FEAT-K12-002`｜课内跟学与课文背诵

**目标与范围**：围绕已授权教材的 Unit 组织生词、课文点读、逐句朗读和复习闭环，不扩展为默认社交或开放式学科社区。

- **前置合规门**：账号为 `ACTIVE_MINOR` 且监护授权有效；课程版本已发布、可用且授权目的包含学习/朗读/评分；朗读评分策略通过未成年人语音和 AI/ASR 风险评估。
- **角色权限**：学生提交本人作答/录音；监护人查看授权范围内进度摘要；教师只可查看所分配班级中已授权的任务结果；教研维护内容版本；评分审核角色只读评分证据并不能修改原始作答。
- **数据隔离**：`attemptId`、`sessionId`、`subjectUserId`、`classId`、`contentVersionId` 全部服务端绑定；原始录音与评分结果分离保存，教师/机构默认只看结果摘要，不读原始音频。
- **状态机**：单元 `NOT_STARTED -> IN_PROGRESS -> SUBMITTED -> SCORED -> REVIEWED -> COMPLETED`；录音 `LOCAL_ONLY -> UPLOAD_PENDING -> UPLOADED -> RETENTION_PENDING -> DELETED/EXPIRED`；删除或撤回不改变可保留的审计摘要。
- **API**：`GET /api/v1/k12/lessons/{lessonId}`、`POST /api/v1/k12/lessons/{lessonId}/attempts`、`POST /api/v1/k12/attempts/{attemptId}/recording`、`GET /api/v1/k12/attempts/{attemptId}/feedback`；所有写请求幂等。
- **数据**：`k12_lesson_enrollment`、`k12_learning_attempt`、`k12_reading_attempt`、`media_asset_ref`、`scoring_policy_version`、`feedback_summary`、`retentionUntil`；不把原始音频写入埋点。
- **异常**：`GUARDIAN_CONSENT_REQUIRED`、`RECORD_PERMISSION_DENIED`、`UPLOAD_RETRYABLE`、`SCORING_UNAVAILABLE`、`ATTEMPT_ALREADY_SUBMITTED`、`CONTENT_REVOKED`；评分不可用时只能进入“待复核/稍后重试”，不得伪造分数。
- **事件**：`k12.lesson.started.v1`、`k12.lesson.completed.v1`、`k12.reading.submitted.v1`、`k12.reading.scored.v1`、`k12.recording.deleted.v1`。
- **跨端**：App/Web/H5 为主；小程序提供课程索引、点读和受平台能力限制的录音降级；录音、弱网和断点上传遵循现有同步规范，四级画质不影响音频权限和删除入口。
- **验收**：学生可按 Unit 追踪生词、课文和逐句反馈；重复提交不重复记分；授权撤回/内容撤回后新提交被阻断；无权教师不能查询学生；原始录音按配置期限删除且报告仍能说明评分状态和版本。

### 3.3 `FEAT-K12-003`｜未成年人适龄界面

**目标与范围**：根据服务端确认的 `gradeBand`、学习目标、监护人设置和无障碍偏好切换小学/初中/高中展示策略，隐藏不必要的社交和商业诱导。

- **前置合规门**：未成年人账号和监护授权有效；适龄策略版本已审核；内容年龄/学段标注完整；奖励、排行榜、商业入口和动效策略已经过专项审查。
- **角色权限**：学生只能使用服务端下发的展示配置；监护人可在授权范围内调整内容适龄、排行榜和奖励动效；教师/机构只能读学习相关配置摘要；运营不能通过客户端实验覆盖保护性设置。
- **数据隔离**：`presentationProfileId` 与 `subjectUserId`、`policyVersion` 绑定；监护策略和学习记录分开；不得把学段、年龄或儿童标签写入公开排行榜、营销埋点或组织报告。
- **状态机**：`ADULT_DEFAULT -> PROFILE_PENDING -> ELEMENTARY/MIDDLE/HIGH -> PARENT_OVERRIDE -> SAFE_FALLBACK`；门控关闭或配置异常时为 `SAFE_FALLBACK`，而不是回退到成人商业首页。
- **API**：`GET /api/v1/k12/presentation-profile`、`PUT /api/v1/k12/parent/presentation-policy`；服务端根据账号、授权和策略版本计算结果，客户端不得传入任意 `gradeBand` 获得高权限内容。
- **数据**：`k12_presentation_profile`、`k12_presentation_policy`、`gradeBand`、`contentWeight`、`animationPolicy`、`leaderboardPolicy`、`commercialSurfacePolicy`、`policyVersion`。
- **异常**：`PRESENTATION_POLICY_MISSING`、`GRADE_BAND_UNRESOLVED`、`POLICY_VERSION_EXPIRED`、`PARENT_REAUTH_REQUIRED`、`K12_GATE_CLOSED`；异常时隐藏 K12 入口并保留可理解的安全提示。

- **跨端**：适用 App/微信小程序；Web 端若未配置 Phase 3 展示壳，不得自动显示儿童模式。移动端沿用 `apps/mobile` 的 Token 和组件语义，不复制 Phase 1 页面；所有模式支持 Reduced Motion、字体放大和静态降级。
- **验收**：不同学段只显示对应内容和权重；默认弱化排行榜压力、关闭商业诱导和付费随机奖励；门控关闭时 Phase 1 启动包、路由和首页快照中均不存在 K12 元素；配置跨设备一致且可审计。

### 3.4 `FEAT-K12-004`｜防沉迷强监管

**目标与范围**：由服务端按当期有效规则控制夜间锁定、工作日学习时长上限、每日使用策略和锁定提示。feature-matrix 当前写明的 `22:00~08:00` 及工作日上限是待合规复核的基线，不把未经复核的数值扩展为其他法定规则。

- **前置合规门**：地区规则、时区、夜间窗口、工作日/节假日策略、账号类型和监护配置均有有效版本；计时、设备互斥、断线恢复和客服申诉可审计。
- **角色权限**：服务端计时器和 `k12Compliance` 决定锁定；学生不能跳过；监护人只能设置不低于监管要求的更严格策略；教师/机构不能解除个人锁；客服只能按工单查看状态。
- **数据隔离**：使用流水按 `subjectUserId + policyVersion + timezone` 计算；设备心跳、使用时段和锁定原因不进入公开社交或组织排行榜；组织只读聚合分钟和完成状态。
- **状态机**：`AVAILABLE -> WARNING -> LOCKED_NIGHT -> LOCKED_DAILY_LIMIT -> LOCKED_POLICY -> PARENT_REVIEW -> RESUMABLE`；`SUSPENDED`/`REVOKED` 可从任意状态强制进入 `LOCKED_POLICY`。
- **API**：`GET /api/v1/k12/usage-policy`、`POST /api/v1/k12/usage/heartbeat`、`POST /api/v1/k12/usage/session/start`、`POST /api/v1/k12/usage/session/close`、`GET /api/v1/k12/usage/status`；心跳只延续服务器租约，不改变已结算分钟。
- **数据**：`k12_usage_policy`、`k12_usage_session`、`k12_usage_ledger`、`k12_lock_record`、`calendar_rule_version`、`timezone`、`policyDecisionVersion`；客户端时钟只作展示。
- **异常**：`NIGHT_LOCK_ACTIVE`、`DAILY_LIMIT_REACHED`、`USAGE_POLICY_UNAVAILABLE`、`CLIENT_CLOCK_UNTRUSTED`、`DUPLICATE_USAGE_EVENT`、`PARENT_REAUTH_REQUIRED`；规则服务不可用时 fail-closed，不能因缓存失效放行。
- **事件**：`k12.usage.warning.v1`、`k12.usage.locked.v1`、`k12.usage.resumed.v1`、`k12.usage.reconciled.v1`、`k12.usage.policy_updated.v1`。
- **跨端**：All；App/Web/H5/小程序均展示锁定态，端侧统一使用服务端状态。小程序和低配机只显示静态倒计时/说明；离线不允许开始新的受监管学习 session，已下载内容在同步前遵循锁定策略。
- **验收**：在当前已批准规则下，夜间窗口到达即锁定、工作日上限不可超出；切换设备、改系统时钟、重复心跳、断网重连不能规避计时；锁定提示不羞辱学生、不含商业 CTA；所有锁定/恢复/策略变更可按 `requestId` 回放。

### 3.5 `FEAT-K12-005`｜家长锁与监护远程监督

**目标与范围**：提供监护人绑定、只读学习看板、每日时段/目标/报告/隐私与支付控制，并以独立认证保护家长模式。

- **前置合规门**：`SUBFEAT-K12-003` 的监护授权为 `ACTIVE`；家长模式认证、通知、撤回、数据导出和客服工单路径就绪；支付默认为关闭，只有当期规则和资质明确允许时才可配置确认流程。
- **角色权限**：监护人可管理有效绑定子女；学生只读自己的学习流且不能读取家长手机号/凭证；教师/机构不具备家长锁权限；平台审计只读操作记录，不读取家长密码原文。

- **状态机**：绑定 `INVITED -> CONSENT_PENDING -> ACTIVE -> EXPIRED/WITHDRAWN/REVOKED`；家长模式 `LOCKED -> AUTHENTICATING -> ACTIVE -> IDLE_TIMEOUT -> LOCKED`；撤回后所有新查询进入 `RESTRICTED`。
- **API**：`GET /api/v1/k12/parent/dashboard`、`GET /api/v1/k12/parent/usage`、`PUT /api/v1/k12/parent/policies`、`POST /api/v1/k12/parent/unlock-session`、`POST /api/v1/k12/guardian-links/{id}/withdraw`。
- **数据**：`guardianLinkId`、`subjectUserId`、`guardianUserId`、`consentVersion`、`policyVersion`、`dailyTarget`、`allowedWindows`、`contentAgePolicy`、`rewardPolicy`、`leaderboardPolicy`、`paymentPolicy`、`passcodeHash`。
- **异常**：`GUARDIAN_LINK_INACTIVE`、`PARENT_REAUTH_REQUIRED`、`POLICY_TOO_PERMISSIVE`、`DASHBOARD_SCOPE_DENIED`、`CONSENT_WITHDRAWN`、`MULTI_DEVICE_CONFLICT`；不返回可用于猜测绑定关系的详细错误。
- **事件**：`k12.parent.mode_unlocked.v1`、`k12.parent.policy_updated.v1`、`k12.parent.dashboard_viewed.v1`、`k12.guardian.link_withdrawn.v1`、`k12.parent.payment_policy_changed.v1`。
- **跨端**：App/微信小程序为主；小程序使用条件编译和平台安全能力，不新增 `apps/miniapp-wechat` 业务项目；家长页面不放入 Phase 1 “我的”导航，入口只由 Phase 3 绑定状态生成。
- **验收**：无有效监护授权不能进入家长看板；家长可以查看时间、目标和报告并设置更严格限制；密码/二次认证失败不泄露绑定信息；撤回授权后立即停止新的家长读取和远程策略写入，历史审计仍可受限保留。

## 4. 派生子功能详细设计

### 4.1 `SUBFEAT-K12-001`｜开放前置条件与总门控

- **前置合规门**：以 `K12_GATE` 为唯一入口；必须完成业务分类、地区允许性、许可/备案、线上培训要求、收费/预收费规则、内容审核、未成年人保护、网络安全、个人信息保护和 AI 虚拟教师分类风险复核。
- **角色权限**：只有 `k12Compliance`/授权审计角色能提交证据和转移门控；内容编辑只能提交素材；运营只能读取生效状态；客户端无写权限。
- **数据隔离**：门控记录按功能、地区、租户和版本隔离；平台级应急动作不能由租户自定义放宽；证据原件进入受限凭证库，业务表保存引用和 hash。
- **状态机**：使用 1.1 的 `OFF -> ... -> ENABLED`；证据过期、投诉升级、资质暂停或安全事故均可转 `SUSPENDED`/`REVOKED`。
- **API**：`GET /api/v1/k12/gates/{featureCode}`；管理侧 `POST /api/v1/admin/k12/gates/evidence`、`POST /api/v1/admin/k12/gates/{gateId}/transition`、`POST /api/v1/admin/k12/gates/{gateId}/suspend`。
- **数据**：`k12_gate_decision`、`qualificationEvidenceRef`、`rightsEvidenceRef`、`safetyAssessmentRef`、`decisionVersion`、`effectiveAt`、`expiresAt`、`reasonCode`、`flagState`。
- **异常**：`K12_GATE_CLOSED`、`GATE_EVIDENCE_EXPIRED`、`REGION_NOT_ALLOWED`、`QUALIFICATION_REQUIRED`、`SAFETY_REVIEW_REQUIRED`；默认关闭，不能静默降级为成人 K12 入口。
- **事件**：`k12.gate.evaluated.v1`、`k12.gate.enabled.v1`、`k12.gate.suspended.v1`、`k12.gate.revoked.v1`。
- **跨端**：所有端只消费门控结果；启动包、默认路由、预取和搜索索引均须在服务端门控后生成；管理端显示证据状态，不把内部证据原件下发学习端。
- **验收**：任一前置条件缺失即无法开启；过期/撤回在缓存 TTL 内按 fail-closed 收敛；同一门控决策可按版本回放；Phase 1 全量 flag 和路由静态检查不出现 K12 页面或默认数据。

### 4.2 `SUBFEAT-K12-002`｜未成年人账号与年龄识别

- **前置合规门**：Phase 3 门控有效；年龄识别方式、年龄段规则、证据保存、误判申诉和未成年人内容安全流程已由当期合规复核确认。年龄证据方式不在本文冻结为某一种法定实现。
- **角色权限**：登录主体只能提交本人年龄信息；监护人可在邀请流程中补充授权；`k12Compliance` 可查看证据状态而非默认查看原件；教师/机构不得参与年龄判定。
- **数据隔离**：复用现有 `usr_user.userId` 和 `ageGroup` 作为主账号事实，补充 `k12_age_assessment`；不新建平行用户表。原始证据和手机号加密/受限，普通档案只保存 `ageGroup`、状态和引用。
- **状态机**：`AGE_UNVERIFIED -> AGE_DECLARED -> AGE_EVIDENCE_PENDING -> AGE_CONFIRMED`；失败为 `AGE_REJECTED`，需要更正时回到 `AGE_EVIDENCE_PENDING`；确认未成年人后进入 `MINOR_GUARDIAN_PENDING`，不得直接进入 K12 学习。
- **API**：`POST /api/v1/k12/account/age-assessment`、`GET /api/v1/k12/account/status`、`POST /api/v1/k12/account/correction-request`；不返回原始证据或审核内部规则。
- **数据**：`userId`、`ageGroup`、`gradeBand`、`assessmentMethodCode`、`evidenceRef`、`assessmentStatus`、`policyVersion`、`reviewedAt`、`retentionUntil`、`appealId`。
- **异常**：`AGE_EVIDENCE_REQUIRED`、`AGE_ASSESSMENT_REJECTED`、`AGE_POLICY_UNAVAILABLE`、`MINOR_GUARDIAN_REQUIRED`、`ACCOUNT_STATUS_RESTRICTED`；不因年龄不明而把用户默认当作成人放行 K12。
- **事件**：`k12.account.age_assessment_started.v1`、`k12.account.age_confirmed.v1`、`k12.account.age_rejected.v1`、`k12.account.restricted.v1`。
- **跨端**：年龄流程仅在 Phase 3 专属注册/绑定链路中出现；App/Web/H5/小程序按平台可用能力呈现，不修改 Phase 1 成人注册页。所有端都支持中断后恢复和删除/更正入口。
- **验收**：年龄未确认或状态不允许时，K12 路由、课程和家长绑定均不能访问；不复制用户主表；年龄更正有审计、幂等和人工复核路径；原始证据不出现在日志、埋点、报告和客户端缓存。

### 4.3 `SUBFEAT-K12-003`｜监护人授权、绑定与撤回

- **前置合规门**：监护关系校验方式、同意文本版本、手机号触达、授权期限、撤回和申诉流程已核验；未确认时 `ACTIVE_MINOR` 不可建立。
- **角色权限**：未成年人发起绑定但不能自证为监护人；监护人完成授权并可撤回；平台只处理状态和证据；教师/机构只能消费授权结果，不得发起代授权。
- **数据隔离**：绑定记录使用 `guardianLinkId`，同时关联 `guardianUserId`、`subjectUserId`、关系类型、同意版本和证据引用；监护人手机号加密保存，教师和机构永不返回。
- **状态机**：`INVITED -> CONSENT_PENDING -> VERIFIED -> ACTIVE`；异常进入 `REJECTED`；到期 `EXPIRED`；监护人撤回 `WITHDRAWN`；平台紧急处置 `REVOKED`。`ACTIVE` 失效后新数据处理转为 `RESTRICTED`。
- **API**：`POST /api/v1/k12/guardian-links/invitations`、`POST /api/v1/k12/guardian-links/{id}/verify`、`POST /api/v1/k12/guardian-links/{id}/consent`、`POST /api/v1/k12/guardian-links/{id}/withdraw`、`GET /api/v1/k12/guardian-links`。
- **数据**：`k12_guardian_link`、`consentVersion`、`consentedAt`、`withdrawnAt`、`expiresAt`、`evidenceRef`、`verificationMethodCode`、`policyVersion`、`auditRef`。

- **异常**：`RIGHTS_EVIDENCE_MISSING`、`RIGHTS_SCOPE_MISMATCH`、`RIGHTS_EXPIRED`、`COPYRIGHT_COMPLAINT_OPEN`、`CONTENT_REVOKED`、`OFFLINE_ASSET_NOT_REVALIDATED`；不以编辑备注替代授权证据。

- **跨端**：只向学习端下发 `PUBLISHED + AVAILABLE`；撤回时清理搜索、推荐、缓存、RAG 索引和新下载；离线包在恢复连接后按授权策略校验，不能继续分发已撤回内容。
- **验收**：任意学习内容都能追溯来源、版权状态、凭证、版本、编辑/审核人和发布范围；无授权内容无法发布；投诉可定位并在必要时一键下架；撤回不破坏历史学习记录的可解释性。

### 4.21 `SUBFEAT-K12-021`｜主体资质、分类鉴别与地区许可

- **前置合规门**：逐地区确认是否属于学科类校外培训、当地是否允许相关主体新增/开展、需要何种许可、线上培训监管、收费/预收费和平台备案要求；本文不替代专业法律判断。
- **角色权限**：合规人员录入/审核证据；平台管理员按已批准决策发布 flag；机构只能提交自身材料；运营不能自行把 `PENDING` 改成 `ENABLED`；审计员只读决策链。
- **数据隔离**：资质记录按主体、地区、业务模式和功能拆分；机构资质不自动覆盖平台其他租户；证书原件受限，决策表保存编号 hash、状态、有效期和证据引用。
- **状态机**：`NOT_ASSESSED -> CLASSIFICATION_PENDING -> LICENSE_PENDING -> EVIDENCE_REVIEW -> APPROVED -> EXPIRED/SUSPENDED/REVOKED`；`NOT_APPLICABLE` 必须有专业复核依据，不能由产品配置直接设置。
- **API**：`POST /api/v1/admin/k12/qualification/evidence`、`GET /api/v1/admin/k12/qualification/{subjectId}`、`POST /api/v1/admin/k12/qualification/{id}/decision`、`GET /api/v1/k12/qualification/public-summary`（只返回可公开摘要）。
- **数据**：`qualificationProfile`、`subjectType`、`businessModelCode`、`regionCode`、`classificationDecision`、`licenseType`、`evidenceRef`、`effectiveAt`、`expiresAt`、`reviewerId`、`decisionReason`。
- **异常**：`QUALIFICATION_NOT_ASSESSED`、`LICENSE_PENDING`、`REGION_NOT_ALLOWED`、`QUALIFICATION_EXPIRED`、`QUALIFICATION_REVOKED`、`PUBLIC_SUMMARY_FORBIDDEN`；所有异常默认关闭对应功能。
- **事件**：`k12.qualification.submitted.v1`、`k12.qualification.approved.v1`、`k12.qualification.expired.v1`、`k12.qualification.suspended.v1`、`k12.qualification.revoked.v1`。
- **跨端**：门控服务端统一；官网只可展示已批准的公开摘要；学习端不展示“资质已通过”的营销承诺，除非文字由合规审核发布；后台显示完整证据链但按角色脱敏。
- **验收**：没有有效资质/分类/地区决策不能上线相关页面、课程、收费或 API；过期自动关停；平台、机构、内容三类主体边界不混淆；每次决策具备证据、版本、时间、角色和审计。

### 4.22 `SUBFEAT-K12-022`｜审计、投诉与应急下线

- **前置合规门**：审计日志、内容纠错/版权投诉、未成年人申诉、客服 SLA、双审、应急联系人、回滚/下线 runbook 和数据保留策略已演练；重大动作必须可回放。
- **角色权限**：合规人员处理门控和应急暂停；审核员处理内容；客服只看脱敏工单；审计员只读；运维执行已批准的 flag/回滚；任何单一角色不得完成录入、审核、发布全链路。
- **数据隔离**：审计记录按 `tenantId + resourceType + resourceId`；投诉附件隔离；儿童原始内容只在最小权限下查看；导出有字段白名单、行数限制、水印和 reasonCode。
- **状态机**：工单 `OPEN -> TRIAGED -> INVESTIGATING -> ACTION_REQUIRED -> RESOLVED -> CLOSED`；紧急事件 `DETECTED -> CONTAINED -> SUSPENDED -> REMEDIATED -> RESTORED/REVOKED`；内容撤回状态与审计状态分开。
- **API**：`POST /api/v1/k12/complaints`、`GET /api/v1/k12/complaints/{id}`、`GET /api/v1/admin/k12/audit/events`、`POST /api/v1/admin/k12/incidents`、`POST /api/v1/admin/k12/emergency-actions/suspend`、`POST /api/v1/admin/k12/emergency-actions/restore`。
- **数据**：`auditLog`（actor、role、reason、before/after hash、requestId、timestamp）；`complaint`、`incident`、`emergencyAction`、`featureGateDecision`、`reviewEvidence`、`resolution`、`retentionUntil`。
- **异常**：审计写入失败、重复投诉、附件违规、审核超时、恢复条件不满足、越权读取和 flag 缓存不一致；安全关键写入失败时拒绝发布/恢复，不静默忽略。
- **事件**：`k12.audit.accessed.v1`、`k12.complaint.created.v1`、`k12.complaint.resolved.v1`、`k12.incident.detected.v1`、`k12.feature.suspended.v1`、`k12.feature.restored.v1`。
- **跨端**：学习端提供内容纠错/版权投诉/隐私请求入口；Admin Web 提供工单、双审、审计和应急控制；导出/恢复由服务端执行，移动端不持有管理密钥。
- **验收**：所有门控、授权、内容、账号、监护、报告、导出和应急动作均可按 `requestId/eventId` 回放；投诉可关联具体版本并触发下架；恢复必须重新验证资质/版权/安全门；普通日志不含敏感原文。
