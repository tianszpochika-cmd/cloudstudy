## 0. 设计结论、编号口径与不可越过的边界

### 0.1 业务目标

GAM 域服务于完整学习闭环：

学习目标 → 真实学习行为 → 规则判定 → XP/星币/Streak/任务进度 → 反馈与复习 → 星系、Avatar、学习空间和收藏成长。

游戏、3D 和随机奖励都是学习反馈层，不得覆盖今日学习流、复习队列、错题修复和阶段 Checkpoint 的主入口。视觉奖励不改变学习成绩、SRS 调度、考试评分、推荐结果或社交排行榜的公平性。

### 0.2 Feature Matrix 与 PRD 六类游戏的编号差异

feature-matrix.md 当前实际登记的 GAM 功能为 22 项，其中核心游戏只登记 FEAT-GAM-009～012 四项；PRD §14.6 规定六类核心学习游戏。本文采用以下口径：

| 台账/来源 | 真实编号或 gameCode | 处理 |
|---|---|---|
| feature-matrix | FEAT-GAM-009 | 拼句小火车 Sentence Train |
| feature-matrix | FEAT-GAM-010 | 单词消消乐 Word Match |
| feature-matrix | FEAT-GAM-011 | 单词保卫战 Word Defense |
| feature-matrix | FEAT-GAM-012 | 拼图解谜 Word Puzzle |
| PRD §14.6 | GRAMMAR_BLASTER | 语法射击 Grammar Blaster；作为同一游戏运行时的 P1 扩展 gameCode，不虚构 FEAT-GAM-023 |
| PRD §14.6 | CATCH_MEANING | 词义捕手 Catch the Meaning；作为同一游戏运行时的 P1 扩展 gameCode，不虚构 FEAT-GAM-024 |

因此，FEAT 覆盖仍严格为 FEAT-GAM-001～022；六个游戏均在本文的游戏目录、状态机、判定模型、接口和验收中落地。若未来产品台账为 Grammar Blaster 或 Catch the Meaning 分配独立编号，只需在 contracts 和 feature-matrix 增加映射，不改变 gameCode、账本和会话模型。

### 0.3 Phase 1 范围与红线

1. 仅面向 18 岁以上成人、大学生和职场用户；未成年人模式属于 Phase 3，本文不实现。
2. Phase 1 不调用生成式 AI、LLM、AI 数字人、AI 发音评分或模型驱动游戏判定；题目、答案、解析、关卡和奖励均来自已发布且经过审核的规则化内容。
3. XP、星币、收藏碎片和装扮均不可提现、不可换现金、不可转赠、不可交易；不创建 NFT、玩家交易市场或可充值钻石。
4. 奖励箱只能由真实学习行为免费获得，不能购买箱子、抽取次数、概率提升、付费复活或付费加分；会员欢迎权益只能是固定可预览的物品或自选券。
5. 不使用轮盘、拉杆、老虎机、投币机、“差一点中大奖”、人民币符号或无限连抽等赌博化表现。
6. 装扮品质只表达视觉稀有度和收藏价值，不产生数值战力，不影响学习推荐、考试评分、排行榜或 SRS。
7. 六个游戏的题目直接来自用户当前学习进度、复习队列、错题或已发布课程包；不做与语言学习无关的独立剧情。
8. 所有复杂动效、Three.js、Rive、WebGL 和粒子效果服从 AdaptivePerformanceEngine；Performance 档必须能完成完整学习和游戏判定。

### 0.4 依赖与事件边界

- learning/practice/review 提供已验证的学习完成事件，不把前端页面打开、预览、暂停或点击作为奖励事实。
- gamification 负责奖励资格、数值结算、任务/成就/Streak、游戏会话和审计。
- avatar 负责外观配置、衣柜、资源版本、快照和学习空间；不得直接修改货币账本。
- admin 负责规则、概率、资源、物品、赛季和 Feature Flag 的审核发布；配置发布后以版本号冻结在每次结算中。
- analytics 只消费脱敏事件；不能反向写回奖励事实。
- 所有跨域事件遵守 docs/05-api/api-conventions.md：事件名为 domain.action.vN，payload 必须包含 schema、occurredAt、actorId、requestId，并支持幂等消费和重放。

### 1.2 标识、时间和版本

| 字段 | 规则 |
|---|---|
| userId | 认证域生成的不可变用户标识；所有 GAM 写操作从 access token 取值，不信任 body 中的 userId |
| requestId | 每个请求唯一；响应、账本、事件和审计记录均保留 |
| idempotencyKey | 客户端为一次业务意图生成；同一用户、同一 endpoint、同一 key 的 request hash 必须一致 |
| sourceEventId | 上游学习事件或游戏事件的全局唯一 ID；相同 sourceEventId 不得重复发放同一资产 |
| occurredAt | 服务端接收和验证的 UTC 时间；客户端时间只作为诊断字段，不参与奖励窗口判定 |
| localDate | 由服务端按账号当前生效的 IANA timezone 从 occurredAt 转换；Streak、每日任务、日限额使用 localDate |
| ruleVersion | 规则配置快照版本；每条账本、任务实例、成就解锁、开箱审计都必须记录 |
| contentVersion | 题目、课程、游戏题包或 Avatar 资源的已发布版本 |
| configVersion | 画质、动画、功能开关或空间配置版本；禁止客户端自带配置覆盖服务端 |
| monetaryUnit | 星币、收藏碎片、补签卡均为非现金整数资产；数据库金额字段不使用小数 |

用户 timezone 修改规则：

1. 默认取认证/用户设置的 IANA timezone，不能只存 UTC offset。
2. 修改只影响变更后的未来事件；已有 streak_day、任务 period 和账本不得重算。
3. 同一账号每 24 小时最多修改一次；切换跨越日期时，服务端记录 oldTimezone/newTimezone 和生效时间。
4. 夏令时、跨日和 23/25 小时日按 IANA timezone 的自然日处理，不按固定 24 小时窗口处理。

## 3. XP、等级、段位与星币数值模型

### 3.1 四种 Phase 1 资产

| 资产 | 来源 | 是否随机 | 是否可购买/交易/提现 | 事实表 |
|---|---|---:|---:|---|
| XP | 合法学习、任务、成就、Checkpoint、游戏合格奖励 | 否 | 否 | gam_xp_ledger |
| 星币 STAR_COIN | 合法学习和固定任务奖励 | 否 | 否；仅可固定兑换 | gam_currency_ledger |
| 收藏碎片 STAR_DUST | 重复外观自动转换、固定奖励 | 否 | 否；仅固定兑换 | gam_currency_ledger |
| 补签卡 STREAK_FREEZE | 学习任务、固定兑换、成就 | 否 | 不可现金化 | gam_currency_ledger |

XP 是累计成长值，不能消费、转移或回滚为用户可用余额。星币、碎片和补签卡余额必须大于等于 0。

### 3.2 有效学习事件

奖励引擎只接受来自已发布内容和服务端验证的以下事件：

| sourceType | 最低资格 |
|---|---|
| LESSON_COMPLETE | 完成课程单元必答步骤，完成率和提交结果由 learning/practice 服务确认 |
| REVIEW_BATCH_COMPLETE | 完成服务端分配的复习批次，至少完成 5 个有效复习对象 |
| READING_COMPLETE | 完成阅读材料必答理解题或规定阅读区段 |
| LISTENING_COMPLETE | 完成听力材料规定的播放/作答步骤 |
| WRITING_SUBMISSION | 完成规则化写作任务并提交；仅提交空内容不算 |
| CHECKPOINT_PASS | Checkpoint 达到规则化通过线 |
| GAME_SESSION_QUALIFIED | 六类游戏达到最小轮次、正确率和完整度门槛 |
| DAILY_GOAL_REACHED | 达到所选每日学习分钟数和 XP 配额 |
| QUEST_COMPLETED | 服务端从有效事件聚合出任务目标并生成完成状态 |
| ACHIEVEMENT_UNLOCKED | 成就规则引擎从有效事件计算出的首次解锁 |
| STREAK_MILESTONE | Streak 服务确认的 7/30/100/365 天里程碑 |

以下事件永远不发奖励：页面打开、动画播放、箱子页浏览、重复领取响应、预览物品、只点击暂停/继续、仅登录、仅切换标签、客户端伪造的分数或时长。

### 3.3 XP 发放基线

基线值固化在 ruleVersion=GAM_RULE_2026_08_20_01；运营只能通过审核发布新版本，不能修改历史账本解释。

| reasonCode | XP 增量 | 唯一/上限规则 |
|---|---:|---|
| ANSWER_CORRECT | +5 | 同一用户、同一 localDate、同一 learningItemId/contentVersion 只计一次；答错重试不产生 XP |
| NODE_FIRST_PASS | +20 | 同一地图节点和内容版本首次通过一次 |
| DAILY_GOAL_BONUS | +50 | 每个 localDate 一次；必须同时满足分钟和配额 |
| DAILY_QUEST | +40 | 每个每日任务实例领取一次，默认 3 个 |
| WEEKLY_QUEST | +100 | 每个每周任务实例领取一次，默认 3 个 |
| CHECKPOINT_PASS | +200 | 同一 Checkpoint 内容版本首次通过一次 |
| GAME_SESSION_BONUS | +10 | 合格游戏会话一次；每日最多 3 次 |
| COMBO_BONUS | +1 | 每局达到 3/5/7 连击时各一次；每局最多 +5、每日最多 +15 |
| STREAK_7/30/100/365 | +50/+200/+500/+1000 | 同一里程碑只发一次 |
| MOCK_IMPROVEMENT | +50 | 同一试卷版本、同一用户、同一进步报告只发一次 |
| ACHIEVEMENT_REWARD | 按成就定义 | userAchievement 唯一解锁一次 |

额外规则：

1. 每日时长档位与奖励分开：5/15/30/45 分钟对应每日目标 XP 配额 10/30/60/100；达标奖励统一为 +50 XP，不把配额误算为奖励。
2. 答题 XP 日上限为 60 个合格学习对象，即最多 300 XP；游戏会话奖励和任务/成就/Checkpoint 的一次性奖励不伪装成答题 XP。
3. 服务器对同一学习对象的多次提交只保留判定最新状态，但奖励键只允许第一次合格事件成功；更正使用 reversal ledger，不更新原账本。
4. 用户看到的 XP 进度由账本余额计算；客户端只显示服务端返回的 delta、balanceAfter、ruleVersion 和 settlementId。
5. XP 不使用双倍卡、付费倍率或随机增益卡作为 Phase 1 基线；如未来引入，必须新增可审计的配置、限额、契约和合规评审。

### 3.4 等级与段位

等级范围 1～100，累计 XP 不因赛季结束而重置。

定义：

- T(1) = 0
- T(L) = 100 × (L - 1) × L / 2，其中 2 ≤ L ≤ 100
- currentLevel = max { L | T(L) <= totalXp }
- nextLevelXp = T(currentLevel + 1)；Lv.100 的 nextLevelXp 为 null
- 当前等级内进度 = totalXp - T(currentLevel)
- 等级条分母 = T(currentLevel + 1) - T(currentLevel)

关键阈值：

| 段位 | 等级 | 起始累计 XP | 称号 |
|---|---:|---:|---|
| STAR_DUST_APPRENTICE | 1～10 | 0 | 星尘学徒 |
| ORBIT_EXPLORER | 11～30 | T(11)=5500 | 轨道探索者 |
| STELLAR_NAVIGATOR | 31～60 | T(31)=46500 | 恒星领航员 |
| GALAXY_MASTER | 61～100 | T(61)=183000 | 银河大师 |

同一事务内按顺序执行：写 XP ledger → 计算等级 → 写 account summary → 若跨等级/段位则写升级事件。达到 Lv.100 后继续累积 XP 但不再显示超出等级；累计 XP 仍完整保留用于报告、任务和审计。

### 3.5 星币产出与固定消费

星币基线：

| reasonCode | 星币增量 | 资格与限制 |
|---|---:|---|
| ANSWER_CORRECT_COIN | +1 | 与同一合格 ANSWER_CORRECT 绑定；每日最多 60 |
| DAILY_QUEST_COIN | +5 | 每个每日任务一次 |
| WEEKLY_QUEST_COIN | +15 | 每个每周任务一次 |
| DAILY_GOAL_COIN | +20 | 每个 localDate 一次 |
| CHECKPOINT_COIN | +30 | 同一 Checkpoint 版本首次通过一次 |
| STREAK_7/30/100/365_COIN | +10/+30/+100/+365 | 同一里程碑一次 |
| ACHIEVEMENT_COIN | 按成就定义 | 成就首次解锁一次 |
| MOCK_IMPROVEMENT_COIN | +10 | 同一报告一次 |

固定消费基线，价格必须存入 catalogVersion：

| 商品 | 价格 | 结果 |
|---|---:|---|
| STREAK_FREEZE_CARD | 100 STAR_COIN | +1 STREAK_FREEZE |
| COMMON_ITEM | 300 STAR_COIN | 直接获得指定普通外观 |
| RARE_ITEM | 600 STAR_COIN | 直接获得指定稀有外观 |
| EPIC_ITEM | 1200 STAR_COIN | 直接获得指定史诗外观 |
| LEGENDARY_ITEM | 3000 STAR_COIN | 直接获得指定传奇外观 |
| SOUND_THEME_PACK | 500 STAR_COIN | 直接获得固定音效包 |
| STAR_DUST_ITEM | 按固定碎片价格 | 直接获得指定外观 |

固定兑换不产生随机结果，不消耗箱子，不提供概率提升。星币账本的消费事务必须先锁定账户并检查余额；余额不足返回 INSUFFICIENT_BALANCE，不能短暂负数。

### 3.6 账本和余额不变式

1. XP 不变式：account.totalXp = max(0, Σ gam_xp_ledger.deltaXp)；任何撤销只能新增负向 reversal entry，不能更新或删除原 entry。
2. 货币不变式：对每个 currencyType，account.balance = Σ gam_currency_ledger.amountDelta，且 balance >= 0。
3. 每条账本具有 sourceEventId + reasonCode + ruleVersion + requestId + balanceAfter；同一用户、资产、sourceEventId、reasonCode 只能有一个成功正向 entry。
4. 结算事务顺序固定为：幂等记录占位 → 锁账户 → 校验资格/日限额 → 写账本 → 更新 balanceAfter → 更新账户汇总 → 写 reward_grant/域状态 → 写 outbox 事件 → 提交。
5. 如果任一步失败，整笔事务回滚；客户端重试使用同一 idempotencyKey，返回首次成功的 response，不再次加余额。
6. 每日对账任务按 localDate 和 ruleVersion 汇总 ledger 与 account summary；差异只允许通过管理员双审的 ADJUSTMENT/REVERSAL 追加修正，并留下审计原因、操作者和审批单号。

### 3.7 防刷、作弊和回放

- 内容资格：奖励只绑定 published contentVersion、用户所属学习队列或已授权课程包。
- 单次判定：每个题目实例有服务端 nonce、sessionId、seq；重复 seq、跨会话重放、过期题包和答案字段不匹配都拒绝。
- 速率限制：单用户每日最多 60 个答题奖励对象、20 个游戏会话启动、3 个游戏会话完成奖励；超过后可以继续学习，但不再发同类经济奖励。
- 时长校验：elapsedTime 使用服务端 session 起止时间与客户端上报的差值交叉校验；极短批量完成、未来时间、逆序时间、不可行速度标记为 SUSPECTED，不立即入账。
- 离线同步：只允许同步已预载、已签名 contentVersion 的事件；服务器重新判题、重算顺序和限额。离线记录不携带奖励结果。
- 设备与隐私：只保留粗粒度 platform、appVersion、performanceTier 和匿名风险标识，不存不必要的设备指纹；风险评分不直接封禁，先冻结可疑奖励并进入运营复核。
- 账户级风险：连续重复答案、异常切换账号、批量并发 session、篡改客户端 build 或 schema 时，返回 REWARD_PENDING_REVIEW；学习内容仍可用。
- 不奖励点击：登录、打开箱子页、查看概率、试穿、地图漫游、动画完成和分享海报不产生 XP/星币。
- 运营纠错：只能追加 reversal/adjustment，不允许手工改写历史结果；后台操作需要 admin 权限、理由和双审记录。

## 4. Streak 连续学习、跨时区、周末保护与破冰

### 4.1 有效日定义

effectiveLearningDay(user, localDate) 成立，当且仅当当天至少有一个服务端验证的有效学习动作：

- 完成一个已发布课程/阅读/听力/写作任务；
- 完成一个满足最小批次的复习任务（至少 5 个对象）；
- 完成一个合格游戏会话（至少 5 个回合且正确率达到合格线）；
- 通过 Checkpoint；
- 达到每日目标。

单纯登录、开始会话、只答一题、预览、查看答案、重复提交不算有效日。每日目标是更高等级的 DAILY_GOAL_REACHED，不替代有效日判定。

### 4.2 Streak 状态

| 状态 | 含义 | UI |
|---|---|---|
| EMPTY | 尚无有效日 | 暖灰火苗 |
| ACTIVE | 当前 localDate 已完成，链条连续 | 品牌渐变火苗 |
| AT_RISK | 今天尚未完成但上一有效日仍可延续 | 暖橙火苗和温和提示 |
| FROZEN | 必需日期缺失，仍在破冰窗口 | 灰色冰冻火苗 |
| BROKEN | 未在窗口内补救；下一有效日从 1 开始 | 灰色静态火苗 |
| PROTECTED | 日期被预设周末保护伞豁免 | 日历保护标识，不增加天数 |

状态转换：

~~~mermaid
stateDiagram-v2
    [*] --> EMPTY
    EMPTY --> ACTIVE: 首个有效学习日
    ACTIVE --> AT_RISK: 当天尚未完成
    AT_RISK --> ACTIVE: 当天出现有效学习
    AT_RISK --> FROZEN: 下一自然日开始且必需日缺失
    FROZEN --> ACTIVE: 补签卡或15题破冰成功
    FROZEN --> BROKEN: 破冰窗口结束
    BROKEN --> ACTIVE: 新自然日首次有效学习，streak=1
    ACTIVE --> PROTECTED: 预设周末休息日
    PROTECTED --> ACTIVE: 保护期结束或保护日实际学习
~~~

### 4.3 跨时区规则

1. 每条行为先存 UTC occurredAt，再使用 streak profile 的生效 IANA timezone 计算 localDate。
2. 行为发生时使用当时的 timezone snapshot；修改 timezone 不追溯旧日期。
3. 账号从北京时间飞到纽约时，纽约当地日期按 America/New_York 计算；不能通过频繁切换时区制造两个“今天”。
4. timezone 修改 24 小时冷却，且一天最多跨越一个本地日期；跨越后的时间点由服务端记录为新规则生效边界。
5. 夏令时只影响本地时间显示和任务截止点，不改变自然日是否有效。
6. 所有客户端展示同时给出“按你的时区（IANA 城市名）计算”，避免跨端误解。

### 4.4 周末打卡保护伞

- 用户可预先设置周六、周日中的 0～2 天为固定休息日；设置在本周第一个受保护周末开始前生效。
- 保护日不要求有效学习、不增加 streak 天数、不产生补签资格，但前后有效日保持连续。
- 保护日如果实际学习，按普通有效学习日处理并记为 QUALIFIED，不额外奖励。
- 不能在缺席之后把该日期改成休息日；不能通过改 timezone 或重复切换 restDays 追溯保护。
- 一周保护天数最多 2 天；连续四周保持后可继续使用，但无额外免费保护次数。用户可随时关闭，未来日期生效。
- 周末保护不等同于补签卡；保护记录、设置变更和实际学习均有审计。

### 4.5 断签冰冻与破冰

触发条件：必需 localDate 没有有效学习、也未被周末保护，且当前时间进入下一自然日。

补救窗口：

- 从检测到 FROZEN 起至第二个后续本地日 23:59:59，最多挽救最近一个缺失日期。
- 每次只允许挽救一个缺失日；多个连续缺失日不能批量补回。
- 方式 A：消耗 1 张 STREAK_FREEZE，写入 RESCUED day；不能使用星币直接临时修改历史日期。
- 方式 B：完成服务器发放的 15 道紧急错题特训，15 道全部完成且正确率不低于 60%；不消耗任何资产。
- 成功后当前日期仍需完成一个有效学习动作，Streak 恢复为原连续天数 + 当前有效日；不能凭空获得缺失日 XP/星币。
- 失败、超时或重复打开特训不改变状态；窗口结束后变为 BROKEN，maxStreak 保留。

## 5. 六类核心学习游戏：统一会话、状态机与判定

### 5.1 统一游戏会话状态机

~~~mermaid
stateDiagram-v2
    [*] --> CREATED: POST /games/sessions
    CREATED --> READY: 服务端锁定题包/内容版本
    READY --> IN_PROGRESS: 首个有效 answer event
    IN_PROGRESS --> PAUSED: 主动暂停/切后台
    PAUSED --> IN_PROGRESS: resume 且未超过10分钟
    IN_PROGRESS --> SUBMITTING: 完成最小回合或点击结束
    SUBMITTING --> COMPLETED: 服务端重算通过
    SUBMITTING --> ABORTED: 用户主动放弃/不足最小回合
    CREATED --> EXPIRED: 15分钟未开始
    PAUSED --> EXPIRED: 暂停超过10分钟
    IN_PROGRESS --> EXPIRED: 超过session expiresAt
    SUBMITTING --> INVALIDATED: 内容/序列/风控校验失败
    COMPLETED --> COMPLETED: 同一幂等请求重放
    ABORTED --> ABORTED: 同一幂等请求重放
~~~

统一约束：

- 每局默认 3 分钟；会话最长 15 分钟，暂停最多 10 分钟。
- 题包由服务端按用户学习进度、到期复习、错题和已发布内容选择；客户端不能指定答案、随机种子或奖励。
- sessionId + seq + eventId 唯一；服务端按 contentVersion 重新判题并计算 accuracy、speed、completion、combo 和 XP。
- 合格会话最低要求：完成规定回合数的 80%，且 accuracy ≥ 60%；GAME_SESSION_BONUS 需要 accuracy ≥ 80%，或由具体游戏更严格规则覆盖。
- 每局结束只结算一次；中途放弃不发游戏完成奖励，但已验证的学习对象仍按日上限进入普通学习奖励。
- 统一 HUD：剩余回合、正确率/连击、暂停、音效开关、无障碍文字提示；完成页显示正确率、复习知识点、XP、奖励进度、再来一局、回到学习。
- 不提供付费复活、付费加分、抽奖、交易装备或现金奖励。

统一得分：

- accuracy = correctRounds / judgedRounds × 100
- completion = completedRequiredRounds / requiredRounds × 100
- speedScore = clamp(100 × (1 - averageResponseMs / (2 × targetResponseMs)), 0, 100)
- gameScore = round(0.7 × accuracy + 0.2 × speedScore + 0.1 × completion)
- 通过：completion ≥ 80% 且 accuracy ≥ 60%；合格奖励：accuracy ≥ 80%，并满足具体游戏最低回合。
- hints、retry、pause 不改变答案真值；使用提示可降低星级/游戏成绩，但不能产生负 XP。

### 5.2 六个 gameCode 的交互和判定

#### 5.2.1 Sentence Train｜拼句小火车

- 题包：当前学习中的句型、表达库或语法复习对象；每局 5 个句子，每句 4～12 个词块。
- 状态：CARDS_HIDDEN → CARRIAGES_SELECTED → ASSEMBLING → VALIDATING → CORRECT/INCORRECT → NEXT_ROUND。
- 交互：拖拽、点击追加、撤销、重置；移动端支持长按拖拽，键盘端支持方向键和空格。
- 判定：词块 ID 序列与服务端标准序列完全一致才正确；标点、大小写按内容规则归一化；同义替换只有在题目定义允许时才算正确。
- 分数：5 题全部完成且正确率 ≥60% 通过；无提示且 5/5、平均耗时 ≤15 秒可获满星；错误重排不重复奖励。
- 异常：缺失词块、重复词块、过期题包、拖拽事件乱序时由服务端以 seq 重排或拒绝；前端只显示“答案已同步，请重试”，不显示答案键。
- 埋点：game.session.started、game.answer.submitted、game.round.judged、game.session.completed、game.hint.used。

#### 5.2.2 Word Match｜单词消消乐

- 题包：8 组词义/释义/音标配对卡，共 16 张卡；每局只从当前复习池取卡。
- 状态：BOARD_READY → CARD_REVEALED_ONE → CARD_REVEALED_TWO → MATCHED/MISMATCHED → COMBO_UPDATE → BOARD_CLEAR。
- 判定：服务端比较两个 cardToken 所属 pairId；连续翻牌无效、重复点击已匹配卡不计分。
- 分数：每组配对正确计一个 round；3/5/7 连消触发动画和 +1 XP combo bonus，各局 combo bonus 最多 +5；翻错不扣 XP。
- 异常：同时点击两张、重复 eventId、切后台超时、卡片版本不一致时只保留首个合法 event；网络重试返回原判定。
- 埋点：game.match.revealed、game.match.judged、game.combo.updated、game.session.completed。

#### 5.2.3 Word Defense｜单词保卫战

- 题包：10 个当前词汇；怪物只呈现词义/语境，不预先显示目标拼写。
- 状态：WAVE_READY → INPUTTING → HIT/MISS → HEALTH_UPDATE → NEXT_WAVE → BASE_SAFE/BASE_BREACHED。
- 交互：60 秒内输入单词发射炮弹；键盘、软键盘、辅助输入均可；客户端只提交标准化答案和输入耗时。
- 判定：Unicode NFKC、大小写、允许的连字符和空格按词条规则归一化；拼写全等为 HIT；题目定义的英美拼写别名可同时正确。
- 分数：10 波中至少 6 波正确且未超过 3 颗心，accuracy ≥60% 通过；8/10 且平均响应 ≤目标时长才发游戏完成 bonus。
- 异常：粘贴不作为单独作弊结论；若出现批量零时延答案、并发输入或 session 外提交，标记风险并暂停奖励，仍保留无障碍可用性。
- 埋点：game.defense.wave_started、game.defense.answer_normalized、game.defense.wave_judged、game.session.completed、gamification.reward.pending_review。

#### 5.2.4 Word Puzzle｜拼图解谜

- 题包：字母重排、缺字补全和词根片段题；每局 8 题，答对后解锁一块固定插画拼片。
- 状态：PUZZLE_LOCKED → PIECE_SELECTED → COMPOSING → VALIDATING → PIECE_UNLOCKED/RETRY → PUZZLE_COMPLETE。
- 判定：标准化后的字母序列/缺失字符与 contentVersion 答案匹配；插画拼片 ID 是题目固定奖励，不通过随机箱获取。
- 分数：8 题完成且 ≥5 题正确通过；使用一次提示仍可通过但不得获得满星；集齐指定拼图集后固定解锁名画展示和成就。
- 异常：拼片资源加载失败时显示静态占位，不阻塞判题；题包下线后 session 进入 INVALIDATED 并补发可重试会话，不重复发奖励。
- 埋点：game.puzzle.started、game.puzzle.piece_unlocked、game.puzzle.hint_used、game.session.completed。

#### 5.2.5 Grammar Blaster｜语法射击（PRD §14.6 P1 扩展）

- 题包：10 个已发布语法规则题；每题显示句子和 2～4 个结构目标。
- 状态：TARGETS_READY → TARGET_SELECTED → VALIDATING → HIT/MISS → NEXT_TARGET → ROUND_END。
- 判定：选择正确语法结构 ID；不能以动画位置或客户端分数判断。
- 分数：10 题中 ≥6 题正确且完成率 ≥80% 通过；连续 3 个正确可触发 combo 动效，bonus 仍受每日/每局上限约束。
- 异常：WebGL 不可用时切换 CSS/文本靶心；动效资源失败不影响选项、判题和奖励。
- 埋点：game.grammar.target_selected、game.round.judged、game.combo.updated、game.session.completed。

#### 5.2.6 Catch the Meaning｜词义捕手（PRD §14.6 P1 扩展）

- 题包：10 个词汇，每轮 3 条释义路线，正确路线由服务端下发 token 标识。
- 状态：LANES_READY → PLAYER_MOVING → LANE_SELECTED → VALIDATING → CAUGHT/MISSED → NEXT_ROUND。
- 判定：服务端校验 laneToken 与题目答案；运动轨迹仅用于表现，不作为语言成绩依据。
- 分数：至少完成 8 轮、正确率 ≥60% 通过；8/10 以上且无超时才发完成 bonus。
- 异常：低端设备禁用粒子和物理效果，使用按钮/键盘选择路线；连续误触不重复扣分；后台恢复超过 10 分钟则会话过期。
- 埋点：game.catch.lane_selected、game.catch.judged、game.session.completed、performance.tier_changed。

## 6. FEAT-GAM-001～022 逐项规格卡

> 每张卡固定包含：目标、规则、主流程、异常、验收、埋点。详细数值见第 3 节，游戏状态机见第 5 节，DDL 和 API 分别见第 10、11 节。

### 6.1 FEAT-GAM-001｜XP 经验值与段位升级

- **目标**：把真实学习量转成可解释、不可购买、可回放的成长进度。
- **规则**：答对有效学习对象 +5 XP；每日目标 +50 XP；Checkpoint 首次通过 +200 XP；等级按三角阈值 1～100 计算；段位为星尘学徒、轨道探索者、恒星领航员、银河大师；重复、点击和客户端分数不发 XP。
- **主流程**：上游事件 → RewardEligibility 校验内容、时长、seq、日限额 → 锁账户 → 写 xp ledger → 计算等级/段位 → 写 summary 和 outbox → 返回 delta、balanceAfter、level、rank。
- **异常**：重复 sourceEventId 返回首次 settlement；规则版本过期返回 STALE_RULE_VERSION；可疑事件进入 pending review；账本冲突整笔回滚。
- **验收**：同一答题事件重试 10 次只产生一条 +5；累计 XP=100/300/5500/46500/183000 时等级和段位边界正确；撤销只能新增 reversal；Performance 档仍能完成学习结算。
- **埋点**：gamification.xp.granted.v1、gamification.level.changed.v1、gamification.reward.rejected.v1、gamification.reward.pending_review.v1。

### 6.2 FEAT-GAM-002｜Streak 连续学习天数与火焰反馈

- **目标**：让用户清楚知道“今天完成一个有效学习任务即可延续”，强化可持续习惯而非失败惩罚。
- **规则**：有效日按 IANA localDate 计算；连续 7/30/100/365 天触发固定里程碑；UI 显示本周 Mon-Sun 点阵、当前天数和 AT_RISK 提示；不使用“你失败了/浪费了多少天”等羞辱文案。
- **主流程**：接收有效学习事件 → 转本地日期 → upsert streak_day → 锁 profile → 计算前后链长 → 更新 max/current → 触发里程碑和火焰状态 → 发布事件。
- **异常**：时区失效回退账号最后有效 timezone 并告警；跨端同时完成由 unique user/localDate 合并；仅登录不改变状态。
- **验收**：UTC 跨日但用户本地未跨日不提前断签；DST 周仍按自然日；完成一次合格游戏可延续；重复事件不增加天数；maxStreak 永不倒退。
- **埋点**：gamification.streak.day_qualified.v1、gamification.streak.status_changed.v1、gamification.streak.milestone_reached.v1、gamification.streak.reminder_shown.v1。

### 6.3 FEAT-GAM-003｜断签灰色冰冻与破冰挑战

- **目标**：为一次断签提供透明、非付费、可控的恢复路径，避免连续学习激励变成惩罚。
- **规则**：最近一个缺失必需日进入 FROZEN；补救窗口至第二个后续本地日结束；方式 A 消耗 1 张补签卡，方式 B 完成 15 道紧急错题特训且正确率 ≥60%；每次最多恢复一个缺失日。
- **主流程**：检测缺失 → 建 rescue case → 展示两种方式 → 锁 rescue/profile → 校验补签卡或读取特训完成事件 → 写 RESCUED day、账本和审计 → 当前日有效学习后恢复火焰。
- **异常**：窗口过期返回 STREAK_RESCUE_EXPIRED；无卡返回 INSUFFICIENT_FREEZE_CARD；特训重复提交只返回原结果；无法恢复多个缺失日。
- **验收**：补签卡扣减与恢复在同一事务；15 题必须全部完成且正确率达标；恢复不虚增 XP/星币；破冰失败不会清除 maxStreak；重试不重复扣卡。
- **埋点**：gamification.streak.frozen.v1、gamification.streak.rescue_started.v1、gamification.streak.rescue_succeeded.v1、gamification.streak.rescue_failed.v1。

- **埋点**：chest.animation.started.v1、chest.animation.skipped.v1、chest.result.revealed.v1、chest.animation.fallback.v1。

### 6.18 FEAT-GAM-018｜掉落概率公示与开箱记录

- **目标**：让用户在抽取前看到完整、可核验、不可针对性修改的规则。
- **规则**：概率版本页面展示箱子版本、状态、生效时间、quality 概率、每个物品概率/选择规则、规则 hash、历史版本；概率以 basis points 显示，所有 item probability 合计 10000；同一箱子 grant 固定使用发放时版本。
- **主流程**：GET probability → 读取 published public snapshot → 显示版本/生效时间 → open 时写 seedCommit、algorithmVersion、draw、结果和 audit → history 分页返回。
- **异常**：概率未审核/过期不允许新 grant；概率页读取失败不允许误导性开箱确认，可重试；管理员不能按用户/消费金额分配秘密概率。
- **验收**：页面打开前可见概率；版本变更有历史；用户能查询自己完整开箱记录；后台能按 seedCommit/ruleHash 重算；无“差一点”表现。
- **埋点**：chest.probability.viewed.v1、chest.probability.version_changed.v1、chest.audit.created.v1、chest.history.viewed.v1。

### 6.19 FEAT-GAM-019｜重复道具自动转收藏碎片

- **目标**：让重复随机结果转为确定性收藏进度，避免用户只能无限重复抽取。
- **规则**：已拥有 item 再次掉落时不增加可穿戴副本，自动转换 STAR_DUST；默认 COMMON/RARE/EPIC/LEGENDARY/COLLECTOR 分别为 12/30/80/200/500 碎片；碎片不可购买、交易、提现，只能固定兑换。
- **主流程**：开箱锁库存 → 判断 user inventory → 首次写 inventory 或重复写 currency ledger → 写 chest_open_audit duplicate=true、shardAmount → 更新 collection progress。
- **异常**：库存并发由 unique(user,item) 和事务锁保证；碎片规则版本失效则整笔回滚；重复点击返回原结果。
- **验收**：重复物品 UI 明确“已拥有，自动转化为 N 收藏碎片”；碎片账本可重算；重复不产生第二件物品；固定兑换不随机。
- **埋点**：collection.item_obtained.v1、collection.duplicate_converted.v1、collection.shard_balance_changed.v1、collection.fixed_redeemed.v1。

### 6.20 FEAT-GAM-020｜Collection Book 收集图鉴

- **目标**：展示拥有、未拥有、来源和套装完成度，提供可规划的确定性成长路径。
- **规则**：按品质、主题、类型、已拥有筛选；展示首次获得时间、来源、套装 N/M、缺失物品的固定获得方式；完成套装发固定称号/成就一次；不展示用户不可见的秘密概率。
- **主流程**：读取 item catalog + inventory → 计算 set progress → 展示已拥有/未拥有 → 查看固定来源 → 达成 set 时发 collection achievement/title。
- **异常**：物品下架保留历史图鉴；缺失资源显示占位；未发布物品不进入公开图鉴；分页游标失效返回 CURSOR_INVALID。
- **验收**：图鉴数量与库存一致；套装完成度可重算；缺失物品至少有一种明确固定来源或标记“活动结束”；隐私设置不泄露他人资产。
- **埋点**：collection.book.viewed.v1、collection.filter_changed.v1、collection.set_progressed.v1、collection.set_completed.v1。

### 6.21 FEAT-GAM-021｜个人星空学习空间

- **目标**：把学习积累转成可布置、可回访的个人星球/书房。
- **规则**：支持背景、书桌、灯、植物、挂画、道具、宠物/小伙伴、奖杯和学习日历；物品必须来自已拥有或固定兑换；坐标、旋转和层级受服务端 schema 限制；无自由公开文本。
- **主流程**：GET space → 读取已有 layout → 拖拽/旋转/恢复 → PUT 带 layoutVersion → 校验 ownership、slot、边界 → 保存 → 生成 3D/快照。
- **异常**：并发保存返回 VERSION_CONFLICT；空间物品下架保留但不可新增；坐标越界归一化或拒绝；3D 失败回退 2D 静态布置。
- **验收**：布局跨端一致；保存方案可恢复；Performance 档无 WebGL 仍可查看/编辑基本布局；空间装饰不会改变任何学习/排行数值。
- **埋点**：space.opened.v1、space.item.placed.v1、space.layout.saved.v1、space.layout.restored.v1、space.render_fallback.v1。

### 6.22 FEAT-GAM-022｜学习赛季 Learning Season

- **目标**：以固定主题和学习目标形成阶段性收藏，不把产品变成付费赛季或博彩赛事。
- **规则**：赛季可为 30 天学习季、CET 备考季、旅行英语季、阅读月、听力月；积分只来自验证学习，默认每日最多计 200 season points；奖励为固定装扮、箱子、徽章、背景、动作；不卖概率提升、不设现金奖金、不让付费决定排行。
- **主流程**：赛季发布 → 用户加入/自动 enroll → 有效事件折算 season points → 达到 tier → 固定奖励自动 grant 或领取 → 结束后冻结记录。
- **异常**：赛季已结束不能新增积分；重复事件不重复加分；付费权益不能改变 points multiplier；赛季奖励资源下线时提供同品质固定替代并审计。
- **验收**：每个赛季有 start/end/ruleVersion/tier；points ledger 可重算；每日 cap 生效；所有奖励可预览且无现金/交易/概率提升；赛季结束后历史可查询。
- **埋点**：season.published.v1、season.enrolled.v1、season.points_granted.v1、season.tier_unlocked.v1、season.reward_claimed.v1、season.closed.v1。

## 7. Avatar、衣柜、资源版本与四档 AdaptivePerformanceEngine

### 7.1 Avatar 配置和资源版本

Avatar 配置是数据，不是客户端资源地址：

~~~json
{
  "baseModelCode": "AVATAR_BASE_01",
  "skinCode": "SKIN_02",
  "faceCode": "FACE_03",
  "hairCode": "HAIR_07",
  "hairColorCode": "HAIR_COLOR_02",
  "expressionCode": "EXPR_DEFAULT",
  "poseCode": "POSE_STUDY",
  "loadoutId": "loadout_01",
  "assetManifestVersion": "AVATAR_ASSET_2026_08_01",
  "configVersion": 12
}
~~~

资源发布流程：

1. 美术/教研上传 glTF 2.0、Draco 压缩模型、贴图、图标和 4 姿态 × 2 光照快照。
2. 服务端校验文件大小、sha256、slot、quality、版权状态、最小 App 版本和内容审核状态。
3. 管理员初审、终审后发布 assetManifestVersion；客户端只读取 published manifest。
4. 用户保存配置时保存 configHash + assetManifestVersion；资源变更产生新版本，不覆盖历史配置。
5. 快照由 job-runner 异步生成并写 OSS/CDN；未就绪时显示 2D 预设头像，不阻塞页面。
6. 资源下线使用 DEPRECATED，不删除用户库存、开箱记录和历史图鉴；旧配置加载失败时按 slot 回退默认安全资源。

性能预算：

- 当前角色和装备总面数 ≤30k 三角面。
- 单件装扮 ≤3k 三角面，贴图 ≤1024²。
- web-view 内存 ≤150MB；超过预算或 context lost 立即降级。
- High 及以上实时渲染目标 ≥30fps；低于 24fps 持续 3 秒自动降级。
- 快照单张 ≤200KB，首图 CDN 加载目标 <1 秒。
- 学习答题页不常驻完整 3D；只使用静态头像/快照。

### 7.2 四档 AdaptivePerformanceEngine

| tier | 适用 | Avatar/空间 | 游戏/地图 | 触发和降级 |
|---|---|---|---|---|
| Ultra | 高性能 Web/App | Three.js 实时 3D、柔和阴影、AO 近似、骨骼待机 | 完整粒子、轻量后处理 | 首启 benchmark 达标；GPU 压力或低帧自动降级 |
| High | 主流 Web/App | Three.js 实时 3D，关闭 AO、降低阴影采样 | 标准动画、轻量 WebGL、少量粒子 | 目标 30fps；低于 24fps/3s → Medium |
| Medium | 普通 App/iPad/入门机 | 无阴影单光源的低面数 3D，或高分辨率快照 + 呼吸动效 | 2.5D/SVG、粒子约 300、关闭 Bloom | 内存压力/资源加载慢 → Performance |
| Performance | 低配、弱网、小程序、省电 | 纯快照/2D 静态精灵，0 GPU 常驻负载 | 文本、静态图、CSS/帧动画、基础音频 | WebGL context lost、内存超限或用户省电 |

引擎规则：

- 冷启动根据设备能力、网络和用户设置选择默认档位；用户可选智能、高品质、平衡、省电。
- 运行中只自动降级，不自动升档；用户手动升档仍受设备硬上限和资源可用性约束。
- webglcontextlost 在 50ms 内捕获并切换 2D/快照；页面不白屏、不阻塞学习。
- 每次 tier change 记录匿名性能事件，不记录不必要设备标识；事件包含从/到档位、reason、renderMode、featureCode。
- 所有动画、音效、触觉可关闭；关闭后保留文本、颜色、图标和无障碍提示，不以颜色作为唯一信息。
- 小程序不做实时 3D，统一走 Performance 快照；H5 默认快照，可由用户手动尝试不超过 Medium 的实时 3D。
- 页面离开销毁 web-view；成员列表使用快照缩略图，不逐个创建 3D 实例。

## 8. 免费奖励箱、合法概率、伪随机和开箱审计

### 8.1 箱子类型和免费来源

| chestType | 免费来源 | 默认主池 |
|---|---|---|
| BRONZE | 三个每日任务全部领取、普通学习挑战 | COMMON/RARE/EPIC |
| SILVER | 完成一个每周挑战、Streak 7、Checkpoint | COMMON/RARE/EPIC/LEGENDARY |
| GOLD | 高阶 Checkpoint、课程阶段毕业、重大学习里程碑 | RARE/EPIC/LEGENDARY |
| GALAXY | 赛季完成、纪念学习成就、经审核的特殊课程毕业 | EPIC/LEGENDARY/COLLECTOR |

- 每个箱子必须由已验证的 sourceEventId 免费生成；同一来源事件只产生一个 grant。
- 奖励箱不进入商业商品、支付、充值货币或会员倍率；会员可获得固定欢迎套装、自选券或可预览固定礼盒，不获得随机箱。
- 固定礼盒是非随机，领取前展示全部内容；不能以“礼盒”掩盖随机结果。

### 8.2 概率版本基线

以下为首发示例规则版本的正式基线，不是 UI 占位值；上线前仍需后台双审并发布同版本快照。概率以 bps（1 bps = 0.01%）存储，quality 概率合计 10000 bps。

| 箱子 | COMMON | RARE | EPIC | LEGENDARY | COLLECTOR |
|---|---:|---:|---:|---:|---:|
| BRONZE | 6500（65%） | 2700（27%） | 800（8%） | 0 | 0 |
| SILVER | 4500（45%） | 4000（40%） | 1300（13%） | 200（2%） | 0 |
| GOLD | 2000（20%） | 4500（45%） | 2800（28%） | 700（7%） | 0 |
| GALAXY | 0 | 3000（30%） | 4500（45%） | 2000（20%） | 500（5%） |

具体物品选择：

- 每一品质池内必须列出完整 itemId、quality、status 和 itemProbabilityBps；默认在该品质池内等概率选择。
- 等概率时 itemProbabilityBps = floor(tierProbabilityBps / eligibleItemCount)，剩余 bps 按 itemId 字典序分配，并在概率页展示实际值。
- 如果使用权重，必须为每个 item 展示 weight 和折算概率；禁止仅展示品质而隐藏具体物品。
- 概率版本发布后不可修改；新版本只能新增版本号、生效时间和变更审计。已发放箱子固定使用 grant 时的 versionId。

### 8.3 HMAC 伪随机和可审计流程

实现 PRNG-HMAC-SHA256-v1：

1. 每个 chest grant 生成独立 256-bit serverSeed，先存 seedCommit = SHA256(serverSeed)；客户端无法提交 seed。
2. 开箱输入为 HMAC-SHA256(serverSeed, probabilityVersionId | chestGrantId | drawOrdinal)。
3. 使用无偏 rejection sampling 把结果映射到 [0, 10000) bps 区间，再按累计概率选择 quality；同样方式选择具体 item。
4. 保存 algorithmVersion、seedCommit、probabilitySnapshotHash、随机值摘要、quality、itemId、duplicate、shardAmount 和 outcomeHash。
5. 开箱成功后，serverSeed 加密保存；用户历史显示规则版本、seedCommit、结果和时间，具备审计权限的后台可解密重算。支持工单按 chestGrantId 导出审计证明。
6. 任何用户画像、消费金额、VIP、设备或历史开箱结果都不能改变 seed、概率、奖池或选择顺序；无保底、暗调、针对性概率。
7. 概率页、开箱页和记录页不得使用“差一点”“再来一次”“连抽”等诱导文案。

### 8.4 开箱结果和重复转碎片

事务顺序：

~~~text
lock chest_grant
  → verify state=GRANTED and free source
  → load pinned probability snapshot
  → derive pseudorandom result
  → lock user account and inventory
  → first owned? insert inventory : add STAR_DUST
  → write chest_open_audit
  → write reward_grant and outbox event
  → mark chest_grant OPENED
commit
~~~

默认重复折算：

| quality | STAR_DUST |
|---|---:|
| COMMON | 12 |
| RARE | 30 |
| EPIC | 80 |
| LEGENDARY | 200 |
| COLLECTOR | 500 |

开箱动效只是结果展示，结果在服务端事务完成后才返回；动画跳过、崩溃或重复请求都返回同一 audit outcome。

## 9. 收藏、学习空间和赛季

### 9.1 收藏图鉴

Collection Book 读取：

- itemCode、名称、类型、quality、主题、资源版本、首次获得时间、获得来源；
- 已拥有/未拥有、套装 N/M、品质分布、主题进度、学习纪念册；
- 缺失物品的固定获取方式：星币兑换、碎片兑换、成就、课程毕业、固定活动或当前不可获得；
- 成套完成一次发固定 title/achievement；不把套装完成绑定于无限随机。

### 9.2 学习空间

空间 schema 只允许结构化布局：

~~~json
{
  "layoutVersion": 4,
  "backgroundItemId": "SPACE_BG_STAR_01",
  "placements": [
    {
      "slot": "DESK",
      "itemId": "DESK_03",
      "x": 0.42,
      "y": 0.76,
      "scale": 1.0,
      "rotation": 0
    }
  ],
  "privacy": "PRIVATE"
}
~~~

- x/y 归一化到 0～1，scale 和 rotation 有服务端上限；不能上传任意脚本、URL 或自由公开文本。
- 个人空间默认 PRIVATE；若未来在 Study Room 展示，只输出用户允许的快照和公开字段。
- 物品来源包括学习解锁、固定星币/碎片兑换、成就、Checkpoint、赛季固定奖励；无付费随机家具。
- 空间渲染遵循第 7 节四档降级。

### 9.3 赛季模型

- 可配置 30 天学习季、季度主题季、CET 备考季、旅行英语季、阅读月、听力月。
- seasonPoints 与 lifetime XP 分开；默认 1 eligible XP = 1 point，但每日最多计 200 points，重复/撤销 XP 不再计入。
- 任务、Checkpoint、Streak 里程碑可以按 season rule 配置固定 bonus，但不得用付费或会员倍率。
- 奖励阶梯由 tierThreshold 固定配置；达到后发固定装扮、背景、动作、徽章或免费箱，所有内容可预览。
- 赛季结束后关闭积分写入，历史进度、奖励、ruleVersion 和积分账本只读可查；未领取的已解锁固定奖励由定时任务自动发放一次。
- 排行榜（如未来启用）只展示学习积分，不用付费决定名次；匿名和隐私开关沿用 SOC 域。

## 10. MySQL 8.x DDL

> 下面 DDL 是 GAM 域的逻辑完整基线。user_id 关联认证域用户，但不强加跨模块外键，避免模块迁移顺序耦合。所有 ledger/audit 表由数据库角色禁止 UPDATE/DELETE；纠错只能追加 reversal/adjustment。Flyway 迁移时按依赖顺序执行。

~~~sql
-- =============================================================================
-- 0. 版本化配置和幂等
-- =============================================================================
CREATE TABLE IF NOT EXISTS gam_rule_config (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  config_key VARCHAR(96) NOT NULL,
  version_no INT UNSIGNED NOT NULL,
  config_json JSON NOT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'DRAFT',
  effective_from DATETIME(3) NULL,
  effective_to DATETIME(3) NULL,
  approved_by BIGINT UNSIGNED NULL,
  approved_at DATETIME(3) NULL,
  change_reason VARCHAR(512) NULL,
  config_hash BINARY(32) NOT NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
    ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_gam_rule_version (config_key, version_no),
  UNIQUE KEY uk_gam_rule_hash (config_key, config_hash),
  KEY idx_gam_rule_status (config_key, status, effective_from),
  CONSTRAINT chk_gam_rule_status CHECK (status IN ('DRAFT','IN_REVIEW','PUBLISHED','RETIRED')),
  CONSTRAINT chk_gam_rule_window CHECK (effective_to IS NULL OR effective_from IS NULL OR effective_to > effective_from)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='GAM 规则、倍率、阈值和展示配置版本';

CREATE TABLE IF NOT EXISTS gam_idempotency_record (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id BIGINT UNSIGNED NOT NULL,
  scope VARCHAR(160) NOT NULL,
  idempotency_key VARCHAR(128) NOT NULL,
  request_hash BINARY(32) NOT NULL,
  state VARCHAR(16) NOT NULL DEFAULT 'PROCESSING',
  http_status SMALLINT UNSIGNED NULL,
  response_json JSON NULL,
  request_id CHAR(36) NOT NULL,
  expires_at DATETIME(3) NOT NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  completed_at DATETIME(3) NULL,
  PRIMARY KEY (id),
~~~

### 10.1 DDL 执行和不变式补充

- gam_account_summary、任务/成就/会话/赛季投影是可重建投影；ledger、sourceEventId、审计表是不可重建事实。
- 生产数据库角色对 gam_xp_ledger、gam_currency_ledger、gam_chest_open_audit、gam_season_point_ledger、gam_game_session_event、gam_quest_progress_event、gam_achievement_progress_event 禁止 UPDATE/DELETE。
- 发布 probability version 前必须在同一审核事务校验：品质概率合计 10000、每品质 item 概率合计等于该品质概率、item quality 与物品定义一致、所有资源 published。
- 应用层用 SELECT ... FOR UPDATE 锁 account、streak_profile、quest、chest_grant、user_season；Redis 锁只是减小并发，不代替 MySQL 锁。
- 对账任务至少每日执行一次，发现 summary 与 ledger 不一致时冻结经济结算，不删除任何事实记录。

### 11.1 通用响应、权限和幂等

Base URL：/api/v1。

权限：

| scope | 允许 |
|---|---|
| gamification:read:self | 读取自己的 profile、ledger、Streak、任务、成就、箱子记录、收藏、赛季 |
| gamification:write:self | 领取任务、破冰、开箱、固定兑换、Streak 设置 |
| avatar:read:self | 读取自己的 Avatar、库存、穿搭、空间、资源版本 |
| avatar:write:self | 保存配置、装备、空间布局 |
| games:read:self | 读取游戏目录和自己的 session |
| games:play:self | 创建、暂停、提交、完成自己的游戏 session |
| gamification:config:write | 后台发布规则、概率、物品、赛季 |
| gamification:audit:read | 后台查看完整开箱、账本和风险审计 |

统一成功包：

~~~json
{
  "requestId": "8a0f5d41-5a1e-4b90-a0b0-1d3d0bb4f6d4",
  "data": {},
  "serverTime": "2026-08-20T10:20:30.123Z"
}
~~~

统一错误包：

~~~json
{
  "requestId": "8a0f5d41-5a1e-4b90-a0b0-1d3d0bb4f6d4",
  "error": {
    "errorCode": "IDEMPOTENCY_CONFLICT",
    "message": "同一幂等键对应的请求内容不同",
    "details": {
      "field": "X-Idempotency-Key"
    }
  },
  "serverTime": "2026-08-20T10:20:30.123Z"
}
~~~

写操作：

- 所有 POST/PUT/PATCH/DELETE 必须带 X-Idempotency-Key；服务端保存 request hash 和首次响应。
- 幂等重放返回首次成功 response；同 key 不同 body 返回 IDEMPOTENCY_CONFLICT。
- 需要并发保护的资源同时带 If-Match: versionNo；版本冲突返回 VERSION_CONFLICT。
- 分页统一 cursor 优先，limit 默认 20，最大 100；响应 data.items、nextCursor、hasMore。
- 不把客户端 score、deltaXp、deltaCoins、probabilityVersion、quality 或 itemId 当作可信结算字段。

### 12.3 埋点验收

- 同一个 sourceEventId 的消费重放不产生重复 analytics 事件，或由 consumer 以 eventId 去重。
- 事件 schema、ruleVersion、actorId、requestId、occurredAt 缺失时进入死信队列，不写入主报表。
- 事件只反映已提交事实；“按钮点击”类事件不得被误命名为“奖励成功”。
- 关键指标：XP grant 成功率、重复/拒绝率、streak 续签率、破冰成功率、任务领取率、游戏合格率、箱子来源分布、重复转碎片率、资源降级率、账本对账差异数。

## 13. 验收矩阵、测试和发布闸门

### 13.1 功能验收

| 范围 | 必测 |
|---|---|
| 数值 | XP/星币/碎片/补签卡并发入账、重复请求、负余额、reversal、日限额和对账 |
| Streak | UTC/Asia-Shanghai/America-New_York、DST、timezone 修改、周末保护、破冰卡/15题、窗口过期 |
| 任务成就 | 日切/周切、无错题兜底、领取幂等、50+ 成就发布和重放 |
| 游戏 | 六个 gameCode、每个状态机、断网恢复、seq/eventId 去重、超时/放弃/风险会话 |
| Avatar | 资源版本、配置保存、slot 唯一、并发 If-Match、快照失败和 2D 回退 |
| 箱子 | 免费来源、概率 sum=10000、具体 item 概率、HMAC 重算、重复转碎片、历史版本 |
| 赛季/空间 | points cap、tier 固定奖励、结束冻结、布局 schema、越界和资源下线 |
| API | requestId、错误码、scope、cursor、幂等、版本冲突、无 userId 越权 |
| 合规 | 无付费开箱、无充值货币开箱、无现金/交易/NFT、无赌博化动效、无 Phase 1 AI |

### 13.2 跨端和四档性能验收

1. Web/H5、iOS、Android 的核心学习和六类游戏在 Performance 档可完整开始、作答、判定和结算。
2. iPad 横屏下任务、游戏 HUD、衣柜和空间可操作；不依赖悬浮 hover。
3. 微信小程序只使用 2D/快照/CSS 降级；不初始化 Three.js 实时上下文。
4. Ultra/High 进入 Avatar 页面目标 30fps 以上；低于 24fps 持续 3 秒自动降档且页面不白屏。
5. web-view 内存超过 150MB、WebGL context lost、快照/CDN 失败时分别验证回退。
6. 用户关闭动画、音效、触觉后，反馈使用文本/图标/进度补偿；无颜色唯一信息。
7. 页面离开后释放 web-view、音频和动画上下文；学习答题页不常驻完整 3D。

### 13.3 安全、审计和数据测试

- 越权读写他人 userId、chestGrantId、sessionId 必须 403。
- 修改客户端 deltaXp、deltaCoins、score、quality、randomSeed、probabilityVersion 必须无效。
- 账本 UPDATE/DELETE、概率历史 UPDATE、已开箱结果覆盖必须被数据库权限/服务层阻断。
- 任意成功奖励均可通过 sourceEventId → reward_grant → ledger/audit → response/requestId 反查。
- 风险事件的学习进度不丢失，但经济奖励进入 pending review；复核结论只能追加审计。
- 删除/注销账户遵循用户域隐私流程；GAM 审计只保留合规所需的匿名化事实，不恢复真实身份。

### 13.4 发布闸门

- Phase 1 默认开启 FEAT-GAM-001～021 中 P0 能力；FEAT-GAM-004、021、022 和两个扩展游戏按 P1 feature flag 灰度。
- 新规则、概率、物品、资源、赛季必须有 draft → in_review → approved → published 轨迹和变更原因。
- 奖励箱上线前必须同时通过：概率公示截图/文案审查、HMAC 重算脚本、重复物品转换测试、无付费入口扫描、iOS/Android 商店合规复核。
- 任何 AI 相关开关在 Phase 1 默认为关闭；本文不定义 AI 输入/输出 schema，不把 AI 结果作为奖励或判定依据。
