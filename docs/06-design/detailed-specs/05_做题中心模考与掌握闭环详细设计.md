## 0. 设计原则、边界与统一语义

### 0.1 Phase 1 边界

1. 所有题目、选项、解析、翻译评分规则和变式题均来自已审核、已发布的结构化内容；不调用生成式 AI，不把模型输出作为判分依据。
2. 目标用户为 18 岁以上成人与大学生。CET-4、CET-6、考研英语一/二只做合法授权或自研模拟，不宣称官方题库、官方成绩或官方 CEFR 认证。
3. 客观题由 assessment-service 权威判分；翻译和引导式写作使用预先配置的规则化评分量表，不在 Phase 1 进行 AI 评分。
4. 客户端只负责交互、暂存和展示；正确答案、考试时钟、状态转移、得分、掌握度和反作弊结论均以服务端为准。
5. 切屏、失焦、时间异常只产生可解释的风险事件和报告标记，不默认扣除学习分或考试分；是否人工复核由运营/教研规则决定。
6. 不采集录屏、截图、摄像头、麦克风或用户原始音视频。题库音频是合法内容资产，不等同于用户录音。

### 0.2 领域边界与单一事实源

| 能力 | 本文件的责任 | 其他模块责任 | 约束 |
|---|---|---|---|
| 今日流候选内容 | 将 learning 提供的候选池物化为 assessment session | learning 维护计划、SRS、到期排程 | 只在本文件生成 exercise_id |
| 题库与组卷 | 题目、材料、选项、试卷版本和组卷规则 | CMS 负责录入、审核、发布 | 只有 PUBLISHED 内容可投放 |
| 作答与判分 | 接收答案、幂等落库、权威判分 | 客户端只做交互 | 不接受客户端 score |
| 错题与掌握 | 错因规则、D+0/D+1/D+7、MASTERED | learning 消费掌握事件并更新全局 SRS | mastery_status 与 mistake_status 分开 |
| 模考时钟与状态 | exam session 状态机、服务端时间、断点恢复 | 账号/设备服务提供认证和设备标识 | 客户端时间永不决定 deadline |
| 学习/模考报告 | 本领域生成报告快照和解释证据 | 画像/首页消费聚合结果 | 所有指标带 calculation_version |
| 录屏/摄像头 | 明确不采集 | 无其他模块可绕过此边界 | 反作弊只保存事件元数据 |

learning 模块现有的 /api/v1/learning/stream/today 可以作为首页聚合入口，但它必须返回本文件创建的 session_id 和 exercise_id；不得另行判分或生成第二套题目实例。做题中心的权威执行接口统一位于 /api/v1/assessment、/api/v1/exam、/api/v1/mastery。

### 0.3 item_id、question_id、exercise_id、session_id 语义

这是本领域所有接口、表和事件的强制约定：

| 标识 | 唯一含义 | 生命周期 | 可以做什么 | 不可以做什么 |
|---|---|---|---|---|
| item_id | 学习对象 LearningItem 的稳定 ID，例如 WORD、PHRASE、COLLOCATION、SENTENCE、GRAMMAR_PATTERN、SKILL | 内容长期存在 | 作为 SRS、错题、掌握图谱的归因对象 | 不表示一道题、一次作答或一个页面槽位 |
| question_id | 题库中的一道稳定题目 ID，包含题干、题型、材料引用和判分规则版本 | 内容版本长期存在 | 作为题目引用、试卷题目和判分依据 | 不表示某个用户的投放实例 |
| exercise_id | 某个 session 中对一个 question_id 的一次投放实例 ID | 随 session 创建，唯一且不可复用 | 作为作答、判分、跳转、断点和埋点主键 | 不作为题库 ID，不跨 session 复用 |
| session_id | 一次可恢复的执行会话 ID。daily stream、quick practice、checkpoint、mock exam 共用同一格式 | 会话创建至关闭 | 关联题目实例、答案、状态、报告 | 不使用 exam_session_id 另起一套语义 |
| submission_id | 一次答案提交修订记录 ID | 每次提交保留 | 幂等重试、答案历史和判分引用 | 不替代 exercise_id |
| mistake_id | 用户与 item_id + 错因指纹合并后的错题闭环记录 ID | 可反复 reopen | 关联 D+0、D+1、D+7 | 不等于 question_id |

API JSON 使用 camelCase，数据库使用 snake_case；任何新字段必须沿用此约定。question_id 与 item_id 可同时存在：一道题可以考查多个 item_id，错题记录至少保存一个主 item_id，并在关联表中保存其余 item_id。

### 0.4 通用题目和作答包络

服务端下发的题目不得包含 correctAnswer、答案选项标志或未公开的评分关键字。

~~~json
{
  "sessionId": "7f50b9a2-9f7f-4f55-8a44-1aa4a7af7001",
  "exerciseId": 120034,
  "questionId": 42018,
  "itemId": 88012,
  "questionType": "CHOICE",
  "position": 3,
  "sourceBucket": "REVIEW",
  "verificationStage": null,
  "prompt": {
    "stem": "Choose the best answer.",
    "materials": [],
    "options": [
      {"key": "A", "text": "..." },
      {"key": "B", "text": "..." }
    ]
  },
  "interaction": {
    "mode": "SINGLE",
    "minSelections": 1,
    "maxSelections": 1,
    "timeLimitSec": 30
  },
  "feedbackPolicy": "IMMEDIATE",
  "contentVersion": "q-2026.08.1"
}
~~~

作答统一使用以下外层，answer 内部结构由 questionType 决定：

~~~json
{
  "exerciseId": 120034,
  "clientSubmissionId": "cli-sub-01-0003",
  "revision": 1,
  "answer": {"selectedOptionKeys": ["B"]},
  "confidence": "SURE",
  "elapsedMs": 12400,
  "clientEventAt": "2026-08-20T10:15:30.500+08:00",
  "checkpointSeq": 12
}
~~~

服务端响应至少包含 accepted、isCorrect、score、maxScore、scoringStatus、errorCauseCandidates、masteryEffect、requestId。模考答题接口在交卷前将 isCorrect 和解析置为 null，避免泄露答案。

## 1. 端到端业务流程与状态总览

### 1.1 做题闭环

~~~text
[learning 候选池 / exam 试卷]
          |
          v
[创建 session，冻结题目版本和 exercise_id]
          |
          v
[客户端展示题型组件]
          |
          v
[提交答案 -> 幂等校验 -> 题型归一化 -> 权威判分]
          |
          +--> 正确：更新学习信号，必要时进入下一题
          |
          +--> 错误：规则化错因 -> mistake_id -> 当日修复队列
                                      |
                                      v
                 D+0 订正 -> D+1 延迟抽检 -> D+7 复验 -> MASTERED
                                      |
                                      v
                 learning 消费 mastery 事件并更新 SRS / 全局掌握图谱
~~~

### 1.2 会话种类

| sessionType | 题目来源 | 是否立即反馈 | 是否计入考试报告 | 默认规模/时间 |
|---|---|---:|---:|---:|
| DAILY_STREAM | 4:4:2 新学/复习/错题候选池 | 是 | 否，进入日报/周报 | 15～20 题 |
| QUICK_PRACTICE | 今日可用内容和薄弱点 | 是 | 否 | 3/5/10/20 分钟 |
| CHECKPOINT | 课程、地图节点或 50 词阶段 | 可按配置 | 生成阶段报告 | 15 题，合格线 60% |
| MOCK_EXAM | 固定版本试卷 | 交卷后 | 是 | CET 120 分钟；考研按试卷版本 |

### 1.3 通用会话状态

| 状态 | 含义 | 可进入 | 终态 |
|---|---|---|---|
| CREATED | 已创建，题目和规则已冻结，尚未开始 | IN_PROGRESS、CANCELLED、EXPIRED | 否 |
| IN_PROGRESS | 允许作答，服务端累计有效活动 | INTERRUPTED、SUBMITTING、COMPLETED、AUTO_SUBMITTED | 否 |
| INTERRUPTED | 客户端断联/异常，计时不暂停，可恢复 | IN_PROGRESS、AUTO_SUBMITTED、EXPIRED | 否 |
| SUBMITTING | 交卷锁已持有，禁止新答案写入 | COMPLETED、AUTO_SUBMITTED | 否 |
| COMPLETED | 正常完成并生成结算 | 无 | 是 |
| AUTO_SUBMITTED | 到时自动交卷并结算 | 无 | 是 |
| CANCELLED | 未开始前主动取消或管理员撤销 | 无 | 是 |
| EXPIRED | 未开始会话过期，或恢复窗口已关闭 | 无 | 是 |

## 2. 八大题型组件标准

题型组件是可复用的 Vue 3 + TypeScript 交互协议，不与页面绑定。组件必须能在 App/Web/H5 共用同一 answer schema；低算力设备只降级动画和连线绘制，不改变输入输出和判分。

### 2.1 八类组件总表

| 编号 | component | 中文题型 | 典型用途 | answer 结构 | 默认判分 | 主要错因 |
|---:|---|---|---|---|---|---|
| 1 | ChoiceBox | 单选/多选卡片 | 词义、语法、阅读、听力选项 | selectedOptionKeys | 选项集合精确匹配；可配置部分分 | MEANING_CONFUSION、GRAMMAR_TRAP、READING_MISREAD、CARELESS |
| 2 | ConnectLine | 图文连线 | 词义、搭配、场景匹配 | pairs | 按正确 pair 数计分；考试按试卷规则 | MEANING_CONFUSION、COLLOCATION_WRONG、DRAG_MISOPERATION |
| 3 | DragSorter | 句子语序拖拽 | 句子积木、语法结构 | orderedTokenIds | 默认完整顺序精确匹配 | SENTENCE_STRUCTURE_ERROR、GRAMMAR_TRAP、DRAG_MISOPERATION |
| 4 | FillBlank | 选词/挖空/缺字补全 | 例句、阅读、语法、短语 | blanks | 每空归一化后独立判分 | SPELLING_WRONG、GRAMMAR_FORM、COLLOCATION_WRONG |
| 5 | SpellInput | 听音/中文回忆拼写 | 听音拼写、主动回忆、连续拼写 | text 或 tokenSequence | 拼写精确匹配，大小写和空白归一化 | SPELLING_WRONG、SOUND_TO_FORM_MISS、MORPHOLOGY_ERROR |
| 6 | ListenChoice | 听音辨义/听力选择 | 听力理解、连读辨识 | selectedOptionKeys + playbackMeta | 选择集合精确匹配 | LISTENING_MISS、CONNECTED_SPEECH_MISS、DISTRACTOR_CONFUSION |
| 7 | ErrorCorrection | 病句改错/高亮纠错 | 语法、长难句结构 | selectedSpanIds + replacements | 目标片段和替换文本按规则匹配 | GRAMMAR_CONCEPT_CONFUSION、SENTENCE_STRUCTURE_ERROR、CARELESS |
| 8 | TranslationInput | 汉译英/受控写作输入 | CET/考研翻译、模板写作 | segments 或 text | 预配置关键词、结构、语法量表 | TRANSLATION_OMISSION、GRAMMAR_FORM、WORD_CHOICE、TIME_INSUFFICIENT |

### 2.2 通用输入、输出和归一化

#### 输入

- prompt：题干、材料引用、音频时长、图片尺寸和可访问性文本。
- interaction：组件模式、可选项、最小/最大输入长度、时间限制、是否允许撤销。
- scoringPolicy：scoringVersion、满分、部分分、归一化规则和反馈时机。
- learningContext：主 item_id、知识点标签、错因候选和 verificationStage；不包含答案。

#### 输出

- answer：只包含用户实际操作结果，不包含正确答案。
- clientSubmissionId、revision、elapsedMs、checkpointSeq。
- confidence：SURE、FUZZY、GUESS、DONT_KNOW；只影响 SRS 和掌握解释，不改变考试原始分。
- 服务端输出 scoringStatus：SCORED、PENDING_MANUAL、REJECTED、LATE。

#### 归一化

1. 文本先做 Unicode NFC、首尾空白、连续空格和换行归一化；英语大小写不敏感，但拼写字母、词形和必要标点按题目规则保留。
2. 选项按 optionKey 排序后比较；连线按 leftId + rightId 排序后比较；拖拽按 tokenId 序列比较。
3. 超时答案由服务端标记 TIMEOUT；客户端传入的 elapsedMs 只用于诊断，不决定是否超时。
4. 答案超过长度、包含未授权字段或无法按 schema 解析时返回 ANSWER_SCHEMA_INVALID，不进入错题闭环。

### 2.3 ChoiceBox：单选/多选

- 输入：mode 为 SINGLE 或 MULTI；单选允许一个 optionKey，多选允许 2～N 个 optionKey；可附 confidence 和耗时。
- 输出：selectedOptionKeys、revision、accepted、score、isCorrect、errorCauseCandidates。
- 判分：SINGLE 为集合相等；MULTI 默认集合完全相等，训练题可由 scoringPolicy.partialCredit 开启按正确选择数计分，但模考默认不开放部分分。选择空集在超时前为未作答，超时后为 TIMEOUT。
- 错因：词义题优先 MEANING_CONFUSION，语法题优先 GRAMMAR_TRAP，阅读题优先 READING_MISREAD，存在看过答案后误点时可由用户确认 CARELESS；系统不根据一次答案宣称心理结论。
- 验收：最小可点击热区 48px；键盘 1/2/3/4 仅映射可见选项；多选有明确已选态和取消态；读屏器可读出题干、选项、选中状态；切换题目不会重复提交上一题。
- 埋点：assessment.question_viewed.v1、assessment.option_selected.v1、assessment.answer_submitted.v1、assessment.answer_scored.v1、assessment.error_cause_confirmed.v1。

### 2.4 ConnectLine：图文连线

- 输入：leftNodes、rightNodes、允许连线方向、最大 pair 数和是否允许重连。
- 输出：pairs 数组，每项为 leftNodeId、rightNodeId；重连保留最后一次有效 pair，并上传 revision。
- 判分：训练模式按正确 pair 数除以总 pair 数；模考遵守 paperQuestion.scoringRule，可配置整题得分或每 pair 部分分。重复 pair 去重，非法节点直接拒绝。
- 错因：配对语义不一致为 MEANING_CONFUSION 或 COLLOCATION_WRONG；拖拽落点不合法为 DRAG_MISOPERATION；连线过早结束且漏项为 INCOMPLETE。
- 验收：SVG 贝塞尔曲线在 Ultra/High/Medium/Performance 四档均可关闭动画；触控拖动误差容忍 12px；连错即时回弹但不自动写入错题，只有提交后才产生判分；键盘用户可用焦点选择两端节点完成配对。
- 埋点：assessment.connect_started.v1、assessment.connect_completed.v1、assessment.answer_submitted.v1、assessment.answer_scored.v1。

### 2.5 DragSorter：句子语序拖拽

- 输入：token 列表、tokenId、拖拽方向、是否允许同义 token、初始顺序。
- 输出：orderedTokenIds、undoCount、resetCount、revision。
- 判分：默认完整序列等于 answerKeyOrder；规则允许时按正确位置数计部分分；重复 token、未知 token、越界索引拒绝。
- 错因：结构错误为 SENTENCE_STRUCTURE_ERROR，语法概念混淆为 GRAMMAR_TRAP，用户把 token 拖到错误位置但知识点正确时为 DRAG_MISOPERATION。
- 验收：触控、鼠标、键盘均可排序；一键撤销和重置可用；移动端不因页面滚动误触；动画超过 200ms 时可被 Performance 画质关闭；提交前明确显示剩余未放置 token。
- 埋点：assessment.drag_started.v1、assessment.drag_reordered.v1、assessment.undo_clicked.v1、assessment.answer_scored.v1。

### 2.6 FillBlank：选词/挖空/缺字补全

- 输入：blankId、候选词（可空）、用户填写 text、每空约束（词性、词形、大小写、标点）。
- 输出：blanks 数组、每空 normalizedText、accepted、score、isCorrect。
- 判分：每空使用预配置 acceptedAnswers、词形规则和拼写规则；整题分为各空分数之和。不可用模糊相似度替代规则。
- 错因：字母错误为 SPELLING_WRONG，词形不符为 GRAMMAR_FORM，固定搭配错误为 COLLOCATION_WRONG，超时为 TIME_INSUFFICIENT 或 TIMEOUT。
- 验收：输入法候选、粘贴、删除和键盘 Tab 行为一致；不把答案写回 URL 或埋点；多空提交后服务端可逐空解释；小程序端不依赖浏览器专属 API。
- 埋点：assessment.blank_focused.v1、assessment.blank_completed.v1、assessment.answer_submitted.v1、assessment.error_cause_confirmed.v1。

### 2.7 SpellInput：听音/中文回忆拼写

- 输入：text 或 tokenSequence、音频播放次数和播放速度元数据、输入时长；播放元数据只用于报告。
- 输出：normalizedText、accepted、score、isCorrect、errorCauseCandidates。
- 判分：大小写、Unicode 和允许的标点归一化；拼写本身精确匹配，题库可配置英美拼写别名，但不允许客户端自定义别名。
- 错因：拼写不符为 SPELLING_WRONG；听音到字形转换失败为 SOUND_TO_FORM_MISS；词形变化错误为 MORPHOLOGY_ERROR。
- 验收：支持中文回忆英文、听音拼写、连续拼写挑战；不在本地保存输入历史超过本题生命周期；输入框可读屏；离线答案必须带内容版本并在恢复网络后重新校验。
- 埋点：assessment.audio_played.v1、assessment.spell_input_changed.v1（只记长度，不记文本）、assessment.answer_scored.v1。

### 2.8 ListenChoice：听音辨义/听力选择

- 输入：合法音频 materialId、播放上限、速度档位、selectedOptionKeys；播放由客户端控制，判分由答案控制。
- 输出：playbackMeta（playCount、speed、replayed）、selectedOptionKeys、score、errorCauseCandidates。
- 判分：按 ChoiceBox 的单选/多选规则；播放次数、是否重播不扣分，只进入听力诊断。
- 错因：听不出关键信息为 LISTENING_MISS，连读/弱读辨识失败为 CONNECTED_SPEECH_MISS，被干扰项吸引为 DISTRACTOR_CONFUSION。
- 验收：App/Web/H5 都能在弱网显示加载态和可重试；不得因音频未加载提交空答案；小程序无 Web Audio 时降级为系统播放器；播放速度不能改变音频原文件。
- 埋点：assessment.audio_load_started.v1、assessment.audio_load_failed.v1、assessment.audio_played.v1、assessment.answer_scored.v1。

### 2.9 ErrorCorrection：病句改错/高亮纠错

- 输入：可选 spanId 集合、replacement 数组（spanId、text）、允许修改范围和题目规则。
- 输出：selectedSpanIds、replacements、score、isCorrect、每个错误点的判分状态。
- 判分：目标错误 span 完整选择且替换文本匹配预置规则才得对应分；未授权 span、重复替换、脚本字段均拒绝。Phase 1 不使用 NLP 模型猜测语法。
- 错因：语法概念混淆为 GRAMMAR_CONCEPT_CONFUSION，句子结构错误为 SENTENCE_STRUCTURE_ERROR，漏看细节为 CARELESS。
- 验收：高亮区域可放大、可读屏；移动端选择文字不阻断滚动；提交后展示规则编号和最小必要解析；用户答案原文只进入受保护答案表，不进入分析埋点。
- 埋点：assessment.span_selected.v1、assessment.replacement_entered.v1（只记长度）、assessment.answer_scored.v1。

### 2.10 TranslationInput：汉译英/受控写作输入

- 输入：text 或 segments、字数/句数范围、必备概念、术语表、结构量表和 scoringVersion。
- 输出：answerHash、length、segmentResults、score、scoringStatus；不在客户端显示 hidden rule。
- 判分：按预配置维度计分：核心概念覆盖、术语命中、句法结构、词形、明显遗漏/增译、标点和长度。各维度加权后封顶，不用生成式模型。若题目标记 MANUAL_REVIEW，则先返回 PENDING_MANUAL，报告中单独显示未计入自动分。
- 错因：概念遗漏为 TRANSLATION_OMISSION，词汇选择错误为 WORD_CHOICE，词形/句法错误为 GRAMMAR_FORM，来不及完成为 TIME_INSUFFICIENT。
- 验收：输入长度、超时、粘贴和撤销可用；答案内容加密传输并按权限读取；报告明确区分自动规则分、人工待评和总分口径；小程序和 App 不调用系统录音权限。
- 埋点：assessment.translation_started.v1、assessment.translation_submitted.v1（只记长度和 hash）、assessment.answer_scored.v1。

## 3. FEAT-ASM-001～020 逐项设计、验收和埋点

以下名称以 requirements/feature-matrix.md 实际编号和名称为准。每项都明确输入、输出、判分、错因、验收和埋点；题型共用第 2 节的组件协议。

### FEAT-ASM-001｜单选/多选卡片 (ChoiceBox)

- 输入：question_id、item_id、CHOICE 题面、选项、SINGLE/MULTI 模式、confidence、elapsedMs。
- 输出：exercise_id 对应的 selectedOptionKeys、判分结果、可选错因候选和 masteryEffect。
- 判分：答案集合精确匹配；多选只有 paperQuestion 明确开启时才部分分；训练即时反馈，模考交卷后反馈。
- 错因：MEANING_CONFUSION、GRAMMAR_TRAP、READING_MISREAD、CARELESS、TIME_INSUFFICIENT。
- 验收：热区至少 48px；键盘 1/2/3/4 快捷键；无障碍焦点顺序；动画可由 AdaptivePerformanceEngine 关闭；连续点击只产生一条幂等提交。
- 埋点：question_viewed、option_selected、answer_submitted、answer_scored、error_cause_confirmed。

### FEAT-ASM-002｜图文连线组件 (ConnectLine)

- 输入：左右节点、允许 pair、触控/鼠标/键盘操作和重连结果。
- 输出：pairs、revision、每 pair 分值、连错提示、最终错因。
- 判分：按题目 scoringPolicy 逐 pair 或整题判分；重复和非法 pair 拒绝。
- 错因：MEANING_CONFUSION、COLLOCATION_WRONG、DRAG_MISOPERATION、INCOMPLETE。
- 验收：SVG 贝塞尔曲线、12px 落点容错、连错回弹、Performance 档关闭粒子且仍可完成、弱网不丢当前 pairs。
- 埋点：connect_started、connect_completed、answer_submitted、answer_scored、component_degraded。

### FEAT-ASM-003｜句子语序拖拽 (DragSorter)

- 输入：token 列表、tokenId、初始顺序、拖拽事件、撤销/重置动作。
- 输出：orderedTokenIds、undoCount、resetCount、score、错误结构标签。
- 判分：默认序列精确匹配；允许 partialPosition 时按正确位置计分。
- 错因：SENTENCE_STRUCTURE_ERROR、GRAMMAR_TRAP、DRAG_MISOPERATION。
- 验收：触控/鼠标/键盘一致；滚动不误拖；撤销、重置和恢复会话后状态一致；低画质仍保留可用占位符。
- 埋点：drag_started、drag_reordered、undo_clicked、reset_clicked、answer_scored。

### FEAT-ASM-004｜Daily Stream 动态编排

- 输入：user_id、用户时区、active learning plan、每日目标、目标题数、候选池快照和 streamRevision。
- 输出：assessment session、15～20 个 exercise 实例、4:4:2 requested/actual 配额、seed、算法版本和降级原因。
- 判分：不单独判分；题目结果回写各自 scoring_result，stream accuracy 为所有可计分 exercise 的 earned/max。
- 错因：不产生新错因，但承接题目错误并将 verificationStage=D1/D7 的任务优先置入 mistake bucket。
- 验收：同一 user_id + localDate + planVersion + streamRevision 在候选快照不变时结果完全一致；候选不足有降级标志且不复制题目；D1/D7 到期任务不得被新学内容永久挤出；首屏 1 秒内可恢复已物化 session。
- 埋点：stream_requested、stream_built、stream_degraded、stream_resumed、stream_completed。

### FEAT-ASM-005｜批次结算与彩带动效

- 输入：session_id、batchSize、已判分 exercise、有效学习秒数和可发放奖励配置。
- 输出：batchSummary，包括 completedCount、accuracy、durationSec、newLearnedCount、mistakeFixedCount、xpEarned、canContinue。
- 判分：accuracy=earnedScore/maxScore；XP 由已发布 reward rule 按有效学习行为结算，重复幂等请求不重复发放；15 题完成触发结算卡，实际降级批次按 actualCount 显示。
- 错因：汇总高频 errorCategory 和 topMistakes，不把彩带动画视作学习行为。
- 验收：完成 15 题只结算一次；切后台恢复后不重复发放 XP；低配机彩带可关闭；屏幕阅读器能读取结算数据；失败时先展示结算重试状态而不是假成功。
- 埋点：batch_started、batch_settled、reward_granted、celebration_shown、celebration_skipped。

### FEAT-ASM-006｜错题自动归因捕获

- 输入：question_id、item_id、answer、scoring_result、题目标签、response time、confidence、用户可选错因。
- 输出：mistake_id、errorCategory、ruleVersion、reasonTrace、mistake_status=PENDING_RETRY、mastery_status 变化和 nextAction。
- 判分：只有服务端确认 isCorrect=false 才创建/合并错题；同一 user + item + error fingerprint 使用 mistake_key 合并累计次数。
- 错因：规则优先从题型和 mismatch 计算，覆盖 MEANING_CONFUSION、SPELLING_WRONG、GRAMMAR_TRAP、LISTENING_MISS，并可扩展 READING_MISREAD、SENTENCE_STRUCTURE_ERROR、TIME_INSUFFICIENT、CARELESS、OTHER。
- 验收：错误写入、错因、答案快照、题目来源和知识点可回放；用户确认错因不会覆盖原始规则；错误事件和错题写入同一事务或由可重放事件补偿；不使用 AI。
- 埋点：mistake_created、mistake_merged、error_cause_suggested、error_cause_confirmed、mastery_state_changed。

### FEAT-ASM-007｜当日流末尾即时攻坚

- 输入：当天 session 中产生的开放 mistake_id、候选变式题池、用户时区、当日剩余时间。
- 输出：尾部 repair exercise、retryCount、repairResult、下一状态；题目优先使用同 item_id 的不同 question_id。
- 判分：D+0 订正必须独立判分；订正成功进入 DELAY_VERIFY_D1，失败留在 PENDING_RETRY；只有完整通过才算 repair success。
- 错因：沿用原错因并允许新错因追加；再次失败更新 lastErrorAt、wrongCount 和 reasonTrace。
- 验收：错误题自动追加到队尾；同一题不无限重复；有变式题时不得只重复原题；无变式题才允许一次原题复现并标记 fallback；退出后恢复仍能看到未完成 repair。
- 埋点：repair_queued、repair_started、repair_submitted、repair_passed、repair_failed。

### FEAT-ASM-008｜24 小时 D+1 延迟验证

- 输入：D+0 订正成功的 mistake_id、correctedAt、用户时区、D1 题型策略和可用 session。
- 输出：mastery verification stage=D1、dueAt、抽检 exercise、验证结果和下一状态。
- 判分：服务端在 correctedAt + 24 小时之前不得发放；D+1 通过进入 DELAY_VERIFY_D7，失败回到 PENDING_RETRY；客户端不能指定 passed。
- 错因：失败保留原错因并追加本次错因，mastery_status 降为 LEARNING；confidence=GUESS/FUZZY 的答对仍记录为弱通过并缩短后续 SRS。
- 验收：D+0 23:59 订正的 dueAt 仍为 24 小时后；次日无学习时进入 overdue 队列；抽检在题面上不暴露“这是 D+1 验证”；同一 verification 重试幂等。
- 埋点：verification_scheduled、verification_exposed、verification_submitted、d1_passed、d1_failed、verification_overdue。

### FEAT-ASM-009｜7 天 D+7 二次巩固复验

- 输入：D1 通过记录、d7DueAt、用户时区、不同题型变式池。
- 输出：stage=D7 验证记录、score、confidence、MASTERED 或回退动作。
- 判分：仅在 D1 通过且达到 d7DueAt 后判定；通过转 mistake_status=MASTERED、mastery_status=MASTERED；失败回 PENDING_RETRY 并重新排程。
- 错因：D7 失败追加当前错误类别；反应过慢或 GUESS 作为解释信号，不单独伪造错误。
- 验收：D7 前不可提前完成；通过后错题本显示“已掌握”并留下完整证据；D7 失败不会删除历史 D1 记录；跨题型验证可回放。
- 埋点：d7_due、d7_exposed、d7_submitted、d7_passed、d7_failed、mastered_marked。

### FEAT-ASM-010｜四阶掌握度生命周期流转

- 输入：学习事件、答题结果、confidence、SRS 反馈、D1/D7 验证结果和连续无错窗口。
- 输出：mastery_status=NEW、LEARNING、MASTERED、CONSOLIDATED，带 from、to、reason、ruleVersion、nextReviewAt。
- 判分：掌握不是单次答对；MASTERED 至少要求 D+0 订正、D+1 通过、D+7 通过；CONSOLIDATED 由后续 SRS 稳定通过规则产生。
- 错因：后续重复错误将 MASTERED/CONSOLIDATED 降为 LEARNING，并重新创建或 reopen 错题闭环。
- 验收：状态只能按转移表变更；人工点击“已彻底攻克”不绕过 D1/D7；同一事件重放不重复计数；全局掌握图谱能区分四阶状态。
- 埋点：mastery_state_changed、mastery_reason_viewed、mastery_next_review_viewed、mastery_reopened。

### FEAT-ASM-011｜错题本检索与筛选

- 输入：cursor、limit、questionType、itemType、examCode、errorCategory、mistakeStatus、masteryStatus、dateFrom/dateTo。
- 输出：items、nextCursor、hasMore、每条错题的原题引用、答案摘要、错因、状态、下次验证时间和解释入口。
- 判分：不判分；列表统计的修复率=已闭环数/进入统计窗口的错题数，分母口径写入响应。
- 错因：按系统规则错因筛选，允许用户选择 OTHER，不允许通过筛选隐藏未解决状态。
- 验收：cursor 分页稳定；多条件组合有索引支持；用户只能读自己的记录；原始答案按权限脱敏；空结果、过期 cursor 和重复请求行为稳定。
- 埋点：mistake_list_viewed、mistake_filter_applied、mistake_detail_viewed、mistake_manual_marked。

### FEAT-ASM-012｜Quick Practice 碎片练习

- 输入：durationMinutes=3/5/10/20、mode=VOCAB/LISTENING/MIXED、可选 focusItemType、用户时区。
- 输出：quick practice session、题目数、服务端计时边界、实时结算和退出恢复点。
- 判分：按题目 scoringPolicy；3 分钟默认 3 个复习词 + 1 个短语 + 1 道语法/游戏题，其他档位由规则池扩展；XP 以有效作答计。
- 错因：沿用题目错因并进入 PENDING_RETRY；不可因时间到而把未作答标成错误，标为 NOT_ATTEMPTED。
- 验收：四档一键启动；超时结束不丢已提交答案；倒计时与服务端校准；退出可继续且不重新抽题；用户可选择专项或混合。
- 埋点：quick_practice_started、quick_practice_mode_selected、quick_practice_timeout、quick_practice_completed。

### FEAT-ASM-013｜Checkpoint 关卡阶段验收测

- 输入：checkpoint_id、解锁节点、试卷版本、15 题综合题包、用户学习进度。
- 输出：checkpoint report、综合分、模块分、薄弱点、是否通过、unlockAction、repairSession。
- 判分：各维度按 paperQuestion 权重计算，综合正确率达到 60% 且完成必答题才通过；不通过进入 Mistake Repair -> 变式复习 -> 延迟复测。
- 错因：按题型和知识点聚合；checkpoint 不通过不新增泛化错因，只记录真实错题。
- 验收：单元/50 词触发；通过后原子解锁下一节点；重复提交不重复解锁/奖励；未通过能直接进入错题修复；报告标注“阶段验收”而非官方考试。
- 埋点：checkpoint_unlocked、checkpoint_started、checkpoint_submitted、checkpoint_passed、checkpoint_failed、node_unlocked。

### FEAT-ASM-014｜CET-4 / CET-6 全真模考

- 输入：examCode=CET4 或 CET6、paperVersion、考试模式、设备摘要和用户时区。
- 输出：120 分钟 mock exam session、固定题目顺序、分区信息、答题卡、交卷结果和诊断报告。
- 判分：按冻结试卷权重累计；听力、阅读、翻译等分区单独出分；写作/翻译若是规则化可自动分，否则 PENDING_MANUAL；不得标为官方成绩。
- 错因：交卷后按 section、questionType、item_id、errorCategory 归因；模考中不即时展示正确答案。
- 验收：服务端 deadline；自动交卷；断点恢复不延时；切屏事件可回放；全真 UI 在手机/平板/Web 响应式可用；音频故障有重试而不伪造正确。
- 埋点：exam_paper_viewed、exam_started、exam_section_entered、exam_answer_saved、exam_submitted、exam_report_ready。

### FEAT-ASM-015｜考研英语一/二真题模考

- 输入：examCode=KY_ENGLISH_1/KY_ENGLISH_2、paperVersion、整卷或单项模式、合法内容授权标识。
- 输出：mock exam 或 section practice session、题型结构、答题卡、得分和弱项报告。
- 判分：按试卷版本 scoringVersion；整卷和完形/阅读/新题型单项练习使用相同 question_id 语义但不同 session_type；没有授权的真题不得发布。
- 错因：区分题型、能力点、时间不足和知识点错误；报告显示规则依据。
- 验收：近 10 年内容只允许已授权/自研版本；ENG1/ENG2 题型配置可独立演进；单项练习不误标为整卷成绩；版本切换不改变已开始 session。
- 埋点：exam_catalog_filtered、exam_paper_selected、exam_section_started、exam_submitted、exam_report_viewed。

### FEAT-ASM-016｜考场防作弊与切屏检测

- 输入：visibility、focus、fullscreen、heartbeat、clientEpoch、monotonicElapsed、deviceHash、clientEventId。
- 输出：asm_anticheat_event、风险等级、累计计数、用户提示、报告标记；不修改原始得分。
- 判分：不参与题目 score；风险规则为事件加权和，visibility hidden 计数达到 3 次提示，超过 3 次标记 SUSPECTED_REVIEW；时间漂移超过 120 秒、倒退、并发设备和心跳缺失追加风险。
- 错因：不产生学习错因；报告可显示 ANTI_CHEAT_SUSPECTED、CLOCK_ANOMALY、INCOMPLETE_EVIDENCE。
- 验收：切屏/失焦/全屏退出/时钟异常可回放；iOS 不支持的全屏能力不惩罚；事件去重；风险规则可配置；无摄像头、麦克风、录屏、截图调用；报告明确“风险标记不等于作弊事实”。
- 埋点：anti_cheat_event_received、visibility_hidden、focus_lost、fullscreen_exit、clock_skew_detected、heartbeat_missed、anti_cheat_warning_shown。

### FEAT-ASM-017｜答题卡快速跳转与标记

- 输入：session_id、exercise_id、answer presence、reviewMark=NONE/REVIEW、当前位置。
- 输出：answerSheet，包含 position、section、status=ANSWERED/UNANSWERED/REVIEW、可跳转 exercise_id 和 lastSavedAt。
- 判分：不判分；答题卡状态由服务端已接受答案推导，未到达服务端的本地答案显示 SYNC_PENDING，不冒充 ANSWERED。
- 错因：不产生错因；跳过和标记只作为学习/考试行为元数据。
- 验收：一键跳转不改变 session 状态；标记可幂等更新；移动端底部浮窗、平板侧栏、Web 右侧栏均可用；断点恢复后状态与服务端一致。
- 埋点：answer_sheet_opened、answer_sheet_navigated、answer_marked、answer_sheet_sync_pending。

### FEAT-ASM-018｜全真模考诊断报告

- 输入：completed session、scoring_result、paper weights、cohort snapshot、errorCategory、antiCheat summary。
- 输出：总分、分区得分率、题型得分率、排位百分比（可用时）、薄弱项雷达、历史曲线、错题讲义索引、解释证据。
- 判分：见第 8 节。所有计算保存 calculationVersion、scorePolicyVersion、dataCutoffAt；样本不足 30 人不展示排位百分比。
- 错因：按规则化错因和知识点聚合，显示 top 3 证据，不生成泛化人格判断。
- 验收：交卷后报告可重复生成同一结果；自动分与待人工评部分开；雷达分能追溯到 section/question；排位样本和口径可查看；分享前可隐藏敏感数据。
- 埋点：report_generation_started、report_generation_completed、report_metric_expanded、weakness_evidence_opened、percentile_unavailable_shown。

### FEAT-ASM-019｜每日/每周学习报告

- 输入：user_id、date 或 weekStart、有效学习事件、答题结果、SRS/掌握事件和焦点时间片。
- 输出：有效专注时长、掌握增量、遗忘/复习曲线、专注力波形、错因趋势、任务完成率、模考变化。

## 4. 4:4:2 Daily Stream 确定性编排算法

### 4.1 输入、输出和参数

默认目标题数为 15，允许用户配置 15～20；实际值由客户端请求和服务端白名单共同裁剪。每日流使用用户 profile 的 IANA 时区，默认 Asia/Shanghai。算法版本固定为 ASM-DS-1。

输入：

- userId、localDate、activePlanId、planVersion、targetCount、streamRevision；
- NEW、REVIEW、MISTAKE 三个候选池；
- 已投放/已完成 exercise 去重集合；
- D+1、D+7 的 dueAt 和 overdue 信息；
- 内容发布状态、权限、题目质量状态和题型配比规则。

输出：

- sessionId、deterministicSeed、seedVersion、algorithmVersion；
- requestedQuota、actualQuota、fallbackCount、shortfall；
- 每个 exercise 的 sourceBucket、verificationStage、questionId、itemId、position；
- degraded、degradeReasons、candidateSnapshotAt；
- 一个已持久化的候选快照。第一次物化之后，重复 GET 只读原 session，不重新抽题。

### 4.2 可复现种子

规范化字符串：

~~~text
ASM_DAILY_STREAM_V1|userId|localDate|activePlanId|planVersion|streamRevision
~~~

服务端使用 HMAC-SHA256 生成 64 位十六进制 seed：

~~~text
deterministicSeed = HMAC-SHA256(daily_stream_secret_v1, canonicalString)
~~~

daily_stream_secret_v1 只在服务端配置中心保存；自动化测试使用固定测试密钥。seed、seedVersion、canonical 组成、algorithmVersion 和候选快照时间写入 asm_assessment_session。这样同一用户同一天同一计划同一 revision 可在服务重试、节点切换和审计回放时得到完全相同的排序；候选池发生变化时不重算既有 session，而是生成新的 streamRevision。

同池排序不得使用数据库的 ORDER BY RAND。排序键为：

~~~text
rankKey = SHA-256(deterministicSeed | sourceBucket | questionId | itemId)
~~~

按 rankKey 升序，之后按 dueAt、qualityScore、questionId 做稳定次排序。qualityScore 只使用已审核的内容质量字段，不含用户答案。

### 4.3 配额计算

对 N 个题目计算 0.4N、0.4N、0.2N 的最大余数分配：

1. 先取 floor(0.4N)、floor(0.4N)、floor(0.2N)；
2. 剩余名额按小数部分从高到低补齐；同分按 MISTAKE、REVIEW、NEW 的保护优先级和 seed 决定；
3. 每个 bucket 至少 0 个，N 在 15～20 时不会出现空配额。

| N | NEW | REVIEW | MISTAKE | 合计 |
|---:|---:|---:|---:|---:|
| 15 | 6 | 6 | 3 | 15 |
| 16 | 6 | 6 | 4 | 16 |
| 17 | 7 | 7 | 3 | 17 |
| 18 | 7 | 7 | 4 | 18 |
| 19 | 8 | 7 | 4 | 19 |
| 20 | 8 | 8 | 4 | 20 |

### 4.4 候选池定义和优先级

- NEW：计划内尚未被用户有效接触的 item/question 组合；已进入开放错题的 item 不再作为 NEW。
- REVIEW：SRS dueAt 已到、未来 24 小时内即将遗忘、或学习流恢复需要补做的内容；D1/D7 到期项不在普通 REVIEW 中重复计算。
- MISTAKE：PENDING_RETRY、到期的 DELAY_VERIFY_D1、到期的 DELAY_VERIFY_D7，以及 learning 模块标记为高风险的错误项。

同一 item_id 出现在多个池时，优先级为 MISTAKE > REVIEW > NEW。MISTAKE 池内部为到期 D1、到期 D7、逾期天数、lastErrorAt、wrongCount；D1/D7 验证题不能因为普通 NEW 排序而被遮蔽。

### 4.5 配额不足降级

目标配额是教学目标，不是制造重复题的硬约束。每个 bucket 先取自己的候选；不足时按下表借位，借位后的 actualBucket 和 requestedBucket 都落库：

| 缺口 bucket | 第一级借位 | 第二级借位 | 说明 |
|---|---|---|---|
| NEW | REVIEW | MISTAKE | 优先补充到期复习；不会把错题伪装成新学 |
| REVIEW | MISTAKE | NEW | 先处理开放错题，再补新学 |
| MISTAKE | REVIEW | NEW | D1/D7 到期任务优先；不得用同一 item 无限重复 |

保护规则：

1. D1/D7 到期任务是 hard due。若已逾期超过 24 小时，可从 NEW 借位；若 due 任务数超过当日 MISTAKE 容量，按逾期时间和 seed 分批，backlogCount 必须返回并进入次日优先队列。
2. 不重复同一 session 的 exercise_id；一般不重复同一 question_id。只有 PENDING_RETRY 没有可用变式题时，才允许一次原题 fallback，并写入 fallbackReason。
3. 三池合计少于 N 时返回 actualCount<N、shortfall=N-actualCount、degraded=true 和具体原因，不通过重复题补足。
4. 内容权限、题目下架、材料加载失败造成的空位不得静默删除；服务端重算一次候选快照，仍不足则按上条返回。
5. 日流对用户展示“今日可用题目不足”而不是“完成了虚假的 100% 配比”。

### 4.6 编排伪代码

~~~text
buildDailyStream(userId, localDate, planVersion, targetCount, revision):
  params = normalize(targetCount, 15, 20)
  seed = hmac(canonical(userId, localDate, planVersion, revision))
  quota = largestRemainder(params.targetCount, [0.4, 0.4, 0.2])
  pools = loadCandidates(userId, localDate, snapshotAt)
  pools = excludeAlreadyMaterializedAndDeduplicateByItem(pools)
  protectDue(pools.MISTAKE, D1, D7)
  selected = takeStable(pools.NEW, quota.NEW, seed)
  selected += takeStable(pools.REVIEW, quota.REVIEW, seed)
  selected += takeStable(pools.MISTAKE, quota.MISTAKE, seed)
  selected += borrowDeficit(selected, pools, quota, seed)
  if selected.count > targetCount:
      selected = trimByPriorityAndSeed(selected, targetCount)
  materializeSessionAndExercisesAtomically(selected, seed, snapshotAt)
  return session
~~~

### 4.7 复现和断点要求

- session 创建事务同时写 session、exercise_instance 和初始 checkpoint；任何一张表失败都不对客户端返回可继续的 session。
- 客户端只保存未上报答案和 UI 状态；服务端保存已接受答案。恢复时以 server checkpointSeq、答案 revision、serverNow 为准，本地较旧数据只能提示冲突。
- daily stream 的每日唯一键为 userId + localDate + activePlanId + streamRevision；相同幂等键返回相同 sessionId。
- 事件 assessment.stream_built.v1 必须含 seedHash、requestedQuota、actualQuota、degraded、degradeReasons 和 candidateSnapshotAt，禁止含答案。

## 5. D+0 → D+1 → D+7 → MASTERED 掌握闭环

### 5.1 两层状态模型

mistake_status 表示一条错题闭环当前处在哪个验证阶段；mastery_status 表示 item_id 的长期掌握阶段。二者不能混用。

| 字段 | 规范值 | 说明 |
|---|---|---|
| mistake_status | PENDING_RETRY | D+0 已错，等待当日即时订正 |
| mistake_status | DELAY_VERIFY_D1 | D+0 订正通过，等待至少 24 小时后的抽检 |
| mistake_status | DELAY_VERIFY_D7 | D+1 抽检通过，等待 D+7 复验 |
| mistake_status | MASTERED | D+7 复验通过的该轮错题闭环 |
| mistake_status | REOPENED | 已 MASTERED/CONSOLIDATED 后再次错误，重新进入 PENDING_RETRY |
| mastery_status | NEW | item 尚未形成有效学习记录 |
| mastery_status | LEARNING | 已学习但未满足长期掌握 |
| mastery_status | MASTERED | D+7 通过，短期到长期掌握门槛已达成 |
| mastery_status | CONSOLIDATED | MASTERED 后又经过后续 SRS 稳定复习并保持无重复错误 |

模块 03 中出现的 PENDING_DELAY_VERIFY_D1、PENDING_DELAY_VERIFY_D7 是历史描述别名；本文件数据库和 API 统一使用 DELAY_VERIFY_D1、DELAY_VERIFY_D7。

### 5.2 D+0 / D+1 / D+7 转移表

| 当前 | 事件/守卫 | 下一状态 | mastery_status | 必须写入 |
|---|---|---|---|---|
| 无开放错题 | 题目权威判错 | PENDING_RETRY | LEARNING | mistake、原题/答案、errorCategory、firstErrorAt |
| PENDING_RETRY | D+0 变式/订正通过 | DELAY_VERIFY_D1 | LEARNING | d0CorrectedAt、d1DueAt=d0CorrectedAt+24h、verification(D0) |
| PENDING_RETRY | D+0 订正失败 | PENDING_RETRY | LEARNING | wrongCount、lastErrorAt、reasonTrace、下一次修复时间 |
| DELAY_VERIFY_D1 | 当前时间 >= d1DueAt 且抽检通过 | DELAY_VERIFY_D7 | LEARNING | d1VerifiedAt、d7DueAt=d0CorrectedAt+168h、verification(D1) |
| DELAY_VERIFY_D1 | 未到 dueAt | DELAY_VERIFY_D1 | LEARNING | 记录 NOT_DUE，不计为验证 |
| DELAY_VERIFY_D1 | 抽检失败/超时 | PENDING_RETRY | LEARNING | verification(D1) FAILED、reopenCount、重排 SRS |
| DELAY_VERIFY_D7 | 当前时间 >= d7DueAt 且复验通过 | MASTERED | MASTERED | d7VerifiedAt、resolvedAt、verification(D7)、mastery 事件 |
| DELAY_VERIFY_D7 | 未到 dueAt | DELAY_VERIFY_D7 | LEARNING | 记录 NOT_DUE，不计为验证 |
| DELAY_VERIFY_D7 | 复验失败/超时 | PENDING_RETRY | LEARNING | verification(D7) FAILED、重排 SRS |
| MASTERED/CONSOLIDATED | 后续任意题目再次判错 | REOPENED 后 PENDING_RETRY | LEARNING | 原历史闭环保留，开启新 cycleNo |

D+1 的“次日”同时满足两个条件：用户本地日期通常为 D+1，且服务端绝不早于 D+0 订正完成后的 24 小时。D+7 使用 D+0 correctedAt + 7×24 小时作为最早时间；若 D+1 延迟完成，D+7 仍以最早 dueAt 为准但必须先通过 D+1。

### 5.3 四阶掌握度转移

| 当前 | 触发 | 下一状态 | 解释 |
|---|---|---|---|
| NEW | 首次有效接触或首次错误 | LEARNING | 有学习证据但不代表掌握 |
| LEARNING | D+0、D+1、D+7 条件未完成 | LEARNING | 继续修复和排程 |
| LEARNING | D+7 复验通过 | MASTERED | 达到本次错题长期掌握门槛 |
| MASTERED | 后续至少两次 SRS 到期复习通过，且稳定窗口内无重复错误 | CONSOLIDATED | 牢固，不等于永久不忘 |
| MASTERED/CONSOLIDATED | 任何真实错误 | LEARNING | 重新进入错题修复 |

### 5.4 错因字典与规则追踪

Phase 1 的自动归因是可解释规则，不是模型置信度。至少支持：

| code | 触发例子 | 前端文案方向 |
|---|---|---|
| MEANING_CONFUSION | 词义/易混选项错误 | 词义辨析 |
| SPELLING_WRONG | 字母或词形拼写错误 | 拼写 |
| GRAMMAR_TRAP | 语法选项或结构错误 | 语法陷阱 |
| LISTENING_MISS | 听音选择/听写错误 | 听力漏词 |
| READING_MISREAD | 阅读定位或推断错误 | 阅读理解 |
| COLLOCATION_WRONG | 搭配或句块错误 | 搭配 |
| SENTENCE_STRUCTURE_ERROR | 语序/句法结构错误 | 句子结构 |
| SOUND_TO_FORM_MISS | 音到字形转换失败 | 听音拼写 |
| TRANSLATION_OMISSION | 翻译核心概念遗漏 | 翻译遗漏 |
| TIME_INSUFFICIENT | 服务端判定超时或明确未完成 | 时间不足 |
| CARELESS | 用户主动确认误操作/粗心 | 粗心或误操作 |
| OTHER | 用户主动选择且无匹配规则 | 其他 |

每个 mistake 保存 reasonTrace，例如题目标签、错位字段、时间状态、用户确认和 ruleVersion；报告可以沿 trace 解释“为什么进入 D+1”，但不输出隐藏答案。

### 5.5 重试、并发和幂等

1. 错误捕获、错题合并和 mastery transition 使用同一数据库事务；事务内对 mistake_id 加行锁，并校验 row_version。
2. 同一答案使用同一 Idempotency-Key 或 clientSubmissionId 重试时返回第一次结果；相同 key 但 request hash 不同返回 IDEMPOTENCY_KEY_REUSE。
3. D1/D7 scheduler 使用分布式锁和 claim token；同一 verification 只能被一个 worker claim，worker 崩溃后按 leaseUntil 回收。
4. verification submit 必须带 verificationId、exerciseId、stage；服务端再次校验 dueAt、归属、当前状态，禁止客户端跳阶段。
5. 事件消费使用 eventId 去重；learning 消费 mastery.mastered.v1 重放不得重复增加 mastered_count。
6. 幂等不是“丢弃重复请求”：系统保留 requestId、response hash、第一次结果和审计记录，便于回放。

## 6. 模考 session 状态机、考试时钟与断点恢复

### 6.1 状态机

~~~mermaid
stateDiagram-v2
    [*] --> CREATED
    CREATED --> IN_PROGRESS: start，校验权益/版本/无并发考试
    CREATED --> CANCELLED: 用户取消或预创建过期
    IN_PROGRESS --> INTERRUPTED: 心跳超时/网络断联
    INTERRUPTED --> IN_PROGRESS: resume，仍未到 deadline
    IN_PROGRESS --> SUBMITTING: 用户交卷或服务端自动交卷
    INTERRUPTED --> SUBMITTING: deadline 到达
    SUBMITTING --> COMPLETED: 判分与报告快照成功
    SUBMITTING --> AUTO_SUBMITTED: deadline 触发自动交卷
    IN_PROGRESS --> AUTO_SUBMITTED: 服务端时间到
    CREATED --> EXPIRED: 创建后超过启动窗口
    INTERRUPTED --> EXPIRED: deadline 后恢复
    COMPLETED --> [*]
    AUTO_SUBMITTED --> [*]
    CANCELLED --> [*]
    EXPIRED --> [*]
~~~

### 6.2 状态转移守卫和副作用

| 当前 | 操作 | 守卫 | 下一状态 | 副作用 |
|---|---|---|---|---|
| CREATED | start | 资源归属、试卷 PUBLISHED、无其他 IN_PROGRESS、幂等键有效 | IN_PROGRESS | 写 serverStartedAt、deadlineAt、冻结题目和 seed |
| IN_PROGRESS | answer/checkpoint | session 属于用户、未到 deadline、revision/seq 更新 | IN_PROGRESS | 写 answer、checkpoint、heartbeat |
| IN_PROGRESS | heartbeat 超时 | 90 秒未收到有效心跳且未到 deadline | INTERRUPTED | 记录事件；计时继续 |
| INTERRUPTED | resume | 当前 serverNow < deadlineAt | IN_PROGRESS | 返回服务端答案/题卡/剩余时间 |
| IN_PROGRESS/INTERRUPTED | submit | 行锁成功；任何时间均可请求 | SUBMITTING | 截止写入、冻结 final revision |
| SUBMITTING | finalize | scoring 完成 | COMPLETED 或 AUTO_SUBMITTED | 生成报告、发布事件、写审计 |
| 任意非终态 | serverNow >= deadlineAt | 定时任务 claim 成功 | AUTO_SUBMITTED | 关闭输入、按最后已接受答案结算 |

用户不能主动暂停全真模考。INTERRUPTED 只是恢复态，deadlineAt 不会因断网、切后台或客户端时间改变。

### 6.3 创建和启动

1. POST /api/v1/exam/sessions 只创建一个 session。服务端锁定 paperId、paperVersion、scoringVersion、question_id 顺序、section 计时规则和 exam seed。
2. 若请求相同 Idempotency-Key，返回原 session；若用户已有同一 paper 的 IN_PROGRESS/INTERRUPTED session，返回该 session 或 SESSION_ALREADY_ACTIVE，不创建第二个。
3. startAt 使用服务端 UTC 时间保存，响应同时给 serverNow、startedAt、deadlineAt、clockOffsetMs；客户端只用 offset 做显示校准。
4. 题目内容快照包含题干版本和材料引用，不包含正确答案；答案 key 由服务端在 scoring 时读取同一 contentVersion。

### 6.4 断点快照和答案同步

客户端：

- 每次服务端接受答案后递增 checkpointSeq；切后台、路由离开、每 15 秒心跳和每次答题都尝试保存。
- 本地保存当前题、未上报 answer、UI 标记和本地 monotonicElapsed；不把本地未确认答案当作服务端已答。
- 恢复时先 GET session，再按 serverLastCheckpointSeq 合并；若本地 revision 大于服务端，显示“待同步”并重新提交同一 clientSubmissionId。

服务端：

- checkpointSeq 只接受大于当前值的快照；相等且 hash 相同返回原结果；相等但 hash 不同返回 CHECKPOINT_CONFLICT。
- 只保存答案 schema 和 UI 状态，不保存录屏/截图。
- lastAcceptedAnswerRevision 逐 exercise 维护；旧 revision 不覆盖新 revision。
- 恢复响应必须返回 serverNow、remainingSec、status、deadlineAt、lastCheckpointSeq、answerSheet、exerciseCursor。

### 6.5 答案修订、交卷和自动交卷

- 模考允许在交卷前修改答案；每次修改保留 submission_id 和 revision_no，只有最后一个 accepted revision 进入最终 scoring_result。
- serverNow >= deadlineAt 的答案标为 LATE，不改变最终答案；如果请求和 deadline 同一毫秒，以数据库事务获得的 serverReceivedAt 为准。
- 交卷使用 session 行锁和 SUBMITTING 状态。重复交卷返回第一次 finalize 结果；交卷期间的答案请求返回 SESSION_SUBMITTING。
- 自动交卷只结算服务端已接受的答案；未作答是 NOT_ATTEMPTED，不自动归为错误。

### 6.6 重试和并发策略

| 场景 | 客户端策略 | 服务端保证 |
|---|---|---|
| GET 超时 | 指数退避 1s/2s/4s，安全重试 | 只读，cursor/session 固定 |
| answer POST 超时 | 保持同一 Idempotency-Key 和 clientSubmissionId 重试 | 返回第一次 accepted/scored 结果 |
| heartbeat 超时 | 15 秒后重试，超过 90 秒生成 INTERRUPTED | 不暂停计时 |
| checkpoint 冲突 | 拉取最新 seq，提示用户选择最新答案 | 不静默覆盖 |
| submit 超时 | 用同一 idempotency key 查询 session/report | 只生成一份报告 |
| 两台设备同时答题 | 后到 revision 必须带 lastKnownRevision | 低 revision 返回 ANSWER_REVISION_CONFLICT |

Redis 锁只用于降低热点竞争，数据库行锁、唯一键和状态机是最终一致性保障。

## 7. 防作弊、设备时间篡改和隐私边界

### 7.1 记录的事件

asm_anticheat_event 只记录事件元数据：

- VISIBILITY_HIDDEN、FOCUS_LOST、FULLSCREEN_EXIT；
- HEARTBEAT_MISSED、MULTI_DEVICE；
- CLOCK_SKEW、CLIENT_TIME_BACKWARD、ELAPSED_GAP；
- PASTE_USED、RAPID_SEQUENCE、ANSWER_AFTER_DEADLINE；
- CLIENT_EVENT_DUPLICATE、CHECKPOINT_CONFLICT。

每个事件含 sessionId、clientEventId、serverOccurredAt、clientOccurredAt（如有）、sequence、count、severity、ruleVersion、deviceHash 和 requestId。payload_json 只允许布尔、数值、枚举、时间和 hash，禁止放屏幕像素、文件路径、音频、视频或答案原文。

### 7.2 风险规则

| 规则 | 阈值 | 用户体验 | 报告 |
|---|---:|---|---|
| 切屏/失焦 | 每次记录；累计 3 次提示 | 不中断答题 | 3 次显示 WARNING，超过 3 次显示 SUSPECTED_REVIEW |
| 全屏退出 | 每次记录 | iOS/小程序不支持时不惩罚 | 作为上下文事件 |
| 心跳缺失 | 90 秒 | 标记 INTERRUPTED，计时继续 | 显示恢复次数 |
| 并发设备 | 同一 session 出现不同 deviceHash | 拒绝旧设备新写入或提示重新登录 | MULTI_DEVICE |
| 时间漂移 | clientEpoch 与 serverEpoch 偏差 >120 秒 | 继续使用服务端时钟 | CLOCK_ANOMALY |
| 客户端时间倒退 | 新时间早于上次 >5 秒 | 不改变 deadline | CLIENT_TIME_BACKWARD |
| 快速重复 | 题目切换/提交频率异常 | 记录，不自动判作弊 | RAPID_SEQUENCE |

风险等级由可配置加权规则计算：

~~~text
riskScore = visibilityCount*1
          + focusLostCount*1
          + clockAnomalyCount*3
          + multiDeviceCount*5
          + answerAfterDeadlineCount*5
          + checkpointConflictCount*2
~~~

riskScore 只标记 REPORT_CONTEXT，不从总分中扣分。管理员报告应同时展示事件明细、规则版本和“风险标记不等于作弊事实”说明。

### 7.3 设备时间与计时可信源

1. session 创建、开始、checkpoint 接收、答案接收、交卷和自动交卷均使用服务端 DATETIME(3)。
2. 客户端 Date.now、系统时区、手工改时间只用于事件比对；deadline 由 serverStartedAt + durationSec 计算。
3. 服务端通过 serverNow 和 clientEpoch 的差值检测异常；不能因用户时区变化而重新计算本地考试时长。
4. 网络离线期间不能延长模考；离线答案只保留本地待同步状态，恢复后若已过 deadline 按 LATE 处理。

### 7.4 录屏不采集边界

- 不调用 getDisplayMedia、系统录屏 API、摄像头、麦克风、相册或截图 API。
- 不保存屏幕截图、视频、摄像头帧、音频波形或生物特征。
- 不通过隐蔽 web-view 或原生扩展绕过权限提示。
- 题库音频和图片是服务端合法内容资源，只提供 materialId、objectKey 和校验 hash。
- 埋点只保存交互事件的时间、枚举、计数、哈希和版本；SpellInput、TranslationInput、ErrorCorrection 的原始答案留在受保护答案表，不进入分析事件。

## 8. 判分、报告计算和可解释性

### 8.1 通用判分

每个 question_id 引用一个不可变 scoringVersion。判分输出：

- earnedScore、maxScore、isCorrect；
- scoringStatus=SCORED/PENDING_MANUAL/NOT_ATTEMPTED/TIMEOUT/LATE/REJECTED；
- normalizedAnswerHash；
- errorCategory、errorRuleVersion、reasonTrace；
- scoreBreakdown（只在允许反馈的 session 返回）。

通用公式：

~~~text
accuracy = sum(earnedScore) / sum(maxScore) * 100
sectionAccuracy = sectionEarned / sectionMax * 100
~~~

空题、非法答案、未作答不进入错误错因；TIMEOUT 只有在题目有时间限制且客户端在 deadline 前已开始作答时才可进入 TIME_INSUFFICIENT。

### 8.2 模考总分和分区

试卷中保存 sectionWeight、questionWeight 和 scoreScale；报告用冻结的 paperVersion 计算：

~~~text
rawScore = sum(questionEarnedScore)
scaledScore = round(rawScore / paperMaxScore * paperReportedMax, 1)
sectionScore = round(sectionEarned / sectionMax * sectionReportedMax, 1)
~~~

scaledScore 是本产品模拟分，不是官方成绩。翻译/写作若 PENDING_MANUAL，则同时返回 autoScore、pendingManualScore、reportedScorePolicy；在最终人工分完成前，报告不得把待评部分当作 0 分。

### 8.3 排位百分比

只在同一 examCode + paperVersion + reportPeriod 的匿名成绩快照中计算：

~~~text
eligibleCount = 同口径且非无效会话的成绩人数
percentile = count(score <= currentScore) / eligibleCount * 100
~~~

并列采用相同分数相同百分位；eligibleCount < 30 时返回 percentile=null、reason=INSUFFICIENT_COHORT，不猜测全国排名。报告展示样本数和口径，不展示其他用户身份。

FEAT-ASM-018 的“全国考生排位击败率”只有在同一 paperVersion 的全国匿名有效成绩快照可用时才可标记 cohortScope=NATIONAL；否则必须标记 cohortScope=PRODUCT_COHORT，并在界面写明“产品内同版本样本”，不能把产品样本包装成全国排名。

### 8.4 薄弱项雷达

每个 dimension 保存 evidenceQuestionIds、evidenceItemIds、errorCategories 和计算版本。默认分数：

~~~text
accuracyScore = dimensionEarned / dimensionMax * 100
speedScore = clamp(100 - max(0, avgResponseMs - expectedAvgMs)
                   / max(expectedAvgMs, 1) * 100, 0, 100)
weaknessRadarScore = round(accuracyScore*0.75 + speedScore*0.15
                           + delayedFailureRateComplement*0.10, 1)
~~~

模考没有延迟验证数据时，delayedFailureRateComplement 使用历史窗口值；没有历史值时权重归一到 accuracyScore 和 speedScore，并在解释中标注数据不足。雷达只表示本产品规则指标，不等于官方能力认证。

### 8.5 日报/周报指标

- 有效专注秒数：服务端在 answer、heartbeat、页面活跃事件之间形成区间；连续无有效事件超过 60 秒切断区间；hidden/blur 区间不计入。
- 新学/复习/错题：按 exercise.sourceBucket 和去重后的 item_id 统计。
- 遗忘率：到期且已尝试的复习内容中判错或延迟验证失败的比例。
- 掌握增量：窗口内首次进入 MASTERED 的 item_id 去重数量。
- 专注力波形：按 5 分钟桶统计 activeSeconds / 300，前端只展示波形不推断情绪。
- 任务完成率：已完成有效任务数 / 当日计划任务数，配额不足和用户主动调整均写入口径。

### 8.6 解释性响应

报告和掌握详情必须能返回：

~~~json
{
  "metric": "weaknessRadarScore",
  "value": 61.5,
  "calculationVersion": "ASM-REPORT-1",
  "window": {"from": "2026-08-01", "to": "2026-08-20"},
  "evidence": [
    {
      "questionId": 42018,
      "itemId": 88012,
      "errorCategory": "LISTENING_MISS",
      "occurredAt": "2026-08-20T10:15:30Z"
    }
  ],
  "explanation": "本周期听力题得分率低于其他维度，且同一 item 在 D+1 抽检中失败；已安排下一次复习。"
}
~~~

解释中不披露正确答案密钥，不将规则指标包装成诊断或官方认证。

## 10. REST API 约定、权限、错误码和幂等

### 10.1 通用响应和权限

所有接口遵循 docs/05-api/api-conventions.md：

- Authorization: Bearer token；所有资源校验 user_id 归属。
- 读接口返回 requestId；写接口同时返回 requestId、serverNow 和必要的 version。
- JSON camelCase，错误结构固定为 errorCode、message、requestId、details。
- 写接口必须带 Idempotency-Key；heartbeat/checkpoint 还必须带 checkpointSeq。
- 分页使用 opaque cursor，limit 默认 20，允许 1～50；cursor 只对同一组过滤条件有效。

| scope/角色 | 能力 |
|---|---|
| assessment:read | 读取本人题目实例、答题卡、日报/阶段结果 |
| assessment:write | 创建本人 Daily/Quick/Checkpoint session、提交答案 |
| exam:read | 读取本人试卷目录、session、答题卡、报告 |
| exam:write | 开始、心跳、断点、答题、交卷本人模考 |
| mastery:read | 读取本人错题、验证队列、掌握解释和报告 |
| mastery:write | 提交本人订正、D1/D7 验证和海报请求 |
| content:manage | 管理员维护题库、选项、材料、试卷和组卷规则；不能代表用户作答 |
| report:review | 被授权的报告复核，仅读脱敏答案和反作弊元数据 |
| system:scheduler | 运行 D1/D7 claim、报告生成、过期会话任务 |

### 10.2 稳定错误码

| HTTP | errorCode | 场景 |
|---:|---|---|
| 400 | ASM_INVALID_ARGUMENT | 字段缺失、枚举或日期非法 |
| 400 | ASM_SCHEMA_INVALID | answer 不符合题型 schema |
| 401 | ASM_UNAUTHENTICATED | token 缺失/失效 |
| 403 | ASM_FORBIDDEN | 无 scope 或非资源所有者 |
| 404 | ASM_NOT_FOUND | session/exercise/report 不存在或不可见 |
| 409 | ASM_IDEMPOTENCY_KEY_REUSE | 同一幂等键 request hash 不一致 |
| 409 | ASM_SESSION_STATE_CONFLICT | 当前状态不允许操作 |
| 409 | ASM_ANSWER_REVISION_CONFLICT | 设备提交了旧 revision |
| 409 | ASM_CHECKPOINT_CONFLICT | checkpointSeq 相同但内容不同 |
| 409 | ASM_SESSION_ALREADY_ACTIVE | 已存在同一用户同一试卷有效会话 |
| 410 | ASM_SESSION_EXPIRED | 会话已过期/不可恢复 |
| 410 | ASM_NOT_DUE | D1/D7 尚未到 dueAt |
| 422 | ASM_ANSWER_REJECTED | 答案非法、未授权或超出题目规则 |
| 422 | ASM_LATE_ANSWER | 已超过服务端 deadline |
| 429 | ASM_RATE_LIMITED | 触发频率限制 |
| 500 | ASM_INTERNAL_ERROR | 内部错误，客户端使用 requestId 联系客服 |
| 503 | ASM_TEMPORARILY_UNAVAILABLE | 判分/报告暂时不可用，可按幂等键重试 |

### 10.3 幂等、重试和分页细则

1. POST/PUT 的 Idempotency-Key 建议使用 UUID，服务端保存 24 小时或直到 session 关闭后按策略清理；同一 key + 相同 body 返回第一次的 status 和 response。
2. 服务器在处理前先插入 asm_idempotency_key=PROCESSING；重复请求看到 PROCESSING 时返回 202 或轮询原 requestId，不并行执行第二次。
3. Answer 还必须带 clientSubmissionId；同一 session/exercise 的 revision 递增。老 revision 可以安全重试，但不能覆盖新 revision。
4. GET 的 cursor 是 base64url 不透明字符串，不允许客户端解码或自行拼接；响应包含 nextCursor、hasMore、limit。
5. 分页数据排序必须稳定：mistake 按 nextActionAt、mistakeId；paper 按 publishedAt、paperId；历史 session 按 createdAt、sessionId。

## 12. 埋点与事件契约

### 12.1 事件公共 envelope

所有事件名使用 domain.action.vN，符合 api-conventions 的 event 约定：

~~~json
{
  "eventId": "evt-uuid",
  "eventName": "assessment.answer_scored.v1",
  "occurredAt": "2026-08-20T10:15:30.500Z",
  "actorId": "user-1001",
  "requestId": "req-uuid",
  "sessionId": "session-uuid",
  "exerciseId": 120034,
  "questionId": 42018,
  "itemId": 88012,
  "properties": {
    "questionType": "CHOICE",
    "sourceBucket": "MISTAKE",
    "scoringStatus": "SCORED",
    "errorCategory": "MEANING_CONFUSION",
    "algorithmVersion": "ASM-DS-1"
  },
  "schemaVersion": "1.0"
}
~~~

事件消费必须以 eventId 幂等，可重放；properties 禁止原始答案、音视频、屏幕像素和未经脱敏的个人信息。

### 12.2 核心事件和用途

| 事件 | 触发 | 最小属性 | 用途 |
|---|---|---|---|
| assessment.stream_built.v1 | Daily Stream 物化 | seedHash、quota、actual、degraded | 算法回放和配额质量 |
| assessment.question_viewed.v1 | 首次有效曝光 | questionType、position | 漏斗和有效曝光 |
| assessment.answer_submitted.v1 | 服务端接受答案 | revision、elapsedBucket | 作答漏斗 |
| assessment.answer_scored.v1 | 判分完成 | scoreBucket、isCorrect、errorCategory | 错因和准确率 |
| mastery.mistake_created.v1 | 首次错题 | errorCategory、ruleVersion | 错因趋势 |
| mastery.verification_scheduled.v1 | 创建 D1/D7 | stage、dueAtBucket | 队列健康 |
| mastery.verification_completed.v1 | 验证完成 | stage、result、confidence | 延迟通过率 |
| mastery.state_changed.v1 | 掌握度转移 | from、to、reason | 图谱和报告 |
| exam.session_state_changed.v1 | 模考状态变化 | from、to、reason | 恢复和自动交卷 |
| exam.anticheat_event.v1 | 风险事件 | type、severity、count | 反作弊审计 |
| report.generated.v1 | 报告就绪 | reportType、calculationVersion | 报告可用性 |
| report.share_asset_generated.v1 | 海报就绪 | templateCode、dataHash | 分享转化 |

### 12.3 埋点质量验收

- 客户端离线事件写入本地队列时保留 eventId，恢复网络后不重新生成 eventId。
- 服务端拒绝没有 actorId、requestId、occurredAt 或 schemaVersion 的事件。
- 同一答案重试不会产生两个 answer_submitted 或两个 reward_granted。
- 事件和数据库结果允许通过 requestId、sessionId、exerciseId、itemId 关联回放。
- 任何埋点审查都必须验证无录屏、无原始音频、无答案文本泄露。

## 13. 验收矩阵与测试场景

### 13.1 关键端到端验收

| 编号 | 场景 | 必须验证 |
|---|---|---|
| ASM-E2E-001 | 15 题 Daily Stream | 6/6/3 配额、seed 可复现、题目无重复、答案逐题幂等、批次只结算一次 |
| ASM-E2E-002 | NEW 候选不足 | REVIEW/MISTAKE 借位、requested/actual 可解释、总候选不足时不制造重复 |
| ASM-E2E-003 | D+0 错题修复 | 原错题、错因、不同变式、PENDING_RETRY -> DELAY_VERIFY_D1 |
| ASM-E2E-004 | D+1 延迟抽检 | 24 小时前 ASM_NOT_DUE；通过转 D7；失败回 PENDING_RETRY |
| ASM-E2E-005 | D+7 复验 | 7×24 小时前不可通过；通过写 MASTERED；历史验证可回放 |
| ASM-E2E-006 | 四阶掌握 | NEW -> LEARNING -> MASTERED -> CONSOLIDATED，后续错误 reopen |
| ASM-E2E-007 | 模考断点 | 切后台/杀进程/弱网后可恢复；server deadline 不变；本地旧答案不覆盖新 revision |
| ASM-E2E-008 | 模考交卷并发 | 双击交卷、超时自动交卷、答案与交卷竞争只产生一个最终结果 |
| ASM-E2E-009 | 防作弊边界 | 3 次切屏提示、超过 3 次风险标记；时钟篡改可记录；无媒体权限调用 |
| ASM-E2E-010 | 报告复算 | 相同 paper/scoring/calculation version 结果一致；样本少于 30 不展示百分位 |
| ASM-E2E-011 | 错题分页 | cursor 稳定、多条件索引、非本人不可读、过期 cursor 返回稳定错误 |
| ASM-E2E-012 | 海报隐私 | 只生成已完成报告；默认不包含完整错题、原题材料和设备风险细节 |

### 13.2 性能、跨端和可靠性门槛

- Daily Stream 已有 session 的恢复接口 p95 ≤ 500ms；首次物化在正常数据库负载下 p95 ≤ 1.5s。
- 单题提交在缓存命中和规则判分场景 p95 ≤ 500ms；报告异步生成返回 requestId，不阻塞交卷。
- App、iPad、Web、H5 使用同一 answer schema；Compact、Medium、Expanded 三档布局均能使用答题卡、断点和报告。
- AdaptivePerformanceEngine 的 Ultra、High、Medium、Performance 四档只影响动效/绘制，不影响可交互题面、判分或状态机。
- 任何服务重启、重复消息、网络重试、客户端重放都不得重复奖励、重复转移掌握状态或重复生成报告。
- 发布前必须通过 schema 校验、DDL migration rehearsal、OpenAPI contract test、规则判分单测、状态机属性测试和关键链路 E2E。

### 13.3 交付前人工检查清单

- [ ] FEAT-ASM-001～020 编号、名称、输入、输出、判分、错因、验收、埋点均有对应章节。
- [ ] 八大题型的组件协议和判分规则没有使用裸 any 或客户端 score。
- [ ] item_id、question_id、exercise_id、session_id 在接口、DDL、事件中含义一致。
- [ ] 4:4:2 seed、候选快照、缺口降级和 backlog 可回放。

## 14. 实现分层和事件发布顺序

1. Contract：先将本文件第 10～11 节落入 packages/contracts/，生成 Java DTO、TypeScript 类型和校验 schema。
2. Content：发布题库、材料、选项、试卷、组卷规则和 scoringVersion；发布前执行内容 hash、版权和答案完整性检查。
3. Delivery：实现 session/exercise 物化、4:4:2、断点和答案幂等；先做 Daily/Quick/Checkpoint，再接模考。
4. Scoring：按八大题型实现规则判分，所有 scoring_result 带版本和 reasonTrace。
5. Mastery：接入错题合并、D+0/D+1/D+7 scheduler、mastery 事件和 learning 消费。
6. Exam：实现服务端时钟、自动交卷、反作弊元数据、答题卡和报告生成。
7. Report：固定 calculationVersion，建立可复算快照和证据链；海报只读取报告快照。
8. Observability：最后打开完整埋点和告警，验证事件幂等、隐私过滤和审计查询。

任何实现若改变状态码、判分公式、题型 schema、报告口径、反作弊阈值或表语义，必须增加版本并在 ADR/契约中说明，不得静默改变既有 session 的历史结果。
