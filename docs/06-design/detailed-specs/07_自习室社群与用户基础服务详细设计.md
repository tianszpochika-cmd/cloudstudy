## 1. 目标与边界

### 1.1 目标

本模块实现“进入自习室→开始专注→正向反馈→提醒复习→多端恢复→问题闭环”：

1. 提供 20～30 人主题虚拟自习室、座位、25/45 分钟番茄钟和合法白噪音。
2. 提供预设鼓励语、系统学习 Feed、点赞和 3～10 人学习小组；不开放自由文本聊天室。
3. 提供手机号、微信、Apple 登录，Access/Refresh 双 Token 轮换、撤销、重放检测、设备踢出。
4. 提供离线包、SQLite/IndexedDB 事件队列、同步游标、冲突合并、弱网重试。
5. 统一承载站内消息、App Push、偏好、内容纠错、FAQ、客服工单和审计。

### 1.2 硬边界

- Phase 1 只面向已确认 18+ 的成人、大学生和职场用户；不做儿童、家长、K12、未成年人支付。
- 公开房间只能使用运营发布模板；用户不能创建自由公开房间。
- **不开放**自由文本留言、私聊、群聊、图片/语音留言、外链、联系方式交换、自由发帖。
- 社交互动只提交服务端 presetCode；禁止 text、message、content、HTML、Markdown、URL 和任意扩展字段。
- 工单/纠错可有受限说明文字，但必须隔离社交域，并限制长度、敏感信息、外链和附件。
- Phase 1 不调用生成式 AI；Feed、通知、榜单和内容安全使用规则、白名单和确定性模板。
- 日志不含手机号、邮箱、第三方 token、Refresh 原文、完整设备指纹或原始 IP；审计只存脱敏/哈希。

### 1.3 权威数据分层

| 领域 | MySQL 事实 | Redis 短状态/投影 | 失效策略 |
|---|---|---|---|
| 账号 | usr_user、identity、device、token family、deletion | OTP、deny jti、在线集合、限流 | 缓存丢失可重建；Token 只存 hash |
| 社交 | room、member、seat、focus、interaction、Feed、榜单快照 | 房间状态、租约、Stream、ZSET | Redis 不可用禁止新租约/互动，仅只读 |
| 通知同步 | message、preference、offline、client event、change log | 去重、重试、游标 | 端侧排队，服务端逐项幂等 |
| 支持审计 | FAQ、ticket、correction、audit | 锁、频控 | 工单正文永不投影到社交 |

## 4. 自习室领域模型、状态机与反刷规则

### 4.1 房间、成员、座位和小组

- 房间模板由运营后台发布，字段为 roomCode、themeCode、displayName、capacity、defaultSoundSet、language、status；普通用户不能自由创建公开房间。
- 房间容量按模板限制为 20～30。成员表保存进入、离开、踢出和过期事实；Redis 只保存当前投影。
- 轻量小组独立于公开大厅，人数 3～10，邀请码为一次性/短期凭据，服务端只存邀请码 hash。
- 公开资料只包含昵称或匿名名、参考等级、已戴勋章、装扮静态快照和固定成就模板；手机号、邮箱、精确位置、目标日期、学习草稿不公开。

### 4.2 座位和专注状态机

~~~text
AVAILABLE
  └─ join/seat.assign → HELD → OCCUPIED
                              ├─ websocket lost → DISCONNECTED → reconnect → OCCUPIED
                              ├─ 5m no learning activity → RELEASED
                              └─ leave/lease timeout → RELEASED

RUNNING → PAUSED → RUNNING
RUNNING → target duration reached → COMPLETED
RUNNING/PAUSED → leave or 5m idle → AUTO_RELEASED
any state → integrity failure → INVALID
~~~

约束：

1. 入座生成 leaseId、leaseVersion、expiresAt；Redis 座位租约 TTL 90 秒，客户端每 30 秒续租。
2. ping/pong 只代表连接存活；只有受信任 learning 事件、题目提交或服务端 focus tick 更新 lastActivityAt。
3. 同一用户最多一张有效座位和一个 RUNNING session；Redis Lua 与 MySQL 唯一约束双重防并发。
4. 状态事实先落 MySQL，再更新 Redis 投影并广播；若采用 outbox 先投影，必须由补偿任务保证最终落库。
5. WS 断线进入 DISCONNECTED，宽限 60 秒；宽限内按原 lease 恢复，超过后释放并重新入座。

### 4.3 番茄专注和榜单防刷

- 专注榜只计 COMPLETED 或规则允许的 AUTO_RELEASED session 的 qualifiedSeconds；重叠区间合并，单日最多计 480 分钟，超出标记 REVIEW。
- 学词榜只消费 learning 域“首次达到掌握阈值”的不可变事件；同一 userId + contentId + masteryTransition + period 只计一次。
- 客户端不能提交 score、minutes、newWords、rank；客户端时间只做显示，服务端以 session、学习事件和服务器时间计分。
- 反刷信号包括时间戳偏差、短周期高频 session、重叠 session、异常设备切换、批量同构事件、重复 clientEventId、设备多账号异常共用。结果为 VALID、REVIEW 或 INVALID，不向用户泄露具体规则。
- 实时榜单是 Redis ZSET 投影；每周一 02:00（Asia/Shanghai）生成不可变 snapshot。快照和奖励按 period + kind + version 幂等；迟到事件进入复核/下周期。
- 用户可通过客服工单申诉，管理员结论、依据和奖励修正写入审计。

### 4.4 低 UGC 预设目录和安全

预设目录只包含 presetCode、本地化 key、图标、目标范围、冷却时间、版本和状态。内置示例：CHEER_UP、STUDY_TOGETHER、CONGRATS、TRY_AGAIN、TONIGHT_20_MIN。

- 每用户每房间每 30 秒最多 3 次、每小时最多 60 次；每目标用户每分钟最多 1 次。
- 服务端拒绝 text、message、content、html、url、emoji、extra 等字段；Emoji 也只能随预设模板下发。
- Feed 只能由服务端模板产生，参数仅允许数字、等级、课程/成就代码；用户昵称必须经过展示层转义。
- 工单/纠错说明独立走长度、控制字符、手机号/微信号/URL、敏感词和附件病毒扫描；不得投影到房间、Feed 或榜单。

## 5. WebSocket 实时协议

### 5.1 传输和握手

端点为 WSS /api/v1/social/ws，子协议 yuxuexing.social.v1.json，文本 JSON，单帧上限 64 KiB。房间订阅是连接建立后的第一条业务命令。

- App/原生端在 HTTP Upgrade 携带 Authorization: Bearer accessToken。
- Web/H5 先 POST /api/v1/social/ws-ticket，服务端设置同源 Secure、HttpOnly、SameSite=Lax 的一次性 cookie，再从同源建立 WSS；Token 不出现在 URL、localStorage 或日志。
- ticket TTL 60 秒，一次性并绑定 user/device/origin；Origin 不在白名单直接拒绝。服务端校验账号、设备会话、Access jti deny key 和协议版本。
- Upgrade 失败用 HTTP 401/403/426；已建立连接的关闭码：4001 AUTH_EXPIRED、4003 FORBIDDEN、4008 RATE_LIMITED、4010 SERVER_SHUTDOWN、4011 RESUME_NOT_POSSIBLE。
- 成功先发 connection.accepted.v1，含 connectionId、serverTime、heartbeatIntervalSec=25、pongTimeoutSec=10、leaseRenewIntervalSec=30、resumeWindowSec=300、maxSubscriptions=3。连接不自动订阅房间。

### 5.2 事件 envelope

~~~json
{
  "kind": "COMMAND",
  "eventType": "room.subscribe.v1",
  "schema": "social.ws.room.subscribe",
  "version": 1,
  "eventId": "evt_01J...",
  "requestId": "req_01J...",
  "idempotencyKey": "idem_01J...",
  "occurredAt": "2026-08-20T12:00:00Z",
  "roomId": "room_123",
  "seq": null,
  "payload": {
    "lastSeenSeq": 418,
    "snapshotVersion": 12
  }
}
~~~

| 字段 | 必填 | 规则 |
|---|---:|---|
| kind | 是 | COMMAND、EVENT、ACK、ERROR |
| eventType | 是 | domain.action.v1；服务端事件不可由客户端伪造 |
| schema/version | 是 | 严格匹配；未知版本 WS_SCHEMA_UNSUPPORTED |
| eventId | 是 | UUID/ULID；短期去重 |
| requestId | 是 | 贯穿 REST、WS、审计和日志 |
| idempotencyKey | 写命令 | 16～128 字符，24 小时重放返回原 ACK |
| occurredAt | 是 | 客户端时间只诊断；排序和计时用服务端 |
| roomId | 房间事件 | 必须是已订阅且有权限的房间 |
| seq | 服务端事件 | 房间内单调递增；客户端命令为 null |
| payload | 是 | 严格 schema；互动 payload 禁止自由文本 |

### 5.3 握手、订阅、恢复和断线重连

1. 客户端在 10 秒内发送 room.subscribe.v1，带 roomId、lastSeenSeq、snapshotVersion。
2. 服务端校验成员关系和当前账号状态。
3. lastSeenSeq 在 Redis Stream 保留窗口内时，先补发缺失事件，再发 room.subscribe.ack.v1；超窗口或 roomVersion 不一致时发 room.resync_required.v1，再发完整 room.snapshot.v1。
4. snapshot 包含座位、成员公开投影、白噪音目录版本、预设目录版本和当前用户租约摘要，不包含自由消息历史。
5. 同房间 seq 必须有序；客户端发现跳号暂停渲染，重订阅或发送 room.resume.v1。
6. 客户端断线按 1、2、4、8、16、30 秒上限并加 0～30% 抖动重连，重新握手并携带各房间 lastSeenSeq。宽限内恢复原座位，超时收到 seat.released.v1。
7. 一个连接最多 3 个房间；切换账号、设备或 Access jti 必须重新握手。

### 5.4 心跳、租约和命令

- 服务端每 25 秒发 server.ping.v1；客户端 10 秒内回 client.pong.v1，连续 3 次未回关闭。
- seat.renew.v1 携带 leaseId、leaseVersion，每 30 秒一次；只更新租约 TTL，不更新学习活动时间，旧版本返回 SOC_SEAT_LEASE_EXPIRED。
- focus.start.v1、focus.pause.v1、focus.resume.v1、focus.finish.v1 与 REST 共用 command handler、幂等键和 MySQL 事务。
- learning.activity.v1 只能由受信任学习域发布；客户端的 focus.progress.v1 只用于恢复和诊断，不能直接计分。
- 客户端不得将 payload 原样广播；服务端广播只含公开状态和当前用户可见字段。

## 6. 认证、设备、身份绑定和注销

### 6.1 手机验证码

手机号必须匹配 1[3-9] 开头的 11 位大陆号码。服务端按手机号 hash、IP、设备和全局限流：同手机号 60 秒 1 次、单手机号每日 10 次、单 IP 每日 20 次；验证码 6 位、Redis TTL 5 分钟、最多错误 5 次，成功后原子核销。验证码不入日志、不入 MySQL 明文。

首次建档创建 usr_user、默认昵称 语学星_XXXX、系统头像、A1、15 分钟画像和设备 session；必须存在 adultConfirmedAt，否则不能签发业务 Token。

### 6.2 微信和 Apple

- 微信服务端用 code 换 openid/unionid，校验 appId、平台、有效期和服务端签名；身份唯一键为 provider + subjectHash。
- Apple 服务端校验 identity token 的签名、iss、aud、exp、nonce，并缓存/轮换 Apple JWK；以 subHash 关联，relay email 只加密/哈希保存，不作外显主身份。
- 原始第三方 subject 仅在加密字段保存，审计只存 hash。登录可以创建账号，但已属于其他账号时返回 AUTH_IDENTITY_BOUND_OTHER，不自动合并。
- 绑定、解绑、换绑要求当前登录和二次认证；解绑前必须保留至少一种可恢复登录方式。

### 6.3 JWT 双 Token 轮换、撤销、重放

| 对象 | 策略 |
|---|---|
| Access JWT | 2 小时，含 userId/deviceId/familyId/jti/iat/exp/ageGate |
| Refresh Token | 30 天，每次成功使用即 USED 并生成下一枚 |
| Token family | ACTIVE、REVOKED、EXPIRED、REUSE_DETECTED |
| Device session | ACTIVE、REVOKED、KICKED、EXPIRED |
| 撤销 | Redis deny:jti TTL 不超过 Access 剩余寿命；MySQL 保存永久审计 |

Refresh 原子流程：

1. 按 tokenHash 锁 refresh 记录和 family。
2. 已 USED 且存在 replacedBy，立即判定重放，撤销整 family、设备 session 和未过期 Access jti，返回 AUTH_REFRESH_REUSE_DETECTED。
3. 过期、撤销、设备不匹配分别返回稳定错误。
4. 旧 token 写 usedAt/replacedBy，新 jti/hash 入库，更新 family 当前 hash，返回新双 Token。
5. 登出、设备踢出、风险冻结、注销均撤销相关 family，并发布不含 token 的 auth.session.revoked.v1。

并发刷新只有一个成功；另一个请求不得产生第二个有效 Refresh。服务端不记录 Token 原文。

### 6.4 设备列表和踢人

设备列表只返回不可逆 devicePublicId、平台、设备展示名、客户端版本、最近活跃时间、粗粒度区域和 current 标记。单设备踢出撤销该设备 family/session、写 deny jti、关闭该设备 WS，并发送安全通知；下线其他设备保留当前设备。重复踢出为幂等成功，不能通过专用接口踢当前设备。

### 6.5 注销和数据脱敏

注销需二次认证，创建 DELETION_PENDING，executeAt 为申请后 7×24 小时；冷静期内可重新认证取消。到期任务：

1. 锁定账号，撤销所有设备、family、WS、Push token。
2. 退出房间和小组，结束专注 session，停止非必要通知。
3. 删除/匿名化昵称、头像、手机号、第三方身份、Feed actor、榜单展示、名片和工单展示。
4. 删除可删除对象存储、离线授权和本地同步凭据；法律/订单/安全审计只保留匿名 actor、事件类型、时间、结果和不可逆 hash。
5. 每个步骤可重试且有删除任务版本；失败时账号保持不可登录并进入人工支持，不重复执行已完成步骤。

## 7. 通知、离线、同步和支持

### 7.1 通知路由

~~~text
domain.action.v1
  → schema 校验 + dedupeKey
  → 类别/偏好/DND/频控/模板
     ├─ 站内消息
     ├─ App Push
     ├─ SMS：验证码/必要安全/必要交易
     └─ Email：周报/安全/数据导出等
~~~

每个业务事件必须有 schema、occurredAt、actorId、requestId。普通学习/互动消息服从偏好、DND 和每日上限；安全、注销和必要交易通知保留发送能力。Push 未授权时由站内消息替代；正文不含验证码、手机号、完整答案或隐私。

### 7.2 离线包

manifest 由内容域发布，本模块负责授权和缓存：

~~~text
PUBLISHED → AUTHORIZED → DOWNLOADING → VERIFYING → ACTIVE_LOCAL → EXPIRED/DELETED
~~~

manifest 包含 packageCode、version、sizeBytes、partCount、sha256、signature、minClientVersion、expiresAt。分片下载记录 etag、partBitmap、downloadedBytes；完成后校验 hash 和签名并原子切换 active 版本。URL 短时有效且绑定 user/device/packageVersion；损坏自动清临时文件重下；不得导出原始商业题库。

### 7.3 同步 envelope 和冲突策略

~~~json
{
  "clientEventId": "ce_01J...",
  "eventType": "learning.checkpoint_saved.v1",
  "schema": "sync.learning.checkpoint",
  "deviceId": "dev_public_123",
  "clientOccurredAt": "2026-08-20T12:00:01Z",
  "baseCursor": "cur_opaque_418",
  "entityType": "learning_session",
  "entityId": "ls_123",
  "payload": {
    "stepIndex": 8,
    "submittedAnswerIds": ["a1", "a2"],
    "elapsedTimeMs": 187000
  }
}
~~~

| 数据 | 策略 |
|---|---|
| 学习事件/专注事实 | 追加不可变 + clientEventId 去重 |
| 已提交 checkpoint | stepIndex/完成态单调前进，旧事件不能回退 |
| 未提交答案/播放位置 | entityVersion + LWW，冲突返回两份摘要 |
| 用户偏好/昵称 | If-Match 乐观锁，版本冲突为 SYNC_CONFLICT |
| 收藏/点赞 | 集合并 + 事件去重，删除用 tombstone |
| 座位/成员 | 服务端状态机，离线不能直接占座 |
| 权益/订单/奖励 | 业务流水 + 幂等，客户端不能本地生成 |
| 注销/删除 | 删除优先，旧事件拒绝或匿名化 |

### 7.4 弱网策略

GET 首次加载显示骨架屏；网络错误、408、429、5xx 使用 1/2/4 秒指数退避加随机抖动，最多 3 次，遵守 Retry-After；4xx 业务校验不自动重试；401 只静默刷新一次 Token。写操作超时通过 Idempotency-Key 查询原结果；无法确认时进入本地队列而不是再次提交。恢复网络后优先补传客户端事件，再拉取变更游标。

### 7.5 纠错、FAQ 和工单

纠错原因枚举：释义、音标、音频、答案、例句、字幕、排版、版权、其他；说明最多 500 字。服务端自动附带 contentId、questionId、lessonId、courseId、contentVersion、appVersion、platform，重复同版本报告合并。状态为 OPEN、IN_REVIEW、CONFIRMED、REJECTED、FIXED、PUBLISHED，任何状态变化写审计并可发站内消息。

客服工单类型为功能、支付、账号、课程内容、Bug、版权、隐私、其他；正文最多 5000 字，附件仅允许图片，需大小、MIME、病毒扫描和短期签名 URL。工单消息是受限客服上下文，不是社交聊天；不能进入房间、Feed 或榜单。

## 9. Redis 键约定和原子操作

Redis 只存短期凭据、实时投影、限流和可重建索引；key 中不得放手机号、邮箱、原始 Token、原始设备指纹或工单正文。

| Key | 类型 | TTL/保留 | 用途 |
|---|---|---|---|
| auth:otp:sms:{phoneHash} | String | 300s | OTP hash、attempt、issuedAt；NX 写入 |
| auth:rate:sms:{phoneHash}:{minute} | String | 120s | 手机验证码频控 |
| auth:rate:ip:{ipHash}:{day} | String | 26h | IP 日限流 |
| auth:deny:jti:{jti} | String | Access 剩余 TTL | Access 撤销黑名单 |
| auth:ws-ticket:{ticketHash} | Hash | 60s，一次性 | userId、deviceId、originHash |
| auth:device:{deviceId} | Hash | 1h | 在线/最近活跃投影 |
| social:room:{roomId}:state | Hash | 1h | status、capacity、count、roomVersion |
| social:room:{roomId}:members | Hash | 1h | userId→member public state |
| social:room:{roomId}:seats | Hash | lease+5m | seatIndex→seat projection |
| social:room:{roomId}:seq | String | 7d | 房间单调 seq |
| social:room:{roomId}:events | Stream | MAXLEN 10000 或 5m | WS 增量事件 |
| social:seat:lease:{leaseId} | Hash | 90s | userId、roomId、seatIndex、leaseVersion |
| social:user:{userId}:seat | String | lease+5m | 一人一座反查 |
| social:focus:{sessionUuid} | Hash | session+1d | RUNNING/PAUSED 投影 |
| social:rate:bubble:{userId}:{roomId} | ZSET | 1h | 预设互动滑动窗口 |
| social:rate:bubble-target:{targetId} | ZSET | 1m | 目标用户接收频控 |
| leaderboard:{kind}:{period} | ZSET | period+7d | 实时临时榜 |
| leaderboard:dedupe:{kind}:{userId}:{sourceId} | String | period+7d | session/词事件去重 |
| sync:cursor:{userId}:{stream} | String | 7d | 游标缓存 |
| sync:idempotency:{userId}:{key} | Hash | 24h | 请求 hash、状态、结果摘要 |
| notify:dedupe:{userId}:{dedupeKey} | String | 7d | 通知去重 |
| notify:push-budget:{userId}:{day} | String | 26h | 每日 Push 预算 |
| offline:download:{deviceId}:{packageVersion} | Hash | 7d | 分片进度投影 |
| support:ticket-lock:{ticketId} | String | 30s | 工单状态并发锁 |

原子要求：

1. 分配座位使用 Lua：检查 room count、seat status、user seat reverse key、leaseVersion，成功后一次性写 seat/member/lease 投影和 seq。
2. 续租使用 Lua：比较 leaseId 与 leaseVersion，只有当前 owner 才刷新 TTL；不得更新 lastActivityAt。
3. 释放使用 Lua：删除 seat lease、user reverse key、成员座位投影并递增 seq；重复释放返回同一结果。
4. 榜单累加先写去重 key，再 ZINCRBY；去重键已存在时不累加。
5. Redis Stream 只用于传输和恢复窗口，MySQL 事实落库失败时禁止把事件标为成功；对账任务按 roomVersion、session 状态和审计补偿。

### 11.2 幂等语义

- 相同 Idempotency-Key + 相同 request hash：返回第一次的 HTTP 状态和响应摘要，不再次执行副作用。
- 相同 Idempotency-Key + 不同 request hash：返回 IDEMPOTENCY_KEY_REUSED。
- 相同 clientEventId：返回原来的 accepted/duplicate/conflict/rejected 结果；不得重新计榜、发奖、发通知或改变座位。
- WebSocket 命令使用 eventId + idempotencyKey；ACK 关联 commandEventId；断线重连不重复执行。
- 需要异步的操作先返回已受理和业务 ID；最终状态通过查询、同步变更或站内通知取得。

## 12. 数据流、事务边界和恢复作业

### 12.1 自习室加入与座位分配

~~~text
REST join
  → 认证/18+/房间权限
  → MySQL member upsert + seat row lock
  → Redis Lua 校验/写 lease + reverse key
  → MySQL seat/member audit commit
  → room seq + Stream event
  → WS snapshot/seat.updated
~~~

MySQL 事务失败时不广播成功事件；Redis 写入失败时回滚/释放座位并返回可重试错误。Redis 与 MySQL 短暂不一致由 reconciliation job 按 lease、member status、roomVersion 修复。

### 12.2 专注和排行榜

~~~text
focus command
  → seat lease / one-running validation
  → soc_focus_session fact
  → learning activity / server tick
  → finish settlement
  → fraud filter
  → leaderboard ZSET projection
  → daily provisional / Monday immutable snapshot
~~~

专注 session、学习掌握事件和奖励流水不互相覆盖；任何补传按 source event/clientEventId 去重。快照生成前保留 sourceWatermark，迟到事件进入复核而不是篡改已发布快照。

### 12.3 事件同步

~~~text
SQLite/IndexedDB append-only queue
  → POST /sync/events, per-event result
  → domain handler + clientEventId dedupe
  → inf_sync_change_log
  → GET /sync/changes?cursor=...
  → local atomic apply
  → persist nextCursor
~~~

客户端事件允许批量最多 100 条；服务端逐项处理，不能因为一条冲突拒绝整个批次。服务端事件按 user stream 单调递增；cursor 是签名不透明 token，不能由客户端自行构造。

### 12.4 异步作业

| 作业 | 周期/触发 | 必须幂等的结果 |
|---|---|---|
| seat-expiry-sweeper | 10 秒 | 释放过期 lease、关闭 AUTO_RELEASED session、广播一次 |
| room-reconcile | 1 分钟 | 修复 Redis 与 MySQL 状态差异 |
| focus-fraud-aggregate | 1 分钟 | 更新 VALID/REVIEW/INVALID 和榜单投影 |
| leaderboard-finalizer | 每周一 02:00 | 生成 snapshot/entries，冻结 period |
| notification-dispatcher | 流式 + 定时 20:00 | dedupe、渠道投递、回执 |
| sync-retry-worker | 退避队列 | 重试临时失败，不重复应用事件 |
| offline-cleaner | 每日 | 清理过期授权/临时分片，保留用户权益 |
| deletion-worker | 每小时扫描 | 分步匿名化、撤销、清理、记录版本 |
| ticket-notifier | 状态变化 | 给工单所有者发站内/可选 Push |

## 13. 验收、测试和发布门槛

### 13.1 API/协议测试

- OpenAPI schema 校验：字段、枚举、错误 envelope、cursor、Idempotency-Key、If-Match 均有契约测试。
- WS：握手无 Token/过期 Token/错误 Origin/错误协议、订阅权限、快照恢复、seq 跳跃、ping/pong、3 次超时关闭、断线重连和租约宽限。
- 并发：同一用户双端抢座、同一座位并发加入、双 Refresh 并发、旧 Refresh 重放、重复互动、重复同步、重复发奖。
- 安全：抓包无自由文本社交字段；任何客户端无法伪造 focus minutes/newWords/rank；工单附件越权和恶意文件被拒绝；审计不含敏感原文。

### 13.2 数据一致性测试

- Redis 清空后，room/seat/session/leaderboard 投影可由 MySQL 重建。
- 断网、杀进程、切后台、时钟回拨、乱序、重复、双端编辑、cursor 过期均有可预期结果。
- 已完成学习不能被旧 checkpoint 覆盖；座位离线不能伪造占用；注销后旧事件和旧 deep link 不复活账号。
- 每个榜单条目可追溯至合格 session/掌握事件；快照冻结后重跑不改变结果。

### 13.3 多端与合规验收

- App iOS/Android、Web/H5 和适用的小程序均覆盖房间列表、座位、番茄、通知、同步、登录、注销和客服主链路。

- 首次登录明确 18+、用户协议和隐私政策；不展示 K12 入口；不出现自由聊天室。
- 变更进入 packages/contracts/ 的 OpenAPI 单一事实源后才允许实现；Java DTO、前端 TypeScript 类型由契约生成，禁止裸 any。
- 迁移、测试、运行说明和 CHANGELOG 由实现阶段同步；本文件作为详细设计基线，不替代实际 migration 和自动生成契约文件。
