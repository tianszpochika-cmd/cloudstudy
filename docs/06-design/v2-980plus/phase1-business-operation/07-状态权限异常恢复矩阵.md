# Phase 1 状态、权限、异常与恢复矩阵

> 本文把统一八态落实到关键业务生命周期。表中的“呈现状态”是跨端业务语义；除非已经出现在 OpenAPI/事件/数据库枚举中，不自动新增后端 canonical enum。

通知、同步和客服的字段/状态/owner/拒绝策略以 [`config/p1r-notification-sync-support-contract.v1.json`](../../../../config/p1r-notification-sync-support-contract.v1.json) 为准。该政策只提供 `D2_CONTRACT_READY / NOT_RUNTIME_VERIFIED` 约束；文中的“必须验证”不等于当前环境已经运行。

## 1. 状态事实原则

1. 页面只能展示 owner 返回的事实和可验证投影，不能用本地文案覆盖后端状态。
2. `401`、`403`、资源不存在、内容未发布、权益不足、阶段未开放、空列表和服务错误必须可区分。
3. 同步 owner 成功但异步下游尚未完成时使用“处理中”，并提供查询或通知回访；不能回滚已经成功的 owner 事实来制造视觉同步。
4. 本地草稿、checkpoint 和离线队列必须标明“仅本地、待同步、已同步、冲突”之一。
5. 超时是未知结果，不直接等于失败；先按 Idempotency-Key 或业务 ID 查询结果。

## 2. 统一八态落地

| 状态 | 页面必须显示 | 主动作 | 证据要求 |
|---|---|---|---|
| 成功/有数据 | 当前事实、更新时间、关键版本和下一闭环动作 | 继续学习、查看结果或返回来源 | API 结果与 owner 数据一致 |
| 空 | 为什么为空、是否正常、如何产生数据 | 去学习、清除筛选、创建或返回今日任务 | 空查询与权限/错误可区分 |
| 加载 | 骨架、阶段提示或已知进度 | 等待或安全取消 | 无重复副作用请求 |
| 错误 | 稳定 errorCode、可理解原因、是否保留输入、retryable | 重试、返回或联系客服 | error envelope 含 requestId/traceId |
| 离线 | 缓存时间、可用能力、待同步数量 | 继续离线、查看下载、稍后同步 | clientEventId/clientSeq 可回放 |
| 权限 | 登录、角色、资源、设备、权益或阶段中的具体原因 | 登录、申请授权、升级或返回 | 401/403/设备拒绝/权益 Gate 独立测试 |
| 恢复 | 上次安全 checkpoint、冲突差异和恢复影响 | 恢复、保留本地、使用云端或放弃 | 恢复前后数据和审计可对账 |
| 处理中 | 任务 ID、阶段、预计回访方式和失败入口 | 查看任务、离开后通知、取消（若安全） | 异步任务/事件/审计可查询 |

## 3. 关键业务生命周期

### 3.1 身份和成人 Gate

| 业务阶段 | 呈现 | 允许动作 | 异常与恢复 |
|---|---|---|---|
| 未登录 | 登录/注册/密码重置入口 | 提交 IAM 凭据 | 限流、锁定和账号不存在不得泄漏账户存在性 |
| 已认证、Gate 未完成 | 只进入成人确认与同意 | 完成成人 Gate、同意或退出 | 不允许进入学习/支付；刷新后从服务器恢复 Gate 状态 |
| 已认证、Gate 通过 | 进入 onboarding 或 returnTo | 管理本人会话和设备 | Access Token 过期合并刷新一次；失败回登录并保留安全 returnTo |
| Gate 拒绝 | 明确 Phase 1 不服务未成年人 | 退出、查看说明 | 不创建儿童/家长/监护/K12 主体或权益事实 |
| 会话撤销/重放 | 清除业务令牌和敏感缓存 | 重新登录、查看设备安全 | 所有端感知撤销；不得静默继续写入 |

### 3.2 Onboarding、测评与计划

| 阶段 | 成功状态 | 可恢复点 | 异常策略 |
|---|---|---|---|
| 目标/时长草稿 | 服务端或本地受控草稿已保存；本地仅标记 `LOCAL_ONLY`/`PENDING_SYNC`/`SAVED`/`CONFLICT`，不是第二个 target 事实 | 最近已确认 target/profile/preference | 校验失败不清空输入；重复提交返回同一结果；超时先按 Idempotency-Key 查询 |
| target 已确认 | B9 target 事实为 `ACTIVE`/`PAUSED`/`COMPLETED`/`ARCHIVED`；`targetVersion` 与兼容 `stateVersion` 等价 | `targetId/targetVersion` 与 profile/preference 版本 | 旧版本或同 key 异摘要返回 409；不接受客户端 tenant/owner/plan，不能由 B1 adapter 另写事实 |
| placement 未开始 | 显示目的、耗时、参考性质 | 无 | 内容不可用时不得创建空会话 |
| placement 进行中 | 显示进度和已保存 checkpoint | 最近已保存题目 | 切后台、断网、刷新后恢复；题目版本变化按 session 快照继续 |
| placement 提交中 | 锁定重复提交，显示处理中 | sessionId + 幂等结果 | 超时先查询，不新建第二个 placement |
| placement 已完成 | 显示参考结果、证据摘要和下一步 | reportId/sessionId | 结果生成失败进入恢复任务，不让客户端重算分数 |
| 计划生成中 | 显示输入摘要和任务 ID | workflow/plan request | 重复事件不生成第二份 active plan |
| 计划可用 | 展示起点、今日任务和推荐原因 | planId + planVersion | 无内容、权益不足或内容下线时生成可解释替代，不静默空白 |

#### M1-011 target 与 first-day read projection 的 D2 状态

下列是 B9 first-day read projection 已冻结的 owner 状态，不是页面自行推导的第二套 enum；OpenAPI/事件 schema 已形成静态 D2 契约，真实处理、查询与通知仍为 `NOT_RUNTIME_VERIFIED`。

| projection state | 必备版本/引用 | 页面与恢复约束 |
|---|---|---|
| `NOT_READY` | 缺失的 target/profile/preference 前置和当前已确认版本 | 显示缺失原因与回到 onboarding 的安全动作，不把权限/错误伪装为“无任务”。 |
| `PROCESSING` | `targetId/targetVersion`、`profileVersion`、`preferenceVersion`、IAM eligibility version/digest、planning-input digest、任务或查询 reference | target 已成功但 learning/投影尚未完成；显示任务 ID/回访方式，重复事件不得创建第二份 active plan。 |
| `READY` | 上述 pin，加 `planId/planVersion`、planning rule、content epoch 与 `projectionVersion` | 仅显示 learner owner 返回的投影；`taskCount >= 1`、`tasks` 非空且计数一致；today/task 事实继续由 learning owner 读取。 |
| `DEGRADED` | 已知 pin、稳定 `degradedReason` 和只读 recovery task/reference | 计划、内容或依赖失败后保留已确认 target；提供查询/重放入口，绝不以空任务表示失败。 |

`learner-service` 只拥有 profile/target/preferences 与 first-day read projection；`learning-service` 拥有 planning input、plan/today；`workflow-service` 只拥有恢复任务和协调，不跨域写任何领域表。placement 的 session/report/完成事件保持 M1-012 边界，算法/SRS/mastery 保持 M1-013 边界。

### 3.3 学习/练习 Session

```text
CREATED → IN_PROGRESS ↔ INTERRUPTED → SUBMITTING → COMPLETED
     └──────────────────────────────→ AUTO_SUBMITTED
CREATED / IN_PROGRESS / INTERRUPTED → CANCELLED | EXPIRED
```

Attempt 状态单独为 `ACCEPTED → ASSESSING → ASSESSED`，失败关闭为 `REJECTED`；报告状态单独为 `GENERATING/READY/PARTIAL/FAILED`。上述状态不得借 session 字段互相代替。

| 场景 | 必须保留 | 恢复动作 | 禁止 |
|---|---|---|---|
| 页面刷新/应用切后台 | session、不可变 content/rule pin、session-scoped checkpoint、受保护草稿 | 以 `baseStateVersion/checkpointVersion/clientEventId/clientSeq/checkpointDigest` 从最后确认 checkpoint 恢复 | 重建一套题目、覆盖较新 checkpoint 或丢失答案 |
| checkpoint 重放/冲突 | checkpoint version 与 digest、session stateVersion | 同版本同摘要返回原确认；其他冲突返回 409 和当前安全恢复点 | 静默 last-write-wins、在终态写草稿或因没有 attemptId 而不能恢复 |
| 重复点击提交 | Idempotency-Key、submissionId/submissionDigest、attemptVersion | 同键同摘要返回原结果；同键异摘要返回 409 | 重复判分、重复报告、重复奖励、重复掌握更新 |
| 内容发布新版本 | 当前 session 的旧快照 | 完成本次或安全退出；下次用新版本 | 中途替换答案规则 |
| 内容紧急下线 | checkpoint 和下线原因 | 阻止新开始；在安全策略允许时终止并安排替代 | 继续分发被撤回内容 |
| 网络超时 | 本地已保存标记和请求键 | 查询幂等结果，再重试 | 直接显示“提交失败”并重新创建 attempt |
| 离线作答 | 有序事件队列、base version | 重连按 clientSeq 补传和去重 | 客户端直接更新 mastery/XP |

### 3.4 SRS、错题和延迟验证

| 场景 | owner 事实 | UI 行为 | 恢复/补偿 |
|---|---|---|---|
| 到期队列为空 | learning 查询结果 | 说明今日无到期项并返回今日任务 | 不把查询错误伪装为空 |
| review 已接受 | reviewEvent + 新排程 | 显示下次复习和原因 | 重放同一 reviewEvent 不重复推进 |
| 错题产生 | assessment 的 attempt/错因；learning 的修复投影 | 进入待修复队列 | 事件延迟时显示处理中，不由客户端造错题 |
| D+1/D+7 到期 | learning verification item | 进入独立验证会话 | 错过窗口按规则重排；不自动判通过 |
| 验证失败 | assessment 结果 + learning 状态更新 | 解释降级、回到修复和 SRS | 重复事件不重复降级 |
| 报告延迟 | assessment/report 或只读投影 | 显示正在生成和任务入口 | consumer 重试、DLQ、回放；原 attempt 不回滚 |

### 3.5 内容和后台

```text
草稿 → 校验通过 → 待一审 → 一审通过 → 待二审 → 二审通过
  → 待发布/定时 → 已发布 → 已下线/已归档
  ↘ 驳回 → 修订草稿
已发布 → 新修订版本 → 双审 → 切换；历史版本保持可回放
```

作者、一审、二审和高风险发布必须满足职责分离。状态转换只能由 content owner 按服务端身份和当前版本执行；客户端提交的 actor/role 不是权限事实。发布失败保留已通过审核的版本和 commandId；学习端继续读取最后一个有效已发布版本，除非发生紧急下线。

### 3.6 订单、权益和退款

```text
SKU 可见 → 订单创建 → 等待渠道确认 → 支付已验证 → 权益激活
                                        ↘ 验证失败/待对账
权益激活 → 到期/撤销/退款中 → 已退款或降级
```

- 客户端成功页、未验签回调和渠道“处理中”不能授予权益。
- 同一渠道事件号/JWS 和 Idempotency-Key 必须去重。
- 支付确认成功但权益投影延迟时显示“权益同步中”，由对账/补偿完成，不重复扣款。
- VIP 到期或退款只降级访问权，保留合法学习记录。
- Phase 1 真实支付默认关闭；未过 Gate 时只允许免费、激活码或明确的沙盒路径。

### 3.7 工单、隐私和删除

| 生命周期 | 呈现 | 关键约束 | 恢复 |
|---|---|---|---|
| 工单已提交 | ticketId、分类、SLA 和状态 | 客服只读最小脱敏上下文 | 重复提交按幂等键合并或关联 |
| 处理中 | 责任队列、最近回复、所需补充 | 敏感操作需要二次验证/授权命令 | 超时升级，不静默关闭 |
| 已解决/重开 | 解决说明和证据 | 不能用关闭工单代替领域事实修复 | 允许在规则期内重开 |
| 数据导出 | requestId、范围、处理中 | 导出链接短时、实名二次验证、全程审计 | 失败可重试，不生成重复完整副本 |
| 账号删除 | 冷静期、影响范围、法律保留说明 | IAM 发起，workflow 编排各 owner 删除/匿名化 | 部分失败进入人工恢复；有回执和对账 |

### 3.8 M1-016 通知、同步与客服状态边界

| 领域 | canonical owner | 必须保留的服务端事实 | 冲突/失败处理 | 禁止晋升的状态 |
|---|---|---|---|---|
| 通知 | `notification-service` | preference 的 `category/channel/enabled/locale/consentVersion/dndWindow/frequencyPolicy/version`；message 的 `messageId/sourceEventId/templateKey/templateVersion/dedupeKey/expiry/pin/deliveryStatus`；读回执按 `messageId` | 同一 dedupe key 只产生一个 delivery fact；通道最多 5 次（含首次）后由 workflow 进入 DLQ/人工恢复；不回滚领域事实 | 未验证的 provider 投递、已读、重试成功或 recovery 完成 |
| 同步 | 每个业务实体的 owner service | `clientEventId/clientSeq/baseVersion/contentVersionId/payloadHash`，以及服务端主体/租户/设备绑定和 owner version | 同 hash 重放原结果；异 hash、乱序、gap、stale、future、content pin 不一致返回显式 `CONFLICT`；workflow 只持 recovery task | 客户端 merge attempt/mastery/XP/entitlement、静默 last-write-wins |
| 客服 | `admin-ops-service.support` | `ticketId/stateVersion/messageVersion/assignmentVersion`、七态、七类、脱敏内容引用、SLA history、resolution、retention/legal hold、owner receipt | mutation 必须 `expectedVersion`；未知扫描或 legal hold 为 DENY；关闭前必须 owner reconciliation receipt | 关闭工单等同领域修复、未知法律保全下 purge/完成、后台第二工单事实 |

客服 canonical 状态严格为 `OPEN/ASSIGNED/WAITING_USER/WAITING_INTERNAL/RESOLVED/CLOSED/REOPENED`；B5/B13 的旧状态只能在 adapter 中转换，不得成为第二套状态机。内容引用必须含 `contentRefId + sha256 + redactionVersion + scanStatus + objectVersion + safePreviewRef`，附件必须是 media 授权引用且扫描为 `CLEAN`。客户端不得设置 tenant、subject、role、owner、assignment、SLA、priority、state 或 retention。

## 4. 权限矩阵

| 动作 | 允许角色 | 必检上下文 | 拒绝时 |
|---|---|---|---|
| 读取/修改个人档案 | learner 本人 | subject、owner、tenant、consent | 401/403；不返回空档案 |
| 创建 session、保存 checkpoint、提交本人 attempt | learner 本人 | subject、tenant、adultGate、phase、content rights、entitlement、服务端 resource owner、policyVersion | 默认 DENY；保留 checkpoint，解释权限/内容/权益原因 |
| 读取本人 assessment 报告/错题/SRS | learner 本人 | subject、tenant、服务端 resource owner、phase/content rights/entitlement、policyVersion | 不得按客户端 userId 越权；不得把 401/403 伪装为空报告 |
| 创建/编辑内容草稿 | content-editor | tenant、permission、resource、rights metadata | 403 + decisionId |
| 一审 | reviewer-l1 | permission、版本状态、作者分离 | 冲突时拒绝并记录职责分离原因 |
| 二审 | reviewer-l2 | permission、一审结果、作者/一审分离、版权 | 缺凭证或职责不分离时 fail closed |
| 发布/下线/回滚 | release-operator | 已审核状态、版本、rights、双人确认、reason | 保留 command，不改变现行发布版本 |
| 订单查询/退款 | finance | permission、订单 owner/tenant、二次确认 | 403；不得通过客服角色代办 |
| 工单处理 | support | ticket assignment、最小数据范围、`expectedVersion`、脱敏内容引用 | 脱敏或拒绝无关字段；未知扫描/legal hold fail closed |
| 隐私导出/删除 | privacy + 用户二次验证 | purpose、scope、retention、legal hold | fail closed 并审计原因 |
| 审计导出 | auditor | permission、purpose、字段脱敏、审批 | 不允许广泛裸数据导出 |
| 角色/策略变更 | platform-admin + 高风险审批 | target subject、policyVersion、reason、双人审批 | PDP/撤销不确定时拒绝 |

## 5. 异常分类与统一动作

| 异常类 | 示例 | 是否自动重试 | 用户动作 | 系统动作 |
|---|---|---:|---|---|
| 输入错误 | 字段缺失、格式错误、状态不允许 | 否 | 修正输入 | 返回 400/409/422 稳定 details |
| 身份/权限 | token 过期、撤销、scope 不足 | 仅一次安全 refresh | 登录、返回或申请授权 | 401/403 分离、fail closed、审计 |
| 短暂基础设施 | timeout、502、Kafka 暂不可用 | 读可预算重试；写先查幂等 | 稍后重试/查看任务 | 熔断、Outbox 重发、告警 |
| 业务冲突 | 版本变化、重复提交、租约过期 | 不盲重试 | 查看差异、恢复或重新进入 | 返回当前版本和安全恢复点 |
| 内容/权益不可用 | 下线、版权过期、权益不足 | 否 | 返回目录、选择替代或处理权益 | 阻止分发，保留历史引用 |
| 异步失败 | 转码、报告、通知、删除子任务失败 | 按任务策略；通知最多 5 次含首次 | 查看进度或联系客服 | retry → DLQ → replay → 人工恢复；不修改 owner 事实 |
| 数据一致性 | owner 成功、投影未更新 | 不重做 owner 写入 | 等待同步/刷新 | 对账、补偿、重建投影 |
| 安全/风控 | 重放、异常设备、可疑回调 | 否 | 二次验证或联系客服 | 锁定/拒绝、审计、告警 |

自动重试必须有预算、退避和幂等保证。客户端不得对支付、发布、领奖、删除、提交考试等高风险动作做无条件自动重试。

## 6. Saga、补偿和人工恢复

| 跨域业务 | 正向事实 | 失败后不回滚的事实 | 补偿/恢复 |
|---|---|---|---|
| target → planning input → first-day projection | learner 已确认 target/profile/preference，IAM 已提供服务端聚合 eligibility version/digest，learning 已确认 planning input/plan，learner 已写首日读投影 | 已确认 target 不因下游失败回滚 | `EVENT-GAP-ONB-001` 已按 target/version、eligibility pin 与 input digest 完成幂等消费契约签收；失败创建 workflow recovery task，B9 返回 `PROCESSING` 或 `DEGRADED` 的只读查询/恢复引用，禁止 BFF/客户端跨域补写；运行链路仍待 M2/M4/M8 实证 |
| placement → plan | assessment 已完成结果 | 已提交作答和评分 | 重放完成事件、幂等生成 plan；失败进入恢复任务 |
| attempt → mastery/SRS/report | assessment attempt/result | attempt 和规则评分 | learning/报告消费者重放；不重新判分 |
| learning completion → reward | learning/assessment 可信完成事实 | 学习完成 | gamification 按 sourceEventId 去重补记；不可让客户端补 XP |
| publish → learner projection | content 发布版本 | 审核和发布审计 | 重建缓存/投影；必要时回到上一有效发布版本 |
| payment → entitlement | 已验签支付事实 | 订单和支付流水 | 对账后补发或撤销权益；全程不可变流水 |
| delete account | IAM 删除请求 | 法律要求保留的匿名审计 | 各 owner 返回删除/匿名化回执；部分失败人工恢复 |

每个恢复任务必须有 `taskId`、源业务 ID、当前阶段、重试次数、最后错误、下一动作、owner、审计和关闭证据；task 由 `workflow-service` 持有，领域 owner 只经受控契约重试/对账。关闭 DLQ 或工单不能替代真正的数据对账。

## 7. 离线和同步决策

1. 只允许离线访问已授权、已下载且仍在有效策略内的内容。
2. App 使用受控本地数据库/安全存储；H5/PWA 只保存有限进度，Token 仍遵守存储边界。
3. 学习和其他离线 owner command 统一带 `clientEventId + clientSeq + baseVersion + contentVersionId + payloadHash`，服务端按主体/设备/聚合严格有序去重；旧 `baseCursor`/`entityVersion` 只作历史适配输入。
4. 同 hash 重复请求回放原确认；异 hash、乱序、gap、stale、future 或 content pin 不一致都显示冲突。优先保护已提交 attempt 和已确认 owner 事实；草稿可让用户比较本地/云端；mastery、XP、权益不能由客户端合并。
5. 权限撤销、内容紧急下线和账户删除优先于离线可用性；下次联网必须撤销缓存或阻止继续分发。

## 8. 验收要求

每个核心旅程至少验证：成功、空、加载、错误、离线、权限、恢复、处理中，以及重复请求、超时未知结果、版本冲突和服务端 Gate。验证结果必须能关联到 [08-验收与追溯规范](08-验收与追溯规范.md) 的 `E2E-P1-*` 和真实 Evidence。
