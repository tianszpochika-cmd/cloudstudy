# Phase 1 业务运行验收与追溯规范

> 本文规定业务运行设计如何转成契约、任务和真实验收。文档存在只证明设计被记录，不证明实现或运行完成。

## 1. 完整追溯链

```text
PRD / Feature Matrix / MVP / AC
  → FEAT-* / PRD-ATOM-* / V2-980-*
  → ACT-P1 / JNY-P1 / PAGE-P1 / RULE-P1 / INT-P1
  → ARCH-* + Gateway operationId + Service/Data Owner
  → OpenAPI / AsyncAPI / JSON Schema / migration / policy
  → 前端、服务、worker、配置和测试
  → E2E-P1 场景
  → Browser/API/DB/Outbox/Kafka/Audit/Trace/Recovery Evidence
  → Gate 和发布结论
```

运行层 ID 是连接现有需求与实现的索引，不替代源需求编号。任何新开发任务必须同时引用源需求、运行旅程/页面、架构能力和验收场景。

## 2. 交付成熟度

| 等级 | 名称 | 必须具备 | 不代表 |
|---|---|---|---|
| `D0` | 范围登记 | 来源、阶段、业务域 | 详细设计 |
| `D1` | 运行设计完成 | 旅程、页面、规则、owner、状态、联调和 E2E 定义 | 契约或代码存在 |
| `D2` | Contract Ready | OpenAPI/AsyncAPI/schema/migration/policy 一致，GAP 已关闭 | 服务已运行 |
| `D3` | Implemented | 代码、单测、契约测试和生成物通过 | 真实全栈通过 |
| `D4` | Runtime Verified | Gateway→owner→Outbox→consumer→页面/审计真实证据通过 | 可生产发布 |
| `D5` | Release Ready | 安全、数据、灾备、staging、回滚和 Go/No-Go 通过 | 永久完成或免维护 |

本业务运行设计包的直接目标是 `D1`。文档中存在 `CONTRACT-GAP` 或 `EVENT-GAP` 的项不能进入 `D2`；存在 `IMPLEMENTATION-GAP` 或 `EVIDENCE-GAP` 的项不能宣称 `D3/D4`。

## 3. 任务卡必填字段

```text
Task ID / title / owner
Source: FEAT-* + PRD-ATOM-* + V2-980-*
Operation Design: ACT-P1-* + JNY-P1-* + PAGE-P1-* + RULE-P1-* + INT-P1-*
Architecture: ARCH-* / service owner / data owner
Contract: operationId / event / schema / migration / error codes
Security: subject / tenant / role / permission / resource / owner / phase / rights / consent
State: success / empty / loading / error / offline / permission / recovery / processing
Reliability: Idempotency-Key / clientEventId / outbox / retry / DLQ / compensation / rollback
Verification: unit / contract / integration / browser / data / event / audit / recovery
Evidence path and remaining GAP
```

缺少 Source、Owner、Contract、Security 或 Verification 中任一项的任务不得进入实现。`V2-EXT-*` 未签收项仍不得进入任务。

## 4. Phase 1 核心 E2E 场景

| E2E ID | 场景 | 最小成功链路 | 必测负例/恢复 | 对应 AC |
|---|---|---|---|---|
| `E2E-P1-PUBLIC-ENTRY` | 官网公开入口 | 官网公开投影 → 登录/下载安全深链 | 后端不可用缓存、过期深链、官网无 Token | K、L |
| `E2E-P1-AUTH-LIFECYCLE` | 注册与会话生命周期 | register → login → refresh → device/session → logout/revoke | 错误密码、锁定、重放、撤销、401/403 | A、D、H |
| `E2E-P1-ADULT-CONSENT` | 成人 Gate 与同意 | 登录 → 成人确认 → policy consent → onboarding | 未成年人拒绝、版本更新、拒绝同意 | A、D、H |
| `E2E-P1-FIRST-DAY` | 首日完整路径 | 目标/时长 → placement → 参考结果 → plan/today → 第一任务 | 中断恢复、重复提交、计划生成失败 | A、I、K |
| `E2E-P1-TODAY-SESSION` | 每日任务与断点续学 | today → content snapshot → session/checkpoint → submit → feedback | 内容更新、离线、超时、重复提交 | B、I、K |
| `E2E-P1-SRS` | 词汇 SRS | due queue → active recall → quality → review → nextReviewAt | 空队列、重复 review、积压、版本迁移 | B、I、K |
| `E2E-P1-MISTAKE-MASTERY` | 错题与掌握闭环 | attempt wrong → mistake repair → D+1 → D+7 → mastery/report | 验证失败、事件延迟、报告重建 | B、I、K |
| `E2E-P1-MULTISKILL` | 听说读写与语法 | 发布内容 → 媒体/阅读/录音/草稿 → 规则反馈 → 进度 | 权限拒绝、媒体失败、草稿冲突、无 AI 降级 | B、F、K |
| `E2E-P1-CONTENT-PUBLISH` | 内容双审发布 | draft/rights → L1 → L2 → publish → learner projection | 自审拒绝、版权过期、发布失败、回滚 | C、H、I、K |
| `E2E-P1-REWARD` | 学习结果到奖励 | trusted completion event → ledger → learner view | 重复事件、事件乱序、客户端伪造 | B、I、K |
| `E2E-P1-SOCIAL` | 受控自习室 | room → join/lease → focus → leave → ranking projection | 租约过期、WS/网络断开、受限互动 | F、I、K |
| `E2E-P1-ENTITLEMENT` | 激活码/沙盒权益 | redeem/order → server confirmation → entitlement → content Gate | 重复码、回调重放、退款/到期、生产开关关闭 | D、I、L |
| `E2E-P1-NOTIFICATION-SYNC` | 通知和离线同步 | domain fact → notification/sync → read/recovery | 重复、乱序、冲突、权限撤销 | F、I、K |
| `E2E-P1-SUPPORT` | 客服工单 | learner ticket → admin queue → reply/resolve → learner view | 越权、敏感字段、超时升级、重开 | C、D、H、K |
| `E2E-P1-PRIVACY` | 导出与注销删除 | verified request → workflow → owner receipts → audit | 部分失败、法律保留、恢复/冷静期 | D、H、I、L |
| `E2E-P1-RECOVERY` | Outbox/DLQ/对账恢复 | owner fact → failed delivery → DLQ → replay → projection/audit | 重放不重复记账、人工关闭有证据 | I、K、L |

完整步骤和关联 ID 以端到端旅程台账、联调矩阵和页面登记册为准。

## 5. 每个 E2E 的 Evidence 最小集

| 证据 | 必须证明 | 不可替代 |
|---|---|---|
| UI/Browser | 用户真实可进入、可操作、八态和返回路径正确 | 静态截图不能替代实际点击和网络交互 |
| Gateway/API | operation、JWT/PEP、requestId、错误码和幂等语义 | 直连领域服务不能替代外部链路 |
| Owner DB | 正确 schema 的业务事实、版本和审计字段 | 内存 Repository、localStorage、Mock JSON 不算 |
| Outbox/Kafka | owner 事务 Outbox、canonical event、consumer 去重和状态 | 打印日志或直接调用 consumer 不算 |
| Projection/Notification | 下游最终一致结果与源事实可对账 | 页面常量或手工插入投影不算 |
| Audit/Trace | requestId→traceId→eventId/decisionId→audit 可回放 | 普通日志片段不等于不可变审计 |
| Recovery | 超时、重复、离线、版本冲突、DLQ 或补偿成功 | 只证明 happy path 不算闭环 |
| Rollback | 内容/配置/发布/迁移回滚或安全降级可执行 | 文档声明“可回滚”不算 |

证据必须绑定当前 commit、环境、时间、合成测试身份、命令/操作、预期、实际、关键 ID 和结果。旧提交或缺少侧车文件的汇总只能标历史参考。

测试身份必须是合成账号；manifest 不记录密码、Token、支付凭证、答案密钥、原始音频或未脱敏自由文本。

## 7. 页面验收

每个 `PAGE-P1-*` 至少检查：

1. canonical route、实际路由和深链/returnTo；
2. 一个主 CTA、次要/危险动作和离开策略；
3. 成功、空、加载、错误、离线、权限、恢复、处理中；
4. 401/403、内容/权益/阶段 Gate 和设备权限；
5. 数据来自正式 Gateway API，而非常量、Mock、内存或 localStorage 事实；
6. mobile、learner-web、iPad/PWA 的业务语义一致且 UI 分平台实现；
7. locale fallback、四主题、键盘/读屏、对比度、触控目标和减少动效；
8. Ultra/High/Medium/Performance 降级，以及媒体/图谱/3D 的静态替代；
9. requestId、埋点和退出/恢复可追踪，且不泄漏敏感数据。

## 8. 联调验收

每个 `INT-P1-*` 至少包含一条成功和以下适用的负例：

- 重复请求/事件不重复产生事实；
- 事件延迟、乱序、重复和 consumer 重启；
- owner 成功但 projection/notification/reward 延迟；
- 服务超时、熔断、重试预算耗尽和 DLQ；
- 401、403、跨 tenant/owner、内容权利失效；
- 内容版本、算法版本、策略版本和 base version 冲突；
- 离线队列补传、clientSeq 顺序和本地/云端冲突；
- 人工恢复、对账、回放和审计关闭。

UI 点击、日志和指标不能被当成 Kafka 领域事实。设计事件名与 AsyncAPI/catalog 不一致时必须先关闭 `EVENT-GAP`，不能由各服务自行选择名称。

## 9. 设计评审 Gate

| Gate | 通过条件 | 阻断条件 |
|---|---|---|
| `BD-G1 范围` | 所有旅程属于 Phase 1；来源和阶段明确 | AI/K12/未成年人/未授权内容/未开放支付混入 |
| `BD-G2 业务` | 角色、入口、主链、失败和下一步闭合 | 只有功能列表，没有端到端出口 |
| `BD-G3 页面` | 每个页面有功能点、CTA、八态、权限和跨端映射 | 语义页面没有 route/实现映射或不可达未标 GAP |
| `BD-G4 规则` | 学习、内容、商业和恢复规则确定且版本化 | 客户端自行决定分数、掌握、奖励或权益 |
| `BD-G5 契约` | operationId、owner、事件/analytics 分类和 error 语义明确 | 重复外部入口、客户端 actor/role、事件命名漂移未处理 |
| `BD-G6 验收` | 每条核心旅程绑定 E2E、负例和 Evidence 类型 | 只写“测试通过”或只有静态检查 |

业务运行设计全部通过 `BD-G1..G6` 后，才可以据此推倒旧计划并生成新的依赖任务图。通过设计 Gate 不代表 G0–G4、运行 Gate 或发布 Gate 已通过。

## 10. 生成新开发计划的顺序

```text
关闭范围和业务决策
  → 关闭 CONTRACT-GAP / EVENT-GAP
  → 页面与服务按 owner/依赖拆任务
  → contract/data/security first
  → 实现与最小集成测试
  → 按 INT-P1 联调
  → 按 E2E-P1 做浏览器/数据/事件/恢复验收
  → Evidence 审核
  → 集成、回归和发布 Gate
```

任务计划不得按旧 B 批次或文件目录机械复制；必须按旅程依赖和事实所有权排序。任何任务的“已完成”只在对应成熟度和 Evidence 条件满足后成立。
