# Phase 1 端到端业务旅程台账

> 版本：v1.0<br>
> 状态：**设计与联调基线，不代表代码、运行态或上线已完成**<br>
> 适用范围：Phase 1 的 18 岁以上成人/大学生、四个既定前端项目与目标微服务。<br>
> 上位事实源：[v2-980plus 设计入口](../README.md)、[统一交互与页面状态](../01-统一交互与页面状态设计.md)、[学习闭环设计](../03-Phase1-学习闭环功能设计.md)、[成长/商业/后台设计](../04-Phase1-成长社群商业后台功能设计.md)、[v2 微服务架构](../../../02-architecture/v2-microservices-architecture.md) 与 [`packages/contracts/`](../../../../packages/contracts/)。

本台账把“页面上发生什么”落实为“由哪个服务保存什么事实、通过什么契约推进到下一步”。它是对 v2 设计的可联调细化，**不能覆盖** `AGENTS.md`、v2 设计、架构、ADR 或契约；冲突时按[文档治理](../../../00-vision/document-governance.md)处理。

## 1. 使用规则与标记

| 标记 | 含义 | 交付要求 |
|---|---|---|
| `operationId` | `packages/contracts/openapi/v1/openapi.json` 中已存在的外部或内部操作标识 | 实现必须使用该契约或先走兼容性变更；不得在客户端手写另一套事实。 |
| `CONTRACT-GAP-*` | 当前没有足以完成这一步的 API、事件绑定、owner 或补偿定义 | 是阻塞项；先补 v2 设计、OpenAPI/AsyncAPI、数据 owner 和测试，不得以 mock、前端状态或跨表写入绕过。 |
| `EVENT-GAP-*` | 业务设计提到动作，但事件目录中没有等价、可消费的集成事实 | 先确定是否应是领域事件；若只是 UI 行为，进入 Analytics/埋点而不是 Kafka。 |
| `无（只读）` | 读取投影、公开内容或静态解释页，不产生领域写事实 | 仍需通过 Gateway、阶段/版权/资源 PEP，并区分 401、403、内容下线与空态。 |
| `目标事件` | 事件目录中的 canonical 事件名；其 producer/consumer、topic 与运行证据以[联调矩阵](06-业务联调矩阵.md)为准 | 不能因为目录中有 schema 就声称事件已投递或消费者已上线。 |

`AC-<章节>.<序号>` 是对 [`requirements/acceptance-criteria.md`](../../../../requirements/acceptance-criteria.md) 相应章节第几个验收项的定位别名（例如 `AC-A.3` = A 节第 3 项），不是新造的需求编号。所有外部写操作还必须满足 `ARCH-GW-001`、`ARCH-IAM-001/002`、`ARCH-DATA-001`、`ARCH-EVT-001`、`ARCH-REL-001` 的证据要求。

> **P1R-M1-014 当前源码覆盖规则**：J10/J11 行保留的 `listB4*`、`createB4*`、`finishB4*`、`consumeB12*`、`startB12*`、`renewB12*`、`getB12*` 及 v1 事件名仅用于追溯旧 B4/B12 旅程，不是当前 canonical 实现入口；其中 `CONTRACT-GAP-GAM-001`、`EVENT-GAP-BIND-GAM-001`、`EVENT-GAP-BIND-SOC-001` 已由 M1-014 在 D2 静态契约层闭合，但仍不是 runtime 证据。当前路由和 operationId 以 `packages/contracts/openapi/v1/openapi.json` 中的 `M1014` 操作为准，当前事件以 `config/p1r-gamification-social-contract.v1.json` 与 event catalog 的 v2 清单为准；不得从这些历史行重新实现 v1 producer、consumer 或客户端奖励权威。

> **P1R-M1-015 当前源码覆盖规则**：J12 的 commerce current source 是升级后的 B13 `M1015` OpenAPI、M1-015 commerce v2 event fragment 与 `config/p1r-commerce-contract.v1.json`。B5 与 B13 v1 commerce 只保留 historical input，不能作为新的 producer、consumer、客户端授权或支付入口；B20 的 fixture/static Gate 也不是 runtime 证据。M1-015 只冻结 `D2_CONTRACT_READY / NOT_RUNTIME_VERIFIED`：生产支付、自动续费、live provider、真实凭据、route 与 traffic 仍全部关闭，B20 runtime=`BLOCKED`、B21=`NO-GO`、B26=`pending`。

### 1.1 共同入口与不可变边界

```text
公开访问 → 注册/登录 → 成人 Gate + 同意 → 目标/时长 → 定级 → 首日计划
  → 今日任务 → 内容/练习 → 规则反馈 → SRS/错题/D+1/D+7 → 报告
                                      ├→ 游戏化 / 受控自习室（辅助出口）
                                      └→ 商业权益（服务端校验，不改变学习事实）

Admin：草稿/版权证明 → 校验 → 一审 → 二审 → 发布/下线/回滚 → 学习端只读投影
```

- 外部业务调用统一走 `api-gateway` 的 `/api/v1`；Gateway 预校验不替代服务侧 JWT 验签与 PEP。`admin-ops-service` 只能聚合、发命令和关联审计，不能跨域写内容、学习、订单或权益事实。
- Phase 1 只有成人主体。未成年人、家长/监护、K12、生成式 AI、ASR/AI 发音评分和 RTC 均不进入本台账的可执行路径。成人 Gate 未通过时不得开放学习、权益或儿童替代主体。
- 所有写操作使用 `Idempotency-Key`；离线学习写入还带 `clientEventId`、`clientSeq`、`baseCursor` 或 `baseStateVersion`、`contentVersionId` 和 payload hash。失败重试不得重复建立订单、attempt、奖励、计划、权益或审核结果。
- `content-service` 只拥有内容/版本/题目/答案规则与版权；`assessment-service` 只拥有 attempt、checkpoint、规则判分和报告快照；`learning-service` 只拥有计划、进度、`lrn_srs_state`、复习和掌握度投影；其他服务不得越权改写。
- 表中的“页面”使用 `Official`（`apps/official-site`）、`Mobile`（`apps/mobile`）、`Learner Web`（`apps/learner-web`）和 `Admin`（`apps/admin-web`）。深链只带 `resourceId`、`contentVersionId`、来源和过期策略，绝不带 Token、权益、积分或可写权限。
