## 1. 权威关系与使用规则

本登记册把现行 v2 的业务设计映射到四个实际应用的页面入口。docs/06-design/v2-980plus/ 是当前业务设计唯一事实源；01-统一交互与页面状态设计.md、02-全端信息架构与交互模式.md、03-Phase1-学习闭环功能设计.md、04-Phase1-成长社群商业后台功能设计.md、07-跨域契约数据事件与验收设计.md 和 08-980plus-功能点设计登记册.md 分别提供状态、信息架构、域级流程、平台域和追溯要求。本文件只补充“逐页如何落到当前四端与当前代码”的登记，不重新定义产品范围。

docs/06-design/phase-1/uiux-specs/00_README_设计文档索引.md 与 24_完整UIUX页面地图与交付蓝图.md 已标为 Historical/Superseded。旧图中与当前四应用、Phase 1、IAM、数据 owner 不冲突的交互语义可以作为参考，但旧 route、旧角色、旧 API 和旧页面拆分不能覆盖本登记册。

逐页开发、重构、验收和排期必须引用一个或多个 PAGE-P1-*。任务卡至少同时写明：来源 V2-980-*、FEAT-* 或 PRD-ATOM-*，canonical route，当前实现映射状态，Gateway operationId 或 CONTRACT-GAP，服务/数据 owner，八态 profile，角色与 Gate，持久化/离线策略，跨端对应，AC-P1-* 验收 ID 和真实 Evidence。登记册中的“存在/合并/缺失”只描述当前代码可达性，不是完成状态。

### 1.1 当前实现映射标记

| 标记 | 定义 | 开发含义 |
|---|---|---|
| 存在 | 当前应用已有可达 route/page 或可确认的页面入口 | 仍需按本登记册补契约、状态、权限和运行 Evidence，不能据此宣称完成 |

### 1.2 八态 profile

下表定义所有登记行的“八态”引用。每个页面仍要把本行的数据、CTA 和恢复动作落实到这八种状态；success、empty、loading、error、offline、permission、recovery、processing 不得只用颜色表达。

| Profile | success | empty | loading | error | offline | permission | recovery | processing |
|---|---|---|---|---|---|---|---|---|
| STATE-AUTH | 会话/主体确认，进入原目标 | 无会话或无可用登录方式，给注册/重置出口 | 恢复会话、登录或验证码请求 | 账号、密码、限流或服务失败，保留可重试信息 | 不提交密码，提示恢复网络 | IAM 401/403 或成人 Gate 未通过，转安全入口 | refresh 失败、锁定、重放或返回地址失效时清除坏会话并回安全页 | 登录、注册、重置和撤销按钮幂等禁用，明确等待结果 |
| STATE-LEARN | 事实源、计划或任务可操作 | 没有目标/任务/内容，给创建目标或选课出口 | profile、计划、catalog 或今日流加载 | 可区分内容、服务和数据错误，保留重试 | 使用明确标记的本地草稿/缓存；不能伪造完成 | 阶段、版权、租户或成人权限拒绝，不降级为空列表 | draft/continue/checkpoint 恢复，冲突需用户确认 | 保存目标、完成任务、选课等写操作带幂等键 |

### 1.3 验收 ID 与契约口径

AC-P1-* 是本登记册的页面验收索引，不新增产品功能。其根验收来源保持为 requirements/acceptance-criteria.md：首日闭环用 §A，课程与练习用 §B，内容/后端用 §C，账号/权益/隐私用 §D，质量与安全用 §F，Gateway 用 §G，IAM/RBAC/ABAC 用 §H，服务/数据/事件用 §I，运行验证用 §K，发布用 §L。表中 operationId 只表示当前生成契约中的命名，不表示该 operation 已由 Gateway、服务、数据库和运行证据闭合；页面需要的字段、权限或动作无法由当前契约确定时必须写 CONTRACT-GAP:<具体缺口>。

### 5.2 必须先过的 Gate

1. IAM Gate：密码只提交给 iam-service；只有 IAM 签发 RS256 JWT；Gateway 预校验不能替代领域服务 PEP；401/403 必须可见。
2. Adult/Consent Gate：服务端判定 18+ 和必要同意后才开放学习能力；offline、客户端 role/tenant 字段、旧页面跳转都不能绕过。
3. Contract Gate：页面动作必须有当前 Gateway operationId、参数/响应/error schema、幂等键和 owner；没有就先关闭 CONTRACT-GAP。
4. Content/Version Gate：课程、题目、媒体语义、官方字幕文本、版权和 release version 必须由 content owner 提供；发布同时要求 media owner 的 `READY/CLEAN`、rights 有效、字幕或文本替代满足，后台发布经双审、质量 Gate 和可回滚事实。
5. Practice/Sync Gate：session/checkpoint/SRS/review 事件可恢复、去重、重放；离线只排队允许的事实，不能本地宣称支付、奖励、掌握或审核成功。
6. Cross-end Gate：同一 canonical PAGE ID、session/attempt/content version 和埋点在 learner-web/mobile/iPad/条件编译小程序一致；平台 UI 可以不同。
7. Evidence Gate：页面状态、权限、响应式、locale/theme、性能降级、API、数据库/事件、审计和恢复都要有真实运行 Evidence；“有 Vue 文件/有 operationId”不构成完成。
