# Phase 1 角色、系统边界与业务总图

> 本文定义 Phase 1 系统怎样作为一个整体运作。详细步骤见端到端旅程台账，页面和技术映射分别见页面登记册与业务联调矩阵。

## 1. 产品运行目标

Phase 1 面向 18 岁以上成人与大学生，用确定性规则完成以下闭环：

```text
建立身份与目标
  → 规则化测评
  → 生成计划和今日任务
  → 学习/练习
  → 即时规则反馈
  → SRS 与错题修复
  → 延迟验证和掌握度更新
  → 报告与下一轮计划
```

内容、商业、游戏化、社交、通知和后台运营都只能服务于这个闭环，不能遮挡或伪造学习结果。Phase 1 不启用生成式 AI、ASR/AI 发音评分、RTC、未成年人/K12、家长监护或开放式陌生人社交。

## 2. 参与者与职责

| Actor ID | 角色 | 允许的核心动作 | 明确禁止 |
|---|---|---|---|
| `ACT-P1-VISITOR` | 未登录访客 | 浏览官网、公开课程、价格、下载、公告和合规信息；进入安全登录深链 | 读取个人学习、订单或后台数据；在官网保存业务 Token |
| `ACT-P1-LEARNER` | 已通过成人 Gate 的学习者 | 管理本人目标、学习、作答、复习、报告、设备、权益和隐私请求 | 修改他人数据、分数、掌握度、奖励、权益或后台内容 |
| `ACT-P1-CONTENT-EDITOR` | 内容编辑/教研 | 创建草稿、导入合法内容、维护题目规则和版权信息、提交审核 | 审核自己创建的版本、直接发布或绕过版权校验 |
| `ACT-P1-REVIEWER-L1` | 一审 | 检查内容准确性、来源、格式和教学质量 | 审核自己创建的版本、替代二审发布 |
| `ACT-P1-REVIEWER-L2` | 二审 | 独立检查版权、合规、答案规则、媒体和发布风险 | 与作者或一审为同一责任人时放行高风险内容 |
| `ACT-P1-RELEASE-OPERATOR` | 发布运营 | 对已通过双审的版本执行发布、定时发布、下线和回滚 | 修改内容事实、跳过双审或伪造审核身份 |
| `ACT-P1-FINANCE` | 商业/财务 | 查询订单、处理授权退款/对账、审计渠道异常 | 客户端直接授予权益、修改学习记录或绕过回调验证 |
| `ACT-P1-SUPPORT` | 客服 | 处理工单、查询最小必要脱敏上下文、发起受控恢复命令 | 直接改密码、分数、权益账本或学习事实 |
| `ACT-P1-PRIVACY` | 隐私操作员 | 审核导出/删除请求、处理法律保留例外、查看删除回执 | 浏览与请求无关的个人数据或静默取消删除 |
| `ACT-P1-AUDITOR` | 审计员 | 只读审计、抽查职责分离、追踪高风险操作 | 修改业务事实或清除审计记录 |
| `ACT-P1-PLATFORM-ADMIN` | 平台管理员 | 管理最小必要的平台配置、角色和应急访问 | 用超级角色绕过 tenant、owner、版权、阶段和隐私条件 |
| `ACT-P1-SYSTEM` | 受控系统任务 | 运行 Outbox、通知、调度、补偿、对账和恢复 | 以系统任务身份跨服务直接写表或吞掉失败 |
| `ACT-P1-PAYMENT-CHANNEL` | 沙盒/受控支付渠道 | 提交签名回调、退款/对账结果 | 直接改变客户端权益；生产渠道未过 Gate 时不得启用 |

角色只提供权限集合。每次决策仍必须叠加 `subject + tenant + permission + action + resource + owner + phase + contentRights + deviceTrust + consent + policyVersion`，缺失关键上下文时默认拒绝。

## 3. 四个前端项目的业务边界

| 项目 | 服务对象 | 业务入口 | 退出/衔接 | 不拥有的事实 |
|---|---|---|---|---|
| `apps/official-site` | 访客 | 品牌、公开课程、价格、下载、公告、关于和合规 | 安全深链到统一登录；下载或公开咨询 | Token、个人档案、学习进度、订单详情 |
| `apps/mobile` | 学习者 | Mobile H5、iOS、Android、iPad；后续小程序条件编译 | 今日任务、继续学习、通知、同步和设备能力 | 评分规则、掌握度、奖励和权益账本 |
| `apps/learner-web` | 学习者 | PC Web、平板浏览器和 PWA 工作区 | 今日任务、课程、练习、报告、设置 | 与 mobile 相同；不得另建一套业务状态 |
| `apps/admin-web` | 后台角色 | 内容、审核、运营、商业、客服、治理、审计 | 任务队列、领域命令、审计时间线 | 不直接拥有内容、订单、学习或 IAM 领域事实 |

mobile 与 learner-web 共享业务语义、契约和状态，但页面实现按平台独立。official-site 不承载登录后业务；admin-web 不复用学习者导航。

## 4. 两条相互衔接的系统主链

### 4.1 学习者主链

```text
官网或应用入口
  → IAM 注册/登录/会话
  → 成人 Gate + 同意
  → learner 目标/每日时长/偏好
  → assessment placement 会话、作答和规则结果
  → learning 计划、首日投影和今日任务
  → content 已发布内容 + media 授权资产
  → assessment attempt/checkpoint/规则评分
  → learning 进度/SRS/mastery_projection/错题调度
  → assessment 报告快照 + learning 统计投影
  → gamification/notification/analytics 的可信下游消费
  → 返回今日任务或下一次复习
```

### 4.2 内容与运营主链

```text
Admin 身份和权限
  → 内容/题目/媒体草稿 + 来源和授权凭证
  → 自动校验
  → 一审
  → 二审
  → 发布/定时发布
  → 学习端只读已发布投影
  → 学习、错误、工单和运营指标回流为只读投影
  → 纠错、修订、下线或回滚
  → 全程审计和可恢复任务
```

两条主链只通过版本化 API、事件和只读投影协作。后台不能跨域直接写学习、订单、身份或奖励表；学习端不能直接提交角色、tenant、owner、分数、掌握度、奖励或权益事实。

## 5. 服务与唯一事实所有权

| 事实 | 唯一 owner | 允许的消费者 | 禁止动作 |
|---|---|---|---|
| principal、账号密码、成人 Gate、同意、会话、设备、角色、策略和账号删除请求/主体最终状态 | `iam-service` | Gateway、领域服务 PEP、本人设备管理、workflow | 领域服务签 Token；客户端覆盖角色/tenant；IAM 跨库删除领域事实 |
| 学习目标、每日时长、偏好、学习档案和隐私导出请求/状态/receipt | `learner-service` | learning 编排、学习首页、受控分析、workflow | IAM/admin 直接改 learner 表；导出协调器复制领域原始事实 |
| 内容、课程、题目、答案规则版本、版权、审核和发布状态 | `content-service` | learning、assessment、media、官网公开投影 | assessment 维护题库主表；客户端持有答案密钥 |
| placement/练习/模考会话、attempt、checkpoint、规则评分、错因和报告快照 | `assessment-service` | learning、报告页面、脱敏后台投影 | assessment 直接写 SRS/mastery；客户端提交最终分数 |
| 计划、今日任务、进度、SRS、复习队列和 `mastery_projection` | `learning-service` | 学习端、报告、gamification、notification | 客户端或 assessment 直接修改掌握事实 |
| 媒体元数据、转码、rendition、录音资产和短期授权 URL | `media-service` | content、学习端、assessment | 在日志/事件中传播原始录音或永久 URL |
| XP、Streak、星币、Avatar 和奖励账本 | `gamification-service` | 学习端、脱敏榜单 | 客户端或学习服务直接记账 |
| 自习室、租约、受控互动、举报和榜单投影 | `social-service` | 学习端、治理后台 | 开放陌生人私聊/自由 UGC 进入 Phase 1 |
| SKU、订单、回调、权益、退款和对账 | `commerce-service` | 学习 Gate、本人权益、财务后台 | 客户端成功页授予权益；其他服务写订单表 |
| 通知模板、发送记录和触达偏好 | `notification-service` | 学习端消息中心、受控运营 | 复制领域事实作为永久权威数据 |
| 客服工单、消息、assignment、SLA 和 resolution | `admin-ops-service.support` | 学习端本人、admin-web、notification、workflow | 复制订单/学习/身份事实；客服直接修 owner 表 |
| 后台聚合、命令发起和操作审计关联 | `admin-ops-service` | admin-web | 跨域写领域表或成为内容/订单 owner；support 子域之外新增领域事实 |
| Saga、定时、补偿、DLQ 和人工恢复 | `workflow-service` | 领域服务和后台任务中心 | 直接改其他服务数据库 |
| 安全/管理/导出审计 | `audit-service` 或受控平台模块 | auditor、privacy、合规 | 用普通日志代替不可变审计 |
| 脱敏指标和只读分析模型 | `analytics-service` | Dashboard、产品和运营 | 反向覆盖领域事实 |

## 6. 每个业务动作的统一运行路径

```text
页面或安全深链
  → 登录、成人 Gate、阶段、内容权利与 route 预检
  → Gateway：API 版本、CORS、限流、requestId/traceId、JWT 预校验
  → 服务 PEP：subject/tenant/permission/action/owner/phase/rights/consent
  → 领域服务：业务状态、版本、输入和 Idempotency-Key 校验
  → owner schema 与 Outbox 同事务提交
  → 返回 requestId + 领域结果
  → Kafka 至少一次投递，消费者去重/重试/DLQ/回放
  → 页面、通知、投影、审计和下一业务步骤
```

同步响应只确认本次 owner 事实是否成功。跨域投影、通知、奖励或报告尚未生成时，页面必须显示“处理中/可回访”，不能伪装成全链路已经完成。

## 7. 身份、关联和版本主键

| 上下文 | 必须携带/派生 | 用途 |
|---|---|---|
| 身份 | `subjectId`、服务端派生 `tenantId`、`sessionId`、policy version | 本人资源、权限和会话恢复 |
| 请求 | `requestId`、`traceId`、`Idempotency-Key` | 同步调用追踪和副作用去重 |
| 离线 | `clientEventId`、`clientSeq`、`baseCursor/baseStateVersion`、payload hash | 有序补传、冲突检测和回放 |
| 内容 | `contentId`、`contentVersionId`、question/exercise ID、规则版本 | 结果可解释、内容下线和历史回放 |
| 学习 | `planId`、`taskId`、`sessionId`、`attemptId`、`reviewEventId` | 计划、作答、SRS 和报告关联 |
| 事件 | `eventId`、`schemaVersion`、aggregate ID、occurredAt | 去重、分区、兼容和重放 |
| 管理 | `commandId`、`decisionId`、`auditId`、reason | 高风险命令、职责分离和审计 |

Token、密码、支付凭证、答案密钥和原始音频不得进入 URL、事件、埋点、普通日志或错误详情。

## 8. 业务时间与一致性

- 所有服务事实时间使用 UTC/RFC 3339；页面按用户时区展示。
- “学习日”由 learner 的时区和服务端日界规则派生，客户端本地时间不能直接决定 Streak、D+1/D+7 或权益到期。
- 内容、评分、SRS 和报告都保留解释所需的规则/算法/内容版本。
- 同步写入只保证 owner 事务一致；跨服务使用最终一致性、Saga、补偿和对账，不使用分布式两阶段提交。
- 超时不等于失败。客户端先用幂等键查询或恢复结果，再决定是否重试。

## 9. Phase 1 明确排除

以下能力即使存在枚举、占位代码或旧页面，也不得进入 Phase 1 默认菜单、营销或运行旅程：

- 未成年人、家长、监护、学校/机构和 K12 课程；
- LLM、AI 反馈/评分、ASR、数字人、RTC 和开放式 AI 对话；
- 陌生人私聊、开放自由发帖和不可控 UGC；
- 未经授权的教材、真题、词典释义、媒体或品牌内容；
- 未通过资质、商店、沙盒、退款和对账 Gate 的真实支付；
- 客户端生成角色、tenant、owner、分数、掌握度、奖励或权益。

## 10. 业务闭环完成定义

一个业务旅程只有同时满足以下条件才可称为“运行闭环”：

1. 入口、角色、前置 Gate、页面和下一步明确；
2. 每个副作用动作有唯一 operation、owner、幂等和稳定错误语义；
3. owner 事实、Outbox、事件消费者和投影/通知可沿 ID 回放；
4. 八态、离线、超时、重复、版本冲突和人工恢复均有策略；
5. 页面、API、owner 数据、事件、审计和回滚 Evidence 可相互对账；
6. Phase 1 范围、安全、版权、隐私和真实支付 Gate 未被绕过。

仅有页面、接口、数据库行、事件声明或测试脚本中的任意一项，都不能单独证明旅程完成。
