# 四端 UI/UX 重设计规模估算

> 日期：2026-09-20。以移动提案 03 的冷紫/深紫白字视觉为方向。本文是范围盘点和规划估算，不是新增需求、批准页面拆分或交付承诺，不改变 PAGE/P1R 状态。

> 后续版本说明：当前视觉与交互已迭代至提案 04，但本文 16–22 / 25–40 倍仍以提案 03 的 demo 深度为分母。本轮没有重新计量工作量，不能把新版更丰富的交互直接代入旧倍数。

## 1. 结论与范围

按当前 Phase 1 成人规则化业务，建议规划 **165 个主要界面**，合理合并/拆分区间 **145–186**；分端交互任务组约 **242–318 组**。完成与本次 demo 相近深度的四端可点击设计，约为 **16–22 个本次 demo 的总工作量**；补齐开发交接所需状态和规则后，约 **25–40 倍**。这些是经验估算区间，不是实际计时，不是模型 token/额度预测。

范围：官网、PC/平板浏览器学习 Web、管理 Web、手机学习端；保留提案双主题方向。官网是否最终开放深色开关可单独决定，不能因此机械把官网页面数翻倍。暂不计 Phase 2 AI/RTC、Phase 3 K12、独立 iPad 横屏设计或微信小程序差异。980/540 是设计单元数量，不是页面数量。

## 3. 计数口径

**主要界面**：需要独立安排信息层次和主要操作的屏幕/工作台。明显不同的列表、编辑、详情、结果分别计数；可实现为 route、tab 或同页工作区，本文不强制新增路由。简单详情可以折为弹窗，因此保留区间。数据条目、不同课程、同类词卡、深浅模式都不重复算新页面。

**交互任务组**：有触发、输入/选择、处理、反馈和返回/恢复的用户任务。例如“录音→拒绝授权→解释→重试或退出”归为一个录音权限任务组，“订单超时→查询状态→继续支付或联系客服”归为一个订单恢复任务组。不是按按钮/动效/API 数量统计。表中数字为按业务组自下而上预估的任务量，还不是逐条确认的完整交互清单。

**状态**：正常、空、加载、错误、离线、权限、恢复、处理中属于页面状态。统一组件可复用，业务特有的失败和恢复仍需逐页说明；不得把页面数简单乘 8，再乘 2 套颜色。

## 6. 为什么超过 89 个页面族

- AUTH-REGISTER-RESET 本身覆盖注册与找回密码；COMMERCE 覆盖权益、订单、支付与恢复；ADMIN-CONTENT 覆盖列表、编辑、预览、版本对比和导入。族不是单张画面。
- 个人中心在信息架构和现有 mobile profile 中存在，但登记册没有独立 PAGE-P1-ME 行，需在正式设计对齐时补清映射。这里已计入个人中心，不假装其独立 ID 已存在。
- mobile 的 B3/B11 同技能兼容页应按统一业务体验整合，不按两套产品全部保留；Web alias 同理。
- PC 的资料/消息详情可放侧栏，移动端往往需要完整详情屏，所以规划为 Web 54、移动 60。
- 管理端现在只有 10 个路由，但多个工作台集中承载大量动作。保留宽屏多栏结构，沿用冷紫 Token 与 Element Plus；不能把手机卡片直接放大成后台。

## 7. 与本 demo 的对比方法

本 demo = 10 个主要移动页面 + 约 20 类详情/确认面板 + 两套主题 + 代表性本地可点击流程。六颗星球的文案变化不算六套新交互。25 项自动检查是检查项数量，不是交互数量。账户/权益/安全中的若干面板目前只提供说明，不能按完整业务流程算完成。

页面数量直接比较：165 ÷ 10 = **16.5 倍**。

相同深度设计的粗估：官网 1–1.5 + Web 4.5–6 + 管理 4.5–6.5 + 移动 5–6.5，再加四端组件/导航/主题/走查公共工作 1–1.5，合计 **16–22 倍**。公共工作不是按颜色重复绘制全部页面，而是补足跨端壳、表格/表单、阅读/媒体组件和使用规则。本 demo 已建立的方向和部分页面可继续使用，范围数不代表全部推倒重画。

开发可交接版本在上述基础上增加约 50%–80% 的状态、校验、权限、恢复、内容长度、响应布局和说明工作，粗算 24–39.6，按估算精度表述为 **约 25–40 倍**。不再在这个数后额外机械乘“深浅模式 × 八态”。

这两档都不包含 Vue/uni-app 正式重写、API 联调、真实身份/媒体/支付接入、后端修复、全量自动化或真机验收。此处不把设计倍数误当完整研发倍数，也不按 16–22 倍简单推算 GPT 消耗。

## 8. 建议的设计推进方式

1. 先固定 Token、字号/间距、导航和核心组件；本次主题和移动 10 页作为已建立的起点。
2. 优先补齐移动端“登录与首次设置→学习→复习→报告→我的”主线，再完善六技能、世界和服务。其 60 页完整范围约为本 demo 的 5–6.5 倍同等深度工作量。
3. 将同一学习流程设计为 Web 工作区：阅读双栏、键盘练习、固定媒体播放器、历史与报告对照，不直接等比例放大移动页。
4. 后台先确认内容→审核→发布与客服恢复流程，再扩展商业化、风控与权限；表格/抽屉模板可共享，但审批与危险动作规则独立评审。
5. 官网最后对齐品牌和已确定的产品能力。不要在核心流程未稳定时同时精修四端所有页面。

下一次拆任务应把本清单中合并/拆页选择和交互任务组逐条签收，再估具体批次；本次只做规模统计，没有新增 P1R 开发任务或更改产品阶段 Gate。
