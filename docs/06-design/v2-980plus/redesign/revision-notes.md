## 2. 修订边界与标记

本次依据是用户提供的两份原文和上一轮审核；未读取外部产品蓝图、冻结映射、源码、实际页面或未提供的 ADR。没有外部调研，也不补造法规、供应商接口、费率、时间阈值和实现结果。

- **明确修正**：有原文对照依据的编号错位、标题范围、行数口径冲突。
- **新增设计**：用户已要求优化后补写的行为、状态、文案与验收规则；这些是修改建议形成的设计文本，不冒充原文事实或已完成能力。
- **DEC 待确认**：涉及改变原有批准范围、隐私采集边界、关键参数或跨团队契约的决策；未确认不能由 Agent 自动当作已批准。

主表已直接替换有问题的描述，不是只在文末追加审核意见。原有效 BC/IC 编号和组织均保留，原 `P1/P2/P3`、`B25`、`SM2_Q03_V1`、简审/双签、默认商业 RTC、Tauri/禁 Electron、服务 owner 等关键术语/约束保留；未核验的外部口径另作说明。

## 5. 建议落地顺序

**先修可确定的矛盾，再做主学习链，最后开扩展能力。**

1. 同步两份主文档及编号关系；核对仓库是否已有对应实现；修正误映射和“三表等行数”的测试断言，不删除真实业务记录来凑数。
2. 冻结 DEC-01/02/03/04/05/07/08 中影响基础学习的部分；将输入来源、任务空态原因、幂等与恢复字段对齐现有接口。
3. 用真实可用种子和合法内容，验证注册→定级/快速开始→计划→练习→补救/复习→报告，以及次日仍有内容承接。
4. 对客服、导出、删除补齐真实闭环和获准数据处理策略；未准备好时不以假成功方式对外承诺。
5. 社交/世界/成长、AI/语音、真实支付和原生分项准入；每项按门控、依赖、异常和实际供应商测试单独验收。

**替换方式**：在项目文档目录备份旧版，再将本包的 `business-chains.md` 和 `interaction-chains.md` 同时替换；其余三个文件可一并保存作依据。所有新增逻辑状态先映射现有接口/schema，避免 Agent 按中文说明各自发明不兼容的字段。未提供仓库，本次没有直接修改或测试代码。
