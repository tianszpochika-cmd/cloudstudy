## 1. 阶段重设（P1+P2 融合，开放≠开发）

核心原则：**合规手续没下来之前，代码可以写、门不能开。**
Phase 2 的 AI/实时能力允许在 R1 做隔离设计、在 R2 写代码走 stub，但默认路由保持关闭，
上线（拿证）之后才进 R3 开门。支付、iOS/Android 原生、小程序真机一律沉到 R3 末尾。

| 阶段 | 目标 | 环境 | 开门条件 |
|---|---|---|---|
| **R1 本地闭环** | 12 条业务链在干净库上全通（删库重建→种子→E2E 全绿） | 本机/`127.0.0.1` 固定端口 | 零外部依赖；test 档文书/自证只活在 R1 |
| **R2 联调验收** | 同 12 条链在 test 机上重放全绿 + 证据归档；P2 代码走 stub 合入 | clyunedev test 机 | 第三方一律 sandbox/stub；行级 PASS 归 QA |
| **R3 上线门后** | 支付真通道、iOS/原生、正式文书、公网发布、回滚演练 | staging→生产 | 合规手续 + G0-G4 签字，缺一不开 |

R1 准入：任何条目必须能讲清“触发→落库→读回→恢复”四步，否则退回。
R1 铁律：干净库重放全绿（脏库绿的不算数）；每链至少抽 1 步做 Web/H5 双端读回。
R1 完成定义：干净库重放全绿（脏库绿的不算数，2026-09-28 test 开荒教训）。
R2 完成定义：test 机同版重放 + 证据包 + QA 行级签字。
R3 不在本包展开，只登记入口与前置手续清单。
