# 第二版三端前端改造计划

**状态**：已确认，待执行  
**分支**：`dev`  
**记录日期**：2026-10-11（Asia/Shanghai）  
**来源决策**：用户确认（独立桌面布局 + 全量页面 + 先交付静态三端 demo）

---

## 1. 目标

按第二版移动端静态原型的**全量功能**，改造并最终重写三个正式前端：

| 端 | 正式工程 | 本阶段静态 demo |
|---|---|---|
| 移动端 | `apps/mobile`（uni-app） | `mockups/webDemo/mobile/`（沿用并挂载现有原型） |
| 学员网页端 | `apps/learner-web` | `mockups/webDemo/learner-web/`（新建独立桌面布局） |
| 管理端 | `apps/admin-web` | `mockups/webDemo/admin/`（基于现有薄原型扩展为独立桌面布局） |

**第一交付物（本计划 Phase 1）**：三端均为**静态 HTML/JS 演示**（假数据、不连后端），通过  
`https://learn.clyune.com/webDemo` 与 `https://learn.clyunedev.com/webDemo` 的枢纽页选择进入；**不得破坏**现有学员正式路由。

## 3. 已锁定决策

1. **学员端、管理端独立桌面布局**  
   - 不用「移动端放大 / 简单适配」  
   - 允许侧栏、多栏、表格、宽屏工作区等桌面范式  
   - 视觉 token（品牌紫、语义色）与移动端原型保持同一家族，布局结构各自独立

2. **全量功能与页面**  
   - 不做「先核心再补全」的缩减范围  
   - 移动端原型能演示的能力，三端静态 demo 均应有对应入口与假数据页  
   - P2/P3 入口（AI、语音评分、K12 等）在静态 demo 中保留为可点的边界页（标明范围/未接通），与移动端一致

3. **Phase 1 只交静态 demo**  
   - 不改写 `apps/mobile` / `apps/learner-web` / `apps/admin-web` 的正式实现  
   - 枢纽与静态资源挂在 Nginx，路径前缀 `/webDemo/`，`^~` 优先于现有 `location /` 反代

---

## 4. 分阶段

### Phase 1 — 静态三端 Demo 枢纽（本轮）

- 写出本计划并推送 `origin/dev`
- 保留/挂载移动端静态原型
- 新建学员网页端全量桌面静态 demo
- 扩展管理端全量桌面静态 demo
- 枢纽页 `webDemo/index.html`（明确标注「静态演示 / 假数据」）
- 服务器：`/srv/cloudstudy/static/webDemo` + Nginx `location ^~ /webDemo/`  
  作用于 `learn.clyune.com` 与 `learn.clyunedev.com`
- 冒烟：枢纽与三端入口 HTTP 200

### Phase 2 — 正式前端重写

- 按静态 demo 确认后的设计，重写 `apps/mobile`、`apps/learner-web`、`apps/admin-web`
- 接现有后端主链路；第二版特有交互若缺接口则补契约与实现
- 按端分里程碑上线预发（clyunedev / clyune），再考虑生产

### Phase 3 — 拟真数据 + 浏览器联调验收

- 灌带测试标记的课程/题库/学习记录种子（可一键清理）
- 两类域名 × 网页端/H5 × 全流程 E2E（注册→定级→今日→练习→错题→报告→设置→客服等）
- 缺陷当场修并回归，产出验收报告

## 5. 范围（按端）

### 5.1 移动端静态

- 继续以现有 `mockups/mobile` 为权威交互稿
- 枢纽中以手机框预览方式打开；不在本 Phase 重做视觉

### 5.2 学员网页端静态（新建 · 独立桌面）

覆盖移动端学习侧全量能力，桌面 IA 建议：

| 区域 | 内容（示例） |
|---|---|
| 未登录 | 登录 / 注册 / 重置密码 |
| 入门 | 成人门、同意书、学习目标、定级、测评报告 |
| 主壳 | 顶栏 + 左侧导航（首页、今日、课程、词汇/复习、世界、报告、我的） |
| 学习 | 今日任务、练题、错题本、SRS 复习、刷词、计划生成/解释、补课、完成庆祝 |
| 内容 | 书架、图书、章节、查词/词汇详情、听力、口语、写作、音标/字母、单词本 |
| 成长 | 周报/日回顾、掌握度、成就、联赛、任务奖励 |
| 世界/社交壳 | 世界、装扮、消息、个人空间、小游戏（演示边界） |
| 账户 | 设置、设备、隐私、通知、无障碍、客服工单、关于、演示工具 |
| 商业/扩展边界 | 商城、支付、退款、订阅、离线包、AI/语音/K12 门（标明演示边界） |

### 5.3 管理端静态（扩展 · 独立桌面）

在现有 16 屏基础上做成桌面工作台，覆盖：

- 登录与身份切换（教研 L1/L2、管理员）
- 工作台仪表盘
- 内容：草稿、送审/双签、发布/下架/回滚、媒体
- 治理：风控建档（只读边界）、举报队列（只读）
- 客服：工单列表与详情（接单/回复/关闭/升级）
- 商城：沙盒订单、退款双人审批
- 系统：权限只读、审计检索、观测/发布门
- 我的：身份与退出

对应 BC/IC 以现有 admin DEMO-GUIDE 与业务链为准。

## 7. 明确不在本计划内

- 不宣布「115 卡 / 全功能已完成」；正式前端第二版 UI 尚未落地
- 不改生产域名 `clyune.com` 上与本预发无关的服务身份（本预发机同时服务 clyune / clyunedev）
- 不动 `qida`、`claude-code-router` 等无关容器

- 静态 demo **不**作为业务验收或出站依据；假数据不上榜、不入账、不扣款
- 不在 Phase 1 清空或改写正式应用数据库（静态资源与正式 API 隔离）
