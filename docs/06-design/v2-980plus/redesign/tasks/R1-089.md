## 6. 逐步执行（每步都要留检查记录）

### 步骤 1

沿现有 command adapter 发 CREATE_DRAFT，server-derived author/tenant 与幂等结果读回；保存成功前页面不生成真实记录ID。

- 产物：正式草稿与 commandId/stateVersion读回。
- 检查：响应丢失重试只一条草稿，失败无幽灵列表项。

### 步骤 2

SAVE_DRAFT 使用编辑开始时 stateVersion 和目标版本；server 验证 title/source/license/content hash、版权提案及 item绑定。

- 产物：owner校验后新稿/新revision，输入错误字段定位。
- 检查：禁止修改已发布快照；保护字段修改使旧校验/审核失效。

### 步骤 3

保存失败保留输入；409 显示服务器版本/本地稿差异；只有显式核对后才能基于新 stateVersion 再保存。

- 产物：冲突界面和保留/放弃动作。
- 检查：身份切换清除不应见的资料；不能自动重发覆盖远端。

### 步骤 4

以合成合法来源及 media refs完成下列用例；新增真实供给/版权例外走已有 DEC-08 分支。

- 产物：当前 owner/API/UI 对账与失败证据。
- 检查：无演示一键补齐 READY/CLEAN。

### 步骤 5

提交本卡 diff、契约生成 diff、逐例原始结果、owner 读回及未测项到父任务 evidenceDirectory；请求主 Agent 按卡独立测试并审批。

- 产物：带 source commit/环境/fixture digest/命令退出码/请求ID和证据索引的交付包；主 Agent 审批收据。
