# 移动端前端产品评审（2026-09-30）

> 评审对象：`http://127.0.0.1:18283/mobile/` 静态交互原型，源代码基于 `0444e22945deac78e0e11c73ffc7d83abbc06977`。
> 范围：移动端 UI、交互、静态内容、演示状态与学习业务表达。
> 状态：下文 §1～7 保留评审时点的意见与待执行建议；后续已实施的六能力与五项 P1 修正见 §8。不改动本包已冻结的业务条目、正式任务台账或验收状态。

## 1. 评审结论

**整体交互基线暂不批准冻结。现有原型具备继续完善的基础，下一步应优先修正学习闭环与静态数据的一致性。**

| 维度 | 当前判断 | 依据 |
|---|---|---|
| 视觉基础 | 本轮抽样页面可继续使用 | 打卡箭头已恢复合理尺寸；刷词层级、选项、卡片和底栏可以正常阅读与操作 |
| 核心交互 | 主流程可以走，存在目的地和动作语义错误 | 续读跳错书；今日回顾进入复习；查看与重练合并 |
| 学习业务设计 | 关键表达需修正 | 目标改变没有对应任务变化；错题变式跨知识点；自评直接记为掌握 |
| 功能覆盖 | 入口丰富，部分核心能力只有入口或说明 | 我的页面含 31 个按钮；写作只有空态；阅读缺完成与下一节；复习缺下次安排 |

本轮未通过的主要原因均能在前端静态原型中复现和解决。不以接口尚未接入作为本轮否决理由。页面数量、历史断言通过数量与学习业务设计合格不能互相替代。

## 3. 冻结前应先关闭的缺陷

以下 P1 表示阻碍当前前端交互基线冻结，属于本轮评审优先级。

### REV-M01 / P1：续读卡片与打开的书不一致

**复现：** 最近阅读为“四级词汇红宝书 · 第二章”；只进入“商务口语 100 句”的目录，不打开正文；回首页，卡片仍显示四级第二章；点击继续读，实际进入“商务口语 100 句 · 第二章 邮件”。

原因复核：[原型源码](mockups/mobile/app.js) `resumeChapter()`（第 800 行）读取当前目录的 `BK.cur/ch`，而卡片描述来自另一份最近阅读记录。

**修正方向：** 最近阅读统一以独立的书/章/位置记录驱动；浏览目录不更新最近阅读。首页、今日、我的从同一记录渲染卡片和打开目的地。每本书可以保留各自阅读位置。

**通过条件：** 读 A → 浏览 B 目录 → 任一续读入口仍打开 A 原章节和位置；只有真正打开 B 正文才切换续读记录。

证据：[错误目的地截图](mockups/mobile/evidence/product-review-20260930/resume-opens-wrong-book.jpg)。映射：`PAGE-P1-READING`、`PAGE-P1-COURSE-SHELF`。

### REV-M02 / P1：保存目标与时长，没有相应的任务重排

**复现：** 设置改为“零基础 · A1、每天 5 分钟”，提示“今日起重排”；今日仍是原来的 8 分钟阅读任务。首页解释却变为“词汇 5 + 语法 0”，与实际任务类型和用时不相符。今日说明声称超出部分标顺延，任务卡没有对应标记或可执行的五分钟安排。

原因复核：`doSetGoal()`（第 444 行）只改目标与分钟数并重绘，没有调整演示任务。

**修正方向：** 建立少量确定的目标/预算演示模板，预览变更影响后确认。已完成记录保留；未开始任务根据所选模板替换、拆成小任务或明确顺延。进行中任务明确选择保留或重新安排。首页解释和今日统计从实际模板/任务生成。

**通过条件：** 零基础与四级有不同的示例学习安排；五分钟目标能开始适合预算的小任务；文案、卡片、数量、待学时间和顺延状态一致；刷新后状态保留。

证据：[今日任务仍未改变](mockups/mobile/evidence/product-review-20260930/goal-five-minutes-unchanged-tasks.jpg)、[首页解释冲突](mockups/mobile/evidence/product-review-20260930/home-five-minute-plan-conflict.jpg)。映射：`PAGE-P1-ONB-GOAL`、`PAGE-P1-PLAN-MAP`、`PAGE-P1-TODAY`、`RULE-P1-DAILY-PLAN`。

### REV-M03 / P1：错题变式没有对应原知识点

**复现：** “She ___ to school every day.” 答错进入错题本；点变式再练，得到“There ___ two pens on the desk.”。原题考三单，变式考 there be；该题还混在“There be 句型”题组中。

原因复核：`mkVarQuiz()`（第 177 行）对所有句子错题使用同一 there be 题。批量练习对句子提供“需要变式/我会了”，不构成客观作答验证；该补充项来自源码复核，本轮没有完整操作批量练习。

**修正方向：** 静态数据也需要原题 ID、知识点、错因和关联变式；不同知识点使用不同题包。缺少匹配变式时说明暂无，并提供复看解析或同知识点例题。词汇变式使用真实释义，不把“词汇待补”当释义。

**通过条件：** 三单错题对应三单变式、there be 对应 there be、阅读对应同类理解任务；批量练习从这些题包取题；缺题不能用无关题目替代。题组标题覆盖其实际内容。

证据：[原题与变式不匹配](mockups/mobile/evidence/product-review-20260930/mistake-variant-mismatch.jpg)。映射：`PAGE-P1-PRACTICE-SESSION`、`PAGE-P1-MISTAKES-MASTERY`、`RULE-P1-MISTAKE-REPAIR`。

### REV-M04 / P1：自评或一次答对被表达为已掌握

**复现：** 不做变式，直接在错题列表点“会了 ✓”，待补救 4→3、已掌握 0→1，记录显示“通过：自评会了”。变式也写着“提交（对了记掌握）”。

原因复核：`markDone()`（第 165 行）把自评和变式通过归为同一 `done/已掌握`；结果页同时提醒“完成≠掌握”，表达不一致。

**修正方向：** 区分“自评会了”“本次修复通过”“待延迟验证”“已验证掌握”。自评可影响本轮展示或复习偏好，但不产生掌握证明。原型中可以用明确的日期样例展示 D+1/D+7，未到期不能由普通学习按钮提前完成。

**通过条件：** 自评后显示自评状态与撤销；正确变式后进入待验证；掌握状态按既有学习规则展示；用户能看到后续安排及来源。

证据：[自评直接进入已掌握](mockups/mobile/evidence/product-review-20260930/self-rating-counted-as-mastered.jpg)。依据：[学习规则 §7](../phase1-business-operation/04-学习机制与学习引擎规则.md#7-错题修复d1d7-和掌握度)。映射：`PAGE-P1-MISTAKES-MASTERY`、`RULE-P1-MASTERY`。

### REV-M05 / P1：今日回顾打开的是复习会话

**复现：** 语法 2/3、阅读 2/2，今日两组全部完成；点“查看回顾”，打开 `#/srs`，显示此前“本批 4、处理 5、记得 4、再看 1”的复习总结，没有刚完成的两组结果。今日标题还显示“今日共约 0 分钟”，该值实际是剩余预计时间。

**修正方向：** 今日回顾独立展示当日完成任务、作答/正确数量、本轮新增错题和后续安排。预计安排时间、已完成预计时间、剩余预计时间及真正记录的学习时长分别命名；没有计时事实时只展示预计用时。复习总结继续留在复习入口。

**通过条件：** 当前例子能回顾 2 组、5 道作答、4 道正确及 1 道新增错题；完成后剩余时间为 0，不把今日总时间表达为 0；既能结束学习，也能自愿进入补救。

证据：[今日完成却写共 0 分钟](mockups/mobile/evidence/product-review-20260930/today-complete-zero-minutes.jpg)、[回顾进入复习总结](mockups/mobile/evidence/product-review-20260930/today-recap-opens-srs.jpg)。映射：`PAGE-P1-TODAY`、`PAGE-P1-REPORT`、`RULE-P1-REPORT`。

## 4. 交互与 UI 优化建议

| 建议 | 现场观察 | 改法与验收重点 |
|---|---|---|
| 首页围绕当前唯一主要学习动作 | 续练、开始今日、刷词、错题和阅读分别竞争注意力；新任务也被称作“继续” | 进行中显示继续；未开始显示开始；完成显示回顾/结束。其他学习工具成为次入口，首页先回答今天做什么 |
| 学习入口集中，缩短我的页面 | 我的有 31 个按钮，内容区约 2652px；课程、词汇、复习、音标等工具被放在个人中心 | 保留四个主 Tab 的前提下，学习页承载“今日/课程/词汇/复习”的清楚分区或工具入口；我的集中档案、偏好、账号与帮助。具体分区需要先出一张页面方案 |
| 明确正常学习与能力预览 | 我的可直接切 staff 演示身份；世界有“今日组队 +1”；原型指南却说此类操作集中在 lab | 学习事件驱动组队进度，人工完成/切身份移到演示工具。未来能力保留在明确的原型预览入口，不混淆当前学习任务 |
| 统一所有静态指标来源 | 同一演示状态中测评报告为 A2、我的写 B1；报告语法 100，首页称语法短板；成长显示 220 XP，排行榜自己 0 XP、排在 280 XP 之前 | 静态样例使用同一份档案、报告、任务和成长数据；区分本周 XP 与累计 XP并标注；榜单按其声明的指标排序。快照可以固定，但其内部必须一致 |
| 查看与重练分开 | 已完成卡片写“查看 / 重练”；源码 `enterTask/startGroup` 对已完成任务直接清空题目作答并开新题组 | 查看打开历史结果；重新练习明确新一轮，保留旧结果。此项本轮为代码复核，未重新操作整轮重练 |
| 设置与首访使用同一目标规则 | 首访只有 15/30/45，设置还有 5；首访写一周后可换，设置立即保存；目标选项没有考研/职场 | 按页面登记的四个目标族及 5/15/30/45 对齐；四级/六级作为大学英语目标内选项；变更时间与影响有一致说明 |
| 按内容设计操作布局 | 320px 世界页三个成长按钮变成两行，最后一行只留联赛；听力显露大量材料/语速控件 | 成长用适配文字长度的网格或入口行；字号放大后有统一退化布局；语速与次要模式可收进选择器。不要仅统一给所有段落加 gap |
| 统一筛选与模式的选中表达 | 刷词模式有明确选中标记；其他筛选、主题、材料、语速控件的表达各不相同 | 共用选择控件规则，选中有文字/图形与合适的可访问状态，不能只靠底色；单选、多选、导航和普通动作分别表达 |
| 去掉面向研发的学习文案 | 201、SKIPPED、P2 门、接口未接、版本锁等内部说明出现在学习页面 | 页面说明用户当前能做什么、已保存什么和下一步；保留简短“演示数据”标识。原型实现说明放指南或演示工具；“收/斩”补认识/加入复习的清楚含义 |
| 复习统计区分词数和操作次数 | 本批 4，处理 5 个；包含本轮再次回忆 | 分别展示 4 个学习项、5 次回忆、再次出现次数和本次结果，不混用计数单位；学习项给出下一次安排 |

按钮名称需要帮助用户预测动作，同一功能使用一致名称，可参考 [W3C 对功能标识一致性的说明](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html)和[标签与操作说明](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions)。这些是本轮建议依据，不代表已经完成 WCAG 合规验收。

44px 是当前原型采用的触区目标；[WCAG 2.2 的最小目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)为 24px 或满足其间距/其他例外条件，不能把项目的 44px 扫描结果等同全部 WCAG 通过。

## 5. 功能是否需要更全面

**需要补齐已有学习业务；本轮建议增加的是闭环能力，而不是新的大栏目。** 下列内容均可以先用静态题目、固定规则示例、本机持久化与可点击状态完成设计。

| 顺序 | 补齐/增强的能力 | 最小前端交付 | 现有设计对应 |
|---|---|---|---|
| 1 | 今日回顾与学习记录 | 日回顾、任务结果详情、旧轮次与重练记录、明确结束；周报能下钻到相同记录 | `PAGE-P1-TODAY`、`PAGE-P1-REPORT` |
| 2 | 目标、学习日历与计划调整 | 四目标族示例，5/15/30/45 模板，每周学习日、休息/顺延示例，变更前预览 | `PAGE-P1-ONB-GOAL`、`PAGE-P1-PLAN-MAP`、`RULE-P1-DAILY-PLAN` |
| 3 | 下次复习与延迟验证 | 队列显示来源、待学/待验证状态和下次日期；修复后 D+1/D+7 的待到期/到期/通过/再次出错样例 | `PAGE-P1-SRS`、`PAGE-P1-MISTAKES-MASTERY` |
| 4 | 阅读单元完成路径 | 本节进度、完成本节、下一节、全书章节进度；查词保留原句上下文，收藏有可查询列表；笔记可第二批补 | `PAGE-P1-READING`、`PAGE-P1-COURSE-SHELF` |
| 5 | 写作静态交互 | 一道自有样例题，输入/字数、本机草稿、刷新续写、提交确认、规则检查/参考答案/自评、修改后再看、历史；未知或失败保留草稿 | `PAGE-P1-WRITING`：已在页面登记册中，当前原型仅为空态 |
| 6 | 课程与词汇统一发现入口 | 学习页能发现内容、区分在学/收藏/已完成/暂无内容，按目标/水平筛选；已有听力/口语样例能回到相关课程与学习记录 | `PAGE-P1-COURSE-SHELF`、技能页与 `PAGE-P1-PRACTICE-HUB` |

写作设计依据见 [Phase 1 页面登记册](../phase1-business-operation/03-全端页面功能登记册.md) `PAGE-P1-WRITING`。可以先设计确定性规则、参考答案与自评，遵循 Phase 1 的非生成式 AI 边界；空态继续保留为可切换场景，不把空态当作唯一交付。

本轮不建议继续扩充商城商品、宝箱类型、榜单、AI 人设、视频通话或未成年人入口。现有这些区域已有较多演示入口，先使其与学习事实和阶段说明一致；新增大型能力另列为后续范围。

## 6. 下一轮可执行顺序与审批条件

1. **先关闭 REV-M01～M05。** 每项给最短复现步骤、修复后操作和一张关键证据；先验证变更涉及的状态，再跑现有核心回归，不重建历史 before 矩阵。
2. **再整理首页、学习、我的三页信息架构。** 保留四 Tab；先用一张布局方案确定入口归属、主要动作与字号放大后的排版，再统一组件。
3. **补齐第 5 节的学习能力。** 先回顾/历史、计划/下次验证、阅读，再写作与内容发现；复用现有页面和静态数据，不先扩充页面数量。
4. **按两个角色视角验收。** 新学习者：目标→定级或快速开始→第一项→反馈→回顾；返回学习者：继续原位置→复习/补救→后续安排→完成。测试正常操作与刷新/返回/空态，不把注入渲染视为真实旅程。

审批所需的直观结果：

- 选择目标后，首页解释与今日任务一致；五分钟用户能开始五分钟任务。
- 卡片指向同一书、章、学习项；答错后修复同一知识点。
- 完成、自评、本次修复、延迟验证和掌握有不同状态表达。
- 今日回顾展示刚发生的学习结果；报告、档案与成长示例没有相互冲突。
- 主动作容易找到；已完成能查看历史；重新练习不抹旧结果。
- 390px 与 320px 的关键路径经过实际点击和截图目检；软键盘/读屏/真机继续按明确范围登记，不能据少量桌面截图自动勾选。
