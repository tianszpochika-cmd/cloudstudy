## 2. 内容与发布

1. 小李新建草稿并“补齐并送审”：只生成当前版本的版权/报告/媒体样例。报告绑定版本及审核模式。
2. 双签：小李送审，王芳 L1，赵磊 L2。申请人及编辑人不能自审，L1 不能操作 L2，缺项/过期签核被拒绝。简审允许授权 L1/L2 一人发布样例，不伪造双签。
3. 编辑标题生成新工作版本，使报告及签核失效；旧在架快照保持不变。模式切换只使工作副本重新送审，不重写历史发布事实。
4. 发布管理按版本列出快照。普通下架可恢复仍合格的同版；旧版回滚选择已存在的合格快照。强停、版权失效或媒体/签核不合格版本禁止恢复。下架/强停/回滚二次确认，并保存操作者与恢复点。
5. 发布/下架/回滚分别记录目录同步，约 1.5 秒模拟完成；刷新按原操作恢复并保存。同步不会重新激活强停版本，不证明真实各端已分发。

第二轮新增流程：

- 标题未保存时，另一窗口更新不会覆盖输入。页面对比编辑起点、我的标题与最新版本，先选择采用最新或保留本地，再保存新版本。缓冲按当前窗口身份/稿件隔离；未提交输入不承诺刷新恢复。
- L1/L2 可填写理由后“要求修改”或“驳回”。理由不能为空，决定保留在原版本，生成新草稿并使旧报告/签核失效。作者查看并确认意见，保存整改修改，再补齐材料重送。L2 退回不沿用原 L1 签核。这里演示版本留痕，正式 version/hash/通知回执仍由服务实现。
- 强停先打开指定版本的原因表单，再二次确认；没有原因不能强停。原因、操作者、时间及目标版本保留，刷新可查看。另一窗口改变在架版本后，旧表单禁止确认，须核对新版本再打开；强停版仍禁止普通恢复。

## 3. 客服与其他入口

- hash-only：接单 → 请求补充或指定接收人并填写升级原因 → 待二线接收 → 指定身份确认接收。交接人与原因随事件保存；提交升级不等于接收完成，接收后无正文仍不能回复关闭。
- 有正文：接单 → 输入回复（自动保存草稿）→ 回复并关闭；空白回复拒绝。关闭后保留回复与事件，禁重复关闭或升级。刷新保持所选工单，返回列表状态一致。
- 退款：仅授权运营/财务可第二审批，第一审批人及申请人不能参与；通过后可申请一次样例开票。没有真实退款或开票。
- 治理仅记录线索建档，历史隔离行为是样例，R3 处置未开放。举报只读。
- 工作台从相同本机数据计算当前在架、待审工作版、风险待建档数及授权待办，随动作重算；不是今日新增或线上指标。
- 媒体未接真实对象服务，开关仅模拟进度；切身份/退出/关闭开关/另一窗口更新会取消旧模拟，防止晚回调串写。
- 权限矩阵只读、审计本机留痕；商城对账及观测发布门未接正式证据，不能宣称已对账或可上线。

## 4. 旧缓存与验证

旧 v1 数据缺版本签核，不能自动补造合格发布记录。旧值保留在 `legacyState/legacyEvidence`，工作副本重新送审，所以在架统计可能降低。无接单人的旧“处理中”单保留旧值并转待接单；无正文的虚假关闭单转待补充。无需清空存储。

旧“已升级”记录没有接收人/原因时转“升级信息待补全”，保留旧事件，由原客服重新补齐；不能自动伪造已接收。旧强停缺原因时提示待责任人核对，继续禁止恢复。

存储失败会撤销本次业务状态变化，并提示“操作未保存”；标题、审核理由、升级信息、强停原因及未保存回复保留在当前页面。恢复存储后点“重试本机保存”，再重试未保存的业务操作；重试存储只恢复保存能力，不自动宣布失败的业务已完成。失败时取消的模拟上传保持取消，可重新开始。
