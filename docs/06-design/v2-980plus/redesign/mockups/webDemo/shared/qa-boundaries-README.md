# 本地资源、存储失败与键盘边界独立检查

## 运行与边界

在现有静态服务提供 `http://127.0.0.1:18283/webDemo/` 时，从仓库根目录执行：

```powershell
node docs/06-design/v2-980plus/redesign/mockups/webDemo/shared/qa-boundaries.cjs
```

需要 Playwright 与 Chromium；可用 `DEMO_QA_ORIGIN` 指定同等静态服务源。脚本不启动、停止服务，不读取正式应用或后端文件，不修改业务实现；只在独立浏览器上下文中操作合成数据。原始报告与逐项截图保存到 `.git/codex-local-backups/boundary-qa-<timestamp>/`，不进入正式文件集。

存储失败由浏览器内临时替换 `Storage.prototype.setItem` 抛 `QuotaExceededError` 注入，恢复原方法后再通过真实按钮完成保存。刷新会创建新的原生 Storage 方法，脚本不会把已丢失的故障注入备份写回原型。测试不输出真实凭据、Token 或隐私资料。

## 实际操作

| 检查范围 | 验证动作 |
| --- | --- |
| 两学员端头像冷启动 | 全新上下文直接打开 `#/avatar`，收集资源请求，外部源为 0，存在可操作的本地服装入口 |
| About 三项说明 | 键盘 Enter 打开说明，本地正文可见；Tab 不进入页面背景控件；Escape 关闭并恢复至原触发按钮 |
| About FAQ 与出口 | Enter 开合所有 FAQ；键盘进入客服、设备与模拟安装、合成商城对应路由 |
| 阅读笔记存储失败 | 真实输入后显示未保存，输入仍在；点击完成不新增记录、不改变完成状态、不改已存快照；恢复存储后完成并刷新读回 |
| 写作存储失败 | 草稿输入保留，检查并提交不会进入确认或写入完成记录；恢复后真实确认提交，只新增一次写作记录并刷新读回 |
| 笔记/写作失败后尝试离页 | 返回按钮、原生 hash 变化和显式 render 重绘均留页；编辑器保持同一 DOM 节点与完整输入，完成不写；恢复存储后导航并刷新读回 |
| Hub 两视口 | 实际 Tab→跳到入口→Enter 进入主区；Space 切主题且刷新保留；Tab/Enter 分别打开三端入口 |
| Gallery 两视口 | Space/Enter 操作主题与反馈；键盘筛选、分页；表单错误时焦点定位与合法提交保留输入 |
| Gallery 弹窗与抽屉 | 原生模态保持页面背景不可操作，Escape 或 Enter 关闭后焦点恢复至触发按钮 |
| Gallery 移除操作按钮 | 载入后聚焦 `#empty`，继续 Tab 到完成加载；完成加载聚焦 `#skeleton`，继续 Tab 到详情抽屉按钮 |

原生 dialog 在循环 Tab 时允许焦点短暂进入浏览器自身工具栏，此时页面 `activeElement` 可能为 BODY。脚本不会把这种浏览器行为误报为可操作的页面背景或业务缺陷；关闭与返回触发按钮仍单独硬断言。
