# 完整合成预览工作流

先加载 `preview-data.js`，随后 `preview-workflows.js` 在 `product-overrides.js` 之后、移动或桌面布局脚本之前加载。模块覆盖页面与输入保存/导航辅助函数，不自行 boot/render，不改正式应用、服务、数据库或部署配置。

## 数据与边界

- 所有合成实体、职责和 empty/full 生成器集中在 `preview-data.js` 的 `PreviewWorkflowFixtures`；交互模块深拷贝消费，不修改共享样例。与正式管理端事实分开。
- 持久 key：`demoStorageKey(false) + '-preview-workflows'`，按端、画像、账号以及主引擎已定义的场景隔离。
- 每次变更先保存内存快照，异常则恢复快照并返回 false，不显示成功、不推进下个步骤。输入 DOM 不重绘，保留以供重试。
- 用户输入经 `lh()` 转义。媒体只读取合成文件元信息，不读取或上传字节。语音只用浏览器文本示范，评分是固定合成数据，无麦克风及真实评测。
- 未来阶段有单独明确的“开启合成预览”步骤。关闭停止尚未完成的 AI/语音模拟。K12 仅有虚构角色、原创短文和本机时间预算，无真实未成年人或监护人资料。
- 合成管理登录不会创建真实权限。只有点击管理预览登录后才设置原型 `S.staff`；不同合成角色分别拥有写权限。
- `PreviewWorkflows.state` 返回深拷贝，提供逐页采集；`key`、`roles`、`routes`、`lastError`、`reload()` 可供独立主审核对。`catalog()` 返回发布指针对应的不可变历史 `text/version`，不读取正在编辑的新草稿；强停版本的 `available=false`。与学员课程联动由主引擎集成，不能把此独立模型说成已修改正式目录。

## 空与密集场景接口

主引擎调用 `PreviewWorkflows.scenario('empty'|'full', route)`；24 页均有真实模型。重复调用同一场景与路由保留场景内已经操作的事实；切换路由重新建立该页专属合成输入。调用 `restoreScenario()` 或 `scenario('normal', route)` 恢复正常账号档案，不自行重绘宿主页面。

- 场景持久 key 追加 `-fixture-<mode>-<route>`，不会覆盖正常账号数据；正常账号切换后重新加载自己的档案。场景建立保存失败返回 false，保留先前档案。模块不会因选择场景自动认证管理身份或开启未来能力。
- empty 清空内容、工单、订单、退款、风险、举报、媒体、任务、审计、积分流水、AI 与语音历史；保留建稿、合成工单及订单创建入口。不存在的实体不能执行保存、审核、发布或关闭。字母和原创教材属于固定学习材料，空态清零学习记录、同意与资格，不删除教材，不把空表单替换为通用空壳。
- full 为内容、工单、订单、风险、举报、媒体、任务、审计、积分流水、AI 交互/请求/采纳、语音评分、K12 隔离历史分别生成 30 条具名事实，字母 26 项满进度、拼读已完成。内容同时具备草稿与历史发布快照，用于验证二者不混淆。K12 的历史合成日与当前预算独立，不声称当前一天完成全部历史。
- 登录、权限和未来准入页始终保持原有表单/规则；空或密集输入不是授予真实权限的手段。未来预览仍须主动开启；进入产品学习不启用 AI/K12。

## 主审验收步骤

1. 用编辑建稿 → 送初审 → 换初审 → 填原因初审通过 → 换终审 → 填原因通过 → 发布运营独立发布；反例为作者自批、同一人员终审、空原因、未审发布。
2. 初审退回 → 编辑修改递增版本 → 重送 → 双审 → 发布；核对事件和审计连续、原版本记录保留。
3. 工单接单 → 回复 → 升级（不同授权目标 + 原因）→ 换接收人 → 接收 → 确认解决 → 关闭 → 重开；缺目标/原因、未接收关闭、安全预览不足回复均拒绝。
4. 客服创建退款 → 财务初审 → 不同财务终审 → 注入渠道失败 → 恢复 → 核对资金与权益分别完成；退款申请人不得自批。
5. 合成 AI 全准入 → 提交 → 停止 → 重做 → 完成采纳；超时后不能生成假完成结果。语音失败后没有评分，完成才有固定样例。
6. K12 默认无授权 → 虚构监护确认 → 教师核验 → 开放 → 作答；撤回、版权失效、预算到达均禁止继续，历史保留。
7. 所有事实在刷新后读回；注入 localStorage 写入异常，核对 revision/实体/审计不变且没有成功反馈。

此文档是实现说明，不代替运行验收；主审需对当前代码实际点通后记录通过。

## 未提交编辑输入

正文、AI 输入、审核/发布原因、工单和退款原因以 `事实 key + -drafts` 独立保存，再按路由与真实实体 ID 分区。密码、文件、身份和实体选择字段不保存。输入缓冲不算业务提交；内容必须手动保存当前版本后才能送审。

所有同页重绘、导航、原生 hash 变化、角色切换、关闭未来预览前先保存旧 DOM 归属的 key/route/entity 缓冲；失败保留当前可见输入并拒绝依赖保存的导航（hash 回到旧路由，不重绘），允许恢复存储后重试。刷新保留输入；宿主会清除管理会话，须再次显式合成登录，不自动授予 staff。账号或 fixture 切换重新读各自缓冲，选择与查询上下文清零。
