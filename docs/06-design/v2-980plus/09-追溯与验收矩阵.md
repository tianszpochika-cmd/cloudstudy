## 3. 端到端追溯链

~~~text
PRD / feature-matrix
  → PRD-ATOM-* 或 FEAT-*
  → V2-980-* scope registry row
  → 域级设计文档 + 统一交互模板
  → ACT-P1 参与者 + JNY-P1 旅程 + PAGE-P1 页面 + RULE-P1 规则
  → INT-P1 联调 + route/page state + API contract + data owner
  → event/audit/analytics + failure/recovery
  → E2E-P1 + acceptance criteria + unit/integration/runtime evidence
~~~

登记册中的来源主键必须能回到 requirements/product-requirements.md 或 requirements/feature-matrix.md。设计文档锚点必须回到本目录；Phase 1 的业务旅程、页面、学习/后台规则、联调和恢复还必须回到 [业务运行设计包](phase1-business-operation/README.md)，执行任务必须回到 [Phase 1 开发计划重基线](../../../requirements/backlog/v2-phase1-rebaseline/README.md) 的 `P1R-*`。契约和数据列必须指向唯一事实源；新任务同时以 V2 ID 和相应运行层 ID 作为关联标签。追溯链完整只证明登记行可定位，不证明该行已完成实现。

## 4. 每个设计单元的验收门

| 门 | 必检内容 | Evidence 示例 |
|---|---|---|
| 产品门 | PRD 行、用户故事、目标、优先级、阶段和独立验收 | 需求链接、评审记录、原型/交互稿 |
| 交互门 | 入口、主 CTA、正常流程、八态、退出/恢复、响应式 | 页面录屏、视觉检查、真实设备操作 |
| 契约门 | OpenAPI、请求/响应、错误码、幂等、分页、版本 | packages/contracts、API 测试 |
| 数据门 | 唯一 owner、迁移、索引、审计、保留和脱敏 | migration、数据字典、回放查询 |
| 安全门 | RBAC、tenant、owner、阶段/内容权利、设备权限 | 403/401/跨租户测试、审计记录 |
| 质量门 | 单测、集成、E2E、离线/弱网、性能档和无障碍 | CI、设备矩阵、性能报告 |
| 阶段门 | Phase 1 无 AI；Phase 2 AI Gate；Phase 3 K12 Gate | Gate 配置、审计和回滚证据 |

## 5. 统计声明

本矩阵验证的是本目录已生成的 980 条范围登记行：930 个业务域设计单元与 50 个跨域扩展登记位。它不把 2342 条 PRD 原子候选直接当成功能数，也不把 980 条登记行当成 980 份可实施详细设计；待细化签收的 `V2-EXT-*` 登记位不得当成可实施功能。v2 逐条细化签收后，必须同步回写 feature-matrix.md、WBS、contracts、测试台账和 CHANGELOG。
