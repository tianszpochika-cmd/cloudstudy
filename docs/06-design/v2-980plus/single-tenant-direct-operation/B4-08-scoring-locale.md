## 2. 设计取舍

1. **NFD 而非 NFKD**：NFKD 会把 `œ→oe`、`ﬁ→fi`、`²→2` 一并折叠——对听写友好但改变面太宽（且“相容折叠”在评分语境下有争议，如 `²` 与 `2` 是否同分）。规划只要求重音折叠 + `ß→ss`，按规划字面落地；`cœur` 误拼 `coeur` 仍判错，属已知保守行为（B4-10 全量回归时若有教研反馈再议，不静默扩大）。
2. **排序：`utf8mb4_unicode_ci` 德语已知偏差（文档，不换 collation）**：
   - 现状：全库 `utf8mb4_unicode_ci`（通用 Unicode 排序，非德语电话簿序）。已知偏差：`ß` 在通用排序中按 `ß` 本字排（电话簿序要求视同 `ss`），变音 `ä/ö/ü` 按基字 + 变音权重排（电话簿序要求 `ä→ae`、`ö→oe`、`ü→ue` 展开排），且大小写/重音权重与德语词典序不完全一致。
   - 决定：不换 collation。理由：① 排序只影响列表/词表展示顺序，不影响判分正确性（判分走本任务归一化）；② 换 `utf8mb4_de_pb_0900_ai_ci` 是全库级变更，需停机重建索引与全量回归，超出 B4 范围；③ 当前德语数据量（5 词）无实际展示问题。
   - 跟踪：德语全量批次若词表展示顺序被教研接受为问题，另立项做 per-column collation（仅影响新列索引，不动既有列）。
