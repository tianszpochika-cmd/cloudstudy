# 3D Avatar 渲染技术方案（Avatar Studio / Wardrobe / 学习空间）

> **状态：Historical / Superseded（当前范围）**。本文件仅保留旧视觉资产和性能降级方案的审计参考，不能作为 Phase 1/P0 的交付、契约或实现依据。当前游戏化 P0 仅为“拼句小火车”；P1 经验收后累计最多四款，3D Avatar、衣柜和星球探索属于后续另行立项的候选能力。范围以 [ADR-0007](../10-decisions/0007-phase1-scope-and-development-governance.md) 为准，前端宿主以 [ADR-0008](../10-decisions/0008-four-frontend-projects-and-platform-targets.md) 为准。

> 需求溯源：PRD v3.3 §16.4 Avatar Studio（3D 半写实个性化人物）、§16.5 Wardrobe、§16.6 品质等级、§16.12 成员资料卡、§18.1 个人中心。
> 依赖主线（历史）：Vue 3 + uni-app（现行项目矩阵见 ADR-0008）、四级画质引擎（cross-platform-and-performance-adaptive.md）。

## 1. 历史方案摘要（非当前承诺）

- 曾设想 3D 风格化半写实人物、预设脸型/体型/发型组合及外观编辑。
- 曾设想 Wardrobe 装扮体系和品质分级。
- 如未来重新立项，必须先通过范围 Gate；当时的性能降级思路可作为参考，且不能阻塞核心学习链路。

## 2. 技术选型

| 项 | 选型 | 说明 |
| :--- | :--- | :--- |
| 渲染引擎 | **Three.js**（web-view 承载） | Three.js 经 web-view/renderjs 在 App 与 H5 均可运行，并可独立于学习页面降级 |
| 模型格式 | glTF 2.0 + **Draco 压缩** | 人物基体 + 装扮部件模块化挂载（骨骼插槽） |
| 承载方式 | App/H5：`web-view` 独立渲染页 + postMessage 通信 | 与主页面解耦，崩溃/卡顿不影响学习链路；小程序端（P1.5）条件编译降级为快照 |
| 快照降级 | 服务端预渲染 + CDN | 人物配置 → 离屏渲染服务生成多姿态/多光照快照图（PNG/WebP），低配机与 H5 直接展示 |
| 状态管理 | Pinia（人物配置 JSON）+ contracts 类型 | 装扮配置为纯数据，渲染层消费同一契约 |

## 3. 平台适配矩阵

| 平台 | 方案 | 画质上限 |
| :--- | :--- | :--- |
| Android/iOS App（高性能） | web-view 实时 3D，实时光影 + 骨骼待机动画 | Ultra/High |
| Android/iOS App（普通） | 实时 3D：关阴影/降面数/关后期 | Medium |
| H5 / Web | 实时 3D 可选；默认快照 + 轻量 CSS 视差 | Medium（可手动开 3D） |
| 低配设备 | **预渲染快照**（多角度静态图 + 切换动效） | Performance |
| 微信小程序（P1.5） | 快照方案（不做实时 3D） | Performance |

判定流程：首启 Benchmark（画质引擎）→ 输出档位 → Avatar 模块读档位选"实时 3D / 降级 3D / 快照"三态；用户可在设置中手动覆盖。

## 4. 快照生成方案（关键降级路径）

1. **生成时机**：用户保存人物配置时，后端异步任务（job-runner）触发离屏渲染（专用渲染 Worker 或云函数），生成 4 姿态 × 2 光照 = 8 张快照。
2. **存储分发**：OSS + CDN，路径含配置版本哈希（`avatar/{userId}/{configHash}/pose_1.webp`），配置变更即失效重生成。
3. **兜底**：快照未就绪时显示 2D 预设头像（PRD §17.3 系统头像），不阻塞任何页面。

## 5. 性能预算

| 指标 | 目标 |
| :--- | :--- |
| 人物模型总面数 | ≤ 30k 三角面（含当前装扮） |
| 装扮部件单件 | ≤ 3k 三角面，贴图 ≤ 1024² |
| web-view 内存 | ≤ 150MB，超限自动切快照 |
| 实时渲染帧率 | 目标 30fps（High+），低于 24fps 持续 3s 自动降档 |
| 快照加载 | ≤ 200KB/张，首图 < 1s（CDN） |

## 6. 与四级画质引擎的映射

| 画质档 | Avatar 表现 |
| :--- | :--- |
| Ultra | 实时 3D + 柔和阴影 + 环境光遮蔽近似 + 待机骨骼动画 |
| High | 实时 3D（关 AO、降采样阴影） |
| Medium | 降级 3D（无阴影、单光源）或高分辨率快照 + 呼吸动效 |
| Performance | 纯快照静态图（0 GPU 常驻负载） |

## 7. 页面使用约束（落实 PRD §16.4）

- 3D 常驻页面仅限：**我的（个人中心）、学习室、奖励页、学习空间**；学习答题页面一律用快照/头像。
- 页面离开即销毁 web-view 渲染上下文（uni-app `onUnload`），杜绝后台驻留耗电。
- 学习室成员列表（§16.12）统一用快照缩略图，不逐个起 3D 实例。

## 8. 里程碑拆分建议

1. **M1**：快照链路先行（配置 → 离屏渲染 → CDN → 展示），保证全端可用；
2. **M2**：App 端 web-view 实时 3D + 装扮插槽系统；
3. **M3**：画质联动、待机动画、场景装扮合成。

> M1 快照方案即可满足 PRD 对 H5/低配的验收要求，实时 3D 为增强项，避免阻塞主链路。
