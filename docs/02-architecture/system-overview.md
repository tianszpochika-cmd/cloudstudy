# 系统架构总览

## 设计原则

- Phase 1 先完成 18+ 成人的规则化学习闭环，不以 AI 或多端数量替代学习质量。
- 多端共享领域模型、OpenAPI 契约、设计令牌和埋点，不强制共享所有 UI。
- 核心学习、权益和内容数据进入 MySQL；媒体进入对象存储；Redis 不作为唯一事实源。
- 生成式 AI 和实时语音均为 Phase 2 独立能力，不影响 Phase 1 可用性。
- 异步任务可重试、可观测、可取消，并且具备幂等键。

## 逻辑拓扑

客户端层：uni-app 学习端（Web/H5/App/iPad）、官网、管理后台、小程序 P1.5。

接入层：CDN、WAF、API 网关、鉴权、速率限制和 requestId。

业务层：Spring Boot Core API 的账户、课程、学习、练习、复习、权益、订单、内容、客服和运营模块。

任务层：内容、通知、分析和通用异步任务 Worker。

数据层：MySQL、Redis、对象存储、CDN 和分析仓库。

Phase 2 智能层：FastAPI AI 编排、商业 RTC、评测和内容安全服务。

## 运行策略

Phase 1 使用模块化单体 Core API 加独立 Worker，先降低部署和排障成本。AI、实时语音和向量检索不在 Phase 1 启动。

## 关键请求流

### 今日学习

客户端 -> Core API -> 读取用户目标和课程进度 -> 规则生成今日任务 -> 返回任务链 -> 记录开始和完成事件。

### 练习与复习

客户端 -> Core API -> 校验内容版本 -> 规则评分 -> 写入练习记录 -> SRS 调度下次复习 -> 更新报告和待办。

### Phase 2 AI 反馈

客户端 -> Core API -> 保存原始答案 -> AI 编排读取受限课程上下文 -> 返回结构化反馈 -> Core API 写入反馈和复习项。该链路不在 Phase 1 启用。
