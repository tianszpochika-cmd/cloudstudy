# 04｜做题判分与多端题型交互域详细设计 (Assessment & Interactive Question Domain)

> **设计基线**：PRD v3.3 第 15、16、24、38 章  
> **所属业务域**：com.englishflow.modules.assessment  
> **目标服务承载**：`assessment-service` + `learning-service`；外部请求经 `api-gateway`，判分和作答事实由服务端拥有。  
> **迁移兼容**：`services/core-api`，仅作为 v1 兼容承载。  
> **面向端**：apps/learner-web (Vue 3 + Vite), apps/mobile (Vue 3 + uni-app)
> **状态**：Historical / transition reference。下文旧 PRD 的题型数量、考试名称、时长和交互草案仅作迁移审计，不是当前功能、内容或契约承诺。

---

## 1. 业务目标与阶段边界

本域负责做题交互全流程驱动，涵盖**多端题型组件库渲染、轻量本地即时预判、服务端防作弊权威判分、试卷/阶段模考 (Checkpoint) 与能力定级报告**。

- **Phase 1 (确定性规则交互引擎)**：
  - 覆盖 8 大核心经典题型交互组件（单选/多选/完形、拼写键入、图文连线、句子成分拖拽排序、听音选图、长难句结构切片选择、段落配对）。
  - 双重判分防作弊机制：前端仅做交互反馈预判，后端进行权威标准答案比对、得分计算与错题归因。
  - 当前可做阶段性规则化测评、计时与报告；涉及四六级/考研等考试名称、真题或统计资料时，必须使用自有/授权内容，并不得暗示官方考试或认证。
- **Phase 2 (多模态与 AI 主观题引擎)**：
  - 引入流式语音发音打分 (Pronunciation Assessment - 准确度/流利度/完整度/音素级音标纠错)。
  - 引入英语作文多维度智能批改 (Grammar / Lexical / Cohesion / Task Achievement)。
- **Phase 3 (中高考与考场级防作弊)**：
  - 引入 K12 中高考模拟考场、防切屏强锁、答题卡涂卡交互与学校班级联考排名。

## 2. 完整功能树与子功能矩阵

```text

│   ├── 字母拼写与盲打组件 (SpellingBox: 物理键盘/虚拟键盘输入、格状光标自动推进、撤销)

│   └── 篇章精读与完形填空 (PassageReading: 左文右题双栏响应式分屏、行号高亮联动)
├── 2. 做题状态机与会话管理 (Assessment Session State Machine)
│   ├── 会话创建 (生成 session_id，注入题目序列，锁定有效答题倒计时)
│   ├── 答案暂存与心跳同步 (本地 IndexDB/SQLite 缓存防断网丢失，后台静默重试)
│   ├── 作弊监控防线 (切屏次数计数器、作答时间合理性阈值异常过滤)
│   └── 交卷结算与事务锁 (原子写入作答记录、结算分数与经验点 XP、更新错题库)
├── 3. 权威判分引擎 (Server-side Grading Engine)
│   ├── 客观题规则正则精准比对 (大小写归一化、标点符号容错规则、缩写同义容差)
│   ├── 连线与排序拓扑序比对算法
│   └── 错因归类与标签自动衍生
└── 4. 阶段 Checkpoint 模考与报告 (Mock Exam & Diagnostic Report)
    ├── 模考全真试卷组卷 (四六级/考研/期末全真配比)
    ├── 考场全真仿真环境 (全局倒计时警告、答题卡浮窗快速定位导航)
    └── 诊断报告生成器 (综合得分、全站排位百分比、薄弱语法点雷达图、靶向提升建议)
```

## 3. 详细交互流程 (UX Flow)

### 3.1 互动拼写题 (Spelling Box) 交互体验
1. **题干渲染**：界面展示中文释义、例句挖空位置、标准发音播放按钮，下方呈现对应字母长度的输入格格子。
2. **输入响应**：
   - 桌面端：支持物理键盘输入，按 Backspace 自动回退，按 Enter 提交。
   - 移动端：调起定制字母键盘（去除无用符号，增大键帽面积）。
3. **即时动态提示**：
   - 若用户卡顿超 8 秒：可点击“灯泡”提示，消耗 1 点脑力值或观看解析，给出首字母或音标提示。
4. **提交与动效**：
   - 正确：全格子闪烁绿光，字母向上跳跃动效，自动播放标准原声并切题。
   - 错误：格子整体摇晃震动，展示红色错误字母并划掉，给出标准拼写与音节划分拆解。

### 3.2 阶段 Checkpoint 模考流程
```text
[学员进入模考大厅] ──► 选择：2024 CET-4 强化模拟卷
    │
    ▼
[创建模考会话 Session] ──► 锁定 120 分钟倒计时，初始化答题卡
    │
    ▼
[答题进行中] ──► 答题卡实时标记（已作答: 蓝 / 未作答: 灰 / 标记疑问: 黄）
    │             ├── 切屏离开检测：提示“请勿切出考场，累计 3 次将强制交卷”
    │             └── 自动定期保存草稿
    ▼
[倒计时归零 / 手动交卷] ──► 触发交卷确认弹窗（检查是否有未做题目）
    │
    ▼
[服务端权威结算] ──► 计算得分、扣除错题、触发 XP 经验与段位计算
    │
    ▼
[生成全真诊断报告] ──► 呈现六维雷达图、CEFR 等级预测、错题一键加入复习流
```

## 4. 数据实体与核心字段设计 (Data Schema)

| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |

### 4.2 作答流水明细表 (asm_answer_record)
| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | BIGINT UNSIGNED | PK, 自增 | 主键 |
| session_id | BIGINT UNSIGNED | FK, 非空 | 关联 asm_assessment_session.id |
| question_id | BIGINT UNSIGNED | FK, 非空 | 关联 cnt_question.id |

> `CREATE INDEX idx_user_incorrect ON asm_answer_record (user_id, is_correct, created_at);`

## 5. 接口契约规范 (API Contracts)

- `POST /api/v1/assessment/session/start`：开启一场新测试或模考，返回试卷题目清单（屏蔽标准答案）与会话 Token。
- `POST /api/v1/assessment/session/answer-item`：单题答题心跳保存（支持断点续答与暂存）。
- `POST /api/v1/assessment/session/submit`：正式交卷，触发批量判分与防作弊校验，返回最终诊断结论。
- `GET  /api/v1/assessment/report/{sessionUuid}`：获取指定测验的详细诊断报告（含各维度得分、错题解析、改进建议）。
