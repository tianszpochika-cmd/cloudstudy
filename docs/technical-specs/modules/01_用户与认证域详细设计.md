# 01｜用户画像、认证与未成年人合规域 (User & Auth Domain)

> **设计基线**：PRD v3.3 第 17、39 章  
> **所属业务域**：com.englishflow.modules.auth & com.englishflow.modules.user  
> **目标服务承载**：`iam-service`（身份、租户、设备、会话、RBAC/ABAC）+ `learner-service`（学习档案/偏好）；外部请求经 `api-gateway`。  
> **迁移兼容**：`services/core-api`，仅作为 v1 兼容承载。
> **认证基线（2026-08-28）**：新 v2 方案以 [ADR-0013](../../10-decisions/0013-self-owned-jwt-authentication-center.md) 为准：`iam-service` 校验平台账号密码，直接签发短时非对称 JWT Bearer Access Token 并发布 JWKS；Refresh Token 由 IAM 会话边界轮换和撤销；四端不保留认证回调流程。
> **状态**：Historical / transition reference。下文保留旧 PRD 的产品细节和数据草案，不能作为新任务、认证契约或实现依据；认证与会话的当前基线只以 ADR-0013、ADR-0012 和 `AGENTS.md` 为准。

---

## 1. 业务目标与价值
构建覆盖多端（App/H5/Web/小程序）的统一用户与账户中心。
- **当前 Phase 1 覆盖**：仅面向 18+ 成人与大学生的自有账号密码公开注册/登录、多设备会话、学习档案与偏好；年龄 Gate 由服务端判定，不在本文声称已具备独立实名能力或外部快捷登录。
- **Phase 2**：引入 AI 学习人格画像、职场/留学定制档案。
- **Phase 3**：引入未成年人身份证校验、家长锁与监护人绑定机制。

## 2. 核心功能拆解与子功能矩阵

用户与认证域 (User & Auth)
├── 1. 多端认证与登录
│   ├── 自有账号密码登录/注册与密码重置
│   ├── IAM 在 Phase 1 签发 RS256 JWT Access Token 并发布 RSA JWKS
│   ├── 设备会话、Refresh Token 轮换、重放检测、撤销与登出
│   └── 不使用外部身份提供方、授权码、PKCE、state/nonce 或 URL Token
├── 2. 会话与多设备管理
│   ├── IAM 签发的 JWT Bearer Access Token + 轮换 Refresh Token
│   ├── Gateway 与领域服务独立 JWKS 验签和服务侧 PEP
│   ├── 多端设备指纹采集与设备列表
│   └── 异地登录告警与单端/多端踢出下线
├── 3. 学员画像与学习档案
│   ├── 基础信息 (昵称、头像、性别、生日、所在地)
│   ├── 语言水平基线 (CEFR A1-C2 / 四六级 / 雅思预估分)
│   ├── 每日学习目标设定 (5/15/30/45分钟，目标掌握词汇量)
│   └── 学习偏好与无障碍设置 (音效开关、发音偏好 美音/英音)
└── 4. 合规与未成年人保护 (Phase 3 预留字段)
    ├── 实名认证与年龄鉴权拦截 (18+ 准入)
    ├── 未成年人家长锁密码与使用时长限制
    └── 账户注销与个人数据脱敏导出

## 3. 详细交互流程 (UX Flow)

### 3.1 自有账号密码 + JWT Bearer 登录流程
1. **客户端发起**：learner-web、admin-web、mobile 在自有登录页提交账号、密码和设备信息到 IAM；official-site 只生成 allow-list 登录链接。
2. **IAM 校验**：IAM 对账号查找、限流、失败计数和 Argon2id/BCrypt 哈希校验；角色、tenant、owner、permission 均由服务端事实生成。
3. **建立会话**：IAM 创建设备会话，在 Phase 1 签发短时 RS256 JWT Access Token，并通过 HttpOnly Cookie（Web）或 Keychain/Keystore 适配器（移动端）交付 Refresh Token。ES256 只能在新增 ADR、同步更新契约与 JWKS key schema、密钥管理和运行实现并通过验证后扩展。
4. **访问与刷新**：请求只使用 `Authorization: Bearer <accessToken>`；`aud=yuxuexing-api`。Refresh Token 每次轮换，重放、过期、撤销或设备失效均拒绝并撤销 token family。
5. **恢复与注销**：Gateway 和每个领域服务独立通过 IAM JWKS 验签并执行 PEP；401 只触发一次受控刷新，失败回到登录入口；注销撤销服务端会话并清除 Cookie。

### 3.2 首次进入水平测评与画像定制交互
1. **引导页**：展示 3 选 1 目标卡片（A. 零基础入门 / B. 大学四六级与日常口语 / C. 职场进阶与雅思托福）。
2. **5 分钟快速定级**：使用 `P1_PLACEMENT_V1` 的 10 道规则化题目（词汇 3、基础语法 3、阅读 2、听力 2）；该文件不再维护另一套题量或评分口径。
3. **生成定制计划**：计算初始 CEFR 等级，生成初始星图地图与每日任务队列。

## 4. 数据实体与核心字段设计 (Data Schema)

### 4.1 用户主表 (usr_user)
| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |

## 5. 接口契约规范 (API Contracts)
- POST /api/v1/auth/register：创建账号并建立服务端 principal
- POST /api/v1/auth/login：账号密码校验并签发 JWT/Refresh 会话
- POST /api/v1/auth/token/refresh：轮换 Refresh Token
- POST /api/v1/auth/logout：撤销当前会话并清除 Cookie
- POST /api/v1/auth/password-reset/request：创建一次性重置流程
- POST /api/v1/auth/password-reset/confirm：消费重置凭证并撤销旧会话
- GET  /api/v1/auth/jwks：读取认证中心公钥集合
- GET  /api/v1/user/profile：获取当前学员画像与学习目标
- PUT  /api/v1/user/profile：更新学员昵称、头像、每日学习目标与偏好
- GET  /api/v1/user/devices：获取多端在线设备列表
- POST /api/v1/user/devices/kickout：强制踢出指定设备
