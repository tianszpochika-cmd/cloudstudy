# ADR-0001：模块化单体优先

## 状态

accepted

## 背景

项目处于产品验证期，团队和流量都未知。过早拆分微服务会增加部署、数据一致性、观测和排障成本。

## 决策

core-api 采用清晰的领域模块边界；AI、实时语音和异步任务作为独立服务/Worker。模块通过内部接口和事件通信，未来再按实际瓶颈拆分。

## 结果

- P0 开发速度更快，数据事务更简单。
- 可以提前建立服务边界和契约。
- 需要避免模块之间直接访问彼此的内部表和实现。
- 当拆分条件满足时，应新增 ADR 和迁移计划。

## 拆分触发条件

独立扩缩容、独立发布频率、不同安全域、不同数据保留策略或明确的团队所有权出现时，再考虑拆分。
