# Round 1 → Round 2 审计（Luna · 2026-10-19）

范围：`docs/design/mobile-uispec-20261017/` 全部 33 页浅色稿 + HTML 文案检索。Round 1 强制「与 Vue/store 逐字对齐」导致工程文案与状态面板泄漏进消费级 UI。

## 1. 入口 / 启动与按钮堆叠

| 页 | 问题 |
|---|---|
| onboarding | 主按钮外还有「账号设置 \| 退出登录」双出口；同意步有「按已有同意继续」+「重新读取」+「展开来源记录」，像后台流程 |
| assessment `held` | 「重新读取」+「返回学习首页」双主路径；说明写「定级进度在服务端…检查点」 |
| forbidden | 多出口并排（管理账号 / 帮助 / 退出 / 重新读取状态），像权限控制台 |
| b10-report offline | 主「重试」外底部再塞「词汇复习」「继续练习」两个次按钮 |
| home | 首屏 CTA「继续课程」尚可，但每页通用的 eyebrow + 长副文案占位过多 |
| login / register | 相对干净（单主按钮），可作为 v2 入口基线；仍有工具条外的「正在登录…」演示态 |

**主题**：启动/恢复路径缺少「一个主动作」；次要出口用文字链或溢出菜单即可。

## 3. 状态条 / 同步条噪音

- 学习与成长页普遍有「B10StatusPanel / B11StatusPanel / 学习同步状态」整卡：标题「已准备好，可以开始」「网络可用 · 学习同步状态」+「待同步 N」+「同步」+「画质 · 舒适」。
- 正常态仍占首屏，和「先主任务」冲突；用户看到的是运维面板，不是学习内容。
- 离线/错误时整页替换成状态块 + 工程副文案（见上表）。

## 4. Eyebrow / Kicker 过载

几乎每页英雄区：`icon + 紫色 kicker` → 大标题 → 两行说明。例：

- b10「看看你的进步」/ b11-reading「阅读角」/ b4-offline「随身学」/ home「今日 · 一点积累…」
- b6-platform / settings / support 列表卡再套一层 eyebrow（「原生与多端」「画质与降级」）

信息重复（导航标题已说明场景），首屏被推到折叠线以下。

## 5. 导航与控件不一致

- 二级页右上角常放「齿轮」但多数只打开画质/动效，不像设置。
- 「画质 · 舒适」「关闭动效」出现在阅读/听力/报告等内容页顶栏，打断学习流。
- Tab 一级页与带返回的二级页标题样式大体统一，但英雄区节奏不统一（有的有 kicker，有的没有）。

## 6. 空 / 错 / 离线模式

- 空态副文案直译后端：「服务端未返回…」
- 离线副文案讲同步语义：「待同步不等于已结算。」
- 部分页空/错做成整页大块；部分页（support/devices）已是卡内单行——**v2 应统一为：内容区轻量 inline / toast，保留一个主重试**。

## 7. 密度与排版

- 英雄区 + 状态卡 + 内容卡三层堆叠，首屏有效内容少。
- 字号阶梯尚可，但说明句偏长（一行一句讲实现细节）。
- 徽章过多（待同步 / 同步失败 / 待次日验证 / 巩固中 同屏）。

## 8. Round 2 优先级（给试点与全量）

1. **文案人性化**（禁词表 + 改写表）——立刻提升「正式产品」感。  
2. **拆掉常驻状态条**；同步/画质收入溢出或设置。  
3. **每屏一个主按钮**；次要出口降级为文字链。  
4. **砍掉或收敛 eyebrow**；标题直接说场景。  
5. **空/错/离线**：人话 + 单主动作；需要实现同步的 copy 在 INTERACTIONS 标「文案相对 Vue 已改，需更新 i18n」。
