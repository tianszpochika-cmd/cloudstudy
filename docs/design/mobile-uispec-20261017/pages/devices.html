交互说明（devices）

  • 主题与直达参数 → 工具条「浅色 / 深色」切换整页 token 并写入 localStorage['uispec-theme']；?theme=light|dark 固定主题；?state=normal|loading|empty|error|forbidden 直达页面状态；?mock=no-devices|load-error|revoke-error|others-partial|refresh-fail|no-current|no-others 演示卡内空态、读取失败、退出失败、部分退出失败、退出后刷新失败、当前设备不可确认与无其他设备；?mock=others-partial&refreshFails=1 演示「部分失败 + 刷新失败」组合，?refreshFails=1 让点击退出后的重新读取失败。截图（每项 ?theme=light|dark 各一张）：devices-{light,dark}.png；devices-{loading,empty,error,forbidden}-{light,dark}.png；devices-{no-devices,load-error,revoke-error,others-partial,refresh-fail,no-current,no-others}-{light,dark}.png。
  • 页面状态（工具条） → 加载态：卡内说明保留「退出设备后，该设备需要重新登录。」，其下另有内联状态行「正在读取设备列表…」，刷新按钮保留「刷新」文案并显示转圈、禁用（骨架行为设计新增）。空态：单行「当前账号还没有设备记录。」，图标 inbox（AppIcon name="inbox"），块内「刷新」按钮为设计新增（vue 只有卡头刷新）。错误态：单行「设备列表暂时无法读取，请重试。」+「重试」，与卡内 bad 条同一句，不再拆成标题 / 正文。无权限态：仅「登录后管理设备与会话。」+「去登录」→ login.html?returnTo=%2Fpages%2Fdevices%2Fdevices（设计新增：真实页 ensureMobilePageAccess 未登录直接跳转）。
  • 卡内页面状态 → 首次读取为卡内内联状态行「正在读取设备列表…」，卡头刷新按钮转圈并禁用；读取失败为卡内 bad 条「设备列表暂时无法读取，请重试。」+「重试」（listMobileDevices catch 兜底原文），列表清空；空为卡内 inbox 图标 +「当前账号还没有设备记录。」（deviceStatus='empty'）。
  • 状态恢复 → 切换离开正常态会关闭退出确认框、取消未完成的读取 / 退出计时并恢复按钮；错误与空态「重试 / 刷新」转圈后回到正常态，不弹成功 Toast；切回正常态恢复各 mock 的预置结果。
  • 页头与导航 → 导航栏「设备与会话」（pages.json 标题）+ 返回 settings.html（真实页从「设置 › 设备与会话」进入）；页内 kicker「账户安全」、标题「设备与会话」、说明「查看已登录设备，退出不再使用的会话。」（devices.vue 的 MobilePageHeader 参数）；不显示底部 TabBar。
  • 已登录设备卡 → eyebrow 图标 shield +「账户安全」，标题「已登录设备」，说明「退出设备后，该设备需要重新登录。」，右上「刷新」；行内显示设备类型（iOS 设备 / Android 设备 / 移动网页 / 网页浏览器 / 网页或移动浏览器，未知类型回落「其他设备」）、「设备编号 …后 8 位」、中文状态（当前设备 / 使用中 / 已退出）与「最近登录：2026年10月18日 21:05」（toLocaleString('zh-CN') 格式化，无法解析时显示「时间未知」）；不显示完整设备标识、账号 ID、指纹或会话编号。
  • 刷新 → 「刷新」按钮转圈并禁用其它操作（文案保持「刷新」，对齐 vue 的 :loading）→ 0.9s 后重新读取并清除已有的成功 / 失败反馈，不弹 Toast；读取前清空旧列表。
  • 退出此设备 → 仅「使用中」且非当前设备显示「退出此设备」；点击打开对话框「退出这台设备？」+「将结束设备 …后 8 位 的登录会话。」，按钮「取消」「确认退出」（危险色）。确认后按钮转圈、文案仍为「退出此设备」，其余操作禁用 → 0.9s 后重新读取列表：成功时该行变为「已退出」、按钮消失，底部成功条「该设备已退出，设备列表已刷新。」；读取失败时列表清空，显示卡内 bad 条「设备列表暂时无法读取，请重试。」+「重试」，其下再显示操作说明「退出请求已提交，但列表刷新失败；请刷新核对最新状态。」（warn 色为设计新增：vue 用 success 类渲染该句）。当前设备只显示「当前设备不能从此处退出。」，没有退出按钮；?mock=revoke-error 时显示 bad 条「退出设备失败，请重试。」并保留原状态。
  • 退出其他设备 → 主按钮文案「退出其他设备（N）」，N 为可退出的使用中设备数，N=0 时为真实禁用态；确认框「退出其他设备？」+「将结束其他 N 台设备的登录会话；当前设备会保留。」。确认后按钮转圈、文案保持「退出其他设备（N）」，全部行操作禁用 → 0.9s 后重新读取列表：成功时成功条「其他 N 台设备已退出。」，对应行变为「已退出」；读取失败时列表清空 + 卡内 bad 条，并显示「退出请求已处理，但列表刷新失败；请刷新核对最新状态。」（与单台路径文案不同，均为 vue 原文）。?mock=others-partial 时两台中一台成功、一台未完成，显示「1 台已退出，1 台未完成，请刷新后重试。」并保留未完成设备的操作按钮；若部分失败同时刷新失败，错误条与「已处理」说明同时出现。?mock=refresh-fail 打开即呈现单台路径的刷新失败结果（列表清空、读取失败条 +「已提交」说明）。对话框取消、遮罩与 Esc 都可关闭，关闭不改动列表。
  • 当前设备不可确认 → ?mock=no-current 在卡内顶部显示 warn 条「当前设备标识暂不可确认。为避免退出正在使用的设备，撤销操作已停用；请重新登录后再试。」（devices.vue 原文）；H5 行仍带 isCurrent 标记显示「当前设备」徽标与「当前设备不能从此处退出。」（isCurrentMobileDevice 优先 API 的 isCurrent）。隐藏所有行「退出此设备」并让「退出其他设备（0）」保持禁用是比 vue 更严格的保守分支（vue 仍渲染行按钮、只让整批退出成为空操作），标记为设计新增。
  • 无其他设备 → ?mock=no-others 只保留当前设备一行，「退出其他设备（0）」为禁用态；?mock=no-devices 卡内只显示 inbox 图标与「当前账号还没有设备记录。」。
  • 反馈与焦点 → 成功与失败 / 说明反馈都显示在卡内列表（或读取失败条）下方，带图标与文字（不只靠颜色）；操作完成后焦点移到反馈条；对话框打开时焦点进入「取消」，Esc 关闭。
  • 登录门禁 → 对齐真实页 onShow：先 ensureMobilePageAccess，未登录直接跳转登录页，不渲染设备页；原型以无权限态承载该分支（设计新增）。
  • 文案边界 → 不显示原始状态枚举、内部错误码、会话 token 或设备指纹；退出结果以服务端确认为准，刷新失败时明确要求用户刷新核对，不把请求提交说成列表已更新。
