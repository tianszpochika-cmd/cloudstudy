  only type, planned action, actual action, phase, and unexpectedness; no message text,

  native `beforeunload`; it is not awaited or required there. The **second** physical back

  document departure is a measured UX failure; no observed second traversal branch is
  setup-incomplete. Assertions remain the visible assessment root + A draft + focus + one
  prompt; raw pending URL is recorded, not asserted. Only after custom cancel completes is
  the assessment URL required.
- Added independently selectable `repeat-native-accept`: the **first** physical back is
  the ordinary SPA pop and must show the custom prompt with root + A draft; it must not fire
  native `beforeunload`. The **second** physical back crosses the document, the explicit
  logger intentionally **accepts** the native `beforeunload`, and the case asserts actual
  event action `accept`, intentional document departure, and zero
  `respond`/`retest`/`ensure`. If the first back leaves without the custom prompt, that is a
  measured UX fail, not setup. If no native event occurs on the second back, the branch is
  setup-incomplete, not PASS. This is browser-native warning acceptance, not nativeApp
  acceptance.
- Old pending-promise / cannot-navigate facts are recorded; they are not used to waive a
