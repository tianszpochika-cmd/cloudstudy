# R1-002 D1 independent preflight

Date: 2026-10-07. Reviewer: independent Luna review. Scope: D1 offline lifecycle / production-class probe criteria and a bounded read-only review of identity candidate A. This is a preflight, not acceptance of an implementation, not authorization for D2/D3, and does not change R1-002 readiness.

## Stage decision

**D1 may proceed within the already named offline implementation scope.** The execution plan cleanly separates offline preparation from the maintenance window and identity decision: D1 is only the named files, offline stage and negative-boundary checks; occupied ports, old runner shutdown, live TLS, database and registration are explicitly outside that approval ([execution plan, lines 5–13](../../R1-002-next-round-plan/execution-plan.md#L5-L13), [lines 26–40](../../R1-002-next-round-plan/execution-plan.md#L26-L40)). Final D1 acceptance is pending review of the stable source and evidence. D2, D3 and `PREPARATION_PARTIAL_NOT_READY` remain unchanged.

The minimum acceptance criteria below are mandatory for the D1 package. A correctly surfaced production-source gap is not hidden by the harness and does not authorize edits to Gateway/IAM service code under this D1 scope.

## Minimum D1 acceptance criteria

1. **Fail-closed lifecycle guard (P0).** The tool reads the registered fixed ports from `config/local-ports.json`; with either port occupied, no valid run receipt, an invalid signature, mismatched source/artifact, wrong owner/mode/type, or an ambiguous process identity, it refuses before launch/stop. Negative evidence must show zero signal sent, zero new listeners, and zero database operation. No adopt-existing, kill-by-port, kill-all, or automatic port substitution. The existing `--all` runner has no suitable signed startup receipt and must never be adopted or stopped by this package ([plan, lines 17–24](../../R1-002-next-round-plan/execution-plan.md#L17-L24), [lines 48–56](../../R1-002-next-round-plan/execution-plan.md#L48-L56)).

2. **Stop only a child this run still supervises (P0).** A stop request must require this run's verified receipt and the same live `ChildProcess` handle created by the supervising process, plus fresh PID/start identity, executable, working directory, copied artifact and port-listener checks. Send only the planned graceful signal, wait for that exact child and verify release of its registered port; timeout is a recorded failure, without escalating to `SIGKILL` or signaling a replacement PID. A detached CLI must refuse on macOS if it cannot retain or obtain a race-resistant OS process handle. macOS PID/PPID, executable/cwd and birth-time checks are useful detection but do not atomically eliminate PID-reuse TOCTOU; a signed receipt cannot fix that race. The plan itself identifies this limit and prefers the same supervisor handle ([plan, lines 42–50](../../R1-002-next-round-plan/execution-plan.md#L42-L50)).

3. **Distinguish test evidence classes (P1).** Label pure unit tests and synthetic OS records as fixtures. Label an actual POSIX child test as a disposable test child spawned and held by the test process. Neither proves the identity of a currently running service nor a cross-CLI macOS PID-reuse guarantee. Do not describe fixture-only branches as OS rejection tests. Do not signal any existing project process during D1.

4. **Bind source, built artifact and loaded production classes (P0).** The signed receipt must bind the Git HEAD and every relevant dirty-source digest, port registry digest, pinned Java executable/version, build command/result, copied run-specific JAR path and SHA-256, and the actual class/dependency CodeSource used by the probe. A manifest label, source path or expected JAR name alone is insufficient. Record only allowlisted non-secret arguments and no environment dump, private key, credential, token, private path or low-entropy secret digest. The receipt signing key is isolated from the IAM RS256 key and is integrity evidence, not an IAM credential or proof that an unreceipted process is owned ([plan, lines 42–50](../../R1-002-next-round-plan/execution-plan.md#L42-L50)).

5. **Exercise the actual two clients, and report the limit precisely (P0).** The probe must bind to the actual Spring Cloud Gateway route WebClient and the actual `GatewayIamPublicJwkSource` WebClient/JVM trust path. They are separate clients; a Node/curl success, a copied trust implementation, or one client standing in for the other is not evidence for both. Offline compilation and selector invocation may establish build/class binding and static negative behavior only. Without starting the synthetic publisher or client against a TLS endpoint, evidence must say that no HTTPS handshake, hostname check, route TLS, independent JVM trust, timeout or HTTP response was executed. The eight TLS cases are future dynamic tests, not D1 passes ([plan, lines 35–38](../../R1-002-next-round-plan/execution-plan.md#L35-L38), [lines 62–75](../../R1-002-next-round-plan/execution-plan.md#L62-L75)).

6. **Preserve honest TLS-07 behavior (P1 security gap).** The current production `GatewayIamPublicJwkSource.parseJwkSet` calls `JWKSet.parse` after envelope extraction, and `matching` selects solely by `kid`; neither method rejects private RSA members. The existing unit fixture supplies a public-only key and asserts that selected output lacks `d`, which does not test rejection of an input carrying private parameters ([source, lines 120–159](../../../../../services/api-gateway/src/main/java/com/englishflow/gateway/config/GatewayIamPublicJwkSource.java#L120-L159), [test, lines 35–48 and 133–142](../../../../../services/api-gateway/src/test/java/com/englishflow/gateway/config/GatewayIamPublicJwkSourceTest.java#L35-L48)). The D1 probe must pass a synthetic private-bearing document through the actual production source and report the observed result without filtering fields, cloning the selector or printing key material. If the source selects that key, classify the public-only rejection as **GAP / unexpected private JWK selected**; do not claim the production source rejected it. Service remediation or a source-contract change requires a separately authorized scope.

7. **Sanitize evidence without changing execution inputs (P1).** Keep real Git-external material paths and private material outside committed evidence. Sanitize archived copies only, preserving lstat/owner/mode/type and source/artifact hashes. Use explicit private-directory placeholders only where required and keep them separate from relative source paths so a placeholder is never treated as a source location. Confirm logs and receipts contain no secret bytes or key-bearing JSON.

## Future window and readiness boundary

D1 acceptance can cover only implementation and offline evidence. The execution plan requires a separately owned maintenance window, preserved recovery bundle, verified full-stack restoration, and registered ports free before D2. Only then may a synthetic TLS publisher use the two registered ports; each production client must be separately observed against it. A later real IAM run has a separate fresh-database/migration gate, and neither TLS nor a test token closes registration or business acceptance ([plan, lines 52–60](../../R1-002-next-round-plan/execution-plan.md#L52-L60), [lines 62–79](../../R1-002-next-round-plan/execution-plan.md#L62-L79)).

Therefore, D1 must not be represented as TLS success, clean database replay, registered-account acceptance, R1-002 `READY`, or closure of either dynamic HTTPS chain. Keep the route client and independent source client open as separate evidence rows; keep TLS-07 private-only behavior open if the production source does not reject private JWKs.

## Identity candidate A: bounded read-only finding

Candidate A preserves `PrincipalId(UUID)`, UUID JWT `sub` and B8 UUID subject while proposing an `IAM_PRINCIPAL_WIRE_V1` `prn_` wrapper only for event wire identity ([draft, lines 7–14](../../R1-002-next-round-plan/identity-decision-A-draft.md#L7-L14)). This is structurally compatible with the frozen M1-018 payload regex, whose accepted `prn_` suffix is broader than canonical UUID; it does not by itself prove semantic equivalence or approve changing identity behavior ([M1-018 schema, lines 60–74](../../../../../packages/contracts/events/v1/fragments/m1-018-iam-v2.events.json#L60-L74)). No contract edit is needed merely to choose one valid value within the current pattern, but the representation mapping and cross-field invariants still need owner and governance approval.

The exact unresolved points for any later D3 decision are:

- **Legacy provenance:** produce an owner-signed, redacted inventory distinguishing official issuer output and persisted owner facts from test fixtures, mocks and seeds. Record source/version/time range and counts or hashes, not real IDs or tokens. Determine whether any valid legacy opaque `prn_` JWT subject or learner owner row exists; if provenance or absence cannot be established, keep mapping/compatibility OPEN. Do not strip, hash or silently reject accepted historical values merely to make codec tests pass ([draft, lines 11–12 and 39–44](../../R1-002-next-round-plan/identity-decision-A-draft.md#L11-L44)).
- **Anonymous registration actor semantics:** the draft proposes `actorId == aggregateId == payload.principalId == encode(createdPrincipalUUID)` but explicitly flags that event-governance review must resolve whether the actor is the newly created principal ([draft, line 9](../../R1-002-next-round-plan/identity-decision-A-draft.md#L9)). The frozen envelope only types `actorId` as a non-empty string up to 64 chars; M1-018 does not encode that equality ([catalog, lines 472–529](../../../../../packages/contracts/events/v1/catalog.json#L472-L529)). IAM/event governance and audit owners must state whether the actor denotes the unauthenticated requester, the new account after creation, or a system actor, and approve the chosen representation before implementation. Do not infer “anonymous” from `SELF_REGISTERED_ADULT_CANDIDATE` or make the equality a new invariant without that approval.
- **Identity resolver and default-deny compatibility:** approve the two HTTP owners using the same verified-sub resolver, optional claim equality rules, legacy mapping owner and its read-only/versioned/revocable facts, default-deny response, and tests retaining current 401/403 and PEP behavior. Mapping success must not grant eligibility or access ([draft, lines 10–14 and 26–35](../../R1-002-next-round-plan/identity-decision-A-draft.md#L10-L35)).
- **Formal decision and frozen checks:** before D3 code, record the selected representation and supported UUID versions, actor semantics, legacy policy, named IAM/learner scope, new ADR identifier assigned by the root reviewer, and unchanged canonical/auth checker results. Do not change canonical fixtures, regex, hashes or task acceptance in order to absorb implementation behavior ([draft, lines 39–60](../../R1-002-next-round-plan/identity-decision-A-draft.md#L39-L60)).

These items are independent of D1. D1 does not approve D3, create an identity mapping, alter event/API/JWT fields, or close the existing UUID/`prn_` compatibility conflict.
